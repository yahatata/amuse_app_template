## 1. 目的

本ドキュメントは、**案 D**（ドメイン単位で進め、そのドメインに必要な shared をその都度移す）に基づく**移管の実行手順**を定義する。  
各ステップで「影響ファイル集合」を機械的に限定し、1 ステップの作業爆発を抑えつつ、全 import の書き換えと index の適切な作成を守る。

**前提**：`新フォルダ別_設計/` および `00_shared.md` の To-Be が確定していること。移管順序のみを本ドキュメントで固定する。

---

## 2. 遵守事項（全ステップで共通）

- ファイルを移動するたびに、**「影響ファイル集合」**（3. で定義）を求め、**その集合に属する全ファイルの全 import** を新フォルダ別_設計・00_shared に照らして**すべて書き換える**。漏れゼロ。
- **影響ファイル集合の一覧は必ず残す**（ステップごとに一覧をドキュメントまたはチェックリストとして記録する）。
- **index** は、そのブロックの export が揃ったタイミングで、必要な分だけ作成・更新する。export 名（関数名）は維持する（03_設計ルール・04 方針）。

---

## 3. 影響範囲の定義（共通チェックに組み込む）

### 3.1 影響ファイル集合のルール

**影響集合** = （このステップで移動したファイル）  
　∪ （それらを import しているファイル）  
　∪ （そのファイルをさらに import しているファイル）  
　∪ … （同様にたどる）

### 3.2 探索の打ち切り条件

次のいずれかに**到達した時点で、その方向の探索を打ち切る**。

- **入口**：onCall / onSchedule / onDocument 等の**エントリポイントとして定義されているファイル**（05_入口一覧の「現在パス」に相当するファイル）
- **ルート index**：`functions/src/index.ts`

- 入口や root index **自体**は影響集合に含めるが、**その先**（入口から呼ばれる別ドメインのファイルなど）は、このステップの影響集合には含めない。
- 結果として、1 ステップで変更するファイルが機械的に閉じる。

### 3.3 各ステップで行うこと

1. 移動対象ファイルを列挙する。
2. 上記ルールで **影響集合** を求め、**一覧に書き出して残す**。
3. 影響集合に含まれる**全ファイル**について、**すべての import** を確認し、設計書に従って書き換える。
4. 入口や root index が影響集合に含まれる場合は、そのファイル内の import も漏れなく書き換える（「その先」は別ステップで扱う）。
