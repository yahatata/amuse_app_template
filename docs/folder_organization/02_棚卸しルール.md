# 02_棚卸しルール.md（テンプレ）

## 1. 目的

旧フォルダ構造（functions/src 直下の各フォルダ等）を対象に、全ファイルを漏れなく棚卸しし、各ファイルの **移行先（ドメイン＋フォルダ）** を決めるためのルールを定義する。

## 2. 棚卸し対象（必須）

- **対象範囲**：`functions/src/**` 配下のファイル（例外があればここに列挙）
- 旧フォルダ単位で棚卸しドキュメントを作成し、対象フォルダ内の **全ファイル** を列挙する
- **出力先**：`旧フォルダ別_棚卸し/XX_<旧フォルダ名>.md`

## 3. 棚卸しの判断軸（固定）

棚卸しで各ファイルに対し、最低限以下を判定・記録する。

### 3.1 種別（どれか1つ）

- **callable**（onCall / https 入口）
- **trigger**（Firestore等イベント入口）
- **scheduler**（定期実行入口）
- **service**（業務処理の本体）
- **repos**（Firestore I/O）
- **shared候補**（横断カテゴリ候補）

### 3.2 入口判定（重要）

- `onCall` / `onRequest` / `onDocument*` / `onSchedule` を含む場合、**入口**として扱う
- 入口はリポジトリ内に「呼び出し元」が無いのが普通。**呼び出し元なし＝未使用確定にしない**

### 3.3 shared判定（重要）

- **「複数から呼ばれる」だけでは shared にしない**
- **「どのドメインでも意味が同じ」** 場合のみ shared 候補とする
- shared候補の場合は、どのカテゴリ（time/idempotency/logging/firebase/validation…）にするかを提案し、必要ならカテゴリ追加も記録する  
  ※カテゴリ追加は `08_意思決定ログ.md` に残す前提

## 4. 未使用（削除候補）の扱い（固定）

- 本フェーズでは**削除しない**。未使用は **“候補”** として記録するだけ。
- “候補”として記録して良い例：
  - `to_be_deleted_*` のみ参照
  - exportされていない、かつ入口でもない、かつ参照も見当たらない
- ただし**最終削除判断は安定化フェーズで別途行う**

## 5. 出力フォーマット（必須：表で統一）

棚卸しドキュメントは、対象フォルダごとに以下の表を必ず含める。

### 5.1 棚卸し表（テンプレ）

各項目には番号（①〜⑨）を付与する。具体ファイルを記載する際は、**各セルの先頭に対応する番号を付けて記入**すること（列の対応関係が一目で分かるようにする）。

| ①ファイル | ②種別 | ③入口(Yes/No) | ④export(Yes/No/不明) | ⑤主に触るデータ/コレクション | ⑥呼び出し元メモ（あれば） | ⑦移行先（ドメイン/フォルダ or shared/カテゴリ） | ⑧未使用候補 | ⑨備考 |
|-----------|--------|----------------|----------------------|-----------------------------|---------------------------|--------------------------------------------------|-------------|-------|
| ①（例）   | ②     | ③              | ④                    | ⑤                          | ⑥                        | ⑦                                                | ⑧            | ⑨      |

#### 項目番号の対応

| 番号 | 項目 |
|------|------|
| ① | ファイル |
| ② | 種別 |
| ③ | 入口(Yes/No) |
| ④ | export(Yes/No/不明) |
| ⑤ | 主に触るデータ/コレクション |
| ⑥ | 呼び出し元メモ（あれば） |
| ⑦ | 移行先（ドメイン/フォルダ or shared/カテゴリ） |
| ⑧ | 未使用候補 |
| ⑨ | 備考 |

#### 記入ルール（簡潔）

- **②種別**：上記 3.1 のいずれか
- **③入口**：onCall/onRequest/onDocument*/onSchedule を含むなら Yes
- **④export**：index.ts（等）から辿れるなら Yes、確認できないなら 不明
- **⑦移行先**：`domains/<domain>/{callables|triggers|scheduler|services|repos}` または `shared/<category>`
- **⑧未使用候補**：Yes/No（Yesの場合は⑨備考に理由）

## 6. 棚卸しドキュメントの構成（必須）

各 `旧フォルダ別_棚卸し/*.md` は以下の順で記述する。

1. **対象フォルダの概要**（1〜2行でOK）
2. **棚卸し表**（上記）
3. **追加メモ**（判断が割れたもの／shared候補の理由／未使用候補の根拠など）
4. **次アクション**（例：入口一覧の更新が必要、設計に回す事項 等）

## 7. Cursorの作業完了時サマリ（README準拠）

棚卸し完了後、チャットに以下を必ず出す。

- **生成/更新ドキュメント**
- **未確定事項**（判断が必要な点）
