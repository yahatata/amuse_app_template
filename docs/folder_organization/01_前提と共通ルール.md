# 01_前提と共通ルール

## 1. 目的

本ドキュメントは、functions/src のフォルダ再編（ドメイン化）における 共通前提・判断基準・禁止事項を固定する。
棚卸し・設計・実行の全作業で、Cursor と人間は本ドキュメントを参照して判断を揃える。

## 2. スコープ

- **主対象**：`functions/src`
- **付随対象**：`functions/src/index.ts`（またはエントリポイントの export 集約）
- **Flutter側**：本改修では原則非スコープ（必要な場合のみ最小限の整理）

## 3. 最小フォルダ構成（ドメイン配下の確定事項）

各ドメイン配下に用意する基本フォルダは以下で確定。

| フォルダ | 役割 |
|----------|------|
| `callables/` | アプリ等から直接呼ばれる入口（onCall / https 等） |
| `triggers/` | Firestore等イベント起点の入口（onCreate/onUpdate 等） |
| `scheduler/` | 定期実行起点の入口（onSchedule 等） |
| `services/` | 業務ロジック本体（整合性・不変条件の中心） |
| `repos/` | Firestore読み書き（I/O）の集約 |

**注**：上記以外のフォルダ追加（例：`types/` など）は、必要に応じて許容するが、追加判断は `08_意思決定ログ.md` に残す。

## 4. “ドメイン”の定義（判断基準）

### 4.1 ドメインとは

ドメインは「UIページ」や「コレクション1つ」ではなく、**業務上の責務（Business Capability）**を指す。

### 4.2 ドメイン境界の決め方（優先順位）

以下の観点で同一と判断できるものを同一ドメインに寄せる。

1. 業務概念・用語が同じ（例：会計、勤怠、営業管理）
2. 守るべき整合性（invariant）が同じ
3. ライフサイクル（生成→更新→確定→集計）が同じ
4. 権限モデル（admin/terminal/staff 等）が同じ
5. 主に触るデータ集合（関連コレクション群）が同じ

## 5. shared（横断）の定義と配置ルール（重要）

### 5.1 shared の定義

shared は「複数ドメインで同じ意味で使うもの」だけを置く。
**“複数から呼ばれる” だけを理由に shared に入れない。**

### 5.2 shared のカテゴリ（固定）

shared は “カテゴリフォルダ” として管理し、カテゴリは必要に応じて追加する。
初期カテゴリ（空でも作成可）：

- `shared/time/`（時間・JST・営業日計算の汎用）
- `shared/idempotency/`（冪等・重複抑止の共通部品）
- `shared/logging/`（構造化ログ）
- `shared/firebase/`（admin初期化等の共通基盤）
- （必要になったら）`shared/validation/`

**禁止**：`shared/utils/` を作らない（ブラックホール化防止）

### 5.3 shared 追加判断

sharedカテゴリ追加や shared への移動判断は **必ず** `08_意思決定ログ.md` に記録する。

## 6. 未使用（削除候補）の扱い（重要）

### 6.1 基本方針

本改修フェーズでは **削除しない**。未使用は「候補」として記録するに留める。

### 6.2 誤判定防止の注意

onCall / trigger / scheduler は、リポジトリ内に「呼び出し元」が存在しないのが普通（外部・Firestore・時間が起点）。

したがって **「呼び出し元が見つからない＝未使用確定」にはしない。**

### 6.3 未使用“候補”として記録して良い条件（例）

- `to_be_deleted_*` のみから参照されている
- 明確に旧仕様の残骸で、入口一覧にも載っていない
- 参照がゼロ（リポジトリ内検索）かつ export もされていない

※ただし削除は安定化フェーズで最終判断する。

## 7. 変更ポリシー（この改修でやること／やらないこと）

### 7.1 やること

- ファイルの配置整理（移動）
- import パスの修正
- export（index.ts等）のパス修正
- ドキュメント（棚卸し／設計／changeSpec）の作成・更新
- 最低限のビルド・検証（07_検証基準 に従う）

### 7.2 やらないこと（原則禁止）

- 業務ロジックの意味変更
- 大規模なリネーム（関数名・export名を変える）
- sharedへの雑な集約（“とりあえずshared”を禁止）

## 8. 実行単位（進め方の共通ルール）

- 作業は **ドメイン単位**で進める
- 1ドメインの移管が完了するたびに、最低限の検証を通す（07_検証基準）
- 変更は小さく刻み、原因切り分け可能な状態を維持する
