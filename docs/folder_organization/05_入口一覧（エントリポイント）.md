# 05_入口一覧（エントリポイント）

## 1. 目的

- **functions/src** からデプロイされる Cloud Functions の **入口（onCall / onRequest / onDocument* / onSchedule）** を一覧化する。
- 棚卸し・設計・changeSpec 実行時に「どの export がどこに属するか」「移行後の整合性」を確認するための参照とする。
- 本ドキュメントは **index.ts の export を漏れなく反映** し、移行後も更新を続ける。

## 2. 用語・凡例

| 用語 | 意味 |
|------|------|
| **入口** | Cloud Functions のエントリポイント。onCall / onRequest / onDocumentCreated / onDocumentUpdated / onSchedule で定義された関数。 |
| **現在パス** | 改修前の `functions/src` 配下の定義ファイル（export 元）。 |
| **移行先ドメイン** | 04_新フォルダ構造 のドメイン一覧に基づく配置先。`domains/<ドメイン名>/callables|triggers|scheduler` 等。 |

## 5. 移行時の整合性確認チェックリスト

- [ ] 各入口の **export 名** は変更しない（03_設計ルール 4.4）。
- [ ] **index.ts** の参照パスを移行先に付け替えた後、ビルドが通る。
- [ ] 05 の「現在パス」を移行後に「新パス」に更新する。
- [ ] スタブ 3 件（lineWebhook, processShiftsByStaff, updateAdministrativeMenuWithDescription）は移行後も index で維持するか、別扱いを 08_意思決定ログ に記録する。
- [ ] shift を index に追加する場合、05 に shift 配下の callables / scheduler を追記する。

## 6. 備考

- **getBlindTemplates** は tournamentBlind と callables の両方から export されている。index では後から読み込まれる callables 側が有効。移行後は 1 か所に統一すること。
- **lineWebhook**：index.ts 内でスタブが定義されており、webhook/lineWebhook.ts の実装は index からは使われていない。リモート維持用スタブのため、移行時も index のスタブを残すかどうか要判断。
- **shift**：shift/index.ts には多数の onCall と scheduleGenerateNextYearBusinessHours があるが、ルート index.ts に `export * from "./shift"` が無い。デプロイ方法に依存するため、移行設計で取り込むか 08_意思決定ログ に記録すること。
