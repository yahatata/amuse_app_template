# 03_設計ルール.md（テンプレ）

## 1. 目的

棚卸し結果（`旧フォルダ別_棚卸し/`）を元に、新ドメイン構造と **ファイル配置（from→to）**、および **index.ts の変更方針**を設計するためのルールを定義する。

## 2. 入力（参照必須）

- `01_前提と共通ルール.md`
- `04_新フォルダ構造.md`
- `05_入口一覧（エントリポイント）.md`
- 該当する棚卸しドキュメント（`旧フォルダ別_棚卸し/*.md`）

## 3. 新ドメイン設計の出力先（固定）

- **出力先**：`新フォルダ別_設計/XX_<ドメイン名>.md`
- 1ドメイン = 1設計ドキュメント（例外がある場合のみ `08_意思決定ログ.md` に記録）

## 4. 設計の判断基準（固定）

### 4.1 ドメインの決め方

UIページ基準ではなく、**業務概念・整合性・ライフサイクル**を優先する

### 4.2 sharedの扱い

- sharedは**最小限**（意味が横断で同一のみ）
- sharedカテゴリ追加が必要な場合は、設計内に明記し、`08_意思決定ログ.md` へ記録する

### 4.3 入口（callables/triggers/scheduler）の扱い

- 入口はドメイン配下に配置する
- 入口の中身が厚い（処理同居）は許容（本フェーズではロジック抽出を必須としない）

### 4.4 index.ts 変更方針（重要）

- **原則**：関数名（export名）を維持する
- パス変更のみで export を付け替える（**大規模リネーム禁止**）
- 入口一覧（05）との整合を取る

## 5. 出力フォーマット（必須）

設計ドキュメントは以下の章立てで統一する。

### 5.1 ドメイン定義（短く）

- ドメインの目的（1〜2行）
- 主に扱うデータ/コレクション（箇条書き）

### 5.2 フォルダ構成（確定）

- `callables/` `triggers/` `scheduler/` `services/` `repos/`
- （追加する場合のみ）追加フォルダと理由

### 5.3 移動一覧（from → to）（表で統一）

| 現在パス | 新パス | 種別 | 備考（互換/注意点） |
|----------|--------|------|---------------------|
|          |        |      |                     |

### 5.4 index.ts 変更方針（表 or 箇条書き）

- どの export をどの新パスへ向けるか
- 互換維持の注意点（関数名維持など）

### 5.5 検証手順（07に準拠）

- このドメイン移管後に必ず実行するビルド/検証
- 失敗時の切り戻し方針（最小単位で戻す）

### 5.6 未確定事項

- sharedカテゴリ追加の是非
- ドメイン境界の迷い
- 未使用候補の扱い（削除は別フェーズ）

## 6. Cursorの作業完了時サマリ（README準拠）

設計完了後、チャットに以下を必ず出す。

- **生成/更新ドキュメント**
- **主要な判断点**（shared追加、境界判断）
- **次にやること**（changeSpec作成→実行 等）
