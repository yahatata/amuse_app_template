# 04_新フォルダ構造

## 1. 目的

本ドキュメントは、**functions/src の改修後のフォルダ構造**を定義する。
設計（03）・changeSpec（06）・実行時の参照として用い、配置の一貫性を保つ。

## 2. スコープ

- **対象**：`functions/src/` 配下
- **付随**：`functions/src/index.ts`（エントリポイントの export 集約）
- ドメイン一覧は棚卸し・設計で確定次第、本ドキュメントの表を更新する

## 3. ルート構成（確定）

```
functions/src/
├── index.ts                 # 全 export の集約（関数名は維持）
├── domains/                 # ドメイン別配置
│   └── <ドメイン名>/
│       └── （4. に従う）
└── shared/                  # 横断カテゴリ（5. に従う）
```

## 4. ドメイン配下の最小フォルダ構成（確定）

各 `domains/<ドメイン名>/` 配下に、以下の基本フォルダを用意する。
（01_前提と共通ルール 3. と同一）

| フォルダ | 役割 |
|----------|------|
| `callables/` | アプリ等から直接呼ばれる入口（onCall / https 等） |
| `triggers/` | Firestore等イベント起点の入口（onCreate/onUpdate 等） |
| `scheduler/` | 定期実行起点の入口（onSchedule 等） |
| `services/` | 業務ロジック本体（整合性・不変条件の中心） |
| `repos/` | Firestore読み書き（I/O）の集約 |

- **index.ts の export 方針**：index.ts は **入口（callables / triggers / scheduler）** を中心に export する。services / repos は原則として内部利用とし、必要時のみ export する（export の肥大化を防ぐ）。
- 上記以外のフォルダ（例：`types/`）を追加する場合は、`新フォルダ別_設計/XX_<ドメイン名>.md` に理由を記載し、必要なら `08_意思決定ログ.md` に記録する。

## 5. shared 配下のカテゴリ（確定）

shared は「複数ドメインで同じ意味で使うもの」のみを置く。カテゴリは以下で固定し、追加時は `08_意思決定ログ.md` に記録する。
（01_前提と共通ルール 5.2 と同一）

| カテゴリ | 役割 |
|----------|------|
| `shared/time/` | 時間・JST・営業日計算の汎用（generateJstDateKey, config/ops 含む）。08 に記録 |
| `shared/devices/` | デバイス・権限チェックの共通（requireAdmin, devicePermissions）。08 に追加記録 |
| `shared/businessHours/` | 営業日・営業時間の作成・編集（shift から分離）。08 に追加記録 |
| `shared/idempotency/` | 冪等・重複抑止の共通部品 |
| `shared/logging/` | 構造化ログ |
| `shared/firebase/` | admin初期化等の共通基盤。環境変数（lib/env）、calculateFirestoreSize 等。08 に記録 |
| `shared/validation/` | （必要になったら追加） |
| `shared/http/` | HTTP 入口（例: controlHook）。特定ドメインに属さない入口。08 に記録 |
| `shared/types/` | 複数ドメインで参照する共通型（例: ActionLog, ActionType）。08 に記録 |

- **禁止**：`shared/utils/` は作らない。
- **特殊フォルダ（08 で記録済み）**：**to_be_deleted**（ドメイン配下に置く未使用関数の退避用。ファイル名に `to_be_deleted` をつける。例：domains/tournament_createTournament/to_be_deleted/getScheduledTournaments_to_be_deleted.ts）。**unused_function_lib**（未使用の lib 由来モジュール退避用。デプロイ対象外。例：functions/src/unused_function_lib/serverStage.ts, runtimePath.ts）。

## 6. パス・命名の規則

- **ドメイン名**：業務上の責務を表す名前（英語・lowercase 推奨）。一覧は 7. を参照。
- **移行先パス**：
  - ドメイン配下：`domains/<ドメイン名>/{callables|triggers|scheduler|services|repos}/`
  - 横断：`shared/<カテゴリ>/`
- **index.ts**：export 名（関数名）は変更せず、参照パスのみ新パスに付け替える（03_設計ルール 4.4）。
