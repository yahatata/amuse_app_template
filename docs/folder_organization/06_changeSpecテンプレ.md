# 06_changeSpecテンプレ.md（テンプレ）

## 1. 目的

本changeSpecは、特定ドメインのフォルダ移管（作成・移動・export付け替え）を、**ロジック変更なし**で安全に実施するための差分仕様である。

## 2. 対象

- **対象ドメイン**：`<domain名>`
- **対象範囲**：
  - `functions/src/domains/<domain名>/**`
  - `functions/src/index.ts`（または export 集約ファイル）
  - （必要な場合のみ）`functions/src/shared/**`
- **非対象（原則）**：
  - 業務ロジックの意味変更
  - 関数名（export名）の変更
  - sharedの無秩序な増加（カテゴリ追加は理由必須）

## 3. 前提・参照（作業前に必読）

- `01_前提と共通ルール.md`
- `03_設計ルール.md`
- `04_新フォルダ構造.md`
- `05_入口一覧（エントリポイント）.md`
- `新フォルダ別_設計/XX_<domain名>.md`（本ドメイン設計）

## 4. 実施内容（概要）

**実施すること（箇条書き）**

- 例：callables/* を新パスへ移動し import 修正
- 例：index.ts の export パス付け替え

**実施しないこと（箇条書き）**

- 例：service抽出等のロジック改善は行わない

## 5. 変更一覧（必須：from → to）

「移動＋import/export修正のみ」を明確化するため、必ず表で列挙する。

| No | 現在パス（from） | 新パス（to） | 種別 | 変更内容 | 備考 |
|----|------------------|--------------|------|----------|------|
| 1  |                  |              | callable/trigger/scheduler/service/repos/shared | 移動 / import修正 / export修正 | 互換維持など |
| 2  |                  |              |      |          |      |

### 記入ルール

- **変更内容** は「移動」「import修正」「export修正」以外を書かない（ロジック変更禁止）
- sharedへ移す場合は **備考** に「カテゴリ（例：time/idempotency）」と理由を書く

## 7. 入口一覧（エントリポイント）への反映（必須）

- `05_入口一覧（エントリポイント）.md` の更新内容を記載
  - 移行先の更新（domain/folder）
  - export整合性の確認結果
- 未使用候補が出た場合は「候補」として記録（削除しない）

## 8. 実行手順（最小・固定）

1. 新規フォルダ作成（不足があれば）
2. ファイル移動（表No順）
3. import 修正（コンパイルが通る状態へ）
4. export（index.ts等）付け替え
5. 07_検証基準 に従い検証
6. 成果物（ドキュメント更新）をコミット単位で整理

## 9. 検証手順（必須：07に準拠）

- **実行するコマンド**（ここは 07_検証基準 の該当項目を引用）
- **成功条件**（例：tsc/buildが通る、lintが通る）

## 10. ロールバック（必須）

- **ロールバック方針**：このドメイン移管だけ戻せる単位で行う
- **手順（最小）**
  1. 移動したファイルを元のパスへ戻す
  2. index.ts export を元に戻す
  3. ビルドで復旧確認

## 11. 既知のリスク・注意点（必要なら）

- 例：export付け替え漏れ、sharedカテゴリ追加の判断、など
