# フォルダ再編_改修 README

## 目的

本フォルダは、**functions/src のフォルダ再編（ドメイン化）**を、安全に・段階的に進めるための ルール／棚卸し／設計／changeSpec／検証を集約する。
Cursor は本READMEの指示に従い、作業前に必ず該当ドキュメントを参照すること。

## 改修のスコープ（基本方針）

- **対象**：主に `functions/src`（Flutter側は必要最小限の整理に留める）
- ドメイン配下の基本フォルダは以下で確定：
  - `callables` / `triggers` / `scheduler` / `services` / `repos`
- 改修の基本は **配置整理（移動＋import/export修正）**であり、ロジック変更は原則しない  
  （ロジック変更が必要な場合は「別タスク／別changeSpec」とする）

## 作業タイプ別：必読ドキュメント（参照順）

Cursor は、作業開始前に必ず以下を **上から順に**読むこと。

### A. 棚卸し（旧フォルダ別棚卸し）を行う場合

1. `01_前提と共通ルール.md`
2. `02_棚卸しルール.md`
3. `05_入口一覧（エントリポイント）.md`（存在する場合は更新・突合も行う）

### B. 新フォルダ設計（ドメイン別設計）を行う場合

1. `01_前提と共通ルール.md`
2. `03_設計ルール.md`
3. `04_新フォルダ構造.md`
4. `05_入口一覧（エントリポイント）.md`

### C. 実行（フォルダ作成・移動・index.ts更新・ビルド確認）を行う場合

1. `09_移管ステップ（案D）.md`（移管順序・影響範囲・遵守事項を確認する）
2. `06_changeSpecテンプレ.md`（該当ドメインのchangeSpecを作る/参照する）
3. `07_検証基準（ビルド・テスト）.md`
4. `05_入口一覧（エントリポイント）.md`（export/入口の整合性確認）

## Cursor のチャット出力ルール（必須）

各作業（棚卸し・設計・実行）ごとに、作業完了時に必ず以下を出力する。

- **実施内容サマリ**（何をしたか）
- **生成/更新したドキュメント**（ファイルパス一覧）
- **変更したコードファイル**（ファイルパス一覧）
- **未確定事項 / 判断が必要な点**（箇条書き）
- **次にやるべきこと**（箇条書き）
- **リスク / 影響範囲**（ある場合のみ）

## 禁止事項（破ると作業停止）

| 禁止事項 | 内容 |
|----------|------|
| ロジック変更を混ぜない | 原則：移動・import修正・export修正のみ。ロジック変更が必要なら、別タスクとして明示する |
| 大規模な一括移動をしない | ドメイン単位で小さく移管し、都度ビルド/検証する |
| shared に雑に配置しない | shared 判定は「複数から呼ばれるから」ではなく「意味が横断で同一」の場合のみ。shared はカテゴリ追加（例：時間/冪等/ログ/Firebase 等）として管理し、`shared/utils` は作らない |
| 未使用判定＝即削除をしない | 未使用は「候補」止まりにし、削除は安定化フェーズで判断する |

## ドキュメント格納場所

| 種別 | パス |
|------|------|
| 旧フォルダ別棚卸し | `旧フォルダ別_棚卸し/` |
| 新ドメイン別設計 | `新フォルダ別_設計/` |
| 作業中の判断の記録 | `08_意思決定ログ.md` |

※ **ドメイン一覧の確定**は、`新フォルダ別_設計/` が揃った時点で行う（04_新フォルダ構造 7. に「暫定」として記載。確定後は 04 の表を更新する）。
