# 07_検証基準（ビルド・テスト）.md（テンプレ）

## 1. 目的

フォルダ移管の完了判定を曖昧にしないため、**最低限の検証（ビルド/静的解析/必要ならテスト）**を定義する。
各ドメイン移管の都度、ここに定める検証を実施する。

## 2. 基本方針（固定）

- **最低限**：FunctionsはTypeScriptビルドが通ること、Flutterは analyzeが通ること
- **重い検証**（エミュレータ起動・実機確認等）は節目で実施（ここで条件を定義する）
- **失敗した場合**は、原因切り分け可能な単位で戻す（ドメイン単位）

## 3. Functions 側 検証（必須）

### 3.1 必須（毎ドメイン移管後）

- TypeScriptビルド（例：`npm run build` または `tsc`）が成功する
- import/export エラーが無い（特に index.ts）

※実際のコマンド名はプロジェクトに合わせて確定し、ここに固定する。

### 3.2 推奨（節目で実施）

- Emulatorでの起動（必要なら）
- `firebase deploy --only functions` 相当の確認（実運用に合わせる）

## 4. Flutter 側 検証（必要時のみ）

本改修はFunctions中心のため、Flutter側を触った場合のみ実施する。

### 4.1 必須（Flutterを変更した場合）

- `flutter analyze` が成功する

### 4.2 推奨（節目で実施）

- `flutter test`（テストがある場合）
- 主要画面の起動確認（必要なら）

## 5. “節目”の定義（いつ重い検証をやるか）

以下のいずれかに該当する場合、推奨検証（3.2 / 4.2）を追加で実施する。

- 入口（callables/triggers/scheduler）のexportを大きく付け替えた
- sharedカテゴリを追加した
- 大量のファイルを移動した（目安：Nファイル以上 → Nはここで決める）
- 連続して複数ドメインを移管した（節目でまとめて実施）

## 6. 成功条件（完了判定）

- **Functions**：必須検証（3.1）がすべてOK
- **Flutter**：変更した場合は必須検証（4.1）がOK
- **入口一覧**（05_入口一覧）と export が整合している（必要ならチェック項目化）

## 7. 失敗時の対応（最小）

1. まずは当該ドメイン移管の範囲で原因を切り分ける
2. export漏れ（index.ts）／import漏れ／パスミスを疑う
3. 直せない場合は、changeSpecのロールバック手順で戻す
