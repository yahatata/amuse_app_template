# デバイス識別・セッション復旧（将来タスク）

**目的**: アップデート・再インストール・データ削除などの事象に強い「端末の同一性」とログイン体験を検討する際のメモ。実装は未着手の整理用。

**関連**: 匿名 Firebase Auth、`devices` コレクション、`DeviceService` の SharedPreferences（`device_id` 等）、`registerDevice` Callable。

---

## 1. 現状の整理（簡潔）

- 端末は **Firebase 匿名認証**により **Auth `uid`** を持つ。
- Firestore では **`devices/{deviceId}`**（自動採番の docId）に **`uid` フィールド**として同じ値を保存。
- アプリは **SharedPreferences** に **`device_id`**（上記 docId）等を保存し、「登録済み」判定に用いる。
- **`registerDevice`** は同一 **`uid`** に対して冪等（既存があれば更新し同一 `deviceId` を返す）。

**課題**: SharedPreferences が消えると「未登録」とみなされやすい一方、Auth が残っていればサーバ上には既存デバイスが存在しうる（クライアントとサーバの認識がずれる）。

---

## 2. 対応案（再インストール・アップデート時）

### 2-1. 起動時の復旧フロー（優先度・効果ともに高い）

- **FirebaseAuth にユーザーが存在する**（匿名含む）が、**ローカルに `device_id` が無い**場合:
  - Firestore で **`devices` を `uid == currentUser.uid` で検索**（または将来 **`devices/{uid}`** なら `doc(uid).get()`）。
  - 見つかったら **`device_id` を再保存**し、登録画面を経由せずホーム等へ遷移する。
- **新しい ID 種別を増やさず**、既存の **Auth `uid` とサーバの `devices` を真実とする**方針に寄せられる。

### 2-2. ローカル保存の強化（任意）

- `device_id` 等を **`shared_preferences` に加え `flutter_secure_storage` 等に二重保存**し、アプリデータ削除時の残存率を上げる（OS 依存であり保証は限定的）。

### 2-3. データモデルの整理（任意・移行要検討）

- **`devices` のドキュメント ID を `authUid` と同一**にする（`devices/{uid}`）と、参照・復旧・ルール記述が単純化しうる。既存データがある場合は **マイグレーション手順**が必要。

### 2-4. `installationId` の位置づけ

- 登録フローで毎回ランダム生成しているだけでは **同一端末追跡に不向き**。
- 必要なら **Firebase Installations** 等との関係を整理するが、**単体で「再インストール耐性」の銀の弾にはならない**ことが多い（アンインストールで変わる前提）。

---

## 3. 原理的な限界

- **アンインストール等で匿名 Auth とローカル状態がともに消える**場合、サーバだけでは **「以前と同一の物理端末か」を証明できない**。
- **完全に同一デバイス 1 本に必ず収束**させるには、**店舗コード・別端末確認・メール／SMS 等の外部チャネル**、または **アカウント紐づけ**のような **追加の信頼の根拠**が必要になりうる。
- よって **「匿名＋ローカル保存のみが理論上の最適」ではなく**、**復旧フローと保存強化でまだ改善余地がある**一方、**要件次第ではアカウント設計の見直し**が検討対象になる。

## 4. 別途検討（admin まわりの将来設計）

以下は **本ドキュメントのスコープ外の可能性**として、プロダクト要件・セキュリティ方針が固まった段階で検討する。

| 検討テーマ | 内容 |
|------------|------|
| **admin の認証強度** | **パスワード等**を要求する設計にするか（端末紛失・共有時のリスクとトレードオフ）。 |
| **admin の紐づけ先** | **デバイス起点（匿名 uid）**のままとするか、**メール等のユーザーアカウントと紐づけるログイン**にするか。後者は端末再発行・権限移譲・監査に有利な場合がある。 |
| **terminal との切り分け** | 一般端末は現状の匿名＋デバイス、admin だけメール＋2FA 等、といった **役割別ポリシー**の是非。 |
