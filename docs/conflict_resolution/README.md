# コンフリクト解消 ドキュメント

_最終更新: 2025-12-23 (JST)_

## 概要

このフォルダは、`billsmigration/draft` と `develop` ブランチの統合時に発生したコンフリクトの解消を管理するためのドキュメントです。

## ファイル構成

### `status.md`
現在のコンフリクト状況のまとめ。
- ブランチ情報
- 未解消コンフリクトファイル一覧
- ファイル分類と注意度
- 推奨着手順序

### `policy.md`
コンフリクト解消の行動指針。
- 基本方針
- 独断解消の判断基準
- 選択肢提示のフォーマット
- 各ファイル処理後のログ項目
- 検証タイミング
- プロジェクト方針

### `log.md`
各ファイルのコンフリクト解消履歴。
- 解消日時
- 判断方法
- 変更内容
- テスト結果

### `progress.md`
進捗管理。
- タスク一覧
- 状態管理
- 担当割り当て
- **更新責任者**: Cursor（AI）が進捗を更新する責任を負う

## 進め方

1. **現状確認**: `status.md` で現在の状況を確認（git出力に基づく事実を反映）
2. **指針確認**: `policy.md` で行動指針を確認
3. **ファイル解消**: userに指定されたファイルのみ解消（推奨順序は `status.md` 参照）
4. **git add**: コンフリクト解消後は**必ず** `git add <ファイルパス>` を実行する
5. **ログ記録**: `log.md` に解消内容を記録
6. **進捗更新**: `progress.md` で進捗を更新（**Cursorが更新責任者**）

## 運用ルール

### ドキュメント整備フェーズ / 実装フェーズ
- **ドキュメント整備フェーズ**: 実コードには触らず、ドキュメントのみ整備（現在のフェーズ）
- **実装フェーズ**: 実コードのコンフリクト解消を開始

### progress.md の更新
- **更新責任者**: Cursor（AI）が `progress.md` の更新を担当する
- **更新頻度**: 各ファイルの状態変更時に即座に更新
- **更新内容**: 状態変更、進捗率の再計算、担当割り当て

### status.md の更新
- **更新方針**: "現在の事実" を反映する（git出力に基づく）
- **更新タイミング**: コンフリクトファイル数や分類が変わった場合

### 実コード解消
- **単位**: ファイル単位で進める（userに複数指定される場合があり、そのときは複数ファイルの処理を行う）
- **git add**: コンフリクト解消後は**必ず** `git add <ファイルパス>` を実行する（コンフリクト解消の完了をGitに通知するため）
- **記録**: 解消後は `log.md` に記録する

## 注意事項

- **実コードはファイル単位で進める**
- **独断解消できない場合は選択肢を提示**
- **判断不能な場合は明確に記録し、人間に委ねる**
- **各ファイル解消後は必ずテストを実行**
