## 1. 位置づけ

`ART-101_Config台帳` は業務設定項目の定義台帳である。  
「現在その値が何か」を管理する資料ではなく、次の内容を管理する:

- どの設定項目が存在するか
- どこに保存されるか
- 何を制御する設定か
- どの値を許容するか・値ごとにどう振る舞うか
- 未設定時にどう動くか
- 標準的にどの値を採用すべきか
- 誰がどの方法で変更・初期設定するのか
- どの function / 画面 / 処理がその設定を読むのか

旧 `B-1_Config台帳_説明.md` の内容を引き継ぎ、新方針の ART フレームで整備する。

---

## 2. 管理対象

### 登録する対象

- 店舗運用や本番動作に影響する業務設定
- 設定値により function・画面・scheduler・業務フローの挙動が変わるもの
- 導入時または保守運用時に人が設定内容を判断する必要があるもの

現時点の主対象設定群:

| 設定群 | 概要 |
|---|---|
| `config` | 店舗基本設定 |
| `payrollConfig` | 給与計算設定 |
| `schedulerConfig` | スケジューラ設定 |
| `requiredStaffByTimeSlot` | 時間帯別必要スタッフ数（挙動設計が他と異なるため注意） |
| `reportingGroupConfig` | レポートグループ設定 |
| `taxReportingBehavior` | 税務レポート挙動 |

### 登録しないもの

- 環境ごとの現在値
- Secret の実値
- 単なるコード定数・一時デバッグ値
- 試験専用の仮設定

## 3. 主な列の定義

（TSK-101 実施中に Excel 正本と整合した内容へ更新すること）

| 列名 | 意味 | 型 / 候補値 |
|---|---|---|
| CFG-ID | 設定識別子（CFG-xxx） | 文字列 |
| config区分 | 設定グループ | config / payrollConfig / schedulerConfig 等（入力規則） |
| 現役区分 | 現役 / legacy / planned / 削除候補 | 入力規則 |
| 論理名 | 人が読める設定名 | 文字列 |
| 保存path | Firestore コレクション/ドキュメントのパス | 文字列 |
| field名 | field のコード上の名称 | 文字列 |
| 適用スコープ | 店舗固有 / 中央共通 / システム全体 | 入力規則 |
| 型 | string / number / boolean / object / array 等 | 入力規則 |
| 必須区分 | 必須 / 任意 / 条件付き | 入力規則 |
| 業務意味 | この設定が何を制御するかの説明 | 文字列 |
| 許容値・形式 | 許容する値の範囲・形式 | 文字列 |
| 各許容値での挙動 | 値ごとにどう動くか | 文字列 |
| 未設定時挙動 | 値が未設定の場合の動作 | 文字列 |
| デフォルト値 | コード上のデフォルト | 文字列 |
| 標準値（推奨値） | 運用として推奨する値 | 文字列 |
| 主な利用元 | 参照する FN-ID / 画面 / 処理 | 文字列（複数なら `;` 区切り） |
| 反映タイミング | いつ設定が反映されるか | 文字列 |
| 変更方法 | 誰がどこで変更するか | 文字列 |
| 初期設定方法 | 導入時にどう初期設定するか | 文字列 |
| 更新区分 | 継続 / 変更時 / 節目 / 単発 | 入力規則 |
| 備考 | その他注意事項 | 文字列 |

---

## 4. 更新時のルール

- 列構造の変更は TSK-101 担当者と確認してから行う
- `現在値` を追記しない（定義台帳であることを維持する）
- `現役区分` が `削除候補` になった行は削除せず状態を変更する
- 設定群の追加・削除は管理対象の判断基準を満たすか確認する
