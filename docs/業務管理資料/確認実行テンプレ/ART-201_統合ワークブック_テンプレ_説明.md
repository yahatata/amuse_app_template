## 1. 位置づけ

`ART-201_統合ワークブック_テンプレ` は定義正本（ART-101〜104）を束ねて、実際の確認・判定を行う確認実行テンプレである。

```
ART-101（Config定義）
ART-102（Function定義）   ← 根拠を受け取る
ART-103（フロー定義）    → ART-201（確認テンプレ） → 店舗別インスタンス
ART-104（外部設定定義）
```

**ART-201 に仕様定義を書かない。** 確認項目の定義は ART-101〜104 にある。

## 2. シート構成と各シートの役割

| シート | 役割 | 入力主体 |
|---|---|---|
| `Config入力` | ART-101 を元に採用する config 値を入力する | 人 |
| `外部設定入力` | ART-104 を元に外部設定の方式・確認状態を入力する | 人 |
| `期待値計算` | 2 入力を受けて検証プロファイル・期待状態・実行要否を計算する | 数式 |
| `Gateチェック` | rules / auth / secret / env / scheduler / debug 残存を横断確認する | AI先行 + 人確認 |
| `Function挙動確認` | ART-102 を元に主要 function の期待挙動を確認する | AI先行 + 人確認 |
| `実機テスト` | 画面・端末・認証・外部連携の実機必須項目を確認する | 人 |
| `業務フロー確認` | ART-103 を元に業務フロー単位の受入確認を行う | 人 |
| `判定サマリ` | NG 数・保留数・再確認要否を集計し go / no-go をまとめる | 数式 + 人承認 |

## 3. 検証プロファイルの定義

（TSK-201 実施中に分岐パターンを埋めること）

検証プロファイルは、少なくとも次の組み合わせで決まる:

| 要素 | 説明 |
|---|---|
| config 値 | ART-101 の各設定項目の採用値（CFG-ID で参照） |
| 外部設定の状態・方式 | ART-104 の各外部サービス設定の方式 |
| 業務モード（必要な場合） | 機能の有効・無効等の条件 |

同一検証プロファイル = 同一チェック観点。どの店舗でも同一プロファイルなら同一確認内容。

### どの入力が何に効くか（原理）

（TSK-201 実施中に具体的な分岐パターンを記載すること）

| 入力 | 効く対象 | 効き方 |
|---|---|---|
| `Config入力` の値 | `期待値計算` / `Function挙動確認` の期待状態 | 値が標準値から乖離すると追加確認が発生する |
| `外部設定入力` の状態 | `Gateチェック` / `期待値計算` の実行要否 | 設定方式によって確認内容が変わる |
| （追加の分岐パターンは TSK-201 で埋める） | | |

## 4. 設計固定原則

| 原則 | 具体的な実現方法 |
|---|---|
| 行は増減させず列で意味を表現する | `実行要否` `適用状態` `期待状態` `非適用理由` `結果` `判定` を列で持つ |
| 数式だけを真実にしない | ロジックの原理を本資料 §3 に記載する（TSK-201 実施中に充実させる） |
| GitHub Issue は前提にしない | 各シートに `NG有無` `NG理由` `対応状態` `再確認要否` `関連メモ` を持つ |
| 定義を生やさない | 確認項目の根拠は ART-101〜104 を参照する。ART-201 に定義を書かない |

## 5. 店舗別インスタンスの派生ルール

（TSK-201 実施中に確定させること）

基本の流れ:
1. `ART-201_統合ワークブック_テンプレ.xlsx` をコピーする
2. ファイル名を `統合ワークブック_{店舗名}_{YYYYMMDD}.xlsx` に変更する
3. `Config入力` シートに店舗固有の config 値を入力する
4. `外部設定入力` シートに店舗固有の外部設定状態を入力する
5. `期待値計算` の数式が自動更新されることを確認する
6. 各確認シートを実施して結果を記録する

## 6. 更新時のルール

- ART-201 に新しい仕様定義を書かない
- 数式ロジックを変更した場合は §3 の原理説明も更新する
- 確認項目の追加・削除は行の増減ではなく `実行要否` `適用状態` で表現する
- シート間参照が壊れていないことを更新後に確認する
