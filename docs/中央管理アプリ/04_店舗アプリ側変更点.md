# 04 店舗アプリ側変更点

> **このファイルの対象リポジトリ**: `amuse_app_template`（店舗用アプリ）  
> 中央管理アプリのリポジトリ（`amuse-admin`）ではなく、**店舗 Functions を変更する**仕様書。  
> 中央管理アプリ実装の前提として、このファイルの変更を店舗アプリ側に加える必要がある。

---

## ⚠️ 重要: best-effort write の原則

このファイルで加えるすべての中央 Firestore への書き込みは **best-effort**（非ブロッキング）で行う。  
中央プロジェクトへの書き込みが失敗しても、**店舗アプリの主業務には一切影響を与えない**こと。  
具体的には:
- `try/catch` で囲み、catch 内では Cloud Logging にのみ記録する（再スローしない）
- `await` しない、または `Promise.allSettled` 等で並列実行する

## 2. 新規作成: `writeToCentralFirestore.ts`

### ファイルパス
`functions/src/shared/centralFirestore/writeToCentralFirestore.ts`

### 役割
中央 Firestore への接続・書き込みを一元管理するモジュール。  
`logOpsError.ts` や `schedulerLogs.ts` はこのモジュールを呼ぶだけでよい。

### 実装仕様

```typescript
import { getApp, getApps, initializeApp, cert } from 'firebase-admin/app';
import { getFirestore, FieldValue } from 'firebase-admin/firestore';
import { logger } from 'firebase-functions';

// 中央プロジェクトの Firebase App（店舗プロジェクトとは別の接続）
const CENTRAL_APP_NAME = 'centralMonitoring';

/**
 * 中央プロジェクトへの接続を取得する。
 * CENTRAL_PROJECT_ID が未設定の場合は null を返す（≒ 機能が無効）。
 */
function getCentralFirestore(): FirebaseFirestore.Firestore | null {
  const centralProjectId = process.env.CENTRAL_PROJECT_ID;
  if (!centralProjectId) {
    return null;
  }

  // 既に初期化済みなら再利用
  const existingApp = getApps().find(app => app.name === CENTRAL_APP_NAME);
  if (existingApp) {
    return getFirestore(existingApp);
  }

  // 中央プロジェクト用の App を初期化
  // 店舗 Functions の SA は IAM で中央 Firestore への roles/datastore.user を持つ
  const app = initializeApp(
    { projectId: centralProjectId },
    CENTRAL_APP_NAME
  );
  return getFirestore(app);
}

/**
 * 中央 Firestore の errorLogs サブコレクションに best-effort write する。
 * 失敗しても caller には伝播しない。
 */
export async function writeCentralErrorLog(
  storeId: string,
  data: Record<string, unknown>
): Promise<void> {
  const db = getCentralFirestore();
  if (!db) return; // CENTRAL_PROJECT_ID 未設定 = 機能 OFF

  try {
    const expireAt = new Date();
    expireAt.setDate(expireAt.getDate() + 90); // TTL: 90日

    await db
      .collection('errorLogs')
      .doc(storeId)
      .collection('logs')
      .add({
        ...data,
        storeId,
        occurredAt: FieldValue.serverTimestamp(),
        expireAt,
        isResolved: false,
      });
  } catch (err) {
    // best-effort: Cloud Logging にだけ記録し、スローしない
    logger.warn('writeCentralErrorLog failed (best-effort)', {
      storeId,
      error: err instanceof Error ? err.message : String(err),
    });
  }
}

/**
 * 中央 Firestore の schedulerLogs サブコレクションに best-effort write する。
 */
export async function writeCentralSchedulerLog(
  storeId: string,
  data: Record<string, unknown>
): Promise<void> {
  const db = getCentralFirestore();
  if (!db) return;

  try {
    const expireAt = new Date();
    expireAt.setDate(expireAt.getDate() + 30); // TTL: 30日

    await db
      .collection('schedulerLogs')
      .doc(storeId)
      .collection('runs')
      .add({
        ...data,
        storeId,
        loggedAt: FieldValue.serverTimestamp(),
        expireAt,
      });
  } catch (err) {
    logger.warn('writeCentralSchedulerLog failed (best-effort)', {
      storeId,
      error: err instanceof Error ? err.message : String(err),
    });
  }
}

/**
 * 中央 Firestore の taskLogs サブコレクションに best-effort write する。
 */
export async function writeCentralTaskLog(
  storeId: string,
  data: Record<string, unknown>
): Promise<void> {
  const db = getCentralFirestore();
  if (!db) return;

  try {
    const expireAt = new Date();
    expireAt.setDate(expireAt.getDate() + 30); // TTL: 30日

    await db
      .collection('taskLogs')
      .doc(storeId)
      .collection('runs')
      .add({
        ...data,
        storeId,
        loggedAt: FieldValue.serverTimestamp(),
        expireAt,
      });
  } catch (err) {
    logger.warn('writeCentralTaskLog failed (best-effort)', {
      storeId,
      error: err instanceof Error ? err.message : String(err),
    });
  }
}
```

### 注意: Firebase App の初期化について
- 店舗 Functions はデフォルトで `initializeApp()` 済み（`index.ts` 等）
- 中央プロジェクト用に **別名**（`CENTRAL_APP_NAME = 'centralMonitoring'`）で2つ目の App を初期化する
- デフォルト App のクレデンシャルを使う（ADC: Application Default Credentials）
- 中央 Firestore への権限は **IAM で店舗 SA に付与**する（§5 参照）

## 3. 変更: `logOpsError.ts` — errorLogs への書き込み追加

### 変更箇所
`logOpsError` 関数内、`logger.error(args.message, payload)` の後に best-effort write を追加する。

### 変更内容（diff 相当）

```typescript
// 追加 import
import { writeCentralErrorLog } from '../centralFirestore/writeToCentralFirestore';

// logOpsError 関数の末尾（logger.error の後）に追加:
export function logOpsError(args: LogOpsErrorArgs): void {
  // ... 既存のペイロード組み立て処理 ...

  logger.error(args.message, payload);

  // ▼ 追加: 中央 Firestore への best-effort write（非同期、await しない）
  void writeCentralErrorLog(projectId, {
    message: args.message,
    functionEntry: args.functionEntry,
    service: payload.service,
    errorSource: payload.errorSource,
    projectId,
    ...(payload.operation !== undefined ? { operation: payload.operation } : {}),
    ...(payload.errorMessage !== undefined ? { errorMessage: payload.errorMessage } : {}),
    ...(payload.errorName !== undefined ? { errorName: payload.errorName } : {}),
    ...(payload.errorKey !== undefined ? { errorKey: payload.errorKey } : {}),
    ...(payload.sourceProduct !== undefined ? { sourceProduct: payload.sourceProduct } : {}),
    ...(payload.sdkCode !== undefined ? { sdkCode: payload.sdkCode } : {}),
    ...(payload.httpStatus !== undefined ? { httpStatus: payload.httpStatus } : {}),
    ...(payload.detailReason !== undefined ? { detailReason: payload.detailReason } : {}),
    ...(payload.context !== undefined ? { context: payload.context } : {}),
  });
  // ▲ 追加ここまで
}
```

### `void` で await しない理由
中央 Firestore への書き込みは副作用。  
`await` すると万一の障害時に主処理がタイムアウトするリスクがある。  
`void` で呼び出し、失敗は `writeCentralErrorLog` 内部で catch して Cloud Logging に記録する。

### `writeSchedulerExecutionLogByCloudTaskBestEffort` への追加

```typescript
export async function writeSchedulerExecutionLogByCloudTaskBestEffort(
  entry: SchedulerExecutionLogByCloudTask
): Promise<void> {
  // ... 既存の店舗 Firestore への write ...

  // ▼ 追加: 中央 schedulerLogs への best-effort write
  void writeCentralSchedulerLog(entry.projectId, {
    jobKey: entry.jobKey,
    eventType: entry.eventType === 'started' ? 'start' : entry.eventType === 'completed' ? 'success' : entry.eventType,
    // started → start / completed → success に正規化
    idempotencyKey: entry.idempotencyKey,
    ...(entry.supervisorRunId !== undefined ? { supervisorRunId: entry.supervisorRunId } : {}),
    functionEntry: entry.functionName,
    ...(entry.reason !== undefined ? { reason: entry.reason } : {}),
    ...(entry.decisionSnapshot !== undefined ? { decisionSnapshot: entry.decisionSnapshot } : {}),
  });
  // ▲ 追加ここまで
}
```

### `eventType` の正規化マッピング

店舗 Firestore の既存 `eventType` 値と中央 Firestore の `eventType` が異なるため正規化する。

| 店舗側（既存） | 中央側（正規化後） | 意味 |
|-------------|---------------|------|
| `'enqueued'`（dispatch）| `'start'` | supervisor が task enqueue した |
| `'started'`（execution）| `'start'` | handler が Cloud Task から呼ばれた |
| `'completed'`（execution）| `'success'` | handler が正常完了した |
| `'skip'` | `'skip'` | 仕様どおりスキップ |
| `'error'` | `'error'` | エラー終了 |

## 5. 変更: downstream task handlers への taskLogs write

### 対象 handler

scheduler 経由以外の、Cloud Tasks によって呼ばれる downstream handler:

| handler 関数名 | functionEntry | service |
|-------------|-------------|---------|
| `openAssessmentTask` | `openAssessmentTask` | `store` |
| `closeAssessmentTask` | `closeAssessmentTask` | `store` |
| `controlHookHttp` | `controlHookHttp` | `store` |
| `processPayrollNotifications` | `processPayrollNotifications` | `payroll` |
| `processStaffPayroll` | `processStaffPayroll` | `payroll` |
| `finalizePayrollRun` | `finalizePayrollRun` | `payroll` |

### 変更方法

各 handler の `logOpsInfo`（start）と `logOpsSuccess`（success）を中央 Firestore にも書き込む。  
handler ごとに個別に追加するのではなく、**`logOpsInfo` / `logOpsSuccess` 関数自体に hook を追加する**。

#### `logOpsInfo` 関数への追加（start イベント）

```typescript
import { writeCentralTaskLog } from '../centralFirestore/writeToCentralFirestore';

export function logOpsInfo(args: LogOpsInfoArgs): void {
  const projectId = args.projectId ?? resolveProjectId();
  // ... 既存処理 ...
  logger.info(args.message, payload);

  // ▼ 追加: scheduler 経由の handler start のみ中央 taskLogs に書く
  // （scheduler handler は functionEntry が SchedulerJobKey に一致するものは schedulerLogs で管理するため除外）
  if (!SCHEDULER_JOB_KEYS.has(args.functionEntry)) {
    void writeCentralTaskLog(projectId, {
      functionEntry: args.functionEntry,
      service: payload.service,
      eventType: 'start',
      ...(args.context !== undefined ? { context: args.context } : {}),
    });
  }
  // ▲ 追加ここまで
}
```

#### `logOpsSuccess` 関数への追加（success イベント）

```typescript
export function logOpsSuccess(args: LogOpsSuccessArgs): void {
  const projectId = args.projectId ?? resolveProjectId();
  // ... 既存処理 ...
  logger.info(args.message, payload);

  // ▼ 追加: scheduler 以外の task handler の success を中央 taskLogs に書く
  if (!SCHEDULER_JOB_KEYS.has(args.functionEntry)) {
    void writeCentralTaskLog(projectId, {
      functionEntry: args.functionEntry,
      service: payload.service,
      eventType: 'success',
      ...(args.context !== undefined ? { context: args.context } : {}),
    });
  }
  // ▲ 追加ここまで
}
```

#### `SCHEDULER_JOB_KEYS` の定義

```typescript
// logOpsError.ts または別ファイルで定義
import type { SchedulerJobKey } from '../config/schedulerConfigTypes';

const SCHEDULER_JOB_KEYS: Set<string> = new Set<SchedulerJobKey>([
  'weeklyPlanner',
  'enqueueTournamentTasksByScheduler',
  'generateRecurringTournamentsByScheduler',
  'scheduledCleanup',
  'scheduleGenerateNextYearBusinessHours',
  'payrollNotificationScheduler',
]);
```

> **なぜ除外するか**: scheduler 系 handler の到達は `writeSchedulerExecutionLogByCloudTaskBestEffort` が中央 `schedulerLogs` に書く。  
> `logOpsInfo` からも書くと重複になるため、`taskLogs` への書き込みから除外する。

## 7. IAM 設定（各店舗プロジェクトのサービスアカウントへの権限付与）

### 背景
各店舗の Cloud Functions は**店舗プロジェクトのデフォルト SA**（`PROJECT_ID@appspot.gserviceaccount.com`）で実行される。  
この SA に、中央プロジェクト（`amuse-central-monitoring`）の Firestore への書き込み権限を付与する必要がある。

### 付与するロール
- **`roles/datastore.user`**（Firestore への読み書き。必要なのは write のみなので `roles/datastore.user` が最小権限）

### コマンド（店舗プロジェクトを追加するたびに実行する）

```bash
# 変数定義
STORE_PROJECT_ID="amuse-app-template"  # ← 店舗の projectId に変える
CENTRAL_PROJECT_ID="amuse-central-monitoring"

# 店舗 SA のメールアドレスを確認
STORE_SA="${STORE_PROJECT_ID}@appspot.gserviceaccount.com"

# 中央プロジェクトの Firestore に書き込む権限を付与
gcloud projects add-iam-policy-binding ${CENTRAL_PROJECT_ID} \
  --member="serviceAccount:${STORE_SA}" \
  --role="roles/datastore.user"
```

### 複数店舗への一括付与

```bash
#!/bin/bash
# ファイル store_projects.txt に店舗 projectId を1行1つで列挙しておく
CENTRAL_PROJECT_ID="amuse-central-monitoring"

while IFS= read -r STORE_PROJECT_ID; do
  STORE_SA="${STORE_PROJECT_ID}@appspot.gserviceaccount.com"
  echo "Adding IAM for ${STORE_SA}..."
  gcloud projects add-iam-policy-binding ${CENTRAL_PROJECT_ID} \
    --member="serviceAccount:${STORE_SA}" \
    --role="roles/datastore.user"
done < store_projects.txt
```

### 新規店舗追加時のチェックリスト
1. 店舗プロジェクト作成
2. `stores/{storeId}` ドキュメントを中央 Firestore に作成（管理アプリ UI から）
3. 上記 IAM コマンドを実行
4. `CENTRAL_PROJECT_ID` を `.env.production` に追加してデプロイ済みか確認
5. 初回動作確認（エラーが中央 Firestore に届いているか確認）
