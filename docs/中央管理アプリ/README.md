## 用語定義（全ドキュメント共通）

このプロジェクト群では以下の呼び分けを徹底する。混在させない。

| 用語 | 意味 |
|------|------|
| **店舗用アプリ** | 各アミューズメントカジノバーが使う業務管理アプリ。Flutter 製。1 店舗 = 1 Firebase プロジェクト。テンプレートリポジトリ `amuse_app_template` から複数店舗向けにリリースされる |
| **店舗プロジェクト** | 店舗用アプリが接続する Firebase / GCP プロジェクト（例: `amuse-app-template`）|
| **中央管理アプリ** | 複数店舗を横断して監視・管理するための保守・運用用 Web アプリ。Next.js 製。開発者・運用者が使う |
| **中央プロジェクト** | 中央管理アプリが接続する Firebase / GCP プロジェクト（`amuse-central-monitoring`）|
| **中央 Firestore** | 中央プロジェクトの Firestore。エラーログ・scheduler ログ・タスクログ・設定を集約する |
| **店舗 Firestore** | 各店舗プロジェクトの Firestore。店舗固有の業務データを持つ |
| **storeId** | 店舗の識別子。`projectId`（Firebase Project ID）と同一値を使う（例: `amuse-app-template`）|

## プロジェクト構成の全体像

```
[店舗用アプリ（N 店舗）]              [中央管理アプリ（1 つ）]
  amuse_app_template（テンプレート）       amuse-admin（新規リポジトリ）
  ├── Flutter アプリ                       ├── Next.js Web アプリ
  ├── Cloud Functions（店舗ごとデプロイ）   ├── Firebase Hosting
  └── Firebase（店舗プロジェクト × N）     └── Firebase（中央プロジェクト）
        ↓ best-effort write                      ↑ 読み取り
        └─────── 中央 Firestore ────────────────┘
```

## このドキュメント群の位置づけ

このドキュメント群は以下の 2 つを兼ねる:

1. **店舗用アプリへの変更仕様書**（`04_店舗アプリ側変更点.md`）  
   店舗用アプリのリポジトリ（`amuse_app_template`）上で実施する Functions の変更内容を記載する

2. **中央管理アプリの要件定義・設計書**  
   新規リポジトリ（`amuse-admin`）で中央管理アプリを実装するための仕様を全て記載する  
   中央管理アプリの実装 AI はこのドキュメント群だけを読めば実装できる状態を目指す
