## 1. 画面一覧（ルーティング）

## 2. ログイン画面（`/login`）

### 表示内容
- Google ログインボタン
- ログイン後: `adminUsers` に UID が存在し `enabled: true` か確認
- 存在しない / `enabled: false` → エラーメッセージ「このアカウントはアクセスが許可されていません」

### 認証後のリダイレクト
- ログイン成功 → `/`（HOME）

## 3. HOME 画面（`/`）

### 目的
**全店舗を一目で把握する**。問題がある店舗を即座に発見できる画面。

### レイアウト

```
┌────────────────────────────────────────────────────┐
│ 中央管理アプリ                        [ログアウト] │
├────────────────────────────────────────────────────┤
│ 最終更新: 2026-06-01 10:00                [更新] │
│                                                    │
│ ┌──────────────────────────────────────────────┐  │
│ │ 要確認エラー総計: 12 件（3 店舗）            │  │
│ │ Scheduler 異常: 1 件                         │  │
│ └──────────────────────────────────────────────┘  │
│                                                    │
│ [フィルター: ⚠️ 要確認のみ / 全店舗]              │
│                                                    │
│ 店舗一覧                                           │
│ ┌────────────┬──────────┬────────────┬──────────┐  │
│ │ 店舗名     │ エラー   │ Scheduler  │ 最終確認 │  │
│ ├────────────┼──────────┼────────────┼──────────┤  │
│ │ 渋谷店     │ 🔴 5件   │ ✅ 正常    │ 10分前   │  │
│ │ 新宿店     │ 🟡 2件   │ ⚠️ 要確認  │ 1時間前  │  │
│ │ テスト店舗 │ ✅ 0件   │ ✅ 正常    │ 30分前   │  │
│ └────────────┴──────────┴────────────┴──────────┘  │
└────────────────────────────────────────────────────┘
```

### 店舗行の表示仕様

| 列 | 表示内容 | 説明 |
|----|---------|------|
| 店舗名 | `stores/{storeId}.displayName` | クリックで店舗詳細へ |
| エラー | 未対応エラー件数（重要度フィルター後）| 🔴 importance=5 以上あり / 🟡 importance=3 のみ / ✅ 0件 |
| Scheduler | 今日の scheduler 健全性 | ✅ 正常 / ⚠️ 要確認 / — 監視対象外 |
| 最終確認 | 最後に `isResolved` が更新された時刻 | — |

### フィルター
- 「要確認のみ」: エラー > 0 または Scheduler ⚠️ の店舗だけ表示
- 「全店舗」: `enabled: true` の全店舗を表示

### 更新
- ページ読み込み時に取得
- 「更新」ボタンで手動再取得
- リアルタイム更新（Firestore onSnapshot）は Phase 2 以降で対応

## 4. 店舗詳細画面（`/stores/[storeId]`）

### タブ構成

```
┌─────┬──────────────┬─────────────────┬────────────────┐
│     │ エラー一覧   │ Scheduler 履歴  │ タスク履歴     │
└─────┴──────────────┴─────────────────┴────────────────┘
```

### 4-1. エラー一覧タブ

#### フィルターバー

| フィルター項目 | 入力形式 | 説明 |
|-------------|---------|------|
| 期間 | 日付ピッカー（from - to）| デフォルト: 直近 24h |
| 重要度 | 複数選択チェック（5/3/1/0）| デフォルト: 全て |
| 対応状況 | トグル（全て / 未対応 / 対応済み）| デフォルト: 未対応 |
| サービス | セレクトボックス | `service` フィールドの値一覧 |
| 関数 | セレクトボックス | `functionEntry` の値一覧 |
| エラーソース | セレクトボックス | `external_api` / `function_common` / `function_custom` |

#### エラー一覧テーブル

| 列 | 表示内容 |
|----|---------|
| 重要度 | アイコン（🔴 5 / 🟡 3 / ⚪ 1 / — 0）|
| メッセージ | `message`（先頭 60 文字）|
| サービス / 関数 | `service` / `functionEntry` |
| 発生時刻 | `occurredAt`（JST）|
| エラーソース | `errorSource` |
| 対応状況 | ✅ 対応済み / 🔲 未対応 |
| 操作 | [詳細] [対応済みにする] |

#### バルク操作
- チェックボックスで複数選択
- 「選択した XX 件を対応済みにする」ボタン

### 4-2. Scheduler 履歴タブ

#### フィルターバー

| フィルター項目 | 入力形式 |
|-------------|---------|
| 日付 | 日付ピッカー（1 日単位）|
| ジョブ | セレクトボックス（`SchedulerJobKey` 6 種）|
| イベント種別 | 複数選択（start / success / skip / error）|

#### Scheduler 履歴テーブル

| 列 | 表示内容 |
|----|---------|
| ジョブキー | `jobKey` |
| イベント | `eventType`（アイコン付き）|
| 実行予定時刻 | `plannedRunAt`（JST）|
| 記録時刻 | `loggedAt`（JST）|
| 理由 | `reason`（skip/error 時のみ）|
| idempotencyKey | `idempotencyKey`（省略表示）|

#### Scheduler 異常アラート

ページ上部に、未解決の `schedulerAnomalies` がある場合は以下のバナーを表示:

```
⚠️ Scheduler 異常が検知されています
  weeklyPlanner: start_missing（2026-06-01）[対応済みにする]
```

### 4-3. タスク履歴タブ

#### フィルターバー

| フィルター項目 | 入力形式 |
|-------------|---------|
| 期間 | 日付ピッカー |
| ハンドラー | セレクトボックス（`functionEntry` の値一覧）|
| イベント種別 | start / success / error |

#### タスク履歴テーブル

| 列 | 表示内容 |
|----|---------|
| ハンドラー | `functionEntry` |
| サービス | `service` |
| イベント | `eventType` |
| 記録時刻 | `loggedAt` |
| コンテキスト | `context` の主要キーを展開表示 |

## 5. エラー詳細画面（`/stores/[storeId]/errors/[logId]`）

### 表示内容

```
┌─────────────────────────────────────────────────────┐
│ ← 戻る（エラー一覧）                               │
│                                                     │
│ 【エラー詳細】                                      │
│                                                     │
│ ▪ メッセージ: closeStore 失敗                       │
│ ▪ 重要度: ⭐⭐⭐⭐⭐（5: 主要業務の実行不能）      │
│ ▪ 店舗: 渋谷店（amuse-app-template）               │
│ ▪ サービス: store                                   │
│ ▪ 関数: closeStore                                  │
│ ▪ エラーソース: function_custom                     │
│ ▪ エラーキー: STORE_CLOSE_FAILED                    │
│ ▪ 発生時刻: 2026-06-01 02:34:15 JST                │
│                                                     │
│ ── コンテキスト ──────────────────────────────────  │
│ {                                                   │
│   "storeId": "amuse-app-template",                  │
│   "businessDate": "2026-06-01",                     │
│   "billId": "bill_abc123"                           │
│ }                                                   │
│                                                     │
│ ── 対応管理 ────────────────────────────────────── │
│ 対応状況: 🔲 未対応                                 │
│ 担当者: [アサイン]                                  │
│ メモ: [メモを追加]                                  │
│                                                     │
│ [✅ 対応済みにする]                                 │
│                                                     │
│ ── マッチしたルール ─────────────────────────────  │
│ - store-all（service=store, importance=5）          │
└─────────────────────────────────────────────────────┘
```

### 操作

| 操作 | 挙動 |
|-----|------|
| 対応済みにする | `isResolved: true`, `resolvedAt`, `resolvedBy` を更新。auditLogs に記録 |
| 対応済みを取り消す | `isResolved: false` に戻す。auditLogs に記録 |
| メモを追加 / 編集 | `memo` フィールドを更新。auditLogs に記録 |
| アサイン | `assignedTo` にメールアドレスを設定。auditLogs に記録 |

## 6. 重要度ルール管理画面（`/settings/importance-rules`）

### 一覧

テーブルで全ルールを表示（§2 の `importanceRules` コレクション）。  
各行に「有効/無効トグル」を設け、即時に `isActive` を更新できる。

### 新規ルール追加

フォーム:
- ルール名（`displayName`）
- 重要度（1/3/5 のセレクト）
- 説明（`description`）
- 条件（`conditions`）: `service`, `functionEntry`, `errorSource`, `errorKey`, `sourceProduct`, `sdkCode`, `httpStatus`, `httpStatusMin` の各フィールドを任意入力

  --role="roles/datastore.user"

## 10. 共通 UI コンポーネント設計

### 技術スタック

| 用途 | 採用技術 |
|-----|---------|
| フレームワーク | Next.js 14（App Router）|
| UI コンポーネント | shadcn/ui（Tailwind CSS ベース）|
| 状態管理 | React Server Components + `useState`（シンプルさ優先）|
| Firebase 接続 | firebase/app（クライアント）+ firebase-admin（Functions）|
| テーブル | TanStack Table（フィルター・ソート機能）|
| 日付ピッカー | React Day Picker |
| 通知（UI）| shadcn/ui の Toast |

### レイアウト構造

```
layout.tsx（認証確認・ナビゲーション）
├── /(authenticated)
│   ├── page.tsx（HOME）
│   ├── stores/
│   │   └── [storeId]/
│   │       ├── page.tsx（店舗詳細）
│   │       └── errors/
│   │           └── [logId]/page.tsx
│   └── settings/
│       ├── importance-rules/page.tsx
│       ├── notification-targets/page.tsx
│       ├── stores/page.tsx
│       ├── admin-users/page.tsx
│       └── audit-logs/page.tsx
└── /login/page.tsx
```

### 認証 Middleware

```typescript
// middleware.ts
export function middleware(request: NextRequest) {
  const session = request.cookies.get('session');
  if (!session && !request.nextUrl.pathname.startsWith('/login')) {
    return NextResponse.redirect(new URL('/login', request.url));
  }
}
```

セッション管理は Firebase Auth の `sessionCookie`（サーバーサイドセッション）を使用する。
