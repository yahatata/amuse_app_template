# Block B 01_決定事項総覧

## 1. このブロックで扱う話

このブロックは、`bills` をどのような層構造で保存し、親 doc が current state をどう要約するかを扱う。

## 2. current-scope の結論

### 2.1 全体構造

`bills` は次の層で持つ。

1. 親 doc
2. bill 直下ライブサブコレ
3. `settlementCycles/{cycleNo}`
4. `baselineSnapshot`
5. `adjustments/{adjustmentId}`
6. `cashActions/{cashActionId}`

### 2.2 親 doc の役割

親 doc は current state summary である。

主に持つもの:

- `status`
- `currentSummary`
- `postSettlementState`
- `reopenSummary`
- `closeSummary`
- `settlementSnapshot`

### 2.3 `settlementCycles`

`settlementCycles` は baseline の版である。

- cycle が進むのは `reopen` の時だけ
- 通常の adjustment / cashAction では進まない

### 2.4 `baselineSnapshot`

`baselineSnapshot` は、その cycle での通常会計 / 再会計確定時点の full snapshot である。

- 1 doc で持つ
- current-scope では subcollection に分割しない

### 2.5 `adjustments`

`adjustments` は baseline に対する売上差分。

- `lines[]` を必須
- `requiredActionRemainingIncl` を持つ

### 2.6 `cashActions`

`cashActions` は実際の返金 / 徴収履歴。

- adjustment 配下ではなく cycle 配下
- `allocations[]` は必須
- 1 回の cashAction が複数 adjustment をまたげる

### 2.7 `currentSettlementCycle` と `latestSettledCycle`

- `currentSettlementCycle`
  - current state を組み立てる基準 cycle
- `latestSettledCycle`
  - 最後に baseline が存在する cycle

### 2.8 `sequenceNo`

同一 cycle 内での順番を表す。

- adjustment と cashAction の両方に持つ
- current state は sequence を踏まえて読める

### 2.9 migration 方針

未リリース前提なので、既存 `bills` / `analyticsMonthly` の migration / backfill は不要。

## 3. 2026-05-09 時点で確定したこと

- `baselineSnapshot` は 1 doc
- `cashActions` は cycle 配下
- `allocations[]` は必須
- `requiredActionRemainingIncl` は adjustment 単位
- migration / backfill は current-scope では不要

## 4. なぜこの方針にしたか

- baseline と差分を混ぜないため
- 実入出金を adjustment の子に閉じ込めないため
- `reopen` を baseline 切替として扱うため
- parent を軽く保ちつつ current state を読めるようにするため

## 5. このブロックの核

一言でいうと、

**「親 doc は current state、cycle は baseline の版、adjustment は差分、cashAction は実入出金」**

という役割分担である。
