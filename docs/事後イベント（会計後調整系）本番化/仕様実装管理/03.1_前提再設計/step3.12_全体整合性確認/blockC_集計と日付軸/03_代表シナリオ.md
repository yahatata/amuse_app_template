# Block C 03_代表シナリオ

## 1. シナリオA: 複数支払手段で通常会計

### 状況

- 現金 3000
- クレカ 2000
- 合計 5000

### current-scope の読み方

- 支払手段 source は現行実装から派生
- `analyticsMonthly.paymentTotals` は売上帰属月ベースの方法別配分
- strict な実入金管理は current-scope 外

## 2. シナリオB: `減額 + 返金前`

### 状況

- baseline は既にある
- adjustment で減額
- 返金はまだしない

### current-scope の扱い

- 売上差分は adjustment 作成時に反映
- 実入出金はまだ反映しない
- 親 doc は `requiredActionType = refund`

## 3. シナリオC: `増額 + 追加徴収済`

### 状況

- adjustment 作成と同時に徴収まで完了

### current-scope の扱い

- 売上差分を反映
- cashAction も反映
- `paymentTotals` は受領方法配分として更新されうる

## 4. シナリオD: tournament の差分

### 状況

- `entry` を 1 件減額
- `addon` を 2 件追加

### current-scope の line

- 別 line に分ける
- `targetCategory = tournament`
- `targetId = templateId / templateKey`
- `operationType = entry / addon`

### 反映先

- `byTemplateTournaments`
- `byCategory.tournaments`
- monthly top-level

## 5. このシナリオ群で確認すべきこと

- current-scope の source だけで `analyticsMonthly` 更新責務を説明できるか
- strict tax / accounting まで current-scope に持ち込まない整理で納得できるか
