# 17_既存データ互換移行方針

## この候補の役割

今回の再設計を実装する際に、既存 `bills`、既存 `analyticsMonthly`、既存 event 断片を migration / backfill の対象にする必要があるかを整理する。

## `step3.11` で先に確定させる必要があるか

- 判定: 必要あり
- 理由:
  - migration が必要か不要かで、Step4 以降の仕様書や changeSpec の構成が大きく変わる
  - 特に、既存データの書き換えを前提にするかどうかは、開発スコープと実装負荷に直結する

## 今回確定する仕様

### 1. current-scope の結論

今回の案件は **まだリリース前の開発期間中** であり、既存本番データに対する移行を考えなくてよい前提で進める。

したがって、current-scope では次を採る。

1. 既存 `analyticsMonthly` を今回の再設計に合わせて backfill しない
2. 既存 `bills` を今回の保存モデルに合わせて migration しない
3. 既存の試験データや検証データを互換対象として保証しない
4. 今回の新仕様は、**新しく作られる `bills` / `settlementCycles / baselineSnapshot / adjustments / cashActions` から適用する**

### 2. なぜ migration 不要でよいか

理由は次の通り。

- 今回は本番リリース後の互換維持ではなく、**リリース前の設計確定と実装**が主目的である
- そのため、既存の開発用データを整形し直すより、**新仕様の整合性を優先**した方が安全である
- `analyticsMonthly` や `bills` を無理に旧形から新形へ寄せると、今の段階では scope が膨らみすぎる

### 3. `analyticsMonthly` について

今回の current-scope では、既存 `analyticsMonthly` に対して次を要求しない。

- 旧月次データの backfill
- 旧集計の再計算
- 過去の試験データへの適用

整理:

- 今回以降の実装で生成される `baselineSnapshot / adjustments / cashActions` に対して、新しい更新責務を適用する
- 既に存在する `analyticsMonthly` の開発用データが新仕様と完全一致していなくても、それを問題としない

### 4. `bills` について

今回の current-scope では、既存 `bills` に対して次を要求しない。

- 旧 parent field の一括変換
- 旧 event 断片の `adjustments / cashActions` 化
- 既存 draft / settle 済み bill の変換

整理:

- 新仕様は、**以後に作られる bill から適用する**
- 既存の検証用 `bills` は、今回の step3.11 の正本対象にしない

### 5. 初期化時に必要なもの

今回の current-scope では、**必須の storeMeta migration はない**と整理する。

ただし、将来次のようなものが必要になった場合は、migration ではなく **初期化時生成** で扱う。

- schema version
- feature flag
- 集計トリガの有効化フラグ
- 新しい summary / read model の生成開始フラグ

方針:

- もし storeMeta や初期設定 doc に追加 field が必要になった場合は、**初期化時に適切な field が作られるようにする**
- 既存 `analyticsMonthly` や既存 `bills` を改修に適合させるための backfill は前提にしない

### 6. Step4 以降への影響

今回の結論により、Step4 以降では次を前提にしてよい。

- migration 章は必須ではない
- もし書くとしても「現時点では不要」と明記すればよい
- 実装仕様は、新規生成データの整合性に集中してよい

## 今回ここで確定しないもの

今回は「移行不要」を確定するが、次は future とする。

- リリース後に既存本番データが生まれた場合の migration 方針
- 段階リリース時の旧新混在対応
- 途中から `reportingEntries` を導入する場合の backfill 要否
- 旧 trial データを残すかどうか

## current-scope の結論

今回の `step3.11` では、**既存データ移行は不要**とする。  
新仕様は、以後に生成される `bills` とその配下データに適用し、必要な初期設定があれば初期化時に作る。
