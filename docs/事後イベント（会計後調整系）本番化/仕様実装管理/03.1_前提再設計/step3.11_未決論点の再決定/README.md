# step3.11_未決論点の再決定 README

このディレクトリは、`step3.12` で全体整合性を確認する前に、その前提となる基盤仕様を見極め、必要なものを確定するための作業場所である。

ここでの進め方は次の 3 段階とする。

1. `3.11` で確定対象になりうる仕様候補を洗い出す
2. 各候補について、「この時点で確定しないと `step3.12` の整合性確認ができないか」を評価する
3. 必要ありと判断した候補について、`step3.11` の中で仕様を確定する

この段階では、詳細 API や画面レイアウトを詰め切ることが目的ではない。あくまで、全体整合性確認の前提となる基盤仕様を確定することが目的である。

## このディレクトリの使い方

- まず [01_進め方と判断基準.md](./01_進め方と判断基準.md) を参照する
- 次に [02_ここで確定させるべき仕様の候補一覧.md](./02_ここで確定させるべき仕様の候補一覧.md) で候補を並べる
- その上で候補別ファイルを使って、各仕様について「3.11で確定が必要か」を評価する
- 必要ありとなったものは、その候補別ファイル内で仕様確定まで進める
- 最後に [03_確定対象の評価結果.md](./03_確定対象の評価結果.md) に、`step3.12` へ渡す確定対象をまとめる

## この時点での初期候補

- 事後イベントとして用意する機能 / 業務パターン
- `analyticsMonthly` / 入出金系データ / 運用 read model の役割分担
- `bills` の SoT と保存モデル
- 親 doc の status / summary / pending 管理
- 売上日 / 入出金日 / 営業日の帰属ルール
- 未会計 / 一部未徴収 / 会計後イベントの接続方針
- 既存データ互換 / 移行方針
- 売上差分明細の粒度・配賦ルール

## 完了条件

- `step3.12` の整合性確認を進めるために必要な基盤仕様が明確になっている
- 各候補について、`step3.11` で確定するか、`step3.12` 以降へ回すかが判断されている
- `step3.11` で確定対象としたものについては、候補別ファイル内で決定内容が残っている
- [03_確定対象の評価結果.md](./03_確定対象の評価結果.md) に、確定対象と保留対象がまとめられている
