# 01_進め方と判断基準

## ゴール

`step3.12` で全体整合性を確認するための前提となる基盤仕様を特定し、その基盤仕様を確定する。

## 進め方

1. 仕様候補を洗い出す
2. 各候補について、`step3.11` で確定させる必要があるかを評価する
3. 必要ありと判断した候補だけを、この段階で確定する
4. 確定対象を `step3.12` の入力として引き渡す

## `step3.11` で確定させる必要があるかの判断基準

次のいずれかに当てはまる場合、その候補は `step3.11` で確定対象とする。

- その仕様が決まっていないと、`step3.12` で整合性確認の観点自体が定まらない
- 他の複数仕様の前提になるため、後ろに回すと議論が発散しやすい
- `bills` / `analyticsMonthly` / status / pending / 営業日の関係に直接影響し、後ろに回すと再設計範囲が広がる
- 仕様書の責務分割に影響し、`step3.15` 以降に大きな手戻りを生む

## `step3.11` でまだ確定しなくてよいもの

次のものは、原則として `step3.12` 以降でもよい。

- 詳細 API 契約の最終形
- 画面レイアウトや UI 微調整
- migration / backfill の実施手順詳細
- テストケースの詳細列挙
- 実装順の細かな分割

- 候補別の評価・決定: 各候補ファイル
