### 2.3 Emulator 統合テスト

新規:

- `__tests__/callables/reopenAccountedBill.spec.ts`
  - happy path（settled bill から reopen）
  - happy path（post_settlement_pending bill から reopen）
  - effective adjustments が `cancelled_by_reopen` になる
  - 完了済 adjustments (`completed_by_cash_action` / `completed_by_offset`) は touch されない
  - cashActions の `allocations[]` / `methodBreakdown[]` は保持
  - 親 doc が `status='open'`、`currentSummary` reset、`postSettlementState` reset、`reopenSummary` 更新
  - `latestSettledCycle` は据え置き、`currentSettlementCycle += 1`
  - 旧 cycle が `cycleState='reopened'`、`closedReason='reopen'`、`closedAt` 設定
  - 旧 cycle の baselineSnapshot は immutable（変更されない）
  - 新 cycle が `cycleState='open'`、`openedReason='reopen'`、`openedFromCycleNo=oldCycleNo`、`nextSequenceNo=1` で作成
  - 新 cycle の baselineSnapshot/snapshot は **存在しない**
  - 当日営業日チェック: `bill.businessDate !== currentBusinessDateKey` で `failed-precondition` (error key `BILLS_REOPEN_NOT_TODAY`)
  - status precondition: `open` / `voided` / `settling` / `in_progress` で `failed-precondition`
  - `latestSettledCycle = 0` で `failed-precondition`
  - idempotent replay（同 idempotencyKey + 同 requestHash で `reused: true`）
  - 異 requestHash で `failed-precondition`
  - permission denied（auth なし / device 不正）
  - end-to-end: reopen 後に `accounting` callable 呼び出し → `billsOnSettle` trigger → 新 cycle baseline 作成 → `latestSettledCycle` 追いつき

- Emulator 依存テストの失敗は Emulator 再起動 → 再実行 を試みる

- 再起動で解消した場合も簡潔に `06_確認結果サマリ.md` に記録する
