[02_changeSpec.md](./02_changeSpec.md) で確定した実装範囲が、仕様書 §5〜§20 と上流文書（12 / 15 / 18 / blockC）に対して漏れなく整合することを確認する。

## 1. 純粋関数 unit test

| ケース | 検証内容 |

| 1 line / extra / amountInclDelta = +500 (increase) | grossSales = +500、`byCategory.extraCost = +500` |

## 2. Emulator integration test

### 2.1 `__tests__/analytics/applyAdjustmentToAnalytics.spec.ts`

`processAdjustmentAnalyticsAtomically` を Firestore Emulator で検証する。

| ケース | 検証内容 |
|---|---|
| 初回呼び出し | `analyticsMonthly/{month}` の `grossSales` / 各 category sales が delta 分 increment、`days/{businessDate}` も同様、`byCategory/summary.totals` が increment、`byUser/{userId}` が increment（userId 有時）、`byTemplateTournaments/{templateKey}` が tournament line ある場合 increment、marker `adj_{adjustmentId}` 作成 |
| 同 adjustmentId で 2 回目呼び出し | marker check で early return、各 sub-collection は変化なし（idempotent） |
| userId 無し bill | `byUser` 更新なし、他は同じ |
| tournament line 含む adjustment | `byTemplateTournaments/{templateKey}` の `daily.{businessDate}.entryCount` 等が increment |
| empty tournament | `byTemplateTournaments` 更新なし |
| 増額（sign +）と減額（sign -）の両方 | increment 値の符号が正しい |
| 既存 doc が無い state での初回 | `set` で初期化、その後 `update` で increment |

### 2.3 `__tests__/analytics/applyReopenRollbackToAnalytics.spec.ts`

`applyReopenRollbackToAnalyticsAtomically` を検証する。

| ケース | 検証内容 |
|---|---|
| 旧 cycle baseline 寄与 rollback | `grossSales` / 各 category sales が inverse increment（負方向）、settle marker `{billId}_cycle{prevCycleNo}_settle` 削除 |
| legacy `{billId}` marker のみ存在する旧 bill の rollback | legacy marker も削除、inverse increment 同 |
| 旧 cycle adjustment 群の rollback | 各 `adj_{adjustmentId}` marker 削除、inverse increment（+ → -、- → +） |
| 旧 cycle collection cashAction 群の rollback | `paymentTotals` inverse increment、`cash_{cashActionId}` marker 削除 |
| refund cashAction が混在しても rollback 対象外 | refund は元々 paymentTotals 触らないため、rollback しない |
| rollback 後に resettle で marker key `{billId}_cycle{newCycleNo}_settle` で再 settle 反映可能 | resettle 経路の挙動と組み合わせて確認 |

## 7. 実機確認観点

`08_実機確認手順.md` で詳細化。Step07 では Functions 側変更のみのため、Flutter 側 UI は変わらない（`requireSpecialAttentionPage` 等は Step06 のまま）。実機確認は次の流れ:

1. settle 後、`analyticsMonthly/{month}` の `grossSales` / `paymentTotals` が正しく増えていることを Firestore Console で確認
2. adjustment 作成後、`grossSales` が delta 分動いていることを確認
3. collection cashAction 後、`paymentTotals.{method}` が増えていることを確認
4. refund cashAction 後、`paymentTotals` に変化がないことを確認
5. reopen 後、上記のすべてが rollback 状態に戻っていることを確認
6. resettle 後、新 baseline で再反映されていることを確認
