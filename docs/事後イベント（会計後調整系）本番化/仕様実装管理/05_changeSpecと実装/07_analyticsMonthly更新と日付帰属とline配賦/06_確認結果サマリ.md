## 7. テスト失敗時の取り扱い

- 初回の rollback spec 実行で `entrySalesIncl` field 名のミスマッチで 1 件 fail（settle path は `entrySalesIncl` で書き込む、自分の rollback aggregator は `entrySales` で読んでいた）
  - 対応: `applyReopenRollbackToAnalytics.ts` で `t.entrySalesIncl ?? t.entrySales ?? 0` の fallback に修正
- 全体テスト初回実行で「rollback spec が他 spec と project が衝突して fail」
  - 対応: `applyReopenRollbackToAnalytics.spec.ts` の `beforeAll` で `admin.initializeApp({ projectId: PROJECT_ID })` を追加し、`testEnv.clearFirestore` の対象 project と admin SDK の project を一致させた
- いずれも修正後に再実行で全 pass
