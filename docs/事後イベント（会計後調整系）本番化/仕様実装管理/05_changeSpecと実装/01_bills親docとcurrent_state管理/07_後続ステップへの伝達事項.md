# 07_後続ステップへの伝達事項

## 1. 後続に引き渡す前提

- Step01 は `bills/{billId}` 親 doc の target contract を先に導入するステップである。
- 後続 step は、親 doc の正規 field として少なくとも次を前提にする。
  - `status`
  - `settlementSnapshot`
  - `currentSummary`
  - `postSettlementState`
  - `reopenSummary`
  - `closeSummary`
  - `ops`
  - `draftAccountingInput`
- 旧 `postEvents` / `closeSnapshot` / root `amounts` などは、Step01 完了直後も暫定共存する可能性がある。
- `functions/src/domains/bills/services/parentSummary.ts` は Step01 で追加した helper であり、後続 step の parent summary 更新でも優先的に再利用する。
- `createBillWithActiveStay` の repo 例外契約は `HttpsError` へ正規化済みであり、後続 helper repo も同じ扱いを維持する。

## 4. 注意事項

- 実装依存:
  - Step01 で旧 field を完全削除しない場合、後続 step は暫定共存を考慮して読取箇所を段階的に切り替える必要がある
  - Step03-05 で parent summary を更新する時は、Step01 で導入した初期値 shape を壊さず、未使用 field を delete ではなく target contract に沿って維持する
- テスト依存:
  - Step03 以降は Step01 で更新した create/start/settle/cancel/close 系テスト前提に追加する
  - Firestore Emulator 依存 suites は、各 step の確認結果に「未確認」ではなく「Emulator 未起動で保留」と明記する
- 運用依存:
  - unreleased 前提のため migration 不要だが、テストデータや既存手動検証手順は旧 field 名のまま残っている可能性がある
