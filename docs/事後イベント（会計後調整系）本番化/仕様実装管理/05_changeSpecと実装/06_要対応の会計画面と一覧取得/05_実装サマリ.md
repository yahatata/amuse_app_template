### 2.4 firestore.indexes.json

新規 index 追加なし。

理由: Step06 の query は

```
where('status', isEqualTo: ...).where('<dotted>', isEqualTo: ...)
```

の 2 つの equality 条件のみで、`orderBy` / 不等式を含まない。Firestore は equality only 多次元 query を **single-field index の zigzag merge join** で処理するため composite index 不要。

仕様書 §13.5 と changeSpec §5.8 で「既存 index と重複していなければ追加」としていたが、実際の query 形に合わせて「不要」と判断した。

## 5. リスク評価と対応

### 5.1 stream 結合の race condition（changeSpec §9.3）

- 3 streams（`carryover` / `collection` / `refund`）を別 listener で受けて `Map<String, BillRequireAttentionViewModel>` に格納
- 同一 billId が 2 つの map に同時に乗ることは仕様上ない（status による排他）が、status 遷移直後の一瞬は theoretical に重複し得る
- 対策: 表示時に `_allVms` を生成する側で `BillCardType` 排他は `classifyBill` が保証するため、view model を作る段階で 1 種類に固定 → race の影響なし

### 5.2 dialog の effective adjustment fetch 失敗

- dialog 起動時に `bills/{billId}/settlementCycles/{cycle}/adjustments where adjustmentState='effective'` を get
- 失敗時は `_error = '対象 adjustment の取得に失敗しました'` を inline 表示し、submit ボタンは disabled
- `cycleNo` は `bill.reopenSummary.currentSettlementCycle` から取得（不在時は `1` fallback、Step02 baselineSnapshot 開始時の cycle = 1 と一致）

### 5.3 callable 失敗時のフィードバック（changeSpec §9.4）

- `FirebaseFunctionsException` を catch し、`code` + `message` を inline 表示
- `finally` で `_submitting = false` に必ず戻す（loading 状態リーク防止）

### 5.4 旧 dialog / 旧 callable との混乱（changeSpec §9.5）

- 要対応一覧画面 → 新 dialog → `recordPostSettlement*` callable
- 既存 `AccountingPage` 等での事後操作 → 旧 dialog → 旧 callable
- 共存で問題なし（書き込み先が `bills/{billId}/settlementCycles/{cycle}/cashActions` で同じため、要対応一覧側の stream が自動的に最新状態を反映する）

### 5.5 firestore.indexes.json 不更新

- equality only 2 条件のため zigzag merge join で動作する想定
- 実機で `failed-precondition: The query requires an index` が出た場合は、本仕様の §13.5 / changeSpec §5.8 に沿って index を追加する（事前準備済み JSON は changeSpec に記載）

## 7. 補足メモ

### 7.1 cycle 番号の取得

- 新 dialog では `bill.reopenSummary.currentSettlementCycle` を読む
- baselineSnapshot 開始時 (cycle = 1) は `reopenSummary` 不在のケースもあるため、`?? 1` で fallback
- Step02 で `currentSettlementCycle = 1` を初期化していれば fallback は走らない

### 7.2 dialog の allocation 単純化（current-scope）

- 仕様書 §17.5「複数 adjustment への按分は post-MVP」に従い、effective adjustment のうち最初の 1 件に全額割り当て
- `amount > target.remaining` の場合は `target.remaining` に clamp（callable 側でも同 validation あり）
- 将来複数 adjustment 対応を入れる場合は dialog 側で allocation UI を増やす

### 7.3 stream の `requiredActionIncl > 0` filter

- Firestore composite index を増やさないため、`requiredActionIncl > 0` は client-side で `classifyBill` が判定
- query 結果に `incl <= 0` の bill が含まれた場合、`fromBill` が null を返して view model に含まれない
- 一覧件数として実害なし

### 7.4 ユーザー別タブの paging

- 現状: 全ユーザー一覧を一度に描画（`buildSectionedUserListPage`）
- 大規模店舗で carryover が多数発生した場合の paging は post-MVP（Step07 以降の `analyticsMonthly` 集計と並行検討）

### 7.5 Functions リグレッション失敗の今後

- 11 suites の既存失敗は本ブランチ着手前から存在。Step01〜07 の本番化対象外
- 別ブランチ / 別タスクで個別に対応する想定（`07_後続ステップへの伝達事項.md` に記載）
