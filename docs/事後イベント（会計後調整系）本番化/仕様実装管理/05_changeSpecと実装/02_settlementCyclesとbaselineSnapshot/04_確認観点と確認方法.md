# 04_確認観点と確認方法

## 1. 自動確認

### 1.1 TypeScript build

- 目的: helper 追加と trigger 更新で型崩れがないことを確認する
- コマンド:

```bash
npm --prefix functions run build
```

- 期待結果:
  - build 成功
  - TypeScript error なし

### 1.2 createBill で cycle 1 が生成されること

- 目的: bill 作成時に `settlementCycles/1` が初期 open 状態で作られることを確認する
- コマンド:

```bash
firebase emulators:exec --only firestore "npm --prefix functions test -- __tests__/helpers/billsApi/createBillWithActiveStay.spec.ts --runInBand"
```

- 期待結果:
  - suite 成功
  - `settlementCycles/1` の存在と初期 field が検証される

### 1.3 settle で cycle / baseline が保存されること

- 目的: `billsOnSettle` が current cycle settled 化と baselineSnapshot 保存を行うことを確認する
- コマンド:

```bash
firebase emulators:exec --only firestore "npm --prefix functions test -- __tests__/triggers/bills.onSettle.spec.ts --runInBand"
```

- 期待結果:
  - suite 成功
  - `baselineSummary` と `baselineSnapshot/snapshot` が検証される
  - 通常 settle で cycle 数が増えないことが確認される

## 2. テスト失敗時の再試行

### 2.1 エミュレータ再起動

エミュレータ依存テストが失敗した時は、まず Firebase Emulator を再起動して再試行する。

実施例:

```bash
firebase emulators:exec --only firestore "npm --prefix functions test -- __tests__/helpers/billsApi/createBillWithActiveStay.spec.ts __tests__/triggers/bills.onSettle.spec.ts --runInBand"
```

### 2.2 今回の補足

- `npx jest ...` を直接使うと workspace 外の Jest が解決され、バージョン不一致で失敗する場合がある
- current-scope では必ず `npm --prefix functions test -- ...` を使う

## 3. 手動 / 目視確認

### 3.1 Firestore 目視確認

対象:

- `bills/{billId}`
- `bills/{billId}/settlementCycles/1`
- `bills/{billId}/settlementCycles/1/baselineSnapshot/snapshot`

見ること:

- cycle 1 の初期 open field
- settle 後の `cycleState=settled`
- `baselineSummary` の存在
- `baselineSnapshot` の arrays と summary
- 通常 settle で cycle doc が 1 件のまま

### 3.2 コードレビュー確認

見ること:

- baselineSnapshot の保存先 path が固定されているか
- Step02 で actual reopen runtime を混入させていないか
- root snapshot 群を削除していないか
