# 08_実機確認手順

## 1. このファイルの目的

このファイルは、Step02 が本当に完了しているかを実機と Firestore 目視で確認するための手順書である。

Step02 の確認対象は、あくまで **通常会計の create / settle パスで `settlementCycles` と `baselineSnapshot` が仕様どおり保存されること** である。

## 2. 事前準備

- 開発環境で Functions / Firestore Emulator を起動できること
- bill を新規作成できる画面へアクセスできること
- Firestore の該当 document を確認できること
- できれば検証用の新しい user / bill を使うこと

## 3. シナリオ1: 新規 bill 作成時に cycle 1 が作られること

### 3.1 画面で行うこと

1. 顧客を入店させる
2. bill を新規作成する
3. まだ会計確定はしない

### 3.2 Firestore で確認する場所

- `bills/{billId}`
- `bills/{billId}/settlementCycles/1`

### 3.3 確認ポイント

`bills/{billId}/settlementCycles/1` が存在し、少なくとも次が入っていること。

- `cycleNo = 1`
- `cycleState = open`
- `openedReason = initial`
- `openedFromCycleNo = null`
- `nextSequenceNo = 1`
- `baselineSummary = null`
- `settledAt = null`
- `closedAt = null`

### 3.4 このシナリオの完了条件

- bill 作成だけで `settlementCycles/1` が作られている
- まだ `baselineSnapshot` は作られていない

## 4. シナリオ2: 通常会計確定で cycle と baseline が保存されること

### 4.1 画面で行うこと

1. bill に item / extra / tournament / chip などを入れる
2. 通常会計を開始する
3. 会計を確定する

### 4.2 Firestore で確認する場所

- `bills/{billId}`
- `bills/{billId}/settlementCycles/1`
- `bills/{billId}/settlementCycles/1/baselineSnapshot/snapshot`

### 4.3 bill 親 doc の確認ポイント

少なくとも次が更新されていること。

- `status = settled`
- `reopenSummary.currentSettlementCycle = 1`
- `reopenSummary.latestSettledCycle = 1`
- `settlementSnapshot` が存在する
- `currentSummary` が settle 結果に更新される
- `meta.contentHash` が入る

### 4.4 cycle 親 doc の確認ポイント

`bills/{billId}/settlementCycles/1` に少なくとも次が入っていること。

- `cycleState = settled`
- `settledAt` が入っている
- `settledBy` が必要に応じて入る
- `closedReason = settle`
- `baselineSummary` が入っている

### 4.5 baselineSnapshot の確認ポイント

`bills/{billId}/settlementCycles/1/baselineSnapshot/snapshot` が存在し、少なくとも次を持つこと。

- `items[]`
- `extras[]`
- `tournaments[]`
- `sideGameChips[]`
- `amounts`
- `categoryBreakdown`
- `paymentTotals`
- `paymentsSummary`
- `contentHash`

さらに、会計時に入れた実データに応じて配列が埋まっていること。

例:

- item を 1 件入れていれば `items[]` に 1 件以上ある
- tournament を入れていれば `tournaments[]` に template 単位の summary がある
- sideGameChip を入れていれば `sideGameChips[]` に amount が入る

## 5. シナリオ3: 通常 settle で cycle が増えないこと

### 5.1 画面で行うこと

1. 通常会計を 1 件完了させる
2. `reopen` は実行しない
3. Firestore の cycle docs を確認する

### 5.2 Firestore で確認する場所

- `bills/{billId}/settlementCycles`

### 5.3 確認ポイント

- doc 数が `1` 件のままであること
- `settlementCycles/2` などが勝手に作られていないこと

## 6. Step02 を完了と言ってよい判定

次をすべて満たしたら、Step02 は完了と言ってよい。

1. bill 作成時に `settlementCycles/1` が `open` で作られる
2. 通常会計確定時に `settlementCycles/1` が `settled` になる
3. `baselineSummary` が cycle 親 doc に入る
4. `baselineSnapshot/snapshot` が作られる
5. `baselineSnapshot` に items / extras / tournaments / sideGameChips の最小 shape が入る
6. 通常 settle だけでは cycle 数が増えない
7. `reopen` をまだ実行していない状態で、Step02 の create / settle パスに不足がない

## 7. 補足

- `reopen` 実行時の cycle 進行は Step05 の確認対象であり、このファイルでは扱わない
- root 直下の旧 snapshot 群が残っていても問題ない。Step02 の完了判定は `settlementCycles` と `baselineSnapshot` が追加保存されているかで行う
