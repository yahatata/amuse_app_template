#### 2.2.1 `cashActions.spec.ts`

- `buildCashActionDoc`
  - 必須 field をすべて埋めて返す
  - multi method（cash + credit_card）で返す
  - multi allocation（adj_1 / adj_2 同時）で返す
  - amountIncl != sum(methodBreakdown) で throw
  - amountIncl != sum(allocations) で throw
  - allocations 空で throw
  - methodBreakdown 空で throw
  - method 文字列空で throw
- `validateMethodBreakdown`
  - 1 件 / multi で正常受理
  - 合計不一致 throw
  - method 文字列不正 throw
  - amountIncl <= 0 throw
- `validateAllocations`
  - allocation 空で throw（仕様書 §9.4.1 / §15.1）
  - 合計 != cashActionAmountIncl で throw（§9.4.2 / §15.2）
  - 異 cycle adjustment 混在で throw（§9.4.3 / §15.3）
  - direction 不整合（refund cashAction で increase 系 adjustment への allocate）で throw
  - completed_by_offset 済 adjustment への allocate で throw（`effective` のみ可）
  - completed_by_cash_action 済 adjustment への allocate で throw
  - over-allocation で throw（§9.4.5 / §15.4）
  - 同一 adjustmentId への重複 allocation で throw
- `applyAllocationsToAdjustments`
  - 1 件 allocation で remaining 部分減
  - 1 件 allocation で remaining=0 → `completed_by_cash_action`
  - 2 件 multi allocation で同時 remaining 減
  - 既存 patches を上書きしないこと
- `resolveCashflowBusinessDate`
  - input 指定があればそれを優先
  - input なし + calcBusinessDate が文字列を返す → calcBusinessDate 結果を採用
  - input なし + calcBusinessDate が AMBIGUOUS / NONE → bill.businessDate を borrow
  - input なし + calcBusinessDate も bill.businessDate も空 → throw
- `buildImmediateCashActionDoc` の後方互換性（既存テストが pass し続ける）

#### 2.2.2 `parentSummary.cashAction.spec.ts`

- `buildPostSettlementStateAfterCashAction`
  - refund cashAction で `totalRefundedIncl += amountIncl`
  - collection cashAction で `totalCollectedIncl += amountIncl`
  - `lastRecordType = 'cash_action'` 固定
  - `lastRecordId / lastRecordAt` が cashAction 値で書かれる
  - `requiredActionType / requiredActionIncl` が summarized remaining から派生
  - `hasPostSettlementActivity = true`
- `buildCurrentSummaryAfterCashAction`
  - refund で `refundedTotalIncl += amountIncl`
  - collection で `receivedTotalIncl += amountIncl`
  - `claimTotalIncl / netSalesIncl` は不変
- `deriveStatusAfterCashAction`
  - remaining > 0 → `post_settlement_pending`
  - remaining = 0 → `settled`

## 4. テスト実行で失敗した場合

### 4.1 Emulator 依存テスト失敗時

1. Emulator を停止
2. 既存の `/tmp/firestore-emulator-*` などキャッシュを片付け
3. Emulator を再起動
4. 再実行

それでも失敗する場合は実装不備 / テスト不備 / 環境依存のいずれかを切り分けて `06_確認結果サマリ.md` に記録する。

### 4.2 unit テスト失敗時

1. 純粋関数の unit テストは Emulator に依存しないので、再起動では治らない
2. 失敗の根本を特定し、実装または test を修正
3. 修正内容を `06_確認結果サマリ.md` に記録
