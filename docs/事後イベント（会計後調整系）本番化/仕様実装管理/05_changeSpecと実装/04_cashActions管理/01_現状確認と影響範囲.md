## 2. 仕様書 04 の current-scope サマリ

仕様書 04 が要求するのは次の範囲。

- 保存先 `bills/{billId}/settlementCycles/{cycleNo}/cashActions/{cashActionId}`
- 必須 field: `sequenceNo` / `cashActionType` / `amountIncl` / `executedAt` / `executedBy` / `cashflowBusinessDate` / `methodBreakdown[]` / `allocations[]` / `note`
- `cashActionType` 値域: `refund` / `collection`
- `methodBreakdown[]`: `method` / `amountIncl`、複数 method 対応
- `allocations[]`: `adjustmentId` / `amountIncl`、1 件以上必須、同一 cycle、`requiredActionRemainingIncl > 0` 制約、over-allocation 禁止
- `cashAction.amountIncl == sum(methodBreakdown[].amountIncl) == sum(allocations[].amountIncl)`
- adjustment 残額更新: allocation に従い `requiredActionRemainingIncl -= allocation.amountIncl`、0 になった adjustment は `completed_by_cash_action`
- immediate（adjustment と同一 transaction）と later（adjustment 既存 + 後続 cashAction）の双方をサポート
- parent 反映:
  - refund: `currentSummary.refundedTotalIncl` 増、`postSettlementState.totalRefundedIncl` 増
  - collection: `currentSummary.receivedTotalIncl` 増、`postSettlementState.totalCollectedIncl` 増
  - 共通: `requiredActionType` / `requiredActionIncl` の再計算、`lastRecordType = cash_action`、`lastRecordAt = executedAt`、`lastRecordId = cashActionId`、未解消なしで `status = settled`
- `sequenceNo` は cycle の `nextSequenceNo` から adjustment と同一カウンタで採番
- 不可条件: allocations なし不可、合計不一致不可、異 cycle 混在不可、over-allocation 不可

### 6.2 immediate cashAction の duplicate 経路

- Step03 で `createPostSettlementAdjustment` 内に immediate cashAction 作成ロジックを既に書いている
- Step04 で新 callable `createPostSettlementCashAction` を立てる場合でも、immediate 経路は **そのまま `createPostSettlementAdjustment` 内で完結する** 方針が自然（仕様書 04 §11.1）

### 6.3 `cashflowBusinessDate` の AMBIGUOUS / NONE

- 仕様書 04 では明示的に AMBIGUOUS / NONE 処理は記載されていない
- `calcBusinessDate` の戻り値が AMBIGUOUS / NONE になる現実のシナリオ（深夜帯・営業日マップ未定義）に対するフォールバック方針を Step04 で決める必要がある
- 候補:
  - A: `bill.businessDate` を borrow（Step03 と同等）
  - B: `executedAt` の UTC 日付をそのまま使う
  - C: 入力で `cashflowBusinessDate` を必須化し、AMBIGUOUS / NONE のときは callable レベルで弾く
