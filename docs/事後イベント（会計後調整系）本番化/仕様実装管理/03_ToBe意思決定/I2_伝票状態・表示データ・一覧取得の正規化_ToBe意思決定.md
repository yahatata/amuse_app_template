## 1. このファイルの役割

本ファイルは、会計管理でどの伝票をどう見せるか、どのデータを表示の正とするか、`terminalHome` からどの一覧へ入るかを決めるための作業ファイルである。

ここで曖昧さを残すと、Step4 で画面仕様とデータ仕様が分離できず、実装時にカード表示・詳細表示・編集導線が再びずれる。

## 2. この項目の進め方

1. Codex が、各論点について `どこで`, `何が`, `なぜ困るか` を chat で整理する
2. 問題ごとに、表示の問題か、取得条件の問題か、状態遷移の問題かを切り分ける
3. 技術設計として決められるものは Codex が推奨案を提示する
4. 業務運用や画面上の見せ方でユーザー判断が必要なものは、選択肢を比較して相談する
5. 決定事項を本ファイルに追記し、画面仕様へ引き継げる状態にする

## 4. chat で必ず整理する内容

各論点について、chat では次の内容を漏れなく出す。

1. 問題がある場所:
   - どのページか
   - どの処理か
   - どのデータか
2. 現状:
   - 今は何を読んでいるか
   - その結果、何がずれているか
3. 判断主体:
   - 技術的に一本化すべきものか
   - ユーザーに見せる運用ルールを決める必要があるか
4. 改善案:
   - 正とするデータ源
   - 一覧に含める status
   - Trigger 反映待ちの見せ方
5. 決定後の出口:
   - Step4 でカード仕様、一覧取得条件、表示ルールを書ける状態にする

## 5. 決定記録

### 5.1 決定済み

- `I2-01`: 一覧カード・会計後カード・履歴画面の表示データ源は親 doc の正規サマリを正とし、編集や明細再構築が必要な場面だけサブコレクションを読む
- `I2-02`: `terminalHome` の現在の `未会計の会計` メニューは `要対応の会計` に改名する
- `I2-02`: `要対応の会計` では、閉店持ち越し未会計と会計後要対応を同じ画面で扱う
- `I2-02`: 一覧の表示軸は `日付ごと / ユーザー別` を維持する
- `I2-02`: 一覧のカテゴリフィルタは `すべて / 未会計 / 追加徴収 / 要返金` とし、デフォルトは `すべて` とする
- `I2-02`: 同じ画面で扱う対象は、内部的には
  - `carryover_unsettled`
  - `post_settlement_collection_pending`
  - `post_settlement_refund_pending`
  の 3 種に整理する
- `I2-02`: `未会計` は `status = open` かつ `closeSummary.unresolved = true` の bill を指す
- `I2-02`: `追加徴収` は `status = post_settlement_pending` かつ `requiredActionType = collection` の bill を指す
- `I2-02`: `要返金` は `status = post_settlement_pending` かつ `requiredActionType = refund` の bill を指す
- `I2-03`: `reopen` 後の status は `open` とし、`in_progress` は採用しない
- `I2-03`: `reopen` 後の bill は会計後要対応一覧ではなく、通常の未会計 bill として扱う
- `I2-04`: 事後イベント成功後は即時リロードではなく、親 doc 更新を待ってから反映し、UI では `反映中` を明示する
- `I2-05`: 会計完了済み bill に対する旧 `修正` 導線は廃止し、post-settlement 操作は新しい会計後導線へ統一する
- `I2-06`: サイドゲームチップ表示は親 doc の正規サマリと店舗設定レートを正とし、固定 `10` レート前提の見え方を残さない
- `I2-07`: `要対応の会計` の日付一覧では、要対応 bills 自体を表示する
- `I2-07`: `要対応の会計` のユーザー一覧では、該当 bill を持つユーザー一覧を表示する
- `I2-07`: ユーザーカードには少なくとも `総件数`, `未会計 x件`, `追加徴収 x件`, `要返金 x件` を表示する
- `I2-07`: カードは簡潔表示を基本とし、必要情報のフルセットは詳細ページ側に集約する
- `I2-07`: `voided` は current-scope の標準一覧状態として採用しない
- `I2-08`: 返金画面では `元の支払内訳`, `方法別の既返金額`, `方法別の残り返金可能額` を表示し、選択した返金方法ごとの上限で入力制御する
