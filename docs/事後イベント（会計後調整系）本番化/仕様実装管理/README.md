# 事後イベント（会計後調整系）本番化 仕様実装管理 README

## 1. このフォルダの目的

このフォルダは、事後イベント（会計後調整系）本番化を **項目再編 -> AsIs 固定 -> ToBe 意思決定 -> 前提再設計 -> 詳細仕様書 -> changeSpecと実装** の順で進めるための、今後の正本ドキュメントと実装検証記録の置き場とする。

この README は、各フェーズで **何を入力にし、何を成果物として作り、次に何を正本として参照するか** を管理し、最終的に実装と検証の進行管理までつなぐための起点とする。

---

## 2. 参照ルール

- Step1 の入力資料として [../改修フォーカス候補.md](../改修フォーカス候補.md) を参照し、項目定義の正本を [01_改修項目再編.md](./01_改修項目再編.md) に切り替えた。
- 以後の作業では、項目定義の参照元を原則として [01_改修項目再編.md](./01_改修項目再編.md) に統一する。
- Step2 以降は、原則として **このフォルダ内で直前フェーズまでに作成した正本** を参照する。
- [../改修フォーカス候補.md](../改修フォーカス候補.md) と [../初期検討事項まとめ.md](../初期検討事項まとめ.md) は、Step1 完了後は **根拠確認・履歴確認のための補助資料** としてのみ扱い、新規の整理や仕様判断の直接参照元にはしない。
- 各フェーズ完了時に、この README の「現在の正本」と「次フェーズの入力」を更新する。
- `Step3` 完了後は、`03.1_前提再設計/` で `step3.11` から `step3.16` を進める。特に `step3.11` から `step3.15` では、前提が固まるまで実装に入らない。
- 税務・会計 read model の厳密化のうち、`step3.11` の current-scope を超えるものは [05_今後検討_税務会計read_model拡張.md](./05_今後検討_税務会計read_model拡張.md) で継続管理する。

---

## 3. 番号ルール

- 従来の `F1` から `F15` は Step1 でのみ使用する旧番号とする。
- Step1 で、依存順に従った **新しい 5 項目** を確定し、以後は **`I1` から `I5`** の項目番号で扱う。
- Step2 から Step3.1 までは、AsIs / ToBe / 前提再設計を `I1` から `I5` を単位として管理する。
- Step4 以降は、`step3.15` で確定した **7 本の詳細仕様書単位**で管理する。
- Step5 以降の changeSpec は、原則として **仕様書 1 本に対して changeSpec 1 本**の対応関係に切り替える。
- 前提再設計のステップ番号は、`Step3` と `Step4` の橋渡し段階であることを明示するため、`step3.11` から `step3.16` を使用する。
- `F1` から `F15` は `01_改修項目再編.md` のマッピング表の中にのみ残し、その後のドキュメントでは原則使わない。

補足:
各ディレクトリ配下のファイルは、次の命名方針を使う。  
- `02_AsIs/` と `03_ToBe意思決定/` は、原則として `I1_...md` から `I5_...md` を使う。  
- `03.1_前提再設計/` では、`step3.11_未決論点の再決定/` をフォルダとして運用し、必要に応じて `step3.12_...` から `step3.16_...` のステップ別ファイルを併用する。  
- `04_仕様書/` は、`step3.15` で確定した 7 分割に従い、`01_...md` から `07_...md` を使う。  
- `05_changeSpecと実装/` では、仕様書 1 本に対して changeSpec 1 本を基本とし、各ステップ配下の `02_changeSpec.md` を changeSpec の正本として運用する。  
税務・会計 read model の厳密化は、`step3.11` で無理に確定し切らず、上記の future doc に論点を逃がして段階的に詰める。

## 5. 進め方

### Step1. 改修項目を再編して「最終5項目」を確定する

- 入力:
  - [../改修フォーカス候補.md](../改修フォーカス候補.md)
- 出力:
  - `01_改修項目再編.md`
- このステップで必ず決めること:
  - `F1` から `F15` を重複なく `I1` から `I5` にマッピングする
  - 各項目の責務境界を決める
  - 実施順と依存順を決める
  - 以後の正式な項目番号を `I1` から `I5` に切り替える
- 完了条件:
  - `F1` から `F15` が重複なく 5 項目にマッピングされている
  - 依存順が明示されている
  - `I1` から `I5` の項目名と対象範囲が定義されている
- README 更新ルール:
  - 「現在の正本」の項目定義欄を `01_改修項目再編.md` に更新する
  - Step2 以降の入力欄から [../改修フォーカス候補.md](../改修フォーカス候補.md) への直接参照を外す

### Step2. 各項目の AsIs を事実ベースで固定する

- 入力:
  - `01_改修項目再編.md`
- 出力:
  - `02_AsIs/I1_*.md`
  - `02_AsIs/I2_*.md`
  - `02_AsIs/I3_*.md`
  - `02_AsIs/I4_*.md`
  - `02_AsIs/I5_*.md`
- 各 AsIs に記載すること:
  - 対象コード
  - 現挙動
  - 制約
  - 不具合再現条件
  - 未確定事項
- 完了条件:
  - 各項目について、事実ベースの 1 ページが成立している
- README 更新ルール:
  - 各項目の AsIs 正本への参照を追加する

### Step3. ToBe 方針の意思決定会を行う

- 入力:
  - `01_改修項目再編.md`
  - `02_AsIs/I1_*.md` から `02_AsIs/I5_*.md`
- 出力:
  - `03_ToBe意思決定/I1_*.md`
  - `03_ToBe意思決定/I2_*.md`
  - `03_ToBe意思決定/I3_*.md`
  - `03_ToBe意思決定/I4_*.md`
  - `03_ToBe意思決定/I5_*.md`
- このステップで分けること:
  - 決定済み
  - 保留
  - ユーザー判断待ち
- 特に業務面で決める対象:
  - 返金
  - 追加徴収
  - 未収
  - ポイント/残高
  - ステータス遷移
  - 閉店中の許可範囲
- 進め方:
  - まず `03_ToBe意思決定/` 配下に `I1` から `I5` の作業ファイルを作成する
  - 各会話では、対象項目の問題点を **漏れなく** 分解し、平易な言葉で chat に出す
  - chat では各問題について、`現状`, `問題がある場所`, `何が困るか`, `判断主体(Codex / ユーザー)`, `改善案または選択肢` を必ず整理する
  - `Codex` が判断できるものは、推奨対応と根拠をその場で提示する
  - ユーザー判断が必要なものは、判断事項と推奨案、代替案を提示し、会話で決定する
  - 会話で決まった内容は、その都度対応する `03_ToBe意思決定/I*_*.md` に追記していく
- 完了条件:
  - 業務ルールが「決定」と「保留」に分かれている
- README 更新ルール:
  - 各項目の ToBe 意思決定正本への参照を追加する

### Step3.1. 前提再設計と詳細仕様書作成準備

Step3.1 は次の 6 つのサブステップに分けて進める。

#### step3.11. 決まっていないことを再度決める

- 入力:
  - `03_ToBe意思決定/`
  - [../検討用メモ_事後イベント6パターン整理とanalyticsMonthly再設計.md](../検討用メモ_事後イベント6パターン整理とanalyticsMonthly再設計.md)
- 出力:
  - `03.1_前提再設計/step3.11_未決論点の再決定/`
- このステップで決める対象:
  - 6 パターンの業務定義
  - pending refund / pending collection（概念整理）
  - 会計後キャンセルの位置づけ
  - 売上帰属日 / cashflow 帰属日
  - `analyticsMonthly` 反映範囲
- 補足:
  - このステップでは、**現行実装から派生できる範囲**を優先して確定する
  - `bills` との整合性を崩す広い税務・会計 read model 論点は、[05_今後検討_税務会計read_model拡張.md](./05_今後検討_税務会計read_model拡張.md) に逃がす

#### step3.12. 全体の整合性を確認する

- 入力:
  - `step3.11` の決定内容
  - `I1` から `I5` の ToBe 正本
- 出力:
  - `03.1_前提再設計/step3.12_全体整合性確認/`
- 確認対象:
  - event 定義
  - parent doc
  - `baselineSnapshot / adjustments / cashActions` の役割分担
  - 未会計導線
  - analytics
  - 監査 / 再処理 / 検知

#### step3.13. 整合性が取れていない部分は再設計する

- 入力:
  - `step3.12` の整合性確認結果
- 出力:
  - `03.1_前提再設計/step3.13_*.md`
- このステップでやること:
  - 再設計対象の特定
  - 代替案整理
  - 修正後の整合確認

#### step3.14. 全体設計を完成させる

- 入力:
  - `step3.11` から `step3.13`
- 出力:
  - `03.1_前提再設計/step3.14_*.md`
- 完了条件:
  - 6 パターン
  - SoT
  - parent doc / `baselineSnapshot` / `adjustments` / `cashActions` / 未会計の関係
  - 売上日 / cashflow 日
  - analytics 更新 matrix
  - 複数 event 時の整合ルール
  が一貫した全体設計としてまとまっている

#### step3.15. 詳細仕様書をどの粒度で分けるか決定する

- 入力:
  - `step3.14` の全体設計完成版
- 出力:
  - `03.1_前提再設計/step3.15_*.md`
- このステップで決めること:
  - 詳細仕様書の責務分割
  - ファイル単位
  - 依存順
  - どの仕様書に何を書くか

#### step3.16. 詳細仕様書作成の着手条件を確認する

- 入力:
  - `step3.14`
  - `step3.15`
- 出力:
  - `03.1_前提再設計/step3.16_*.md`
- このステップで確認すること:
  - 全体設計に未決事項が残っていないこと
  - 詳細仕様書の責務分割が確定していること
  - `Step4` に着手してよい入力条件がそろっていること

### Step4. 詳細仕様書を作成する

- 入力:
  - `03.1_前提再設計/step3.14_*.md`
  - `03.1_前提再設計/step3.15_*.md`
  - `03.1_前提再設計/step3.16_*.md`
- 出力:
  - `04_仕様書/README.md`
  - `04_仕様書/01_bills親docとcurrent_state管理.md`
  - `04_仕様書/02_settlementCyclesとbaselineSnapshot.md`
  - `04_仕様書/03_adjustments管理.md`
  - `04_仕様書/04_cashActions管理.md`
  - `04_仕様書/05_reopenと再会計.md`
  - `04_仕様書/06_要対応の会計画面と一覧取得.md`
  - `04_仕様書/07_analyticsMonthly更新と日付帰属とline配賦.md`
- 各仕様書で必ず固めること:
  - 入力
  - 処理
  - 出力
  - 画面表示
  - エラー
  - 権限
  - 監査ログ
  - 運用資料へ残す事項
  - 非対象
- ルール:
  - `step3.11` から `step3.16` が完了するまでは、詳細仕様書へ見切り発車しない
  - 前提未確定のまま実装へ進めない

### Step5. changeSpecと実装/確認を仕様書単位で進める

- 入力:
  - `04_仕様書/*.md`
- 出力:
  - `05_changeSpecと実装/README.md`
  - `05_changeSpecと実装/00_全体進行管理.md`
  - `05_changeSpecと実装/01_bills親docとcurrent_state管理/`
  - `05_changeSpecと実装/02_settlementCyclesとbaselineSnapshot/`
  - `05_changeSpecと実装/03_adjustments管理/`
  - `05_changeSpecと実装/04_cashActions管理/`
  - `05_changeSpecと実装/05_reopenと再会計/`
  - `05_changeSpecと実装/06_要対応の会計画面と一覧取得/`
  - `05_changeSpecと実装/07_analyticsMonthly更新と日付帰属とline配賦/`
- 各ステップで必ず揃えること:
  - `01_現状確認と影響範囲.md`
  - `02_changeSpec.md`
  - `03_仕様書トレース確認.md`
  - `04_確認観点と確認方法.md`
  - `05_実装サマリ.md`
  - `06_確認結果サマリ.md`
  - `07_後続ステップへの伝達事項.md`
- 進め方:
  - 仕様書を確認してから現状確認を行う
  - changeSpec の前に影響範囲を洗い出す
  - 仕様書トレース確認で漏れを潰してから実装する
  - 実装前に確認観点と確認方法を先に決める
  - 実装後はテストと手動確認を行い、確認結果を残す
