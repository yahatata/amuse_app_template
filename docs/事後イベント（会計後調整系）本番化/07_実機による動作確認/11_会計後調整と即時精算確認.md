## 1. 対応範囲

- Step03 `adjustments管理`
- Step04 `cashActions管理` の immediate 経路

## 2. このファイルの役割

このファイルでは、**会計後の金額変更と、その場で完了する返金 / 徴収**を確認する。

ただし重要な注意点として、現在のコードベースには 2 系統の会計後調整導線が存在する。

1. 新実装の current-scope 本線
   - `terminalHome` の `会計後操作`
   - `createPostSettlementAdjustment`
   - `adjustments`
   - immediate `cashActions`
2. 旧来の互換導線
   - `updateAccounting`
   - `/events`
   - `postEvents`

`terminalHome` から入れる [会計後操作画面](/Users/yahatayuusei/Documents/GitHub/amuse_app_template/lib/Accounting/postSettlementOperationsPage.dart) が、新 callable を使う current-scope 本線である。

現在の `会計後操作` 詳細ページは、次の構成で確認する。

- 減額:
  - 既存明細を複数行追加できる
  - 既存明細一覧は baseline ではなく current state を反映している
  - `すべての明細を対象にする` で current state の全明細を並べられる
  - 数量入力の右側に上限件数 / 枚数が見える
- 増額:
  - 既存明細ではなく `item / tournament / sideGameChip` から追加内容を組み立てる
  - item はカテゴリ切替で一覧を変える
  - tournament は当日分を表示し、entry / reentry / addon ごとに追加できる
- 手入力:
  - 増額 / 減額とも `追加料金` として扱う
  - 入力項目は金額とメモだけ

一方、[会計後調整画面](/Users/yahatayuusei/Documents/GitHub/amuse_app_template/lib/Accounting/postAccountingAdjustmentsPage.dart) は、現時点では **互換導線 (`updateAccounting`)** を使っている。

そのため、このファイルでは確認を 2 層に分ける。

- A. 画面から見た旧導線の現状確認
- B. `会計後操作` 画面からの current-scope 本線確認

**Step03 / Step04 の完了確認として本当に必要なのは B** である。

- bill は「要返金」候補になる
- 操作ページ上では、target 明細・数量・自動計算金額が 1 画面で確認できる
- 既存明細一覧は baseline 固定ではなく current state と一致する

### シナリオ G: 冪等再送（idempotent replay）

#### どこから入るか
- `terminalHome` → `会計後操作 冪等再送確認`

#### 補足
- 通常の adjustment 成功経路は `会計後操作` から確認する
- このシナリオだけは、一時確認ページで同じ `idempotencyKey` を明示して 2 回送る

#### 何をするか
1. 対象 bill の `billId` を入力する
2. `adjustmentType` を選ぶ
3. 金額と `idempotencyKey` を入力する
4. `同じ内容を2回送信する` を押す
5. 画面下の結果表示と、Firestore の doc 数 / `nextSequenceNo` を確認する

#### 期待される Firestore 状態
- adjustment doc が重複作成されない
- immediate cashAction 付きなら cashAction doc も重複しない
- `nextSequenceNo` が余分に進まない

#### 共有してほしいもの
- 実行に使った `billId`
- 画面下に表示される結果 summary 全文
- もし snackbar やエラーが出たら、その文言

#### このシナリオの完了判定
- 2 回目呼び出しで重複副作用が発生しない
