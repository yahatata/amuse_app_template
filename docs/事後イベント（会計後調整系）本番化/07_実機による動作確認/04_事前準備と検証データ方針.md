# 04_事前準備と検証データ方針

## 1. このファイルの役割

このファイルは、各実機確認ファイルに入る前に共通でそろえる前提条件と、検証データの作り方を整理する。

## 2. 共通前提

- Flutter app を起動できること
- Functions / Firestore の接続先を把握していること
- Firestore Console または Emulator UI を開けること
- 実行ログを確認できること
- billId / userId / cycleNo を追跡できること

## 3. 推奨環境

- 実機または Emulator 1 台
- Firestore Emulator UI
- Functions Emulator
- 必要に応じて callable を直接叩ける手段
  - Flutter UI
  - `functions:shell`
  - curl / script

## 3.1 Firestore index の事前確認

- `要対応の会計` 画面では `bills` の複合条件 query を使う
- 必要な composite index は deploy 済みだが、Firestore 側で build 反映に少し時間がかかることがある
- 実機確認前に、少なくとも次を確認する
  - 画面表示時に `The query requires an index` エラーが出ない
  - Firebase Console の Firestore Indexes 画面で、今回追加した `bills` index が build 中のまま長時間止まっていない

## 4. 検証データの方針

- 既存データを汚さないため、検証専用 user / bill を使う
- 1 シナリオごとに billId を分ける
- `reopen` や `analyticsMonthly` は前段シナリオの結果に依存するため、できるだけ連番で追う

## 5. 推奨する bill の使い分け

- `B-01`: 通常会計 / baseline 用
- `B-02`: decrease / refund 系用
- `B-03`: increase / collection 系用
- `B-04`: 要対応一覧 UI 用
- `B-05`: reopen / resettle 用
- `B-06`: analyticsMonthly 追跡用

## 6. 画面導線の大枠

- 通常会計: `terminalHome` → 通常の会計導線
- 会計後調整: `terminalHome` → `会計後調整`
- 要対応一覧: `terminalHome` → `要対応の会計`
- reopen: 現時点では UI または callable 直実行のどちらを使うか、対象ファイル内で明示する

## 7. 先に記録しておくと良いもの

- 実施環境
- 接続先プロジェクト / Emulator
- 実施端末
- 使用した billId 一覧
- スクリーンショット保存先
