# 01_実機確認の進め方

## 1. 基本方針

このフォルダでの実機確認は、以下の順で進める。

1. 事前準備を確認する
2. 対象ファイルのシナリオを上から順に実施する
3. 各シナリオごとに
   - どこから入るか
   - 何を操作するか
   - Firestore のどこを見るか
   - アプリ上で何が表示されるべきか
   - 何ができていれば OK か
   を確認する
4. 結果をその場で記録する
5. 全ファイル完了後に結果集約を更新する

## 2. 参照の優先順位

1. このファイル
2. 各 10 番台ファイル
3. `05_changeSpecと実装/*/08_実機確認手順.md`
4. `04_仕様書/*.md`
5. 実コード

## 3. 実施時のルール

- 実機確認は、**画面・DB・ログの 3 点をセットで見る**
- 画面が正しくても、Firestore 状態がずれていれば NG とする
- Firestore が正しくても、ユーザーが操作できない導線なら NG とする
- 1 シナリオごとに `OK / NG / 保留` を残す
- `保留` の場合は、再現条件と詰まった地点を必ず書く

## 4. 記録の仕方

各シナリオで最低限次を残す。

- 実施日
- 実施者
- 対象環境
  - 実機 / Emulator
  - app build 種別
  - Functions / Firestore の接続先
- 結果
  - OK / NG / 保留
- 補足
  - 期待との差分
  - スクリーンショットの保存場所
  - Firestore doc id

## 5. Emulator を使う場合のルール

- Firestore / Functions Emulator を利用する場合は、対象 billId や cycleNo を必ず記録する
- テストデータの作成に ad-hoc callable / shell / Firestore Console を使った場合も手順へ残す
- Emulator の状態が怪しい場合は、確認を進める前に再起動する

## 6. 期待結果の読み方

各シナリオでは、期待結果を次の 3 層で書く。

- UI 期待値
- Firestore 期待値
- 完了判定

この 3 つが全部そろって初めて「そのシナリオは通過」とする。
