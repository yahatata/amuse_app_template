## 5. この UI の操作方針

- 一覧は営業日ごとに表示する
- 一覧 card から 1 件の伝票操作ページへ遷移する
- 一覧では、純粋な `会計済み` と、返金 / 追加徴収を完了した `会計済み` を見分けられるように、履歴ラベルを追加する
- 一覧 card では初回会計額を基準表示し、返金済み / 追加徴収済みがある伝票ではその金額も併記する
- 4パターンの調整はダイアログではなく専用ページで入力する
- 減額は複数明細を 1 回でまとめて扱えるようにする
- 減額の既存明細一覧は baseline 固定ではなく、baseline に current cycle の `adjustments` を反映した current state から作る
- `すべての明細を対象にする` で current state の既存明細を一括表示できるようにする
- 明細ごとの数量は手入力ではなく選択式にし、減額の `すべての明細を対象にする` では元伝票の個数を自動選択して全額減額しやすくする
- sideGameChip の減額数量はチップ枚数ではなく「購入回数」として扱い、1 回の購入明細を丸ごと対象にする
- 減額対象の既存明細は同じ行を重複選択できないようにする
- 増額は既存明細を前提にせず、`item / tournament / sideGameChip` から追加内容を組み立てる
- 増額で追加済みの明細は、その後の既存明細一覧にも current state として反映する
- tournament の `entry / reentry / addon` 既存回数も baseline ではなく current state の回数として表示する
- 増額の明細追加 / 削除では snack bar を出し、何を追加・削除したかその場で分かるようにする
- snack bar は最新の操作を優先して表示し、古い表示が残っていても次の追加・削除結果がすぐ見えるようにする
- 例外用の手入力は、増額・減額ともに `追加料金` として扱う
- 確認前提の操作なので、対象・件数・金額・精算方法・メモを 1 画面で見渡せるようにする
- 実行前に確認用の文章を表示し、主語・述語・目的語が読めるようにする

## 6. 旧導線との関係

- 旧 `会計後調整（旧テスト）` は残している
- 旧導線は `updateAccounting` / `postEvent*` 系の互換確認用である
- 新実装の current-scope 本線確認は、今後 `会計後操作` を優先して使う
