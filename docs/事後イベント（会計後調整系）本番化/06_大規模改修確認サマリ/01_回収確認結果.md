## 4. 注意事項

### 4.1 実機確認は「手順あり、結果記録なし」

Step03〜07 の `08_実機確認手順.md` は整備されているが、

- 実施日

が `TODO` のまま残っているものがある。

つまり、**実機確認の準備はできているが、実施済みとまでは言えない**。

### 4.2 セキュリティルール / index の確認状況

追加確認の結果、今回の current-scope では次の整理になった。

- `firestore.rules`
  - 新 UI / 新 subcollection read path は、既存の開発用 read 許可で到達可能
  - 本番向け read 制限の再設計は別フェーズ
- `firestore.indexes.json`
  - `要対応の会計` 画面で使う `bills` 複合条件 query 用 composite index を追加
  - `firestore:indexes,firestore:rules` を deploy 済み

補足:

- deploy 時に「プロジェクト側にだけ存在する index が 6 本ある」と出たが、`--force` は使わず温存した
- これは既存経路を壊さないための安全側の扱いである

### 4.3 ローカル作業ツリーの整理は未完了

`git status` 上では、今回の改修に関係する新規・更新ファイルが多数残っている。

この状態は「回収できていない」のではなく、**まだ add / commit されていない**状態である。

そのため、保存漏れ防止の観点では、次にやるべきことは以下である。

1. 生成物を除外する
2. 改修差分を review する
3. 適切な粒度で add / commit する
