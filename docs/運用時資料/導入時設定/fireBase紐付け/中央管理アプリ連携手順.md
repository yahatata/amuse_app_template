# 中央管理アプリ連携手順

## 1. この資料の目的

新しい店舗アプリ / Firebase Project ID を導入したあと、
中央管理アプリ `amuse-admin` でもその店舗を監視・設定参照できる状態まで持っていくための手順をまとめる。

この資料で扱うのは、**店舗側の Functions デプロイ後に追加で必要になった中央連携作業**である。

---

## 2. 先に結論

新規店舗導入時に、中央管理アプリ連携で最低限必要な作業は次の 4 つ。

1. 中央 Firestore の `stores/{storeId}` に店舗を登録する
2. 中央同期用 runtime SA に、店舗 Firebase Project 側 `roles/datastore.viewer` を付与する
3. 中央管理アプリ `設定 > 店舗 Config 同期` で 6 config を同期する
4. 中央管理アプリの `Scheduler 監視` / `Task 監視` / `エラー一覧` で初回確認する

これをやらないと、店舗側の定期実行やエラーが動いていても、中央管理アプリで正しく見えない。

---

## 3. どこで何を何のためにするか

| 手順 | どこで作業するか | 何をするか | 何のためか |
|------|------------------|------------|------------|
| 1 | 中央管理アプリ `設定 > 店舗一覧` | `storeId` / `projectId` / `displayName` で店舗を登録し、有効化する | HOME・監視画面で対象店舗を表示するため |
| 2 | GCP IAM（店舗 Firebase Project 側） | 中央同期用 runtime SA に `roles/datastore.viewer` を付与する | 中央が店舗 `storeMeta/*` を読めるようにするため |
| 3 | 中央管理アプリ `設定 > 店舗 Config 同期` | 6 config を中央 `stores/{storeId}/config/*` へ同期する | Scheduler 監視の区分 C 判定・設定参照 UI の基盤にするため |
| 4 | 中央管理アプリ `店舗詳細` | `エラー一覧` / `Scheduler 監視` / `Task 監視` を確認する | 初回導入後に監視が成立していることを確認するため |

---

## 4. 前提情報

### 4.1 中央管理アプリ側

- Firebase Project ID: `amuse-central-monitoring`
- URL: `https://amuse-central-monitoring.web.app`

### 4.2 中央同期で保存されるデータ

同期対象は次の 6 つ。

- `storeMeta/schedulerConfig`
- `storeMeta/config`
- `storeMeta/payrollConfig`
- `storeMeta/reportingGroupConfig`
- `storeMeta/taxReportingBehavior`
- `storeMeta/requiredStaffByTimeSlot`

保存先:

```text
amuse-central-monitoring
  stores/{storeId}/config/{configKey}
```

---

## 5. 詳細手順

### 5.1 中央 Firestore に店舗を登録する

中央管理アプリの `設定 > 店舗一覧` で登録する。

最低限必要な値:

| 項目 | 値 |
|------|----|
| `storeId` | 店舗識別子。通常は Firebase Project ID と同じでよい |
| `projectId` | 店舗側 Firebase Project ID |
| `displayName` | 中央管理アプリ上の表示名 |
| `enabled` | `true` |

補足:

- `projectId` が空でも中央側は `storeId` へフォールバックするが、**明示的に一致させる** 方が安全
- `enabled=false` のままだと HOME や監視一覧で対象外になる

### 5.2 中央同期用 runtime SA を確認する

現行実装では、中央管理アプリの Config 同期は
Cloud Function `syncStoreConfigFromAdmin` が行う。

現在の runtime SA は次で確認できる。

```bash
gcloud functions describe syncStoreConfigFromAdmin \
  --gen2 \
  --region=asia-northeast1 \
  --project=amuse-central-monitoring \
  --format='value(serviceConfig.serviceAccountEmail)'
```

2026-06-09 時点の実体例:

```text
82891751769-compute@developer.gserviceaccount.com
```

### 5.3 店舗 Firebase Project 側で IAM を付与する

上で確認した runtime SA に対して、**店舗側** Firebase Project で次を付与する。

```bash
gcloud projects add-iam-policy-binding <STORE_PROJECT_ID> \
  --member="serviceAccount:<AMUSE_ADMIN_RUNTIME_SA>" \
  --role="roles/datastore.viewer"
```

目的:

- 中央管理アプリが店舗 `storeMeta/*` を cross-project read できるようにするため

### 5.4 中央管理アプリで 6 config を同期する

1. `設定 > 店舗 Config 同期` を開く
2. 対象店舗を選択する
3. `6 config を同期` を押す
4. `同期完了: <projectId> (...)` が出ることを確認する

成功したら、中央 Firestore に次が保存される。

```text
stores/{storeId}/config/schedulerConfig
stores/{storeId}/config/storeConfig
stores/{storeId}/config/payrollConfig
stores/{storeId}/config/reportingGroupConfig
stores/{storeId}/config/taxReportingBehavior
stores/{storeId}/config/requiredStaffByTimeSlot
```

### 5.5 初回確認を行う

中央管理アプリで最低限次を確認する。

| 画面 | 確認内容 |
|------|----------|
| `設定 > 店舗 Config 同期` | 6 config が読めているか |
| `店舗詳細 > Scheduler 監視` | dispatch サマリ、新規 / 重複 skip / その他 skip / エラー が見えるか |
| `店舗詳細 > Task 監視 > 定期実行系` | 定期実行 queue の履歴が見えるか |
| `店舗詳細 > エラー一覧` | 初期時点で想定外の error が溜まっていないか |

---

## 6. 導入後に設定変更したとき

店舗側 `storeMeta/*` を変えたあと、**中央管理アプリの見え方も設定依存** な場合は再同期する。

特に再同期を推奨する変更:

- `storeMeta/schedulerConfig`
- `storeMeta/config`
- `storeMeta/payrollConfig`
- `storeMeta/requiredStaffByTimeSlot`

最重要:

- `schedulerConfig` を変えたのに同期しないと、中央 `Scheduler 監視` の区分 C や queue 説明が古いままになる

---

## 7. 代表的な失敗と見方

| 事象 | 原因の本命 | 対応 |
|------|------------|------|
| `店舗 Config 同期` が permission error | 店舗側 IAM 未付与 | `roles/datastore.viewer` を runtime SA に付与 |
| 中央 HOME に店舗が出ない | `stores/{storeId}` 未登録、または `enabled=false` | 中央 `設定 > 店舗一覧` を確認 |
| `Scheduler 監視` に Config 未同期バナーが出る | `schedulerConfig` 未同期 | `設定 > 店舗 Config 同期` を再実行 |
| `Task 監視` に何も出ない | まだ自然実行データが無い、または店舗側ログ投入に問題 | 店舗側 Cloud Logging と中央 `taskLogs` を確認 |
