# storeMeta と中央管理アプリ連携

## 1. 目的

店舗側 Firestore `storeMeta/*` のうち、中央管理アプリ `amuse-admin` が監視や設定参照に使うものを整理する。

この資料は次のときに使う。

- 新規店舗を中央管理アプリへ連携するとき
- `storeMeta/*` の設定を変更したあと、中央側でも再同期が必要か判断するとき
- `Scheduler 監視` の見え方と店舗設定の関係を確認したいとき

---

## 2. 中央へ同期される設定

| configKey | 店舗側正本 | 主な用途 |
|-----------|------------|----------|
| `schedulerConfig` | `storeMeta/schedulerConfig` | Scheduler 監視の区分 C、queue 説明、設定参照 |
| `storeConfig` | `storeMeta/config` | 設定参照、運用確認時の比較 |
| `payrollConfig` | `storeMeta/payrollConfig` | 給与系 queue / 通知の設定参照 |
| `reportingGroupConfig` | `storeMeta/reportingGroupConfig` | 設定参照 |
| `taxReportingBehavior` | `storeMeta/taxReportingBehavior` | 設定参照 |
| `requiredStaffByTimeSlot` | `storeMeta/requiredStaffByTimeSlot` | 設定参照 |

中央保存先:

```text
stores/{storeId}/config/{configKey}
```

---

## 3. 特に重要な設定

### 3.1 `schedulerConfig`

最も重要。

中央 `Scheduler 監視` では、同期済み `schedulerConfig` を使って

- `planningHorizonDays`
- job の enabled / disabled
- `scheduleKind`
- `runAtJst`

を解釈し、区分 C を出す。

したがって、店舗側で `schedulerConfig` を変えたあと中央同期しないと、中央画面の読み方が古くなる。

### 3.2 `requiredStaffByTimeSlot`

現在は主に設定参照用途だが、中央運用で

- 店舗設定と実挙動の照合
- シフト関連の運用確認

をするときの比較材料になる。

---

## 4. いつ再同期するべきか

次のいずれかに当てはまれば、中央管理アプリ `設定 > 店舗 Config 同期` を再実行する。

| 条件 | 再同期の必要性 |
|------|----------------|
| 新規店舗を中央管理アプリへ追加した | 必須 |
| `schedulerConfig` を変更した | 必須 |
| `storeConfig` / `payrollConfig` を変更した | 強く推奨 |
| 中央画面で Config 未同期バナーが出た | 必須 |
| 中央設定参照 UI の値が古い | 必須 |

---

## 5. 同期しないと何が起きるか

| 設定 | 起きうること |
|------|--------------|
| `schedulerConfig` | `Scheduler 監視` の区分 C と job 説明が古い |
| `storeConfig` | 設定参照 UI が古い |
| `payrollConfig` | 給与系 queue の説明と実際の設定がずれる |
| その他 3 設定 | 設定参照 UI の比較材料が古い |

補足:

- 店舗アプリ本体は店舗側 `storeMeta/*` を正本として動く
- 中央側が古くなるのは、主に**監視画面の解釈と設定参照**である

---

## 6. 同期手順

1. 中央管理アプリ `設定 > 店舗 Config 同期` を開く
2. 対象店舗を選ぶ
3. `6 config を同期` を押す
4. 同期完了メッセージを確認する

失敗時の本命:

- 中央同期用 runtime SA に、店舗側 Firebase Project で `roles/datastore.viewer` が付いていない
