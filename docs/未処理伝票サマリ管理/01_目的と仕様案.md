# 未処理伝票サマリ管理

## 目的

会計後に「返金待ち」「追加徴収待ち」「未会計繰越（carryover）」の状態になっている伝票を、
画面を開かなくても素早く確認できるようにする。

現状は `bills` を都度クエリして件数や金額を把握する必要があり、ダッシュボードへの表示や
運用上の確認コストが高い。これを解消するために、`storeMeta` 内に集計サマリを持ち、
詳細は専用サブコレクションで管理する。

---

## 対象とする状態

| 状態キー | 意味 | 発生タイミング | 解消タイミング |
|---|---|---|---|
| `refund_pending` | 返金調整が作成されたが cashAction がまだ実行されていない | `createPostSettlementAdjustment`（返金）実行時 | cashAction（返金）実行時 |
| `collection_pending` | 追加徴収調整が作成されたが cashAction がまだ実行されていない | `createPostSettlementAdjustment`（追加徴収）実行時 | cashAction（徴収）実行時 |
| `carryover_unsettled` | 閉店時に会計未完了の伝票が残っている | 閉店処理（store close callable）実行時 | 翌日以降の会計完了時 |

---

## 仕様案

### `storeMeta/pendingActionsSummary`（集計サマリドキュメント）

全体の件数・金額を保持する。UI のダッシュボードや通知バッジ表示に使う。

```
refundPending: {
  count:       N      // 返金待ち件数
  totalAmount: N      // 返金待ち金額合計（円）
}
collectionPending: {
  count:       N      // 追加徴収待ち件数
  totalAmount: N      // 追加徴収待ち金額合計（円）
}
carryoverUnsettled: {
  count:       N      // 未会計繰越件数
}
lastUpdatedAt: Timestamp
```

### `pendingItems/{billId}` サブコレクション

各 bill の詳細を保持する。一覧表示や個別確認に使う。

```
billId:          string
pendingType:     "refund_pending" | "collection_pending" | "carryover_unsettled"
businessDate:    string   // YYYY-MM-DD
amount:          N        // 対象金額（円）。carryover は 0
linkedAdjustmentId: string | null
createdAt:       Timestamp
note:            string | null   // 補足（carryover 理由など）
```

---

## 書き込み・解消のタイミング

| イベント | 操作 |
|---|---|
| 返金 adjustment 作成 | `pendingActionsSummary` の `refundPending` をインクリメント、`pendingItems` に追加 |
| 追加徴収 adjustment 作成 | `pendingActionsSummary` の `collectionPending` をインクリメント、`pendingItems` に追加 |
| 返金 cashAction 実行 | `refundPending` をデクリメント、`pendingItems/{billId}` を削除 |
| 追加徴収 cashAction 実行 | `collectionPending` をデクリメント、`pendingItems/{billId}` を削除 |
| 閉店処理 | 未会計の bills を走査して `carryoverUnsettled` に追加 |
| 翌日以降の会計完了 | `carryoverUnsettled` をデクリメント、対応する `pendingItems` を削除 |

---

## callable への影響範囲

以下の callable にサマリ書き込み・解消処理を追加します。

| callable | 対応 |
|---|---|
| `createPostSettlementAdjustment.ts` | adjustment 種別に応じて `refund_pending` or `collection_pending` を追加 |
| 後続 cashAction callable | 対応する pending エントリを解消 |
| 閉店処理 callable | 未会計伝票を `carryover_unsettled` として書き込む |
| 通常会計 callable（carryover 伝票が対象のとき） | `carryover_unsettled` を解消する |

---

## 実装上の考慮点

- `pendingActionsSummary` のカウンター更新は callable の Transaction 内で行い、整合性を保つ
- callable が途中で失敗した場合に備え、`pendingItems` の存在有無を SoT として `pendingActionsSummary` の数値を定期的に再集計する補正バッチ（or admin callable）を用意することが望ましい
- `pendingItems` は bill 単位なので 1 つの bill に複数の pending 状態は通常発生しないが、異常系として考慮しておく

---

## 完了の定義

- `storeMeta/pendingActionsSummary` と `pendingItems` サブコレクションが実装されている
- 上表の全タイミングで書き込み・解消が動作している
- UI のダッシュボードが `pendingActionsSummary` を読んで件数・金額を表示できている
- admin callable（または補正バッチ）による整合性修復が動作している
