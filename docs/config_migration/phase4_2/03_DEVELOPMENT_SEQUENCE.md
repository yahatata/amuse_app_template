# Phase4.2: 開発順序概要（安全性・効率重視）

最終更新: 2026-03-04

---

## 方針

- 各ステップは必ず **仕様確定 -> changeSpec 作成 -> 実装 -> 確認/テスト** の順で進める。
- Firestore への書き込みはすべて Functions 経由で行う。
- 既存 `all_staff_attendance_page` は併用し、既存仕様を維持する。
- スケジューラーは通知・確認のみ（計算実行は行わない）。

---

## 実施順序（推奨）

1. **Step01 基盤・設定**  
   期間計算共通化、payrollConfig ローダー、初期化、型定義を整備。

2. **Step02 対象データ抽出（Callable）**  
   属性1/2/3の判定を Functions 側で確立し、UIが安全に使えるデータを返却。

3. **Step03 計算実行・確定（Callable）**  
   計算実行、確定、`payrollReflectedAt`、`attendanceLogs` の中核を実装。

4. **Step04 計算用タブ UI**  
   adminHome から遷移、計算可能期間判定、抽出ボタン、属性表示、選択UIを実装。

5. **Step05 計算結果タブ UI**  
   サマリ、staffカード、詳細、確定、過去参照、CSV出力を実装。

6. **Step06 支払い管理**  
   staff単位/一括の支払い済み登録、保留、期限後警告連携を実装。

7. **Step07 通知基盤**  
   通知コレクション、既読/未読、種別、フラグ、adminHome表示を実装。

8. **Step08 スケジューラー補助化**  
   通知・確認専用に変更し、計算実行処理を除外。

9. **Step09 最終統合・検証**  
   横断テスト、運用確認、未決事項の最終確定、リリース判断。

---

- 各ステップで「概要」「判断が必要な項目」「詳細」を明記済み。
