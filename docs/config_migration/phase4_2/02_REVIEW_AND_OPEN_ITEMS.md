## 1. レビュー結果サマリ

| ドキュメント | 評価 |
|--------------|------|
| **00_OVERVIEW** | 目的・スコープ・依存関係が明確。決まっていないことを列挙済み |
| **01_TOBE_DETAILED_SPEC** | 【確定】/【要詰め】の区別が明確。属性定義・データモデル・支払い管理・通知を網羅 |

**対応済みの確認事項**: 属性3の定義、payrollConfig と payroll の関係、計算可能期間の挙動、Callable の引数、スケジューラーの役割、期間計算ルール（endDay≠0）、属性の折りたたみ、payrollReflectedAt、attendanceLogs の識別、既存機能との関係（all_staff_attendance_page 併用、monthlyPayroll 新規のみ）、論理削除の表示位置（属性3）など。

## 2. 未決事項（実装時に詰める）

### 2.1 01_TOBE に記載の要詰め項目

| # | 項目 | 内容 |
|---|------|------|
| 1 | 計算結果チェックの具体的な内容 | 実装時にユーザーと詰める |
| 2 | payrollConfig の expectedRange の詳細 | 閾値・判定ロジック |
| 3 | 通知のアーカイブ仕様 | 2ヶ月でアーカイブするか、取得しないか |
| 4 | 古い payrollRun の削除タイミング | バッファの具体的な期間 |
| 5 | 通知コレクションの名前 | 実装時に決定 |

### 2.2 その他の確認推奨項目

| # | 項目 | 内容 |
|---|------|------|
| 6 | **store スコープ** | マルチテナントの場合、通知・payrollConfig が store ごとであることを明記 |
| 7 | **paymentPeriodKey の一意性** | 1 store に複数支払日がある場合（異なる給与体系）の扱い。通常は 1 store = 1 給与体系想定 |
| 8 | **確定前の run の扱い** | 最新 run が「正式」だが確定前。確定時に latestConfirmedRunId を設定する流れを明記 |
| 9 | **CSV エクスポートの対象** | 表示中の計算結果か、選択した支払日キーか |
