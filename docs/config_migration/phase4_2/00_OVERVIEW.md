# Phase4.2: 給与計算システム改修 — 概要

最終更新: 2026-03-04

---

## 1. 改修の目的

給与計算を**手動主導**とし、スケジューラーは**補助**とする。管理者が勤怠を確認した上で計算対象を選択し、計算・確定・支払い管理まで一貫して行えるシステムに改修する。

---

## 2. 改修のスコープ

| 領域 | 内容 |
|------|------|
| **UI** | adminHome から遷移。給与計算専用メニューを追加。計算用タブ・計算結果タブの2タブ構成 |
| **計算フロー** | 計算対象 attendances を属性別に表示し、チェックで選択して計算実行。確定ボタンで再計算不可に |
| **データモデル** | monthlyPayroll スキーマの見直し。支払日キー・計算履歴・確定状態・支払い済み管理 |
| **設定** | 計算対象期間は storeMeta/config の payroll.startDay/endDay を参照（SSOT）。payrollConfig に支払日・想定範囲（異常値チェック用）を追加 |
| **通知** | 通知機能の新規実装。計算期間入り・リマインド・支払い済み未登録の警告等 |
| **スケジューラー** | 通知・確認のみ。計算実行は行わない |

---

## 3. 主要な機能一覧

### 3.1 計算用タブ

- 計算対象 attendances を属性別に表示（3, 2, 1 の順）
- 属性1: 期間内の attendance
- 属性2: 期間外だが前回以前の給与計算に反映されなかった attendance（要確認・上に表示）
- 属性3: 期間内だが未退勤として登録されている attendance（表示は行うが計算対象とはしない。原則チェック不可）。論理削除された attendance（期間内）も属性3に含める
- 各属性セクションは折りたたみ可能。**折り畳まれた状態がデフォルト**
- デフォルトで属性1・2はチェック済み。一括選択・一括解除
- 集計プレビュー（attendance 件数・概算金額・合計時間）と想定範囲からの異常値警告
- 未選択理由の表示（期間外・前回未反映・その他）
- 計算対象期間は payroll.startDay/endDay で算出。給与期間終了後であれば何回でも計算可能（確定前）。計算のたびに新規ドキュメント作成
- **計算可能期間**（storeMeta/payrollConfig）による挙動: 当日（JST）が計算可能期間に含まれる場合は「対象データの抽出を開始する」ボタンを表示。含まれない場合は「現在、給与計算可能期間ではないため、対象の抽出が行えません」と表示する。ボタン押下で Functions を起動しデータを取得・表示し、操作を行えるようにする

### 3.2 計算結果タブ

- サマリを画面上部に表示
- staff ごとの給与・勤怠サマリをカード表示。カード押下で詳細確認
- 確定ボタン（確定後は再計算不可）
- 確定時の警告（再計算不可、未退勤等で含めていない attendance の一覧）
- 計算結果チェック機能（内容は実装時に詰める）
- CSV エクスポート（確定前・確定後の区別を出力に含める）
- 過去の計算結果参照（計算実行日が当月の結果をデフォルト表示。実装時にコメントで修正箇所を明確化）
- 0円の staff は表示除外（attendance 起点で作成するためそもそも表示されない）

### 3.3 支払い管理

- 支払い済み登録: **staff ごと**および**一括**の両方が可能。一括は設定（payrollConfig）でボタン表示・処理可否を制御
- 支払い済み登録時、どの admin デバイスが登録したかを記録（deviceId のみ。user は判別不可）
- 支払日翌日以降: 未登録なら警告表示・通知
- 保留ステータス: 保留にすれば警告は出さず、通知のみ（低頻度）
- 支払い済み登録が行われなかった場合の通知リマインド

### 3.4 通知

- 通知先: 管理者デバイスのみ（adminHome）
- adminHome で半永続的に確認（2ヶ月想定でアーカイブ or 取得しない）
- 未読・既読、通知種別（警告・報告・強警告・エラー通知等）
- フィルター・タブによる表示分け
- フラグ付（後で見返すものを識別）
- 拡張性: 将来的に LINE・メール送信を想定

## 4. データモデル概要

### 4.1 計算対象期間と storeMeta/payrollConfig

- **計算対象期間（給与期間）**: storeMeta/config の **payroll.startDay / payroll.endDay** を参照（SSOT）
- **storeMeta/payrollConfig**（新規 or 拡張）: 支払日（日付キー・計算可能期間の導出に使用）、想定範囲（異常値チェック用）、一括支払い済み登録の可否。計算可能期間は payroll（給与期間）と paymentDate から導出する

### 4.2 monthlyPayroll コレクション（見直し）

- ドキュメント ID: 支払日を参照した日付キー（例: `2025-03-25`）
- 親 doc: status（計算中・確定済み等）、計算実行時間、再計算履歴
- サブコレ `payrollRuns/{runId}`: 計算回数分。staff ごとの給与・勤怠・対象 attendanceIds
- 正式な給与データ: 最新かつ確認済みの run を親 doc から参照
- 古い run は一定タイミングで削除可能（バッファ）

### 4.3 通知コレクション（新規）

- 未読・既読、通知種別、フラグ、拡張性（LINE・メール送信）

## 5. 共通原則 【確定】

- **Firestore への書き込みは Functions を経由して行う**。Flutter からの直接書き込みは行わない。

## 6. 依存関係

- **Phase4.1 完了**: attendances の actualWorkMinutes / nightWorkMinutes、payrollReflectedAt 等が前提
- **既存**: storeMeta/config の payroll.startDay / payroll.endDay は継続利用（期間計算に使用）

## 7. 決まっていないこと（実装時に詰める）

| 項目 | 内容 |
|------|------|
| 計算結果チェックの具体的な内容 | 実装時にユーザーと詰める。Cursor が勝手に決めない |
| 異常値チェックの閾値・判定ロジック | payrollConfig の想定範囲の詳細 |
| 通知のアーカイブ・取得しない仕様の詳細 | 2ヶ月でアーカイブするか、取得しないか |
| 古い payrollRun の削除タイミング | バッファの具体的な期間 |

---

## 8. 既存機能との関係

- **all_staff_attendance_page**: 給与計算専用画面と**併用**。既存の all_staff_attendance_page の仕様は変わらない（フィールド名・ファイル名等の変更は行わない）
- **既存 monthlyPayroll データ**: 移行は行わない。**新規のみ**対応
