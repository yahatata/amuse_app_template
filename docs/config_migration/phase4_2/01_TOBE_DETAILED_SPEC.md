## 2. 計算対象 attendances の属性と表示

### 2.1 属性の定義 【確定】

| 属性 | 説明 | チェック | 表示順 |
|------|------|---------|--------|
| **属性1** | 期間内の attendance（計算期間に含まれる日付の attendance） | デフォルト ON、一括選択可 | 3番目（下） |
| **属性2** | 期間外だが、前回以前の給与計算に反映されなかった attendance | デフォルト ON、一括選択可 | 2番目（中）・**要確認として上に表示** |
| **属性3** | 期間内だが未退勤として登録されている attendance | **表示は行うが計算対象とはしない**（原則チェック不可） | 1番目（上） |

**属性2の補足**  
前回の計算時に対象期間に含まれていたが、計算対象にできなかった attendance（特に未退勤のまま残されたもの）を翌月の支給対象として扱う場合がある。これらは計算対象期間より過去の attendance だが、**計算対象に含むべき**。計算期間より未来の attendance で未退勤のものは、このタイミングでの計算対象でもなく、表示も不要。

**属性3の補足**  
期間内だが未退勤の attendance は**表示は行うが計算対象とはしない**。原則チェック不可。今回の計算期間より未来の attendance（未退勤含む）は、計算対象でもなく**表示の必要もない**。属性3で表示する attendances は「今回の計算では対象とできないもの」として明示する。

### 2.2 論理削除された attendance 【確定】

- **期間外**で論理削除された attendance: **表示しない**。
- **期間内**で論理削除された attendance: 念のための確認用として、**属性3**に含めて表示する（表示は行うが計算対象とはしない）。

### 2.3 未退勤・閉店時フラグ 【確定】

- 閉店時には未退勤をフラグ付するに過ぎず、退勤処理は**必ず実行する**という運用でカバーする。
- 属性3の「原則チェック不可」は、未退勤のまま残っている attendance を計算に含めないための仕様。

### 2.4 表示順序 【確定】

- **属性3 → 属性2 → 属性1** の順で表示する。
- 属性2は「要確認」として上に表示する。

### 2.5 属性ごとの折りたたみ 【確定】

- 各属性セクション（属性1・属性2・属性3）は**折りたたみ可能**とする。
- **折り畳まれた状態がデフォルト**とする。
- ユーザーが属性ごとに表示を開閉できるようにする。

### 2.6 属性とデータの紐付け 【確定】

- 未選択理由の表示を行う。
- 理由の種別: **期間外**、**前回未反映**、**その他**（判別不可は「その他」）。
- 実装時に、データの内容と理由の紐付けをユーザーと確実に行う。

## 3. 計算用タブの詳細

### 3.1 一括選択 【確定】

- 一括選択・一括解除のボタンを用意する。
- **属性1・2はデフォルトでチェック済み**とする。

### 3.2 集計プレビュー 【確定】

- 計算実行前に、選択中の attendances から以下を表示する:
  - attendance 件数
  - 概算金額
  - 合計時間
- storeMeta/payrollConfig に設定した**想定範囲**から外れている場合は**警告**を出す（あくまで警告。実行は可能）。

### 3.3 計算対象期間・計算可能期間 【確定】

- **計算対象期間**（どの期間の勤怠を計算するか）は、**storeMeta/config の payroll.startDay / payroll.endDay** を参照して算出する。SSOT のため、計算対象期間の設定は既存の payroll のみを使用する。
- **計算可能期間**（storeMeta/payrollConfig）による挙動:
  - **当日（JST）が計算可能期間に含まれる場合**: 「対象データの抽出を開始する」ボタンを表示する。ボタン押下で Functions を起動し、データを取得・表示し、操作を行えるようにする。
  - **当日が計算可能期間に含まれない場合**: 「現在、給与計算可能期間ではないため、対象の抽出が行えません」と表示する。
- 給与期間が終了した後（periodEnd が今日以前）であれば、**何回でも**計算実行が可能（確定前まで）。
- 計算のたびに**新規ドキュメント**（payrollRun）を作成する。
- 古い計算結果は他で参照しない（最新の run が正式データとなる。確定後はその run が確定データ）。

### 3.4 確定後の再計算 【確定】

- 確定ボタン押下で、その計算結果で確定する。
- 確定後は**当該期間の再計算を行えない**。

### 3.5 対象データの抽出 【確定】

- 「対象データの抽出を開始する」ボタン押下で、**Functions（Callable）を起動**する。
- Callable は payroll.startDay/endDay から計算対象期間を算出し、該当する attendances を属性別に取得して返す。
- 返却されたデータを Flutter で表示し、ユーザーがチェック・計算実行等の操作を行えるようにする。
- Firestore への書き込みは Functions 経由とする（読み取りも Callable 経由で行うか、必要に応じて設計）。

### 3.6 給与計算実行 Callable 【確定】

- 給与計算実行用の Callable（例: `executeMonthlyPayroll`）を用意する。
- **引数**: 選択した `attendanceIds`（配列）を受け取る。計算対象期間（periodStart, periodEnd）は payroll から算出するか、引数で受け取る。
- **権限**: 呼び出し元デバイスの `role` が **admin のみ**。認証済みであること。
- **処理**: 選択された attendance のみを対象に給与計算を実行し、payrollRun を作成する。
- **payrollReflectedAt**: 計算実行時に対象とした attendance に付与する。再計算時は新しい run の対象 attendance に再付与し、前回の run にのみ含まれていた attendance は payrollReflectedAt をクリアする（または上書き）。確定時は確定 run の対象 attendance に付与。
- **attendanceLogs**: 計算実行時は `actionType: 'monthly_payroll_reflect'` で書き込む。計算結果の確定時は、確定操作を識別できる log（例: `actionType: 'payroll_confirmed'`）を書き込む。**計算実行と確定が log として識別できるようにする**。

## 5. 支払い管理

### 5.1 支払い済み登録 【確定】

- なんらかの操作で支払い済みを登録する仕様とする。
- **どの admin デバイスが登録したか**を残す。仕様上 user は判別できないため、**deviceId のみ**を記録する。

### 5.2 支払日翌日以降の警告・通知 【確定】

- 支払日翌日以降、支払い済み登録がされていない場合:
  - **警告表示**および**通知**を行う。

### 5.3 保留ステータス 【確定】

- 支払い済み登録とは別に、**保留**というステータスをつけることを可能にする。
- 保留にしていれば:
  - **警告は出さない**
  - **通知のみ**（保留のものも低頻度で出す）

### 5.4 支払い済み未登録時のリマインド 【確定】

- 支払い済み登録が行われなかった場合、通知でリマインドする。

### 5.5 staff ごと・一括の支払い管理 【確定】

- **staff ごと**および**一括**の両方で支払い済み登録が可能とする。
- **一括**は設定（payrollConfig）でボタン表示・処理可否を制御する。
- staff ごとに給与付与のフラグ付けを行い、誰に支払ったか・誰に支払っていないかをシステム上で管理できるようにする。

## 7. データモデル

### 7.1 storeMeta/config（payroll）と storeMeta/payrollConfig 【確定】

**計算対象期間（給与期間）の SSOT**: `storeMeta/config` の **payroll.startDay / payroll.endDay** を参照する。計算対象期間の設定は既存の payroll のみを使用する。

**配置**: `storeMeta/payrollConfig`（新規ドキュメント or config の拡張）

**計算可能期間の導出**: 計算対象期間（payroll.startDay/endDay から算出）と paymentDate から導出する。例: 給与期間 2/26〜3/25 の計算可能期間は 3/26 〜 4/24（支払日 4/25 の前日まで）。当日（JST）がこの範囲に含まれるかでボタン表示を判定する。

| フィールド | 型 | 説明 |
|------------|-----|------|
| paymentDate | string (YYYY-MM-DD) | 支払日（予定）。ドキュメント ID のキーとしても使用。計算可能期間の導出にも使用 |
| bulkPaymentRegistrationEnabled | boolean? | 一括支払い済み登録の可否。true でボタン表示・処理可能 |
| expectedRange | object | 想定範囲（異常値チェック用）【要詰め: 詳細】 |
| expectedRange.attendanceCountMin | number? | attendance 件数の下限 |
| expectedRange.attendanceCountMax | number? | attendance 件数の上限 |
| expectedRange.estimatedAmountMin | number? | 概算金額の下限 |
| expectedRange.estimatedAmountMax | number? | 概算金額の上限 |
| expectedRange.totalHoursMin | number? | 合計時間の下限 |
| expectedRange.totalHoursMax | number? | 合計時間の上限 |

※ expectedRange の詳細は実装時に詰める。

### 7.2 monthlyPayroll コレクション（見直し） 【確定】

**配置**: `monthlyPayroll/{paymentPeriodKey}`

- **paymentPeriodKey**: config の支払日を参照した日付キー。ドキュメント ID とする（例: `2025-03-25`）。

**親ドキュメントのフィールド**:

| フィールド | 型 | 説明 |
|------------|-----|------|
| paymentPeriodKey | string | 支払日キー（docId と同一） |
| status | string | 現在の状態。例: `draft`（計算中）, `confirmed`（確定済み）, `paid`（支払い済み）等 |
| calculatedAt | Timestamp | 計算実行日時（最新の run のもの） |
| confirmedAt | Timestamp? | 確定日時 |
| confirmedByDeviceId | string? | 確定した admin デバイス ID |
| runHistory | array? | 再計算の履歴（runId のリスト等） |
| latestConfirmedRunId | string? | 最新かつ確認済みの run の docId。正式な給与データとして扱う |
| ... | | その他、必要に応じて |

**サブコレクション**: `monthlyPayroll/{paymentPeriodKey}/payrollRuns/{runId}`

| フィールド | 型 | 説明 |
|------------|-----|------|
| runId | string | docId |
| calculatedAt | Timestamp | この run の計算実行日時 |
| calculatedByDeviceId | string? | 手動実行時のデバイス ID |
| triggerSource | string | `manual` \| `scheduler` |
| staffResults | array \| map | staff ごとの給与・勤怠サマリ。下記参照 |

**staffResults の構造** 【確定】

- staff ごとに 1 エントリ。
- 各エントリに含める: staffId, staffName, totalWorkHours, nightTimeHours, hourlyWage, nightHourlyWage（あれば）, basicPay, nightTimePay, totalPay
- **対象とした attendance の ID 一覧**を含める。計算結果から attendances を参照可能にし、給与支給後のフラグ付けを行えるようにする。
- ドキュメント肥大化の懸念: 1 staff あたり 10 attendance × 30 日で 300 を超えるフィールドになる可能性があるが、**階層を減らした方が良い**という判断。payrollRuns のドキュメントに staffId, staffName, 実務時間, 夜間実務時間, 時給, 総支給額に加え、**attendanceIds**（配列）を寄せる形とする。

**古い run の削除** 【要詰め】

- 正式なデータ以外は、必要に応じてバッファを持たせた一定のタイミングで削除可能とする。
- 具体的なタイミングは実装時に詰める。

### 7.3 通知コレクション 【確定】

**配置**: 新規コレクション（名前は実装時に決定。例: `notifications` 等）

| フィールド | 型 | 説明 |
|------------|-----|------|
| id | string | docId |
| type | string | 通知種別: `warning`, `report`, `strong_warning`, `error` 等 |
| title | string | タイトル |
| body | string? | 本文 |
| isRead | boolean | 未読・既読 |
| isFlagged | boolean | 後で見返すフラグ |
| createdAt | Timestamp | 作成日時 |
| targetDeviceIds | array? | 通知先デバイス（拡張用） |
| ... | | 拡張性を意識したフィールド |

## 8. スケジューラー・環境変数

### 8.1 スケジューラーの役割 【確定】

- スケジューラーは**通知・確認のみ**を行う。**計算実行は行わない**。
- 計算期間に入ったら通知、リマインド、計算がすでに行われた場合は計算結果の確認（attendance との付き合わせ）を行う。エラー時は修正ではなく通知。
- スケジューラーはあくまで**補助**を行う関数。手動実行用の計算ロジックと共通化する場合は、**範囲を気をつけて**共通化する（スケジューラーが呼ぶのは通知・確認のみ）。

### 8.2 期間計算の修正（endDay≠0 の場合） 【確定】

計算対象期間の算出時、**実行日が endDay より前**のときは「前々月 startDay 〜 前月 endDay」を対象にする。

| 条件 | 対象期間 |
|------|----------|
| 実行日 ≥ endDay | 前月 startDay 〜 今月 endDay |
| 実行日 < endDay | 前々月 startDay 〜 前月 endDay |

※ 給与期間終了日が今日以前であることが計算実行の前提。

## 11. 共通原則 【確定】

- **Firestore への書き込みは Functions を経由して行う**。Flutter からの直接書き込みは行わない。給与計算関連の全処理（計算実行、確定、支払い済み登録等）は Callable 経由とする。

## 12. 実装時の注意事項

1. **属性と理由の紐付け**: データの内容と「期間外」「前回未反映」「その他」の理由を、ユーザーと確実に紐付ける。
2. **計算結果チェック**: 内容をユーザーと詰める。Cursor が勝手に決めない。
3. **拡張性**: 通知は LINE・メール送信を将来的に想定し、スキーマ・処理を拡張しやすい形で設計する。
4. **計算対象期間の SSOT**: 計算対象期間（給与期間）は **storeMeta/config の payroll.startDay / payroll.endDay** を参照する。以下を網羅的に payroll 参照に統一する:
   - 計算用タブ: 属性1〜3の判定、期間表示
   - 集計プレビュー: 期間の算出
   - Callable（給与計算実行）: 期間の算出・バリデーション
   - monthlyPayrollTrigger: 期間の算出
   - 計算結果タブ: 期間表示・過去結果の期間判定
   - getPayrollData 等の既存 Callable: 既に payroll 参照の場合は維持
5. **attendanceLogs**: 計算実行（`monthly_payroll_reflect`）と計算結果の確定（`payroll_confirmed` 等）が log として識別できるようにする。
