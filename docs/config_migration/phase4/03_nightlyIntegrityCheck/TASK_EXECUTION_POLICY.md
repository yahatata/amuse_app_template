# Phase4 03: nightlyIntegrityCheck 改修 — タスク進め方方針

## 基本ルール

1. **各項目（1〜5）終了後に必ず以下を挟む**
   - **処理済み項目の確認**: 実施した内容のユーザー確認
   - **次のタスクに関する確認事項**: あれば提示してユーザー判断を求める
   - 確認事項がなければ「確認事項はありません。」と出力する

2. **項目 4（UI）について**
   - ユーザーと**必ず並走**する
   - 本改修以外の調整も含めて行う可能性あり

---

## タスク構成

| 項目 | 内容 |
|------|------|
| 1 | 既存 nightlyIntegrityCheck の廃止（unused 移管、index 削除） |
| 2 | 閉店処理用整合性チェックの実装（TS: Callable、未 close トーナメント・未退勤スタッフ検出） |
| 3 | 閉店処理フローへの組み込み（TS: closeStoreTerminal との連携） |
| 4 | 閉店処理 UI の改修（Dart: ユーザーと並走） |
| 5 | ドキュメント・テスト |

---

## 実施フロー

```
項目 1 実施
  → 処理済み確認
  → 次のタスクに関する確認事項（あれば）
  → ユーザー了承後に項目 2 へ

項目 2 実施
  → 処理済み確認
  → 次のタスクに関する確認事項（あれば）
  → ユーザー了承後に項目 3 へ

項目 3 実施
  → 処理済み確認
  → 次のタスクに関する確認事項（あれば）
  → ユーザー了承後に項目 4 へ

項目 4 実施（ユーザーと並走）
  → 処理済み確認
  → 次のタスクに関する確認事項（あれば）
  → ユーザー了承後に項目 5 へ

項目 5 実施
  → 処理済み確認
  → 次のタスクに関する確認事項（あれば）
  → 完了
```
