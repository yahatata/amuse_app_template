# Phase0A 環境変数設定・デプロイ手順（タスク5 成果物）

作成日: 2026-03-04  
対象: D-01（LINE_CHANNEL_ACCESS_TOKEN）, D-12（QR_SECRET_KEY）  
方針: 環境変数は**コマンドまたはコンソール**で登録する。**env ファイルは使用しない**（後述）。

---

## 1. 目的

- 機密・設定値をコードに平文で持たせず、環境変数で注入する（D-0009 の default なし方針）。
- **テンプレートリポジトリが完成しリリースを始めた後は、env ファイルを絶対に使用しない。** デプロイによる意図しない上書きを防ぎ、設定の正を「ファイル」にしない。
- 開発段階では、ローカル・emulator 用に限り .env 等の利用を許容する（本番値は書かない）。

---

## 2. 本番・ステージング（リリース後は env を使わない）

### 2.1 基本方針

- 環境変数の**登録**は **CLI コマンド** または **GCP コンソール** のみで行う。
- **.env / .env.* ファイルは使用しない。** 初回リリース時も、保守・更新時も同様。

### 2.2 設定方法

| 方法 | 手順 |
|------|------|
| **GCP コンソール** | Cloud Console → Cloud Functions → 対象関数 → 編集 → 「ランタイム、ビルド、接続の設定」→「環境変数」でキーと値を追加・編集する。 |
| **gcloud CLI** | 既存関数の環境変数を更新: `gcloud functions deploy <FUNCTION_NAME> --update-env-vars KEY1=value1,KEY2=value2 ...`（リージョン・プロジェクトの指定が必要）。新規デプロイ時に設定する場合は `--set-env-vars` で同様に指定する。 |
| **Secret Manager（推奨・秘密向け）** | 機密は `firebase functions:secrets:set SECRET_NAME` または GCP Secret Manager で登録し、コードでは `defineSecret` で参照する。デプロイで値が送られないため、更新時に上書きされない。 |

### 2.3 必須キー（D-01 / D-12）

| キー | 用途 | 設定手段の例 |
|------|------|----------------|
| `LINE_CHANNEL_ACCESS_TOKEN` | D-01: LINE Webhook / Messaging API | コンソールの環境変数、または Secret Manager |
| `QR_SECRET_KEY` | D-12: QR トークン HMAC 署名 | 同上 |

### 2.4 デプロイ前の確認

- 上記キーが**コマンドまたはコンソールで設定済み**であることを確認する。
- 未設定のままデプロイしない（本番では未設定時 throw とする）。

### 2.5 本番未設定時の挙動

- コード側（タスク6で実装）で、本番/ステージングと判定した場合は **未設定なら throw** とする。
- 開発時はエラーにせず、ローカル用の設定経路（開発段階のみ .env 等）を参照する。

---

## 3. 開発時（開発段階のみ .env 等を許容）

### 3.1 基本方針

- **開発段階**（テンプレート完成・リリース前）: ローカル・emulator 用に限り、**ローカル設定ファイル（.env.local 等）の利用を許容**する。本番のトークン・秘密鍵は書かない。
- **リリース開始後**: env ファイルは**一切使用しない**。開発者環境でも、本番用の値は .env に持たせず、必要ならコマンド/コンソールで設定した環境で検証する。

### 3.2 開発段階でのローカル用ファイル（参考）

- テンプレート例: `functions/env.local.example`（キー名のみ。Git にコミット可）
- 実ファイル例: `functions/.env.local`（各開発者が作成。Git に含めない）
- 実装側でローカル/emulator 判定時にのみ読み込む。本番では読まない。

### 3.3 注意

- ローカル設定ファイルに本番値を入れない。
- ログ出力時に token/secret を出さない。

---

## 4. 「env を使わない」方針のまとめ

| 対象 | 方針 |
|------|------|
| 本番・ステージング | **常に** コマンドまたはコンソールで設定。.env は使わない。 |
| 開発段階のローカル | .env.local 等の利用を**許容**（本番値は書かない）。 |
| テンプレート完成・リリース開始後 | **すべての環境で** env ファイルは使用しない。 |

---

## 5. タスク6実装時・タスク8（Phase3）への引き継ぎ

- **タスク6**: D-01 は `defineString` から default を削除する。値の取得は、本番では `process.env` または `defineSecret` を想定し、設定はコマンド/コンソールのみ。開発時はローカル用の読み込み経路を用意する（開発段階のみ）。
- **D-12**: `qrCodeUtils.ts` の fallback を削除し、本番では未設定時 throw。設定はコマンド/コンソールのみ。
- **タスク8（Phase3 実施）**: デプロイ前チェック（環境変数がコマンド/コンソールで設定済みであること）と、問題時の「値を正しく設定し直して再デプロイ」する手順を Runbook にまとめる。Phase0A では具体手順書の作成は行わない。
