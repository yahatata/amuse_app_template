# 現状の使用パターンの確認（LINE ミニアプリ・`public/`）

**前提**

- 対象は `docs/共通化/line_mini_app/01_対象の選定/00_対象の選定.md` の **4項目のみ**。
- 参照した対象範囲は **`docs/共通化/line_mini_app/02_対象ファイル・対象箇所の確認/対象ファイル・対象箇所の確認.md`**（以下 **Step2**）に列挙された **対象ファイル・対象箇所のみ**（`public/` 全体の再探索は行っていない）。
- **旧資料は参照していない**。
- 本書は **As-is** の整理であり、実装方針の提案は含めない。
- **件数の意味**: 本書の各区分の件数は、**Step2 で整理した対象箇所を母数**として、**Step3 で主要パターンへ再分類した件数**である（**実装コード上の呼び出し全件を再集計した件数ではない**）。

**「主要パターン」の扱い（本書での定義）**

- **主要パターン**＝Step2 の対象箇所のうち、**同一パターンに該当する対象箇所が 2件以上** のもの。
- **件数が 1件** のみの型は、**主要パターン表には載せず**、**例外整理表**（単一箇所・特殊事情）に寄せる。

**「1件」および「対象箇所」の定義（本書）**

- **1件**（Step3 で数える件数）＝ **1対象箇所** を **1件** と数える。
- **対象箇所**＝ **1つのユーザー操作**、**1つの表示分岐**、または **1つの失敗処理**に対して、**独立して認識できる実装のまとまり**。
  - **ファイル単位ではない**（同一ファイルに同じ論点の実装が3箇所あれば **3件**）。
  - **コード行単位ではない**（同一 `confirm()` 呼び出しや `showModal` に相当するブロックが何行でも **1件**）。
  - **UI部品の個数ではない**（ボタンが2つあっても **1つの** 確認フローなら **1件**）。
  - **Step2**（`02_対象ファイル・対象箇所の確認`）で整理した **対象箇所** を母数とする。

**Step3 における「1件」と主要パターン**

- 各区分の **件数** は、上記 **対象箇所** を **重複なく** 数えたものである。
- **主要パターン** に束ねて記載する場合も、**束ねる前の対象箇所の数** が **件数** の根拠になる。

**1件として数える単位の例（代表・ミニアプリ）**

| 論点の例 | 1件として数えるもの |
|----------|---------------------|
| 確認 | **1つの** `confirm()` 呼び出し箇所、または **それに相当する** 確認 UI の **1ブロック** |
| ユーザーへの結果出力 | **1つの** トースト／モーダル／インライン表示の **まとまり** |
| ローディング | **1つの** 非同期処理起点に対する **1つの** オーバーレイ／スピナー／ボタン無効化のまとまり |
| エラー（ログ・表示） | **1つの** 失敗処理に対する **1つの** `console.*`／画面表示のまとまり |

**エラーログ・失敗処理の 1件（補足）**

- 原則: **1つの失敗処理**に対して **1つの** ログ／表示のまとまり → **1件**。
- **複数の `console.error` とユーザー向け表示**が **同一 catch／同一コールバック** にある場合、**一体動作として 1件** と見るか、**Step2 で対象箇所を分けて列挙している** かで **別件** と見るかが分かれる。**迷う場合は Step2 の列挙（対象箇所の切り方）に従う**。

**件数の母数（Step2 との対応）**

- 各区分の **件数** の母数は、Step2 に列挙された **対象箇所** の数である。

| 区分 | 母数（**対象箇所数**） |
|------|------------------------|
| §1 ローディング | **23** |
| §2 保守運用時用のエラーログ | **20** |
| §3 ユーザーへの結果出力 | **11** |
| §4 確認ダイアログ | **6** |
