# 共通化価値評価（LINE ミニアプリ）

Step 2「候補ごとに共通化価値を評価する」の成果物。  
入力は **`01.5_候補整理.md`**（整理後候補名を評価単位とする）。**採否（残す / 保留 / 落とす）を付けた**。関数シグネチャ・例外網羅・changeSpec は扱わない。

**再評価（フラット化）**  
初版の文言に「製品 UI/UX を主戦場」と読める箇所があり、開発者向け **console / デバッグ UI** が **「落とす」** になっていた。指示の **8 メリットはエンドユーザー向けに限定した定義ではない**（変更コスト・レビュー・テスト・判断コスト等は開発・保守にもそのまま効く）ため、**同一の基準で再評価**し、当該2件は **保留** に修正した。

## Step 2 の読み方（本評価の前提）

1. **「共通 UI コンポーネント化できるか」だけで価値を決めない。** helper・初期化フロー・表示ポリシー・参照ルールに寄る候補も、同じ「共通化の目的（メリット）」に対して評価する。
2. **8 メリットの適用はエンドユーザー向け画面に限定しない。** ログ方針・デバッグ導線も、一貫性・変更コスト・レビュー・テスト・判断コスト・バグ混入抑制などに **フラットに** 寄与しうるとして評価する（「ユーザー向け 8 メリット」のような言い切りはしない）。
3. **着地先（仮）は参考。** 行ごとの結論は、メリットと補助観点から付けている（着地先で機械的に残す／落とさない）。
4. **`staff` / `user` の両方にあるかだけで価値を決めない。** user 専用（カート）・staff 集中（大規模カレンダー）も、補足・分割前提として別評価する。
5. **`config.js` / `__CONFIG__` は「設定値の多少」では評価しない。** 参照・Firestore 上書き・読取タイミング・スタッフ／ユーザー差の**揺れ**として見る。
6. **境界衝突候補の見方（短く）**  
   - **`alert` / `confirm`**: 主軸は **表示ポリシー**（確認が要る操作の経路・モーダル／インライン／ネイティブの三経路）。  
   - **初期化失敗インライン**: 主軸は **表示ポリシー × 初期化フロー**（いつ再試行するか、どの失敗で何を見せるか）。  
   - **`__CONFIG__` / Firestore**: 主軸は **初期化フロー / service と参照ルール**（`await` の型・上書きの有無・フラグ参照の揺れ）。  
   - **LIFF / Firebase 認証**: 主軸は **初期化フロー**（シーケンス本体と `window` 公開・Callable 差の切り出し）。  
   - **プレースホルダ vs 業務 HTML**: 主軸は **UI 部品（型）と業務マークアップの参照ルール**（同一関数内混在を雑にまとめない）。  
   - **レイアウト基盤**: 主軸は **レイアウト規約・共通シェル**（トークン／ページ集合／`user.css` 拡張との境）。トークン化は **副次で Step3**。  
   - **非同期実行ヘルパー**: 主軸は **UX ルール**（disable・文言・オーバーレイ包みの推奨形）。**グローバルオーバーレイ**とは Step3 で対で整合。

7. **「特に効いた観点」列の書式（方式B：番号＋正式略記）**  
   - `1 修正漏れ`／`2 将来仕様変更`／`3 見た目・挙動`／`4 実装判断の繰り返し`／`5 テスト・レビュー集約`  
   寄与が弱い・適用が局所的な場合は括弧で注記。5 観点に主に当てはまらない場合は `—`。

## 4. Step 2 時点での所感

- **残す候補の傾向**: **責務が局所的で効果が読みやすい**ものが残った（初回ローディング、QR 状態、フォーマット、操作系スタイル土台）。いずれも **一貫性・変更の一箇所化・レビューしやすさ**に直結しやすい帯域。  
- **迷いが多かった種類**: **初期化〜認証〜`window` 公開〜`__CONFIG__`** の縦の線、**`alert` / `confirm` / インライン / モーダルの横の線**、**プレースホルダと業務 HTML**、**非同期ヘルパー × オーバーレイ**、**レイアウト基盤とトークン／ページ差**、および **ログ／デバッグ（本番方針・DEBUG ガード）**。指示どおり **保留を厚く**し、境界は Step3 で軸を一文ずつ置く前提とした。  
- **Step 3 に入る時の注意**:  
  - **保留 18 件**は着手順を付ける前に、**表示ポリシー / 初期化フロー / 参照ルール / UI 部品 / 開発時観測**のどの軸で切るかを候補ごとに短くラベル化する。  
  - **残す 4 件**でも、スタイル行は **レイアウト基盤・エラー UI** との **class / DOM の重なり**を突き合わせる。 QR 行は **alert vs showError** の差分をポリシー側に逃がさない。  
  - **大規模 HTML・業務組み立て**はスコープを小さくしたサブブロックから成立性を見る。
