# 対象ファイル・対象箇所の確認（LINE ミニアプリ・`public/`）

**前提**

- 共通化の対象は `docs/共通化/line_mini_app/01_対象の選定/00_対象の選定.md` の **4項目のみ**。
- **旧資料フォルダは参照していない**（`01_対象の選定/旧資料` は未使用）。
- 対象は **`public/` 配下**の現行ファイル。`404.html` は Firebase 既定テンプレート、`user/config.sample.js` は設定テンプレート。
- **分類**は UI 部品名ではなく、**表示目的・タイミング・ユーザーに求める行動**（主分類のみ）。

**対象箇所（定義）**

- **対象箇所**＝ **1つのユーザー操作**、**1つの表示分岐**、または **1つの失敗処理**に対して、**独立して認識できる実装のまとまり**。
  - **ファイル単位ではない**（同一 HTML に同じ論点が複数あれば、対象箇所も複数）。
  - **コード行単位ではない**（同一 `confirm()` や確認ブロックは **1対象箇所**）。
  - Step3（`03_現状の使用パターンの確認`）では **1対象箇所＝1件** として数える。詳細な例は Step3 の「『1件』および『対象箇所』の定義」を参照。

**列挙**

- 本書は **対象箇所** を列挙する（多くは **ファイルパス＋説明**）。**`public/user/index.html` / `public/staff/index.html`** は **1ファイルに多数の機能**が集約されているため、**対象箇所ごと**に分けて記載する。

## 2. 保守運用時用のエラーログ

**Functions 側の扱い**: ミニアプリは **`httpsCallable('関数名')`** または **`fetch(.../getFirebaseCustomToken)`**。実装の所在は **`functions/src/domains/*`**（HTTP のみは `callables` ファイル名を明記）。

| クライアント側ファイルパス | 対象箇所 | Functions 側対応箇所 | 補足 |

| `public/user/index.html` | `checkStoreRegistration` の `catch` → `showError('...' + error.message)` | **なし**（Firestore `getDoc` 失敗が主） | **error.message 表示あり** |

#### 要確認メモ（§2）

- **共通利用あり**: **`getMenuItems`**（Flutter `lib/Utils/menuItemsManager.dart` と `public/user/index.html`）。**`createStaffAccount`**（Flutter `createStaffAccountPage` と `public/staff/index.html`）。
- **HTTP のみ**: **`getFirebaseCustomToken`** は `httpsCallable` ではなく **`fetch` + onRequest**。クライアントは `console.error` / `showErrorWithRetry`、Functions は **`domains/user/callables/getFirebaseCustomToken.ts`**。
- **クライアントに `error.message` を出すが、Functions の構造化ログと突合しづらい**場合: ミニアプリは **`alert` 中心**で、スタックは **staff の `showError` 第2引数時のみ**画面に出る。
- **ユーザー用 `createUserAccount` と Flutter `createUserByApp` は別物**。取り違えに注意。

## 要確認メモ

- **§2（保守運用時用のエラーログ）** は **callable / HTTP エントリと `functions/src/domains/*` の対応**を追記済み。詳細は **§2 末尾の「要確認メモ（§2）」** も参照。
- **`public/user/index.html` の `updateCheckinStatusUI`**: 非同期はあるが **ローディング・ボタン無効がなく**、失敗は **握りつぶし**。無反応・表示ズレの可能性。
- **単品 `processOrder`・`showTournamentRegistration`・`showAllTournamentsCalendar`**: **ローディング／再操作防止が薄い**。
- **`showError` / `alert` に `error.message` を連結する行**は **§2 と §3 の境界**（利用者向けに整形しているつもりでも技術文がそのまま出る）。
- **`public/staff/index.html` の `showError(message, error)`** は **スタックを画面に出す**ため、§2 の「保守運用向け」に強く寄る。
- **ルート `public/index.html`・`404.html`・`user/config.sample.js`**: 本4区分に**該当する処理がほぼない**ため、表では最小限にとどめた。
