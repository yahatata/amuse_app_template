# warning ログ整理 — 実装サマリ（2026-05-11）

- **文書日付**: 2026-05-11（[`エラーログ拡張仕様書_差分実装版.md`](./エラーログ拡張仕様書_差分実装版.md) の改訂履歴・§16.6 の追記日と同一）

## 1. 目的

[`warningログ方針.md`](./warningログ方針.md) に従い、`functions/src` 配下の本番業務コードから **`console.warn` を撤去**し、警告は **`logger.warn`** または **`logOpsError`** に統一した。また、アナリティクス集計まわりでは **同一事象のログが重複しない**よう配賦処理とログ出力位置を整理した。

本書は実装の要点のみをまとめる。**正式な `errorKey` の一覧**は [`エラーログ拡張仕様書_差分実装版.md`](./エラーログ拡張仕様書_差分実装版.md) **§16.6** および同書の **改訂履歴（2026-05-11）** を正とする。

| 項目 | 内容 |

## 3. アナリティクス（支払い方法別配賦・**B案**）

方針どおり、配賦ヘルパー内では個別に warn せず、**呼び出し側で一度だけ**構造化ログする。

### 3.1 実装の要点

- **`distributePaymentMethodsWithIssues`**（`functions/src/domains/analytics/services/helpers.ts`）  
  - `paymentTotalsMap` と **`issues`**（フォールバック利用・フォールバック不可・無効キー正規化など）を返す。  
  - **ログは出力しない**。
- **`processBillAnalyticsAtomically`**（`updateAnalyticsForBill.ts`）  
  - **`logInvocation`** で呼び元を明示: `functionEntry` は **`billsOnSettle`** または **`migrateSettledBillsForBusinessDay`** のみ（内部ステップ名はここに載せない）。  
  - 配賦結果の **`paymentTotalsMap`** を **`addToMonthlyIndex` / `addToDailySummary` / `addToByUser`** に渡す（各 `addTo*` はマップのみ参照）。
- **ログ出力タイミング**  
  - 支払い配賦に関する `logger.warn` / `logOpsError` は、**Firestore トランザクションがコミット成功したあと**（`outcome.applied`）に限定し、**TX リトライによる二重ログ**を避ける。

### 3.2 issue 種別とログ種別

| issue（kind） | ログ |
|---------------|------|
| `PAYMENT_TOTALS_EMPTY_WITH_FALLBACK` | `logger.warn`（フォールバックで継続した旨） |
| `PAYMENT_TOTALS_EMPTY_NO_FALLBACK` | `logOpsError`（**`errorKey`: `ANALYTICS_PAYMENT_TOTALS_EMPTY_NO_FALLBACK`**） |
| `PAYMENT_TOTALS_INVALID_METHODS_NORMALIZED` | `logger.warn`（無効キーを `cash` に正規化した旨） |

### 3.3 呼び出し側

- **`billsOnSettle`**（トリガー経路）と **`migrateSettledBillsForBusinessDay`**（Callable）から、上記 `functionEntry` を渡して `processBillAnalyticsAtomically` を実行する。

## 4. その他ドメインでの warning 整理（抜粋）

`console.warn` の置き換え・重複削除・構造化の代表例。

| 領域・ファイル（例） | 内容 |
|----------------------|------|
| **`verifyPaymentSplit`** | クライアントとサーバの分割計算不一致時は **`logger.warn`** とスカラー中心の要約。成功ログ経路は既存の構造化に合わせる。 |
| **`completeAccountingV2`**（`accounting.ts`） | settled 後の activeStay / visitLog 更新失敗、party.userId 欠落によるスキップなどを **`logOpsError`** で記録（§16.6 の **会計系 errorKey** 参照）。 |
| **`setRankingData`** | 賞品付与対象ユーザーのドキュメント不在を **`logOpsError`**（**`TOURNAMENT_RANKING_GRANT_USER_NOT_FOUND`**）。 |
| **`addon`** | 上位で既に記録される事象と **重複していた `console.warn` を削除**。 |
| **`getActionLogs`** | 0 件クエリなどを **`logger.warn`** で構造化。 |
| **`cancelOrder`** | `_TodaysOrders` 不在など補助処理の想定内事象を **`logger.warn`** で構造化。 |
| **`createStaffAccount`** | リッチメニュー更新失敗など非致命的事象を **`functions.logger.warn`** で構造化。 |
| **`devicePermissions`** | 端末名未取得などを **`logger.warn`** で構造化。 |

## 5. 今回 §16.6 に追加した正式 `errorKey`（4 件）

詳細な定義・運用は **エラーログ拡張仕様書（差分実装版）§16.6** を参照。

| `errorKey` | 用途の要約 |
|------------|------------|
| `ACCOUNTING_POST_SETTLE_STAY_VISIT_LOG_UPDATE_FAILED` | settled 後の activeStay / visitLog 更新が失敗した場合 |
| `ACCOUNTING_SETTLE_PARTY_USER_ID_MISSING` | settled 時に `party.userId` がなく滞在・来店更新をスキップした場合 |
| `ANALYTICS_PAYMENT_TOTALS_EMPTY_NO_FALLBACK` | `paymentTotals` が空でフォールバックもなく、支払い方法別集計が欠落しうる場合 |
| `TOURNAMENT_RANKING_GRANT_USER_NOT_FOUND` | `setRankingData` で賞品付与対象のユーザードキュメントが存在しない場合 |
