## 4. 手動確認の推奨項目

- **103**: 複数注文がある一覧で、1 件だけ「更新中…」が付くこと。別カードのスワイプは `_servingOrderId` が null のときのみ可能。
- **105**: ネットワーク遅延時も、最初から「営業時間を取得しています…」が出ること。
- **107**: `to_be_deleted` 経由以外では未使用のため、本番組み込み時に再度 UI 確認。
- **78**: 入店中ユーザー一覧 → 注文 → メニュー選択 → 数量確認で「注文確定」後、**ダイアログ全体**に半透明＋スピナーがかかり、キャンセル・数量変更・外タップで閉じられないこと。
- **99 更新**: 会計管理 → 会計内容修正 →「修正」押下後、**失敗が速くても**一瞬でも全画面オーバーレイ（CPI）が表示されること（スナックバーだけに直跳びしないこと）。

### 2026-03-23 — 99：`accountingEditDialog` 修正ボタン押下でローディングが出ない場合

- **ファイル**: `lib/Accounting/accountingEditDialog.dart`（`_updateAccounting`）
- **現象**: 写真の「会計内容修正」ダイアログで「修正」を押すと、**オーバーレイが一度も表示されず**スナックバーで失敗通知だけになることがある。
- **原因**: `_isSubmitting = true` の `setState` の直後に `await httpsCallable(...)` すると、**失敗応答が極端に速い**と、ローディング用の **1フレームも描画されない**まま `finally` で `_isSubmitting = false` になる（実装は元からあったが、見た目上「ローディングなし」になる）。
- **対応**: `setState(() => _isSubmitting = true)` の直後に **`await WidgetsBinding.instance.endOfFrame`** を入れ、Callable 呼び出し前にオーバーレイが描画されるようにした。

### 2026-03-23 — 99：`accountingEditDialog` 送信中オーバーレイをダイアログ内のみ → 画面全体へ

- **ファイル**: `lib/Accounting/accountingEditDialog.dart`（`build`）、`lib/Accounting/accountingPage.dart`（`_showEditDialog` の `showDialog`）
- **理由**: 他画面と同様、**ディム範囲とロックのイメージを画面全体で揃える**ため（会計管理の一覧・AppBar まで含めて半透明にする）。
- **内容**: `Dialog` 直下の `Stack` にあった送信中オーバーレイをやめ、`PopScope` → **全画面サイズの `SizedBox` + `Stack`**（手前に `Center(Dialog)`、その上に `Positioned.fill` の `ColoredBox`＋`AbsorbPointer`＋**CPI のみ**）。半透明は `Colors.black.withValues(alpha: 0.35)`。
- **78（注文確定）とのロックの同一性**: **同じパターン**（`PopScope(canPop: !送信中)`、`Positioned.fill`＋`AbsorbPointer`＋半透明、`showDialog(barrierDismissible: false)`、送信中は主要ボタン・入力の無効化）。**差分は 99 は会計画面全体を覆う `SizedBox`、78 は `AlertDialog` を `Stack` で包む**（ルートの広さはどちらもモーダル内で全画面相当）。

### 2026-01-30 — トーナメント進行ホーム：卓操作・参加者登録ダイアログの誤閉じ防止

- **ファイル**: `lib/tournament/active/pages/tournament_home_page.dart`（各 `showDialog`）、`lib/tournament/active/widgets/dialogs/register_participants_dialog.dart`、`assign_seat_dialog.dart`、`add_table_dialog.dart`、`remove_table_dialog.dart`、`reseat_all_dialog.dart`（本体＋内側のリシート確認 `showDialog`）
- **問題**: 更新・登録処理中は `content` 内オーバーレイで主領域はロックされるが、`showDialog` の **`barrierDismissible` デフォルト（true）** のため、**背面タップでルートが閉じる**。`PopScope` もなく **戻るで閉じ得た**。
- **対応**:
  - `tournament_home_page` から開く上記 6 経路すべてに **`barrierDismissible: false`**（キャンセルボタンで閉じる）。
  - 各ダイアログの **`AlertDialog` を `PopScope(canPop: !_isLoading)` でラップ**（参加者登録のみ `!_isRegistering`）。送信中・登録中は **戻るで閉じない**。
  - `reseat_all_dialog` の **確認用サブダイアログ**にも `barrierDismissible: false` を付与（実行確定前の誤閉じ防止）。
- **同様調査メモ**: アプリ全体の `showDialog` は用途が多く**一律は未対応**。**非同期更新中に内部でローディングを出しているダイアログ**で、呼び出し側が `barrierDismissible` 未指定のものは**同型のリスク**あり。会計系（99 等）・注文確定（78）は既に別途 `false` ＋ `PopScope` パターン。**卓系は本項でトーナメント進行ホーム経路を揃えた**。
- **半透明の意味**（追記）: 本プロジェクトでは半透明＝**触れない状態**の合図。誤閉じ防止のみ `barrierDismissible: false` だと、**ダイアログ内の `content` だけ**に半透明を載せると、背面のスクリムと「ロック範囲」の見た目が合わない。**`MediaQuery` 基準の全画面 `SizedBox` ＋ `Stack`** 上で `Center(AlertDialog)` の**手前**に `Positioned.fill` で `ColoredBox(alpha: 0.35)` ＋ `AbsorbPointer` ＋ CPI（卓系・参加者登録は 2026-01-30 追記で統一）。
