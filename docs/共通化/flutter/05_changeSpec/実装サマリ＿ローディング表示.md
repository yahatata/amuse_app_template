## 4. 手動確認の推奨項目

- **103**: 複数注文がある一覧で、1 件だけ「更新中…」が付くこと。別カードのスワイプは `_servingOrderId` が null のときのみ可能。
- **105**: ネットワーク遅延時も、最初から「営業時間を取得しています…」が出ること。
- **107**: `to_be_deleted` 経由以外では未使用のため、本番組み込み時に再度 UI 確認。
- **78**: 入店中ユーザー一覧 → 注文 → メニュー選択 → 数量確認で「注文確定」後、**ダイアログ全体**に半透明＋スピナーがかかり、キャンセル・数量変更・外タップで閉じられないこと。
- **99 更新**: 会計管理 → 会計内容修正 →「修正」押下後、**失敗が速くても**一瞬でも全画面オーバーレイ（CPI）が表示されること（スナックバーだけに直跳びしないこと）。
- **42 追記**: デバイス管理 → 行の「オプション編集」→ 保存後、**一覧再取得が終わるまで**半透明＋CPI が残り、戻る・更新アイコンが効かないこと。
- **menuList 追記**: カテゴリ別メニュー → 注文確認 →「注文確定」後、**Callable 完了まで**画面全体に半透明＋CPI、戻る・更新が効かないこと。
- **シフト追記**: シフトカレンダー → 日付ダイアログで「最終確定」、または AppBar「一括最終確定」→ 確定後、**処理完了まで**同様にロックされること（個別は日付ダイアログ閉鎖後にオーバーレイが最前面になること）。

### 2026-03-23 — 99：`accountingEditDialog` 修正ボタン押下でローディングが出ない場合

- **ファイル**: `lib/Accounting/accountingEditDialog.dart`（`_updateAccounting`）
- **現象**: 写真の「会計内容修正」ダイアログで「修正」を押すと、**オーバーレイが一度も表示されず**スナックバーで失敗通知だけになることがある。
- **原因**: `_isSubmitting = true` の `setState` の直後に `await httpsCallable(...)` すると、**失敗応答が極端に速い**と、ローディング用の **1フレームも描画されない**まま `finally` で `_isSubmitting = false` になる（実装は元からあったが、見た目上「ローディングなし」になる）。
- **対応**: `setState(() => _isSubmitting = true)` の直後に **`await WidgetsBinding.instance.endOfFrame`** を入れ、Callable 呼び出し前にオーバーレイが描画されるようにした。

### 履歴（実施日未検証）— トーナメント進行ホーム：卓操作・参加者登録ダイアログの誤閉じ防止

※ 旧見出し「2026-01-30」は未照合。
