## 2. 共通基盤で何を追加・変更したか

- `FunctionCustomError` を追加。
  - 必須: `errorKey`, `message`
  - 任意: `context`, `cause`
  - `service` / `functionEntry` / `operation` は持たせない。
- `logOpsError` を差分仕様・changeSpec方針で拡張。
  - 主軸: `errorSource`, `service`, `functionEntry`, `projectId`, `errorMessage`, `errorName`, `context`
  - `function_custom` 時のみ `errorKey`
  - `external_api` 時のみ `sourceProduct`, `sdkCode`, `httpStatus`, `detailReason`
  - `context` は payload 直下で `context` オブジェクトとして保持（フラット展開しない）
- `errorSource` 判定を共通化。
  - 明示指定 > `errorKey`/`FunctionCustomError` > external shape > `function_common`
- external 抽出処理を共通化（`externalFromCause.ts`）。
  - shape 優先（`status`, `code`, `details` 等）
  - 取得できない項目は未設定
  - 補助指定は `sourceProductHint` のみ
- `functionEntry -> service` マップを `serviceByFunctionEntry.ts` として追加。
  - 対応表（主表+export外）由来
  - 未登録は `unknown_service`

### 12.6 A-throw（台帳 #35–#124）判定と実装（2026-04-06 追記）

## 13. 追記: 3業務群（会計 / 店舗開閉・端末 / トーナメントスケジュール）での FunctionCustomError 接続拡張

本節は、§3・§12.6 の続きとして、**会計・店舗・トーナメント（スケジュール系）**の 3 業務群に対し、`FunctionCustomError` の throw／callable・repos 境界での `mapFunctionCustomErrorToHttpsCode` 接続、および関連する `logOpsError` 文脈の整理を実装した内容をまとめる。

### 13.1 会計（請求・会計・イベント系 repos / callables）

| 区分 | 主なファイル（`functions/src/` からの相対） | 主な `errorKey` / 内容 |
|------|-----------------------------------------------|------------------------|
| 冪等・リクエスト整合 | `domains/bills/repos/appendItem.ts` / `appendExtra.ts` / `appendSideGameChip.ts` / `recordTournamentAction.ts` | `ACCOUNTING_IDEMPOTENCY_MISMATCH`（requestHash 不一致など） |
| callable 境界 | `domains/bills/callables/accounting.ts` | `ACCOUNTING_PAYMENT_TOTAL_MISMATCH`（支払合計不一致）、`ACCOUNTING_INSUFFICIENT_BALANCE`（残高不足）ほか既存 FCE の `HttpsError` 変換 |
| 会計取り消し | `domains/bills/callables/cancelAccounting.ts` | 精算前のみ等のガード → `ACCOUNTING_INVALID_STATE`、catch で FCE → `HttpsError` |
| 請求作成 | `domains/bills/repos/createBillWithActiveStay.ts` | `getCurrentBusinessDateKeyOrThrow` 呼び出しをトランザクション try 内に寄せ、同トランザクション由来の `FunctionCustomError` を外側 catch と一貫して扱う |

### 13.4 §12.6.2 の「維持」記載との関係

§12.6.2 では `continueBusinessTerminal` やスケジュール系トーナメントの一部を「変更最小のため維持」としていたが、**本バッチ（§13）**では、上記のとおり **端末・継続営業**および **スケジュール系 3 callable** に `FunctionCustomError` 接続を追加した。トーナメント実戦系（多数の `Error`/`HttpsError` 混在）の全面 `TOURNAMENT_*` 割当は、引き続き別タスクとする。
