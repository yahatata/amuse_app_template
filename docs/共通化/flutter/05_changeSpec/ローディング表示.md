## 1. 目的

本 changeSpec は、Flutter におけるローディング表示について、仕様書で定めた 3 類型のルールに基づき、今回の対象箇所に対する To-be と実装対象を確定するものである。

今回の主目的は **UI/UX の向上** であり、特に以下を狙う。

- 処理中であることが分かること
- 更新系処理で誤操作・重複実行・状態不整合を防ぐこと
- 読込 / 読取 / 更新を同一強度で扱わず、類型ごとに自然な待機表示と操作制御にすること

## 3. 共通方針

### 3.1 読込

- 読込時の待機表示は **CPI に統一**する
- 原則としてロックは行わない
- AppBar を残した本文領域での CPI、または画面全体 CPI を認める

### 3.2 読取

- 読取系で待機表示が必要な場合は **CPI に統一**する
- 原則としてロックは行わない
- 待機表示が不要な軽微処理は現状維持を認める

### 3.3 更新

- 更新系では **ローディング表示 + UI ロック** を原則必須とする
- ボタン単位のみの待機表示を標準としない
- 処理中 UI を実質回避できないことを求める
- ローディングとロックは **処理終了時に解除**
- 結果出力は **解除後**
- 結果出力自体のための追加ロックは行わない

## 5. 実装上の補足

### 5.1 99 の扱い

`accountingEditDialog.dart` は同一ファイル内に読込と更新が同居する。  
本 changeSpec では、

- `_loadAvailableOptions` 等の **読込**
- 会計修正実行の **更新**

の両方を対象に含める。

### 5.2 103 の実装置き場

`order_card.dart` は `StatelessWidget` であるため、To-be のローディング表示およびロック実装は、当該ウィジェット単体ではなく、親側の状態管理またはオーバーレイ等の方式で実現する可能性がある。  
本 changeSpec は UI/UX 要件を定めるものであり、最終的な状態管理の置き場は実装時に決定する。

### 5.3 107 の利用前提

`admin_controls.dart` は現時点では本番導線からの参照が限定的または未確認である。  
ただし、今後使用予定ありとして、本 changeSpec の対象に含める。  
実装前に、本番導線での利用箇所確認を行う。

- 読込対象 99 に CPI が追加されている
