# 現状の使用パターンの確認（Flutter・`lib/`）

**前提**

- 対象は `docs/共通化/flutter/01_対象の選定/00_対象の選定.md` の **4項目のみ**。
- 参照した対象範囲は **`docs/共通化/flutter/02_対象ファイル・対象箇所の確認/対象ファイル・対象箇所の確認.md`**（以下 **Step2**）に列挙された **対象ファイル・対象箇所のみ**（`lib/` 全体の再探索は行っていない）。
- **旧資料は参照していない**。
- 本書は **As-is** の整理であり、実装方針の提案は含めない。
- **件数の意味**: 本書の各区分の件数は、**Step2 で整理した対象箇所を母数**として、**Step3 で主要パターンへ再分類した件数**である（**実装コード上の呼び出し全件を再集計した件数ではない**）。

**「主要パターン」の扱い（本書での定義）**

- **主要パターン**＝Step2 の対象箇所のうち、**同一パターンに該当する対象箇所が 2件以上** のもの（Step3 整理時の定義どおり）。
- **件数が 1件** のみの型は、**主要パターン表には載せず**、**例外整理表**（単一箇所・特殊事情）に寄せる。

**「1件」および「対象箇所」の定義（本書）**

- **1件**（Step3 で数える件数）＝ **1対象箇所** を **1件** と数える。
- **対象箇所**＝ **1つのユーザー操作**、**1つの表示分岐**、または **1つの失敗処理**に対して、**独立して認識できる実装のまとまり**。
  - **ファイル単位ではない**（同一ファイルに同じ論点の実装が3箇所あれば **3件**）。
  - **コード行単位ではない**（同一 `showDialog` 呼び出し内の `AlertDialog` が何行にまたがっても **1件**）。
  - **UI部品の個数ではない**（1つの確認ダイアログに `TextButton` が2つあっても **1件**）。
  - **Step2**（`02_対象ファイル・対象箇所の確認`）で整理した **対象箇所** を母数とする。

**Step3 における「1件」と主要パターン**

- 各区分の **件数** は、上記 **対象箇所** を **重複なく** 数えたものである。
- **主要パターン** に束ねて記載する場合も、**束ねる前の対象箇所の数** が **件数** の根拠になる（**同一の主要パターンに属すると判断した** 各 **対象箇所** が **1件ずつ** 母数に含まれる）。

**1件として数える単位の例（代表）**

| 論点の例 | 1件として数えるもの |
|----------|---------------------|
| 確認ダイアログ | **1つの** `showDialog` 呼び出し箇所 |
| ユーザーへの結果出力 | **1つの** `SnackBar`（等）表示箇所 |
| ローディング | **1つの** `onPressed` 内のローディング制御のまとまり／**1つの** `build`・`FutureBuilder`・`StreamBuilder` の待機分岐のまとまり |
| エラー（ログ・表示） | **1つの** `catch` における **1つの** エラー表示／エラーログ出力のまとまり |

**ローディングの 1件（補足）**

- **1つの非同期処理の起点**に対して、**1つの** 待機表示／再操作防止のまとまりがあれば **1件** とする。
- 例: 画面初期取得の待機 **1件**、保存ボタン押下時の待機 **1件**、`confirm` 後の送信処理の待機 **1件**。
- 例（同一ボタン内）: `onPressed: _isLoading ? null : _save` と `child: _isLoading ? CircularProgressIndicator() : Text('保存')` → **ボタン内ローディング＋再操作防止** の **1件**。
- 例（同一ファイル内）: 保存ボタンのローディング・削除ボタンのローディング・一覧読み込み時の全画面スピナーが **それぞれ別の非同期起点** なら **3件**。

**確認ダイアログの例**

- `showDialog(` … `AlertDialog` … の **呼び出し1箇所** → **確認ダイアログ 1件**（`title` / `actions` の記述の広さや `TextButton` の個数は **件数に含めない**）。

**エラーログ・失敗処理の 1件（補足）**

- 原則: **1つの失敗処理**に対して **1つの** ログ／表示／出力のまとまり → **1件**。
- 例: `catch (e) { debugPrint('$e'); }` → **1件**。`catch (e) { SnackBar(...); }` → **1件**。
- `catch (e) { debugPrint('$e'); ScaffoldMessenger.of(context).showSnackBar(...); }` のように **ログとユーザー向け表示の両方**がある場合も、**同一の失敗処理の一体動作**として **1件** と見るか、**Step2 で対象箇所を分けて列挙している** かで **別件** と見るかが分かれる。**迷う場合は Step2 の列挙（対象箇所の切り方）に従う**。

**件数の母数（Step2 との対応）**

- 各区分の **件数** の母数は、Step2 に列挙された **対象箇所** の数である。
- §1 ローディングの母数 **119** は、Step2 の **§1.1〜§1.3**・**§1.5.2**（`firebase_options.dart` を除く）・**§1.5.3** に含まれる **対象箇所** の合計（§1.5.2 は **14**＝15件のうち対象外1を除く）。

### 1.3 CF 呼び出し追跡と冪等性（ローディング文脈・更新操作）

**目的**

- §1 の **ローディング表示**とセットで走りがちな **`httpsCallable`** について、**どの callable がどこから呼ばれるか**をコード追跡し、**更新操作**に該当するものだけ **`functions/src` の実装**に基づき **冪等性（再実行時の二重副作用の抑止）の有無**を整理する。

**更新操作の定義**（冪等性を確認する対象）

- 再実行されたときに、**状態・結果・外部副作用**のいずれかが **変わりうる**処理。
- **最低限、次のいずれかに当てはまるもの**を更新操作とする: 永続状態が変わる／再実行で結果が変わる／外部に送る／消費・発行・予約・通知・実行／状態遷移がある。
- **原則として更新操作ではない**（本節では冪等性の詳細確認をしない）: 一覧取得・詳細取得・集計取得・単なる表示切替・ローカル補助のみ。

**調査方法**

- `lib/**/*.dart` の `httpsCallable('…')` を列挙し、呼び出し元ファイルと対応する `functions/src/domains/**/callables/*.ts`（または `shared/**`）を確認。**調査日**: 2026-01-30。
