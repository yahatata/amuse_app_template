# 境界候補一覧（Flutter・退避・判断用）

**`02.5_基盤業務境界整理.md` で「境界候補」としたものだけを抜き出した。**  
基盤部品だけ先に固めると**表示ポリシーや業務ルールと矛盾**しやすい帯域。**今回の基盤優先ラウンドでは着手順を後ろに回しやすい**が、Step3 以降で**人間が軸を一文ずつ決める**前提の一覧。

**関連**: `02_共通化価値評価.md` / `02.5_基盤業務境界整理.md` / `02.5_業務候補一覧.md`

---

## 凡例（人間目線の例）

- **スタッフ**: 店内オペ・レジ・卓管理・バックオフィス寄りの画面を想定した利用者。
- **ユーザー（来店客）**: 卓上端末・来店用アプリなど、**客側・プレイヤー側**の画面を想定した利用者。  
  ※ 店舗・プロダクトの正式ロール名に合わせて読み替えてよい。

---

## 1. 入力・補足情報付き確認ダイアログ

| 項目 | 内容 |
|------|------|
| **境界に置いた理由（要約）** | 単純確認より **入力検証・補足フィールド・業務文言** と密結合。基盤の「確認ダイアログ」と**無闇に束ねない**。 |
| **スタッフの具体例** | 会計で「返金理由」を短テキスト併記しながら取消確認する／締め処理で締め日と担当を選んでから確定する、など。 |
| **ユーザー（来店客）の具体例** | 卓上でチップ購入時に枚数と注意文を確認しながら確定する／退席前に残高照会の補足チェックを伴う確認、など。 |

---

## 2. 破壊的操作・取消・締め等の確認ダイアログ

| 項目 | 内容 |
|------|------|
| **境界に置いた理由（要約）** | **トーン（危険度・赤ボタン）・文言強さ・戻れなさ**が店舗ポリシー・オペ手順と一体。画面ルール依存で切り口が揺れる。 |
| **スタッフの具体例** | 会計締めの「取り消せません」系の強い警告／シフト申請の削除・勤怠の打ち直し取消、など。ミス時の説明責務が重い。 |
| **ユーザー（来店客）の具体例** | 卓からの強制退出・ゲーム中断の確認／購入・決済のキャンセル不可の明示、など。恐怖のない押し付けにならない一文が要る。 |

---

## 3. （変更なし）SnackBar・短期的メッセージ

| 項目 | 内容 |
|------|------|
| **境界に置いた理由（要約）** | **いつ SnackBar にするか／ダイアログにするか**は表示ポリシー。部品統一だけでは決まらない。 |
| **スタッフの具体例** | 「保存しました」を SnackBar で流すが、会計エラーはダイアログ、など**同じスタッフアプリ内でも経路が混在**しうる。 |
| **ユーザー（来店客）の具体例** | カート更新の軽い成功はトースト風／通信エラーは全画面ブロック、など**客が気づきやすさ**優先で経路が変わる。 |

---

## 4. （変更なし）非同期完了後の画面遷移・ダイアログクローズ

| 項目 | 内容 |
|------|------|
| **境界に置いた理由（要約）** | **「終わったらどこへ行くか」**は業務フロー依存。ローディング基盤だけでは一律ルール化しにくい。 |
| **スタッフの具体例** | 会計送信成功後に一覧へ戻る／その場でレシート印刷ダイアログを出す、など画面・店舗運用で分岐。 |
| **ユーザー（来店客）の具体例** | 注文確定後に卓画面へ戻る／結果だけ表示してモーダルを閉じる、など**滞在時間・離脱**の設計とセット。 |

---

## 5. （変更なし）例外→ユーザー向けエラー表示

| 項目 | 内容 |
|------|------|
| **境界に置いた理由（要約）** | ユーザーに見せる**文言・経路・粒度**はポリシー。**エラーコード統一・集約基盤**には本ラウンドで踏み込まない（`02.5` 冒頭サマリ）。 |
| **スタッフの具体例** | 会計 API 失敗時「再試行」と「窓口へ」の出し分け／オフライン時は曖昧な一言にするか、店側判断。 |
| **ユーザー（来店客）の具体例** | 決済エラーで専門用語を出さず店員呼び出しへ誘導／卓上は panic させず「しばらく待って再試行」、などトーンが客向けと異なる。 |

---

## 6. ユーザー向けメッセージ（エラー・警告・成功・確認）の直書き集散

| 項目 | 内容 |
|------|------|
| **境界に置いた理由（要約）** | **文言カタログ vs 部品引数 vs 画面直書き**の軸が未定。業務ドメインの言い回しと密接。 |
| **スタッフの具体例** | 「締め処理」「返金」「勤怠」の用語統一／同じ「確認」でも会計とシフトで語感を変えるか、など。 |
| **ユーザー（来店客）の具体例** | 「オーダー」「注文」「カート」の客向け表記揃え／煽らないエラー文のテンプレ、など。 |

---

## 7. UI ラベル・ボタン・リスト項目の直書き集散

| 項目 | 内容 |
|------|------|
| **境界に置いた理由（要約）** | **短いラベル**はウィジェット直付けが多く、formatter ほど pure util に切り出しにくい。業務画面と分離しづらい。 |
| **スタッフの具体例** | 会計ボタン「確定」「締め戻し」の並び・省略／一覧の「金額」「ステータス」列見出しの揺れ。 |
| **ユーザー（来店客）の具体例** | 卓上の「戻る」「キャンセル」が画面で意味が変わる／メニュー項目の注釈の有無、など。 |
