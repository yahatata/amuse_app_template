# 共通化全体像

本ファイルは、共通化タスク全体の目的・中タスク・進行順を整理するための全体像ドキュメントである。
詳細は必要に応じて各個別ファイルを参照する。

## 共通化対象（実装基盤）

- 今回の共通化対象には **Flutter 側**（`lib/`）と **LINE ミニアプリ側**（`public/` 配下）がある。
- **タスクの種類・進め方は同一**だが、**実装基盤が異なる**ため、**原則として別々に行う**（対象選定から検証まで、基盤ごとに進める想定）。

## 大タスク：共通化

**目標**：以下の恩恵を受けることのできる機能やルールを共通化して実装完了すること。

- UI の一貫性向上: 見た目の統一
- UX の予測可能性向上: 操作結果の統一
- 変更コスト削減: 後から直しやすくなる
- バグ混入率低下: 重複実装由来の不具合を減らす
- レビュー効率向上: 確認観点を絞れる
- テスト観点の集約: テストを共通部品側に寄せられる
- 実装判断コスト削減: 毎回の迷いを減らせる
- デザイン負債抑制: 小さなズレの蓄積を防ぐ

## 中タスク：フローの 1 つ 1 つ

| # | 中タスク |
|---|----------|
| 1 | 対象の選定（Flutter: `flutter/対象の選定/00_対象の選定.md`／LINE: `line_mini_app/対象の選定/00_対象の選定.md`） |

## 各中タスクの目標と完了条件

### 1. 対象の選定

**目標**：次工程に進める共通化対象が選定されていること。

**完了条件**

- 共通化候補の洗い出し結果が整理されている
- 候補ごとの評価結果が整理されている
- 着手する対象が決まっている
- 対象選定の根拠が記録されている

### 2. 仕様の決定

**目標**：対象について To-be の方針が決まっていること。

**完了条件**

- 対象の中で、今回共通化する範囲が決まっている
- 共通化対象の責務が決まっている
- 利用方法が決まっている
- 既知の例外ケースの扱い方針が決まっている
- 検証観点が決まっている

### 3. 対象ファイル・対象箇所の確定

**目標**：適用対象と代表箇所が把握できていること。

**完了条件**

- 対象ファイル一覧が整理されている
- 対象箇所一覧が整理されている
- 代表実装箇所が特定されている
- 適用対象外の箇所がある場合、その扱いが整理されている

### 4. 現状の使用パターンの確認

**目標**：As-is の主要パターンと例外が整理されていること。

**完了条件**

- 現状の主要な実装パターンが分類されている
- 似た実装の差分の種類が整理されている
- 既知の例外ケースが整理されている

### 5. changeSpec 作成

**目標**：実装可能な変更仕様に落とし込まれていること。

**完了条件**

- changeSpec の対象範囲が明確である
- 変更内容が実装単位で整理されている
- 検証観点が changeSpec に記載されている
- 必要な前提条件・注意点が整理されている

### 6. 実装

**目標**：changeSpec に基づく実装が完了していること。

**完了条件**

- changeSpec に記載した実装が完了している
- 対象箇所への適用が完了している
- ビルド・静的解析・最低限の動作確認が通っている
- 実装差分が整理されている

### 7. 検証

**目標**：実装結果が仕様どおりであり、影響範囲を含めて問題ないことが確認されていること。

**完了条件**

- changeSpec の検証観点を確認できている
- 共通化対象の期待挙動が確認できている
- 影響範囲に問題がないことを確認できている
- 必要な修正があれば反映済み、または別タスク化されている

## 補足・運用ルール

- 候補ごとに進めることを基本とする
- 対象ファイル・対象箇所の確定および現状の使用パターンの確認結果は、必要に応じて仕様更新に反映する
- changeSpec には検証観点を明記する
