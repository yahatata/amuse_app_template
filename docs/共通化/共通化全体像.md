# 共通化全体像

本ファイルは、共通化タスク全体の目的・中タスク・進行順を整理するための全体像ドキュメントである。  
詳細は必要に応じて各個別ファイルを参照する。

## 共通化対象（実装基盤）

- 今回の共通化対象には **Flutter 側**（`lib/`）と **LINE ミニアプリ側**（`public/` 配下）がある。
- **タスクの種類・進め方は同一**だが、**実装基盤が異なる**ため、**原則として別々に行う**（対象選定から検証まで、基盤ごとに進める想定）。

## 大タスク：共通化

**目標**：  
**UI/UX の向上** および **保守運用時の負担軽減** に寄与し、かつその効果が殊更に大きいと判断した機能やルールについて、仕様決定、実装、検証までを完了すること。

### 今回重視するメリット

- **UI/UX の向上**
  - 見た目や挙動の一貫性向上
  - 操作結果の分かりやすさ向上
  - 処理中状態やエラー時の認知しやすさ向上
  - 画面や機能ごとの差によるユーザーの困惑低減

- **保守運用時の負担軽減**
  - エラー検知・原因調査のしやすさ向上
  - ログの散在による確認負荷の軽減
  - 障害時の影響把握・切り分けのしやすさ向上

### 用語（Step2〜Step3）

- **対象箇所**・**1件**の定義は、`flutter/03_…` および `line_mini_app/03_…` の **「『1件』および『対象箇所』の定義」** を正とする（**1件＝1対象箇所**。ファイル数・コード行数・UI部品個数ではない）。

### 補足

- 今回は、**開発効率向上そのものを主目的には置かない**。
- 結果として開発・レビュー・修正がしやすくなる副次効果が出ることはありうるが、それは主たる採用理由にはしない。
- 今回の共通化対象は、**「複数箇所で使われている」だけではなく、UI/UX または保守運用への寄与が特に大きいもの** を優先する。

## 補足・運用ルール

- 候補ごとに進めることを基本とする
- 現状の使用パターンの確認結果は、必要に応じて仕様更新に反映する
- 対象ファイル・対象箇所の確認結果は、必要に応じて changeSpec に反映する
- changeSpec には検証観点を明記する
- UI 上の二重タップ不可は UX 上の共通化対象として扱うが、実データの重複防止は Functions 側の冪等性で担保する
- 保守運用時用のエラーログと、アプリ操作者向けの結果出力は別概念として扱う
