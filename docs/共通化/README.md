# 共通化

ロード・ダイアログなど、プロジェクト全体に関わる共通化の仕様・ルールをまとめる。実機テスト改善の前提として実施するが、単独フォルダで管理する。

**実装基盤ごとにフォルダを分ける**（詳細は **共通化全体像.md** を参照）。

## 構成

- **共通化全体像.md** - 大タスク・中タスク・Flutter / LINE ミニアプリの扱い
- **flutter/** - Flutter（`lib/`）向け
  - **対象の選定/** - 00_対象の選定、01_候補一覧、**01.5_中間整理_Step2前処理**（Step 1.5／Step 2 前整形・任意推奨）、02_共通化価値評価、03_設計成立性確認、04_着手対象決定
  - **仕様書/** - 仕様書
- **line_mini_app/** - LINE ミニアプリ（`public/` 配下）向け
  - **対象の選定/** - 00_対象の選定、01_候補一覧、**01.5_候補整理**（Step 1.5／Step 2 前整形・任意推奨）、02_共通化価値評価、03_設計成立性確認、04_着手対象決定
  - **仕様書/** - 仕様書

## 対象候補（Flutter 側の例）

- ロード表示（CircularProgressIndicator、ボタン内ロード、画面全体ロード等）
- ダイアログ（確認・エラー・成功、キャンセル時の遷移等）
- その他（SnackBar、エラーメッセージ等）

## 進め方

1. 現状の使用パターンを洗い出し
2. 共通化対象と仕様を確定
3. 共通コンポーネント／ユーティリティの設計
