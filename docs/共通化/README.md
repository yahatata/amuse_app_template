# 共通化

ロード・ダイアログなど、プロジェクト全体に関わる共通化の仕様・ルールをまとめる。実機テスト改善の前提として実施するが、単独フォルダで管理する。

**実装基盤ごとにフォルダを分ける**（詳細は **共通化全体像.md** を参照）。

## 構成

- **共通化全体像.md** - 大タスク・中タスク・Flutter / LINE ミニアプリの扱い
- **flutter/** - Flutter（`lib/`）向け（フォルダ名の **01〜04** は中タスクの進行順）
  - **01_対象の選定/** - 00_対象の選定、**旧資料/**（01_候補一覧、01.5_候補整理、02_共通化価値評価、02.5_基盤業務境界整理／02.5_業務候補一覧／02.5_境界候補一覧、03_設計成立性確認、04_着手対象決定）
  - **02_対象ファイル・対象箇所の確認/** - 対象ファイル・対象箇所の確認
  - **03_現状の使用パターンの確認/** - 現状の使用パターンの確認
  - **04_仕様書/** - テーマ別サブフォルダ（例: `ローディング表示/`、`ユーザーへの結果出力/`、`確認ダイアログ/`、`logOpsError実装/`、`エラーログ拡張/`）。各フォルダに **同名の仕様書**（例: `ローディング表示/ローディング表示.md`）と関連資料を置く。**改修方針メモ**（例: `ローディング表示/改修方針メモ.md`＝中タスク5 changeSpec の入力候補・[共通化全体像.md](./共通化全体像.md) と対応）
  - **05_changeSpec/** - changeSpec 正本（例: `ローディング表示.md`、`実装サマリ＿ローディング表示.md`、`changeSpec_エラーログ拡張.md`、`logOpsError実装サマリA.md` / `logOpsError実装サマリB.md`）
- **line_mini_app/** - LINE ミニアプリ（`public/` 配下）向け（フォルダ名の **01〜04** は中タスクの進行順）
  - **01_対象の選定/** - 00_対象の選定、**旧資料/**（01_候補一覧、01.5_候補整理、02_共通化価値評価、02.5_基盤業務境界整理／02.5_業務候補一覧／02.5_境界候補一覧、03_設計成立性確認、04_着手対象決定）
  - **02_対象ファイル・対象箇所の確認/** - 対象ファイル・対象箇所の確認
  - **03_現状の使用パターンの確認/** - 現状の使用パターンの確認
  - **04_仕様書/** - 仕様書

## 対象候補（Flutter 側の例）

- ロード表示（CircularProgressIndicator、ボタン内ロード、画面全体ロード等）
- ダイアログ（確認・エラー・成功、キャンセル時の遷移等）
- その他（SnackBar、エラーメッセージ等）

## 進め方

1. 現状の使用パターンを洗い出し
2. 共通化対象と仕様を確定
3. 共通コンポーネント／ユーティリティの設計
