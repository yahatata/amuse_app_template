## 3. 判定ルール

| 値 | 意味 |
|----|------|
| 未 | 未実施 |
| PASS | 期待結果を満たす |
| FAIL | 満たさない |
| 保留 | 環境不足等。**理由必須** |
| 再確認待ち | 修正後の再実施待ち |

### A / B / C

- **A:** 原則必須。skip する場合は理由必須
- **B:** 推奨。再現困難なら保留＋理由、または自動確認代替理由
- **C:** 見るだけ / 押さない。`DO_NOT_EXECUTE` の手順に「実行ボタンを押す」と書かない

### FAIL 時

1. 発見事項を記録  
2. 修正要否を判定  
3. 修正するなら調査 → コード修正 → 自動確認 → commit → 必要なら deploy / Flutter 再ビルド  
4. 該当 ID を再確認  
5. PASS になるまで閉じない  

### 保留

理由例: テストデータ不足 / 端末不足 / 時刻境界待ち / retired staff 不在 / destructive 後回し。  
「なんとなく」は不可。
