## 1. 綺麗化の目的

- 営業時に顧客へ見せられる状態へ整える
- UI、導線、文言、状態表示、主要業務フローを確認する
- デッドコード、未使用ファイル、未使用 Function 等を整理する
- 開発途中・テスト・デバッグ要素を営業デモから排除する

---

## 2. 綺麗化の定義

### 含むもの

- デッドコード削除
- 未使用ファイル削除
- 未使用 Cloud Functions 整理
- 未使用依存整理
- 不要画面・不要導線・不要ボタン整理
- debug / test / demo UI の隔離または非表示化
- 主要業務フローの実機確認
- UI の見た目・操作性・文言の改善
- 営業デモシナリオの通し確認

### 含まないもの

- システム内部資料の作成
- 営業提案資料の作成
- 新機能開発
- 大規模な仕様変更
- 本番インフラの再設計
- 運用設計全般

---

## 3. 基本方針

- まず機械的に確認できる不要物を整理する
- その後に実機確認へ進む
- 削除は小さなバッチ単位で行う
- 各バッチで analyze / build / test を確認する
- 不明なものは削除しない
- 仕様判断と技術的削除判断を分ける
- Firebase Console 上の Function 削除はコード削除と分ける
- UI 非表示とコード削除を分ける
