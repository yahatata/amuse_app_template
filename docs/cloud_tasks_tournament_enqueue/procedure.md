# Scheduled Tournament Cloud Tasks 投入（30日制限対応）─ 進め方

本ドキュメントは `docs/cloud_tasks_tournament_enqueue` 配下の各ステップを進める際の手順を定義する。

---

## フロー

```
・modification_list.md や、前ステップフォルダ内の実装サマリをはじめとする、
  docs/cloud_tasks_tournament_enqueue 内のファイルを丁寧に確認し、changeSpec の作成を行う
    ↓
・人間レビュー・修正依頼・修正のループ
    ↓
・実装の開始、確認観点の出力
    ↓
・確認の実行・テストファイルの作成・実行
    ↓
・人間レビュー・修正依頼・修正のループ
    ↓
・実装サマリの出力（人間が確認し修正が必要になるケースあり）
    ↓
・次のステップへ
```

---

## 各フェーズの説明

### 1. changeSpec の作成

- `modification_list.md` の該当ステップを確認する
- 前ステップの `stepN/implementation_summary.md` があれば参照する
- 現状実装と To-Be を丁寧に比較し、`stepN/changeSpec.md` を作成する

### 2. 人間レビュー・修正依頼・修正のループ

- changeSpec を人間がレビューする
- 修正依頼があれば changeSpec を更新する
- 合意するまで繰り返す

### 3. 実装の開始、確認観点の出力

- changeSpec に従って実装を行う
- 実装完了後、確認観点（チェック項目）を出力する
- 確認観点は `stepN/verification_points.md` などにまとめる

### 4. 確認の実行・テストファイルの作成・実行

- **エミュレーターの起動を最初に行う**（必要な場合）
- コード確認、テストファイルの作成・実行を行う
- 確認結果を記録する

### 5. 人間レビュー・修正依頼・修正のループ

- 確認結果を人間がレビューする
- 追加の修正依頼があれば実装を修正する
- 合意するまで繰り返す

### 6. 実装サマリの出力

- `stepN/implementation_summary.md` に実装内容をサマリとして出力する
- **サマリは詳細に記載する**（以下を必須とする）：
  - **実装内容の詳細**：ファイル単位の具体的な変更（削除したコードの範囲・内容、追加したコード、修正理由）
  - **テストの詳細**：実施したテストの名称・観点・アサート内容・実行コマンド・結果（PASS/FAIL）
  - **確認観点と結果**：verification_points の各項目に対する実施内容と結果
- 人間が確認し、修正が必要なケースがある

### 7. 次のステップへ

- 上記が完了したら、次のステップに進む
