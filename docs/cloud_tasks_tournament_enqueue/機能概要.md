# Scheduled Tournament Cloud Tasks 投入機能 概要

本ドキュメントは、`docs/cloud_tasks_tournament_enqueue` 配下で作成・更新した機能の概要をまとめる。Cloud Tasks の 30 日制限に対応したトーナメント自動開始・レジスト締切の仕組みを説明する。

---

## 1. 目的

- **Cloud Tasks の 30 日（720h）制限**を回避しつつ、トーナメントの開始・レジスト締切を**取りこぼしなく**実行する
- 単発作成・定期作成・定期生成など**作成経路によらず同一経路**でタスク投入を管理する

---

## 2. アーキテクチャ概要

```
[作成経路]                    [enqueue バッチ]                 [実行]
createScheduledTournament  ──┐
createTournamentRecurrence ──┼──► runEnqueueTournamentTasks ──► Cloud Tasks ──► controlHook
generateRecurringTournaments ┘         ▲                              │               │
                                       │                              │               ▼
                            enqueueTournamentTasksByScheduler    enqueueTournamentTask   status 遷移
                            （毎日 5:00 JST）                      （新 payload）     （scheduled→running→registered）
```

- **作成時**: Cloud Tasks を直接投入しない。`taskSyncNeeded=true` を立てるのみ
- **enqueue バッチ**: 日次 Scheduler または作成完了後に `runEnqueueTournamentTasks` を実行。taskIndex と突合し、30 日以内分を Cloud Tasks に投入
- **controlHook**: 投入されたタスクを受領し、planVersion/planHash 一致時に status 遷移を実行

---

## 3. 主要コンポーネント

| コンポーネント | ファイル | 役割 |
|----------------|----------|------|
| enqueueTournamentTasksCore | `functions/.../services/enqueueTournamentTasksCore.ts` | 対象取得・taskIndex 突合・Cloud Tasks 投入のコアロジック |
| enqueueTournamentTasks | `functions/.../callables/enqueueTournamentTasks.ts` | 手動実行用 Callable |
| enqueueTournamentTasksByScheduler | `functions/.../scheduler/EnqueueTournamentTasksByScheduler.ts` | 日次 5:00 JST で enqueue バッチを実行 |
| enqueueTournamentTask | `functions/.../services/tasks.ts` | 新 payload で Cloud Tasks に 1 件投入 |
| controlHook | `functions/src/shared/http/controlHook.ts` | タスク受領・no-op 判定・status 遷移・taskIndex 更新 |

## 4. 環境変数

### 4.1 必須（Cloud Tasks 投入・実行）

| 変数名 | 説明 | 用途 |
|--------|------|------|
| `CONTROL_HOOK_URL` | controlHook の HTTP エンドポイント URL | タスク実行時に呼び出す URL |
| `TASKS_QUEUE` | Cloud Tasks のキュー名 | タスク投入先 |
| `TASKS_LOCATION` | Cloud Tasks のリージョン | キュー配置先 |
| `TASKS_INVOKER_SA` | タスク実行用サービスアカウントのメール | OIDC トークン発行 |
| `PROJECT_ID` | GCP プロジェクト ID | キューパス構築（デフォルト: amuse-app-template） |

### 4.2 enqueue バッチの有効/無効

| 変数名 | 値 | 意味 |
|--------|-----|------|
| `ENQUEUE_SCHEDULER_ENABLED` | `true` | enqueue バッチを実行する（Scheduler・作成経路両方） |
| `ENQUEUE_SCHEDULER_ENABLED` | 未設定 / `false` | 即 return。タスク投入を行わない |

**重要**: Step 6（controlHook 新 payload 対応）デプロイ完了まで `ENQUEUE_SCHEDULER_ENABLED` は無効化すること。有効化手順は `step8.5/scheduler_enable_procedure.md` を参照。

## 5. Firestore データの更新（要点）

### 5.1 scheduledTournaments ドキュメント

| タイミング | 更新内容 |
|------------|----------|
| **新規作成時** | `schedulePlanVersion: 1`, `taskSyncNeeded: true`, `taskSyncReason: ['created']`, `schedulePlanUpdatedAt` |
| **編集時（startAt 変更）** | `schedulePlanVersion` インクリメント, `taskSyncNeeded: true`, `taskSyncReason: ['startAtChanged']` |
| **編集時（テンプレート/blindStructure 変更）** | `taskSyncNeeded: true`, `taskSyncReason: ['regEndAtChangedByTemplate']` |
| **編集時（cancelled のみ）** | `taskSyncNeeded: false` |
| **enqueue 完了時** | 全 taskType が enqueued/executed なら `taskSyncNeeded: false` |

### 5.2 taskIndex サブコレクション

**パス**: `scheduledTournaments/{tournamentId}/taskIndex/{taskType}`  
**taskType**: `startTournament`, `closeRegistration`

| タイミング | 更新内容 |
|------------|----------|
| **enqueue バッチ（突合後）** | 存在しない場合: `set`（planHash, enqueueState: pending 等）。planHash 不一致時: `update`（pending に戻す） |
| **Cloud Tasks 投入成功** | `enqueueState: 'enqueued'`, `taskName`, `lastEnqueuedAt` |
| **Cloud Tasks 投入失敗** | `enqueueState: 'failed'`, `error` |
| **controlHook 実行成功** | `enqueueState: 'executed'`, `lastRunAt`, `lastRunResult: 'success'` |
| **controlHook no-op** | `lastRunResult: 'noop'` |
| **controlHook エラー** | `failed`, `error` を記録 |

### 5.3 views/runtime（status 遷移）

| taskType | 実行時更新 |
|----------|------------|
| startTournament | `status: 'running'`, `startedAt` 設定 |
| closeRegistration | `status: 'registered'`, `registAt` 設定 |

## 6. 呼び出し経路

| 経路 | トリガー | 処理 |
|------|----------|------|
| **日次 Scheduler** | 毎日 5:00 JST | `runEnqueueTournamentTasks({})` を実行。全店舗対象 |
| **単発作成後** | createScheduledTournament 成功後 | `runEnqueueTournamentTasks({ storeId, tenantId })` |
| **定期作成後** | createTournamentRecurrence 成功後 | 同上 |
| **定期生成後** | generateRecurringTournaments 完了後 | 閾値以下: `runEnqueueTournamentTasks({ storeId })` 等。閾値超え: スキップ |
| **手動** | enqueueTournamentTasks Callable 呼び出し | `runEnqueueTournamentTasks()` |

---

## 7. 対象期間・クエリ条件

- **期間**: `now - lookbackHours` ～ `now + horizonDays`（デフォルト: 過去 6 時間 ～ 未来 14 日）
- **クエリ条件**: `status == 'scheduled'`, `startAt` が範囲内, `isArchived != true`（取得後にスキップ）, `taskSyncNeeded` が true または未設定
- **30 日制限**: `enqueueDueAt <= now + 30日` のタスクのみ Cloud Tasks に投入
