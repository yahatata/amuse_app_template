# リッチメニュー紐づけ不具合：原因分析と修正方針

## 現象

- **ensureStaffRichMenu**（Callable）ではリッチメニューが正しくリンクされる
- **lineWebhook**（follow/unblock）・**createStaffAccount**（スタッフ登録時）ではリンクされないユーザーがいる
- 例: `Ubd1dbd818a35314555ae3e9a958f78d7` → `GET /v2/bot/user/{userId}/richmenu` が `{"message":"the user has no richmenu"}`

---

## 想定される原因

### 1. lineWebhook が呼ばれていない

| 要因 | 内容 |
|------|------|
| Webhook URL 未設定 | LINE Developers Console の Messaging API で Webhook URL が正しく設定されていない |
| チャネル不一致 | デバッグしている LINE アカウントが、Webhook を設定したチャネルと異なる |
| 過去の友だち追加 | Webhook 設定前に友だち追加済みの場合、その時点の follow イベントは届かない |

**確認方法**: ブロック→解除した際に `firebase functions:log` で `Processing unblock event` や `linkUserRichMenu: Rich menu linked successfully` が出るか確認する。

### 2. createStaffAccount でのリンク失敗

| 要因 | 内容 |
|------|------|
| スタッフ登録の経路 | Admin 経由など LIFF 以外で作成した場合、`uid` が LINE User ID でない可能性 |
| エラー握りつぶし | `linkStaffRichMenu` 失敗時は `console.warn` のみでスタッフ登録は成功扱いになる |

**確認方法**: スタッフ登録直後に Cloud Functions ログで `linkStaffRichMenu: Rich menu linked successfully` または `linkStaffRichMenu: Failed` を確認する。

### 3. コードの二重化による経路の違い（修正済み）

**修正前**: lineWebhook が独自に `process.env.LINE_CHANNEL_ACCESS_TOKEN` と `defineString` を使い、lineRichMenu とは別経路で API を呼んでいた。

**修正後**: follow/unblock でも `linkStaffRichMenu` / `linkUserRichMenu`（lineRichMenu）を経由するように統一。ensureStaffRichMenu と同じトークン・リッチメニューIDの取得経路を使用する。

---

## 実施した修正（ensureStaffRichMenu に寄せる）

### 1. lineRichMenu.ts に `linkUserRichMenu` を追加

- `linkStaffRichMenu` と同様の構造でユーザー用リッチメニューをリンク
- `LINE_CHANNEL_ACCESS_TOKEN`, `USER_RICHMENU_ID` は lineRichMenu 内で参照

### 2. lineWebhook.ts の follow/unblock を lineRichMenu に統一

- **修正前**: 自前で `fetch` し、`staffRichMenuId` / `userRichMenuId` を直接使用
- **修正後**: `linkStaffRichMenu`, `linkUserRichMenu` を呼び出すのみ

→ トークン・リッチメニューIDはすべて lineRichMenu 経由で統一。

### 3. createStaffAccount.ts

- もともと `linkStaffRichMenu` を使用しているため変更なし
- ensureStaffRichMenu と同一の lineRichMenu 経由でリンク

---

## デプロイ後の確認手順

1. **lineWebhook の動作確認**
   - LINE で友だちをブロック→解除
   - `firebase functions:log` で `linkUserRichMenu: Rich menu linked successfully` を確認

2. **createStaffAccount の動作確認**
   - 新規スタッフ登録
   - ログで `linkStaffRichMenu: Rich menu linked successfully` を確認

3. **既存ユーザー（リッチメニュー未リンク）の対応**
   - ユーザーLIFF で `ensureStaffRichMenu` を呼ぶ（現状は checkStoreRegistration から削除済みの場合、必要に応じて復活させる）
   - または手動で `curl -X POST "https://api.line.me/v2/bot/user/{userId}/richmenu/{richMenuId}"` を実行
