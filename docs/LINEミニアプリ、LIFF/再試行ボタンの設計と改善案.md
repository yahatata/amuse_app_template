# 再試行ボタンの設計と改善案

## 1. 問題の整理

### 1.1 前提

- **遅い/ハングする箇所**：`getFirebaseCustomToken` → `signInWithCustomToken` あたり
- **再試行の目的**：signOut で状態をリセットし、reload で一からやり直す
- **現状**：再試行ボタンを押しても「表示が続くだけ」で動かない
- **推測**：`await auth.signOut()` がハングし、`location.reload()` に到達していない

### 1.2 制約

- signOut を待ち続けると、認証が壊れた状態では戻ってこない
- signOut + reload を「短時間で必ず完了」させる必要がある
- LINE を閉じて開き直しても表示できないことがある → 原因はクライアント側だけとは限らない

---

## 2. 方針：「signOut にブロックさせない」

### 2.1 考え方

- signOut は「可能なら実行する」が、**reload を止めてはいけない**
- signOut がハングしても、一定時間で打ち切り、強制的に reload する

### 2.2 具体案：signOut にタイムアウトを設ける

```javascript
// 再試行時の処理
() => {
  const doReload = () => location.reload();
  const auth = window.Firebase?.auth;
  if (auth) {
    const signOutWithTimeout = Promise.race([
      auth.signOut(),
      new Promise((r) => setTimeout(r, 2000))  // 最大2秒で打ち切り
    ]);
    signOutWithTimeout.then(doReload).catch(doReload);
  } else {
    doReload();
  }
}
```

- signOut が 2 秒以内に完了 → その直後に reload
- signOut が 2 秒経っても完了しない → その時点で reload
- auth がない場合 → すぐ reload

→ **最長でも 2 秒で reload まで到達する**。

### 2.3 代替案：signOut を待たず即 reload

```javascript
() => {
  if (window.Firebase?.auth) {
    window.Firebase.auth.signOut().catch(() => {});  // fire-and-forget
  }
  location.reload();
}
```

- メリット：ほぼ即時に reload
- デメリット：signOut が完了する前に reload するため、次回ロード時の Firebase Auth の状態が不透明な可能性

→ まずは **2 秒タイムアウト案** を推奨。

---

## 3. 遅さの原因を把握する（検証が難しい場合）

### 3.1 考えられる要因

| 候補 | 性質 | signOut + reload で効くか |
|------|------|--------------------------|
| signInWithCustomToken のハング | クライアント側 Firebase | ○ 新しいページでやり直せる |
| getFirebaseCustomToken の遅延/失敗 | サーバー・ネットワーク | △ 再試行で一時的な回復の可能性 |
| liff.init / getIDToken の遅延 | LINE SDK・ネットワーク | △ 同様 |
| LINE WebView の状態異常 | LINE 側 | × アプリを閉じないとリセットされにくい |

### 3.2 検証が難しい場合の対応

- **既存デバッグログ**：`2h`, `2i`, `2j`, `2k` の時間差で、遅いステップを特定できる
- **稀な事象への対応**：再試行ボタンが確実に動くようにする（上記タイムアウト案）ことが最優先
- 原因究明は、発生時のログ取得・共有を前提に、後から深掘りする形が現実的

---

## 4. 実施する改善

1. **再試行コールバックの修正**
   - signOut に 2 秒程度のタイムアウトを設け、その後に必ず reload
   - `showErrorWithRetry` と `loading-retry-container` の両方に適用

2. **User / Staff 両方で統一**
   - 同じロジックで共通化する

---

## 5. 補足：LINE を閉じても直らない場合

- ネットワークやサーバー側の遅延・エラーが原因のときは、reload をしても同じ状況になり得る
- その場合は signOut + reload では解決しづらく、ネットワーク・Cloud Functions 側の改善が前提になる
- 一方で、signOut がハングして reload されない状態は、再試行のチャンスすらなくなるため、まずは **再試行ボタンが必ず動く** ようにすることが重要
