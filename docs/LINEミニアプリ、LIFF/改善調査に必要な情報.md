# 改善調査に必要な情報

以下の2つの改善を行うために収集・確認すべき情報をまとめます。

---

## 改善1: リッチメニューからLIFFを開いたときの描画・読み込み

### 症状

- リッチメニューの項目をタップしてLIFFを開くとき、描画できないケースがある
- 読み込みに時間がかかりすぎるケースがある
- 両方とも基本的にくるくる（ローディングスピナー）は回っている

### 調査に必要な情報

#### デバッグモード有効時

1. **処理ログのタイムスタンプ**
   - 各ステップ間の所要時間（例: `2b. liff.init実行中` ～ `2c. liff.init完了` が何秒か）
   - どのステップで時間がかかっているか

2. **最後に表示されたログ**
   - 描画できない場合、どこまで進んだか（最後のログ番号）
   - ログが途中で止まっている場合、どのステップで止まったか

3. **発生条件**
   - ユーザーLIFF / スタッフLIFF のどちらで発生するか
   - 初回表示時のみか、2回目以降もか
   - キャッシュを消した後か、通常時か
   - 回線（Wi-Fi / 4G / 5G）の違い

#### 技術的確認

| 項目 | 確認方法 |
|------|----------|
| liff.init の所要時間 | デバッグログの 2b→2c の間隔 |
| getFirebaseCustomToken の所要時間 | デバッグログの 2h→2i の間隔 |
| Firestore 読み込みの所要時間 | checkStoreRegistration / checkStaffRegistration の前後の間隔 |
| loadLinePlanFromFirestore の影響（スタッフのみ） | 2b→2c の間隔（Firestore storeMeta/config 読み込み） |

---

## 改善2: リッチメニューがスタッフ用に切り替わらない

### 症状

- 元々ユーザーとして登録していたアカウントでスタッフ登録を完了しても、リッチメニューがユーザー用のまま
- スタッフ登録時、メニューを開いたとき、ブロック解除後でも切り替わらない
- 現状、どのタイミングでも切り替えられていない

### 現在の実装（切り替えタイミング）

| タイミング | 実装箇所 | 内容 |
|------------|----------|------|
| **follow / unblock** | `lineWebhook.ts` | 友だち追加・ブロック解除時に staffs を参照し、スタッフならスタッフ用、そうでなければユーザー用リッチメニューを設定 |
| **スタッフ登録完了時** | `createStaffAccount.ts` | 登録成功後に `linkStaffRichMenu(uid)` を呼び出し |
| **ユーザーLIFF起動時（スタッフ＋ユーザー登録済み）** | `public/user/index.html` の checkStoreRegistration | users と staffs の両方に存在する場合、`ensureStaffRichMenu` を fire-and-forget で呼び出し |

### 調査に必要な情報

#### 1. ensureStaffRichMenu の呼び出し結果

デバッグモード有効時、ユーザーLIFFで「4b. スタッフ登録あり→ensureStaffRichMenu呼び出し」の後に:

- **4c. ensureStaffRichMenu結果: {"success":true,"updated":true,"reason":"rich_menu_linked"}** → API呼び出しは成功
- **4c-ERR. ensureStaffRichMenu失敗: ...** → クライアント側でエラー
- 4c も 4c-ERR も出ない → ensureStaffRichMenu が呼ばれていない、または処理が完了していない可能性

#### 2. Cloud Functions ログ

```bash
firebase functions:log
```

以下を確認:

- `linkStaffRichMenu: Rich menu linked successfully` が出力されているか
- `linkStaffRichMenu: Failed to link rich menu` や `linkStaffRichMenu: Error` が出ていないか
- `ensureStaffRichMenu` 実行時のスタックトレースやエラー内容

#### 3. LINE API の仕様・制限

- Per-user リッチメニューは、ユーザーがすでにデフォルトリッチメニューを使っている場合の挙動
- LINE Developers Console の該当チャネルで、デフォルトリッチメニューと Per-user リッチメニューの優先度
- LINE公式: [リッチメニュー - Per-user リッチメニュー](https://developers.line.biz/ja/docs/messaging-api/using-rich-menus/)

#### 4. 確認したい事実

- 対象アカウントの `staffs/{uid}` が Firestore に存在するか
- 対象アカウントの LINE User ID と Firebase UID が同一か（LIFFでは通常同一）
- `linkStaffRichMenu` に渡している `lineUserId` が正しいか
- `STAFF_RICHMENU_ID` 環境変数が設定されているか
- スタッフ用リッチメニューが LINE Developers 上で「アクティブ」になっているか

---

## デバッグモードの有効化

両LIFFでデバッグ表示を有効にするには:

- スタッフ: `public/staff/config.js` の `DEBUG_SHOW_LIFF_PROCESS: true`
- ユーザー: `public/user/config.js` の `DEBUG_SHOW_LIFF_PROCESS: true`

変更後、`firebase deploy --only hosting` でデプロイしてください。
