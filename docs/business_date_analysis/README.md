# 営業日判定要件分析

## 概要

このドキュメントは、プロジェクト内で使用されている日付データについて、営業日判定が必要かどうかを分析したものです。

営業日は日を跨ぐ可能性があるため（例：20:00~28:00）、単純なカレンダー日付ではなく、日時から営業日を判定する必要がある場合と、そうでない場合を明確に分類しています。

## 判定基準

### 営業日判定が必要なケース

以下のいずれかに該当する場合、営業日判定が必要です：

1. **日時から営業日を計算してドキュメントを参照/格納する場合**
   - 例：`calcBusinessDate(now)`で営業日を計算してクエリフィルタに使用
   - 例：伝票作成時に営業日を計算して`businessDate`フィールドに格納

2. **営業日を跨ぐ可能性があるデータを扱う場合**
   - 例：伝票（bills）、注文（orders）、会計履歴（accountingHistory）など

3. **営業日ベースの集計・分析を行う場合**
   - 例：analyticsMonthly、日次集計など

### 営業日判定が不要なケース

以下のいずれかに該当する場合、営業日判定は不要です：

1. **単純なカレンダー日付で十分な場合**
   - 例：出勤記録（attendances）、シフト管理（shiftRequests）など
   - 例：トーナメントスケジュール（scheduledTournaments）の日付範囲フィルタ

2. **既に営業日が確定しているデータを参照するだけの場合**
   - 例：既存の`bill.businessDate`を読み取って使用する場合

3. **タイムスタンプとして記録するだけで、営業日判定が不要な場合**
   - 例：`createdAt`、`updatedAt`などのメタデータ
   - 例：出退勤時刻（`clockIn`、`clockOut`）

4. **営業日とは無関係な日時計算の場合**
   - 例：TTL期限（`expiresAt`）、翌月の日時計算など
