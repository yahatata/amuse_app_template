# 仕様整理

## ほぼ確定でよい仕様

### 1. 壊れた旧 task は救済より削除優先

既存復旧 docs の方針どおり、payload 不正の古い task は再利用より削除優先で考えるのが安全です。

### 2. region は `asia-northeast1` に寄せる

現行コードの queue / function 解決も `asia-northeast1` 前提が中心です。  
ここは今後の運用資料でも統一した方がわかりやすいです。

### 3. SA 名は統一方針を持つべき

`tasks-invoker` 系へ寄せる方針は、そのまま維持するのが自然です。

## ユーザー判断が必要な仕様

### 1. 既存 task の掃除方針

選択肢:

1. malformed task のみ削除
2. 同型失敗 task をまとめて削除
3. queue ごと大掃除

おすすめは 1 です。  
必要 task の誤削除リスクを抑えやすいためです。

### 2. `default-store` 橋渡しの残し方

選択肢:

1. 当面は補完ロジックでしのぐ
2. 早めに完全排除する

復旧優先なら 1、長期整理優先なら 2 です。  
この判断は scheduler / task producer 全体へ影響します。

### 3. queue の整理単位

選択肢:

1. ドメインごとに現状維持
2. scheduled-job 系をさらに集約
3. ドメインごとに明確に分離し直す

今すぐは 1 を維持し、動作確認を優先する方が安全です。
