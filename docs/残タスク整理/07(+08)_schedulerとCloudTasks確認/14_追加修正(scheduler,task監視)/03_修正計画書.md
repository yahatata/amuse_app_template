## 1. 進め方の原則

### 1.1 壊さず効率的に進める

| 原則 | 内容 |
|------|------|
| **Phase 順守** | Phase 0（Config）→ A（Scheduler UI）→ B（Task 定期）の順。後続 Phase は前 Phase デプロイ後に着手 |
| **既存関数再利用** | `buildSchedulerRunSummaries` / `buildSchedulerChildTaskSummaries` を拡張・呼び出し変更中心。全面書き換えしない |
| **並走可能な分離** | Phase 0（同期 endpoint + 設定 UI）と Phase A の **集計ロジック単体テスト** は doc 確定後に並行可能 |
| **店舗 Functions は触らない** | 本タスクの必須スコープ外。R-4（start ログ改善）は Phase G 任意 |
| **1 PR / 1 Phase 推奨** | レビュー・ロールバック容易。Phase 0 は Functions を含み、Phase A〜C は Hosting 中心で完結 |

### 1.2 デプロイ単位

| Phase | デプロイ先 | 内容 |
|-------|-----------|------|
| 0 | amuse-admin Hosting + firestore.rules + Functions | Config 同期 |
| A | amuse-admin Hosting | Scheduler UI |
| B | amuse-admin Hosting | Task 定期 UI |
| C | amuse-admin Hosting | Task 都度 UI |
| D | 両 repo docs のみ | 運用資料 |
| E | amuse-admin Functions（detectSchedulerAnomalies）| 任意・後回し可 |
