# 目的: Scheduler / Task 監視 追加修正

作成日: 2026-06-04  
更新: Phase 7 運用確認・ToBe レビュー合意後

---

## 1. 背景

2026-06-04 の Phase 7 確認（[13_Phase7_実施結果.md](../13_Phase7_実施結果.md)）および同日の supervisor / task 実行分析で、次が判明した。

| 問題 | 影響 |
|------|------|
| supervisor 1 回で job あたり **複数 dispatch** があるのに、UI は **最新 1 slot** のみ表示 | 03:00 の「skip 多数 + 新規少数」が見えない |
| dispatch skip 時に execution が「対象外」になり、当日の本処理完了が Scheduler 行に出ない | 「全部予約不要・正常」と誤読 |
| open/close 等 **毎日動く handler** が Scheduler 6 行だけでは追いにくい | 責務混在 |
| 区分 C（horizon 内の非試行 slot）が UI に無い | supervisor の試行範囲が判断できない |

店舗側の定期実行ロジック（supervisor / handler）は **6/4 時点で技術 PASS** である。  
本タスクは **中央管理アプリ（`amuse-admin`）の監視 UI と付随インフラ** の修正が主目的である。

---

## 2. やること（要約）

1. **Scheduler 監視** を「当日 supervisor のタスク生成（dispatch）専用」に再定義する
2. **Task 監視** を「定期実行系 / 都度実行系」に分離し、キュー × 期間で実行を見る
3. **店舗 Config 中央同期**（schedulerConfig 等）を実装し、区分 C とキュー説明の基盤とする
4. 運用資料（正常系定義・期待状態一覧 §10 等）を ToBe に合わせて更新する

## 3. 完了の定義

以下をすべて満たした時点で本タスクを完了とする。

### 3.1 機能

- [ ] Scheduler 監視: `planningDate=当日` × 6 job について、新規 / 重複 skip / その他 skip / エラーの **サマリ** と **A/B/C 展開** が表示される
