# 目的

## 背景

- 日次運用の中心は `schedulerSupervisor`（毎日 03:00 JST）が `storeMeta/schedulerConfig` を読み、各 scheduled job を Task Queue / Cloud Tasks へ投入する構成である
- 2026-04-07 の復旧作業（`docs/タスク実行復旧_20260407/`）で、手動投入・限定デプロイは PASS したが、**その後の定期運用（supervisor 経由の自動 enqueue → 各 job 完了）** の継続確認は残っている
- Cloud Tasks まわりには、旧 region・旧 queue・旧 producer 経路が残っている可能性がある
- GCP未実行検知用の `logOpsInfo(start)` は 11 handler に導入済みだが、scheduler 層ログとの役割分担や、未対応 handler の統一が未整理

## 何のためにやるか

本番店舗運用で、次を説明・確認・復旧できる状態にする。

1. 今日の scheduled job が **意図どおり enqueue され、完了した**
2. 使っている queue は **必要なものだけ** で、重複・旧版がない
3. 止まった・失敗したとき **どの層を見ればよいか** が決まっている
4. 今後追加する scheduler / task 経路も **同じ方針** で実装できる

## スコープ

### 含む

- Cloud Scheduler（`schedulerSupervisor` 入口）
- `storeMeta/schedulerConfig` とコード上 `jobKey` の整合
- scheduled-job 系 Task Queue（6 job）
- HTTP Cloud Tasks（`tournament-queue`, `business-date-assessment-queue`）
- Firebase Task Queue（給与計算・給与通知）
- queue / scheduler / task 経路の **不要・重複・旧版** の洗い出しと整理
- ログ 3 層の整理、未実行・失敗の検知方針、`.cursor/rules` 更新

### 含まない（別タスク）

- 給与通知の **業務採用・簡略化・見送り** → `12_給与確認タスクキュー方針`
- Cloud Monitoring アラートの具体設定（ポリシー JSON・通知チャネル）→ 本タスクでは方針と Logs Explorer クエリ草案まで
- `default-store` 文字列の完全排除 → 段階移行継続（09 / 環境変数きれい化と連携）

## 完了の定義（合意済み）

次をすべて満たすこと。

### 1. job 完了まで確認できている

`schedulerConfig.jobs` で **enabled: true** の各 job について、代表 run で次の連鎖が取れる。

```
schedulerSupervisor 実行
  → schedulerDispatchLogs に enqueued（または skip の理由が説明可能）
    → handler の logOpsInfo(start)
      → logOpsSuccess または仕様どおりの skip（execution log の completed / skip）
```

supervisor の成功のみ、enqueue のみでは **完了とみなさない**。

### 2. 期待状態一覧と実環境が突合済み

[04_期待状態一覧.md](./04_期待状態一覧.md) の queue / job / producer-consumer が、実 GCP と一致している。  
不要・重複・旧版について **削除または parked 理由** が記録されている。

### 3. ログと検知方針が文書化されている

[06_ログと検知方針.md](./06_ログと検知方針.md) に、3 層ログ・相関キー・日次確認の見方が書かれている。

### 4. ルールが更新されている

scheduler / Cloud Tasks 新規追加時に参照する `.cursor/rules` が、本タスクの方針を反映している。

## きれい化の考え方（合意済み）

削除・整理の主軸は次の 3 点とする（「壊れているから消す」は副次的）。

| 優先 | 対象 | 例 |
|------|------|-----|
| 1 | **不要** | コードから参照されない queue、旧 region の残骸 |
| 2 | **重複** | 同じ仕事をする queue / scheduler が 2 本ある |
| 3 | **旧版** | `schedulerSupervisor` 方式に置き換わった旧 onSchedule 経路 |

削除前は対象 ID 一覧を保存する（queue / task 削除は復元不可）。
