## このアプリの目的

このリポジトリは、店舗運営をまとめて扱う Flutter + Firebase アプリです。現状のコードと docs から見ると、主な責務は次の通りです。

- デバイス単位で権限を分けながら、店舗オペレーションを回す
- お客様の入退店、注文、トーナメント、サイドゲーム、会計を一連で扱う
- スタッフ勤怠、シフト、給与確認、運営ダッシュボードを支える
- 店舗設定、営業時間、スケジューラー、Cloud Tasks を通じて日次運用を自動化する

つまり「単なる会計アプリ」でも「単なるトーナメントアプリ」でもなく、店舗運営の実務全体を 1 つの運用基盤にまとめることがこのアプリの目的です。  
そのため残タスクも、単体機能の不足だけでなく、運用整合・権限制御・自動化・本番品質の観点を一緒に見る必要があります。

## 全体所見

- 会計後調整まわりは、仕様書とコードとテストがかなり進んでいます。ただし「税務・会計上どこまで正式データとして残すか」は未確定です。
- `table device`、スタッフ退職処理は、設計途中または未着手に近く、まだ「何を作るか」を固める段階です。
- `scheduler` / `Cloud Tasks` / 給与通知は、仕組み自体はありますが、「本番で安心して任せられる」と言い切るには再検証が必要です。
- `config`、HOME UI、不要 function 整理は、機能追加というより「本番運用に耐える構造へ整える」系のタスクです。
- docs には現行コードより古い記述もあります。ここでは、可能な限り現行コードと現在残っている docs の両方を照合して整理しています。

## 優先順位の考え方

おすすめの進め方は次の順です。

1. 本番事故に直結しやすいものを先に固める  
   `01`, `05`, `06`, `07`, `08`
2. 本番導入判断に必要なものを次に固める  
   `11`, `12`, `10`
3. 新機能・未着手系を設計する  
   `03`, `04`
4. 仕上げとして整理する  
   `02`, `09`
