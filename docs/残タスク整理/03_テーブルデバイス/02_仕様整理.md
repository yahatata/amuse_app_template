# 仕様整理

## このファイルの役割

仕様そのものの最終判断は `tobe_spec` を優先します。

## 確定仕様

### 1. `tableDevice` は独立 role とする

`terminal` の一部として扱うのではなく、`role: table` を追加して専用ルート・専用 Home を持たせる。

### 2. 利用者は顧客ではなく店舗従業員

目的は強い秘匿ではなく、卓運用に不要な操作や誤操作を減らすこと。

### 3. 卓と端末の紐づけは `devices.optionParams` に持つ

- `optionParams.table_device_table.tableId` を使用する
- 同一卓に複数の `tableDevice` を紐づけてよい
- `tableId` 未設定時は、admin 対応を促す固定メッセージを表示する

### 4. 卓状態の単一参照先は `tables/{tableId}`

- `tournamentDetail` を追加して、卓デバイスの遷移判断に使う
- `tournamentDetail` は「トーナメント登録を保持している間」残る
- サイドゲーム中でも、トーナメント登録を保持しているなら `tournamentDetail` を残してよい

### 5. サイドゲーム時の `tables.status` はゲーム名を使う

- 固定値 `sideGame` は使わない
- `tables.status` は `storeMeta/config.sideGameTypes` に含まれるゲーム名を持つ
- `sideGame.active == true` と組み合わせて進行中判定する

### 6. 有効化設定と強制クリアパスコードは `storeMeta/config`

- `features.tableDeviceRegistrationEnabled` を使う
- `tableDevice.forceClearPasscode` を使う
- `forceClearPasscode` は高い秘匿性ではなく、誤操作防止用途として扱う

### 7. デバイス登録画面でも `role: table` を選べる

`device_registration_page.dart` で `table` を選択可能にし、登録直後から table 用ルーティングへ入れる前提。

### 8. callable の権限は `table` と `admin`

通常利用は `table` ロールだが、保守・検証用途として `admin` も許容する。

## 実装で特に注意する点

### 1. `tournamentDetail` は「単なる補助情報」ではない

卓デバイス Home で `tables/{tableId}` を単一参照先にするための中核データであり、終了・解除・sideGame 開始/終了時に整合を崩さないことが重要。

### 2. sideGame の保存先を揃える

開始時に:

- `tables.status = gameName`
- `sideGame.gameName = gameName`
- `sideGame.active = true`

を揃える前提で実装する必要がある。

### 3. 論理削除対応は 1 画面だけでは終わらない

- `removeTableFromTournament`
- `TableSelectPage`
- `TournamentSelectPage`
- `RemoveTableDialog`

の複数箇所で `isEnabled` を見る必要がある。

### 4. 卓デバイス版 sideGame 画面は管理版のコピーで終わらない

管理版に残っているデバッグ用 UI は除去する必要がある。

### 5. `role: table` 時の options 運用を崩さない

`table` ロールでは、実質 `table_device_table` だけを使う前提に寄せる。`terminal` 向け options を混在させない方が安全。
