# 仕様整理

## ほぼ確定でよい仕様

### 1. 専用の制限 UI を持たせる方が自然

現行アプリの terminal HOME は機能が多すぎるため、卓端末を単なる terminal の一種として出すより、専用 HOME を持たせた方が安全です。

### 2. 端末と卓の紐づけ情報は device 側に持つのが自然

既存 spec どおり `devices.optionParams` に `tableId` を持たせる設計は整合的です。  
卓詳細側に「どの端末か」を逆保持するより、端末設定として持つ方が扱いやすいです。

### 3. 卓端末の役割は最小権限に寄せるべき

卓端末は、店舗管理や全体会計ではなく「自卓に関する操作」へ絞るのが自然です。

## ユーザー判断が必要な仕様

### 1. role を分けるか

選択肢:

1. **`table` を独立 role にする**
2. **`terminal` のまま option だけで絞る**

おすすめは 1 です。  
理由は、HOME 表示、権限制御、端末管理画面、今後の監査ログの説明が一気にわかりやすくなるためです。

### 2. 有効化方式

選択肢:

1. `storeMeta/config` の runtime flag で有効化する
2. build-time の `--dart-define` 前提で有効化する

おすすめは 1 です。  
店舗差分や段階導入を考えると runtime の方が運用しやすいです。

### 3. 卓端末が扱う業務範囲

候補:

1. トーナメント卓のみ
2. サイドゲーム卓のみ
3. 両方対応

この判断は、現場オペレーションと誤操作許容度で決めるのがよいです。  
両方対応は便利ですが、画面設計と権限制御は複雑になります。
