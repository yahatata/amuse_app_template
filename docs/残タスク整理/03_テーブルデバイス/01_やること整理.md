# やること整理

## 仕様として確定済みの事項

- ✅ `tableDevice` は店舗従業員（ディーラー）が操作する卓専用端末として扱う
- ✅ `role: table` を独立 role とする
- ✅ 卓状態の単一参照先は `tables/{tableId}` とし、`tournamentDetail` を追加する
- ✅ サイドゲーム時の `tables.status` は固定値 `sideGame` ではなく、`sideGameTypes` に含まれる**ゲーム名**を使う
- ✅ `tableDevice` はデバイス登録画面でも登録可能にする
- ✅ 同一卓に複数の `tableDevice` を紐付けてよい
- ✅ `tableId` 未設定の `table` 端末は、管理者対応を促す専用メッセージを表示する
- ✅ `tableDeviceRegistrationEnabled` と `forceClearPasscode` は `storeMeta/config` で扱う

## これから行う必須実装タスク

1. `role: table` 追加に伴う Flutter / Functions / デバイス登録フローの実装
2. `devices.optionParams.table_device_table` を使った卓紐付け UI と取得処理の実装
3. `tables.tournamentDetail` 追加と、既存 tournament callable の更新
4. `scheduledTournaments/{id}/tablesSeat/{tableId}.isEnabled` を使った論理削除対応
5. `TableDedicatedHomePage` / `TableDeviceDrawer` の実装
6. `TableDeviceTableDetailPage` / `TableDeviceSideGamePage` の実装
7. `registerTableToTournament` / `unregisterTableFromTournament` の実装
8. `registerTableToSideGame` / `unregisterTableFromSideGame` の実装
9. `storeMeta/config.features.tableDeviceRegistrationEnabled` と `tableDevice.forceClearPasscode` のスキーマ・defaults・Flutter 読み取り実装
10. Firestore rules / 権限制御 / 運用導線の確認

## 実装時に見落としやすいタスク

- `TournamentSelectPage` の device 卓絞り込みで `tablesSeat` の**存在だけでなく `isEnabled == true`** を見る
- `TableSelectPage` / `RemoveTableDialog` で論理削除済み卓を非表示にする
- サイドゲーム開始時に `tables.status = gameName` と `sideGame.gameName = gameName` を揃える
- サイドゲーム終了時に `tournamentDetail` の有無で `status` を `tournament` / `open` に戻し分ける
- 卓デバイス版 sideGame 画面では、管理版にあるデバッグ用 UI を除外する
- `role: table` のとき `options` を実質空運用に寄せる
- `forceClearPasscode` の取得失敗時フォールバックと運用資料更新を忘れない

## 以前は未確定だったが、いまは確定済みの事項

- **未紐づけ卓端末の扱い**  
  固定メッセージを表示し、admin デバイスで紐付けまたは role 変更を促す
- **トーナメントとサイドゲームの同居方針**  
  トーナメント登録を保持したままサイドゲームへ移行できる。終了後は `tournamentDetail` に基づいてトーナメントへ戻る
- **有効化方式**  
  build-time ではなく `storeMeta/config` の runtime 設定を使う
- **複数端末許容**  
  同一卓への複数 `tableDevice` 紐付けを許容する

## 完了の定義

- `role / option / tableId / config` の扱いがコードに反映されている
- 登録から運用までの画面遷移が実装されている
- 卓端末が何をしてよくて何ができないかが UI と callable の両方で制御されている
- `tables` / `tablesSeat` / `sideGame` の状態遷移が仕様どおりに揃っている
- テスト計画と実機確認計画を含む実装計画ファイルが作成されている
