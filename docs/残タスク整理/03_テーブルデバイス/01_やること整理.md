# やること整理

## 必須タスク

1. `table device` の役割を正式に定義する
2. device role / option / tableId 紐づけのデータモデルを確定する
3. Flutter 側の専用ルート・専用 HOME・専用詳細画面を設計する
4. Functions 側の卓操作 callables を設計する
5. 端末登録・管理 UI で卓紐づけを扱えるようにする
6. Firestore rules / 権限制御 / 運用導線を確認する

## ユーザーが未記載だが必要なタスク

- **未紐づけ卓端末の扱い**  
  卓が未設定の端末で何を見せるかを決める必要があります。
- **卓変更時の再設定フロー**  
  一度紐づけた端末を別卓へ移す運用が発生します。
- **トーナメントとサイドゲームの同居方針**  
  同じ卓端末で両方を扱えるのか、排他にするのかを決める必要があります。
- **端末盗難・誤操作時の防御**  
  kiosk 的に使うなら、戻る導線や設定遷移の制御も必要です。

## 完了の定義

- role / option / tableId の扱いが決まっている
- 登録から運用までの画面遷移が決まっている
- 卓端末が何をしてよくて何ができないかが明確
- 実装フェーズへ渡せる粒度の spec になっている
