# LIFFトーナメント参加導線

## このタスクの要点

現状の LIFF からのトーナメント参加は、「入店中で bill を持っていること」を暗黙前提にしています。  
そのため、入店前ユーザーも同じ導線で扱いたいなら、今の参加処理とは別の概念を導入する必要があります。

## 現状整理

- LIFF ホームでは `getUserStatus` を使って、入店中でない場合は注文・トーナメントボタンを非表示にしています。
- ただし `showTournamentRegistration` は、注文系のように事前 `getUserStatus` を再確認せず、直接 `registerForTournament` を呼んでいます。
- `registerForTournament` は `activeStays/{userId}` を読み、そこから `billId` を取って `recordTournamentAction` まで進みます。

## いま言える状態評価

- 現行仕様: 入店中ユーザー向けとしては一応整合している
- 未解決点: 入店前参加を認めたいなら、今のフローのままでは危険
- 本質: 「参加」と「予約」を分ける必要があるかどうか

## このタスクの本質

このタスクは、UI 文言の古さだけではありません。  
根本は次の問いです。

- LIFF での操作は「参加登録」なのか
- それとも「参加意思の表明」や「予約」なのか

ここが曖昧だと、課金タイミング、no-show 対応、定員管理が全部ぶれます。
