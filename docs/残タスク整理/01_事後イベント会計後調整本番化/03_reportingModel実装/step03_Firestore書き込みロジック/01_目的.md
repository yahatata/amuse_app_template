## 実装する関数の一覧

### `entryWriter.ts`

```typescript
// reportingEntries/{entryId} に書き込む
// entryId が既に存在する場合は何もしない（冪等性）
writeReportingEntry(
  db: Firestore,
  entry: ReportingEntry
): Promise<{ written: boolean }>
```

**冪等性の担保方法:**  
`reportingEntries/{entryId}` を `create`（存在する場合は失敗）で書く。  
すでに存在する場合は `written: false` を返してスキップ。  
これにより `aggregationMarkers` なしで二重書き込みを防ぐ。

### `monthlyUpdater.ts`

```typescript
// reportingMonthly/{monthKey} を incrementally 更新する
// aggregationMarkers で冪等性を保証
applyEntryToReportingMonthly(
  db: Firestore,
  entry: ReportingEntry
): Promise<void>
```

**`aggregationMarkers` のキー形式:**  
`reportingMonthly/{monthKey}/aggregationMarkers/entries_{entryId}`

**更新フィールド:**  
`totalAmountIncl` / `categoryBreakdown.{key}.amountIncl` / `paymentMethodBreakdown.{key}` / `categoryPaymentMatrix.{key}` を `FieldValue.increment` で更新。

## テスト方針

### AI が実行するテスト（Firestore mock 使用）

**`entryWriter` のテスト**

| ケース | 確認内容 |
|---|---|
| 新規エントリ | `reportingEntries/{entryId}` に正しいデータが書き込まれるか |
| 同一 `entryId` で2回呼ぶ | 2回目は `written: false` が返り、Firestore への書き込みが発生しないか |

**`monthlyUpdater` のテスト**

| ケース | 確認内容 |
|---|---|
| 新規エントリ（monthly doc なし） | `reportingMonthly/{monthKey}` が初期化されて作成されるか |
| 既存 monthly doc への加算 | `FieldValue.increment` で正しく加算されるか |
| `aggregationMarkers` が存在するとき | 処理がスキップされ、monthly doc が変化しないか（二重計上を防ぐ） |
| `aggregationMarkers` が存在しないとき | マーカーが作成されてから monthly doc が更新されるか |
| 負値エントリ（rollback） | `FieldValue.increment` で減算されるか |

### 実機確認（このステップでは不要）

Firestore mock のテストのみで十分。  
実 Firestore への書き込みは Step 04 以降の統合テストで確認する。
