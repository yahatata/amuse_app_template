# reportingModel 実装ステップ概要

## 実装の全体方針

- **新規ドメイン（`functions/src/domains/reporting/`）を先に完成させてから既存コードに組み込む**
- 既存の `analytics` ドメインのパターンを最大限踏襲する
- feature flag（`reportingAggregatorEnabled`）で ON/OFF 制御し、既存動作に影響を与えない
- 各ステップは「型チェック → ユニットテスト → 一貫性確認 → 申し送り」のサイクルで完結させる

## 参照先（全ステップ共通）

- **確定版仕様書**: `03_reportingModel実装/01_確定版仕様書.md`
- **設計DRAFT**: `02_税務readModel設計検討/DRAFT_設計検討メモ.md`（参考・アーカイブ）

## ステップ分割の考え方

### フェーズ A: 新規ドメイン（Step 01〜03）

Firestore に触らない純粋なロジックから始め、段階的に Firestore 書き込みを追加する。  
この3ステップはすべてユニットテスト可能で、既存コードに影響を与えない。  
Step 01 → 02 → 03 は依存関係があるため順番に実施する。

### フェーズ B: 既存コードへの統合（Step 04〜07）

最も影響範囲が大きい `billsOnSettle`（Step 04）を最初に単独で統合し、実機確認を経てから残り3つを連続実施する。  
Step 05〜07 は同一パターンの繰り返しなので、1セッションで3つまとめて実施可能。

### フェーズ C: 仕上げ（Step 08〜09）

管理ツールと本番準備。コアロジックがすべて確認済みの状態で行う。
