# Step 02: entryBuilder（エントリ shape 構築）

## このステップの目的

会計イベントのデータを受け取り、`ReportingEntry` の shape を返す**純粋関数群**を実装する。  
Firestore に触れないため、ユニットテストが完全に書けるステップ。  
ここで `categoryPaymentMatrix` の構築ロジックが正しいかを検証する。

---

## 進め方

### 事前確認（このステップ開始時に必ず読む）

1. `03_reportingModel実装/01_確定版仕様書.md`（セクション 6 を中心に）
2. **直前ステップの申し送り**: `step01_型定義と設定/04_作業履歴と申し送り.md`
3. 既存コードの参照（`paymentMethodsByCategory` のデータ形式を把握するため必須）:
   - `functions/src/domains/bills/callables/accounting.ts`（`normalizePaymentMethods` 関数。データが `string` 型と `Array` 型の2パターンあることを確認）
   - `functions/src/domains/bills/repos/createPostSettlementAdjustment.ts`（adjustment の `lines` の shape）

1. `changeSpec.md` と `テスト仕様.md` を作成する（実装前）

5. あなたがテスト結果と主要な変換ロジックをレビューする

## テスト方針

### AI が実行するテスト（必須ケース）

**`buildSettleEntry` のテスト**

| ケース | 確認内容 |
|---|---|
| `paymentMethodsByCategory` が `string` 型のとき | `categoryPaymentMatrix` が正しく構築されるか |
| `paymentMethodsByCategory` が `Array` 型のとき | 分割払いの金額が正しく集計されるか |
| `dateRule.settle = "settledAt"`（デフォルト） | `reportingMonth` が `settledAt` 基準の yyyyMM になるか |
| `dateRule.settle = "businessDate"` | `reportingMonth` が `businessDate` 基準になるか |
| carryover（`settledAt` が `businessDate` より後の月） | デフォルトでは `settledAt` の月になるか |
| `entryId` の形式 | `{billId}_settle_{cycleNo}` の形式になるか |

**`buildCashActionEntry` のテスト**

| ケース | 確認内容 |
|---|---|
| 通常ケース | `categoryBreakdown` が `adjustmentLines` から正しく構築されるか |
| `entryId` の形式 | `{billId}_cashAction_{cashActionId}` の形式になるか |
| `paymentBreakdown` | `methodBreakdown` から正しく変換されるか |

**`buildReopenRollbackEntry` のテスト**

| ケース | 確認内容 |
|---|---|
| 符号反転 | 元の `amountIncl` が負値になるか |
| `entryId` の形式 | `{billId}_reopen_{cycleNo}` の形式になるか |

### 実機確認（このステップでは不要）

純粋関数のみのため、実機確認は不要。

## 重要注意事項

`paymentMethodsByCategory` のデータ形式が2パターンある（`accounting.ts` で確認済み）。  
どちらのパターンでも `categoryPaymentMatrix` が正しく構築されることをテストで必ず確認すること。

```typescript
// パターン1: string
"items": "cash"  →  categoryPaymentMatrix["items_cash"] += categoryBreakdown["items"]

// パターン2: Array（分割払い）
"items": [{ method: "cash", amount: 2000 }, { method: "card", amount: 1000 }]
  →  categoryPaymentMatrix["items_cash"] += 2000
     categoryPaymentMatrix["items_card"] += 1000
```

---

## あなたの確認ポイント

- `categoryPaymentMatrix` が両パターンで正しく構築されているか（テスト結果で確認）
- `dateRule` の設定値が `reportingMonth` に正しく反映されているか
- `buildReopenRollbackEntry` が元のエントリを正確に符号反転しているか
- `entryId` の採番が確定版仕様書のルールと一致しているか
