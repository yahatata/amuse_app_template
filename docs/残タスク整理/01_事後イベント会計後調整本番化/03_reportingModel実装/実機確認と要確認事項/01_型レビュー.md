# 型レビュー — Step 01〜03 で作成した型の確認依頼

## レビュー対象

### 1. ReportingEntry（`functions/src/domains/reporting/types.ts`）

reportingEntries/{entryId} に格納されるメインの型。

| フィールド | 型 | 説明 |
|---|---|---|
| `entryId` | `string` | `{billId}_{entryType}_{cycleNo or cashActionId}` |
| `entryType` | `'settle' \| 'cashAction' \| 'reopen_rollback' \| 'resettle'` | エントリ種別 |
| `billId` | `string` | 対象伝票 ID |
| `cycleNo` | `number` | 決済サイクル番号 |
| `reportingMonth` | `string` | `yyyyMM` 形式の計上月 |
| `eventAt` | `Timestamp` | イベント発生時刻 |
| `originBusinessDate` | `string` | 元の営業日 |
| `linkedAdjustmentId` | `string \| null` | 関連調整 ID |
| `linkedCashActionId` | `string \| null` | 関連 cashAction ID |
| `categoryBreakdown` | `Record<string, { amountIncl: number }>` | カテゴリ別金額内訳 |
| `paymentBreakdown` | `Record<string, number>` | 支払方法別金額内訳 |
| `categoryPaymentMatrix` | `Record<string, number>` | カテゴリ×支払方法マトリクス（キー: `{category}_{method}`） |

### 2. ReportingMonthly（`functions/src/domains/reporting/types.ts`）

reportingMonthly/{monthKey} に格納される月次集計型。

### 3. TaxReportingBehavior（`functions/src/domains/reporting/types.ts`）

storeMeta/taxReportingBehavior に格納される設定型。

| フィールド | 型 | デフォルト | 説明 |
|---|---|---|---|
| `dateRule.settle` | `'settledAt' \| 'businessDate'` | `'settledAt'` | 決済時の計上月の基準日 |
| `dateRule.adjustment` | `'adjustmentDate' \| 'originalBillDate'` | `'adjustmentDate'` | 調整時の計上月の基準日 |
| `dateRule.immediateCashAction` | `'cashActionDate' \| 'adjustmentDate'` | `'cashActionDate'` | 即時 cashAction の計上月 |
| `dateRule.laterCashAction` | `'cashActionDate' \| 'originalBillDate'` | `'cashActionDate'` | 後続 cashAction の計上月 |
| `dateRule.resettle` | `'settledAt' \| 'businessDate'` | `'settledAt'` | 再決済時の計上月の基準日 |
| `revenueRecognition.basis` | `'accrual' \| 'cash'` | `'accrual'` | 収益認識基準 |
| `revenueRecognition.pendingAdjustmentTiming` | `'onCashAction'` | 固定 | 保留調整の計上タイミング |
| `reopenPolicy.reportingTreatment` | `'reverseInOriginalMonth'` | 固定 | reopen 時の処理方針 |
| `granularity.reportingEntry` | `'lineLevel'` | 固定 | エントリ粒度 |

## 確認ポイント

1. **ReportingEntry の entryId 命名規則**は仕様通りか？
   - settle: `{billId}_settle_{cycleNo}`
   - resettle: `{billId}_resettle_{cycleNo}`
   - cashAction: `{billId}_cashAction_{cashActionId}`
   - reopen: `{billId}_reopen_{cycleNo}`

2. **categoryBreakdown のキー名**は以下で正しいか？
   - `items`, `extraCost`, `tournaments`, `sideGameChip`

3. **categoryPaymentMatrix のキー形式** `{category}_{method}` は適切か？

4. **TaxReportingBehavior のデフォルト値**は運用方針と合致しているか？

5. **ReportingGroupConfig** は Step 01 では型定義のみ。実際に使用する Step で再確認が必要。

6. **フィーチャーフラグ** `reportingAggregatorEnabled` のデフォルト `false` で問題ないか？
