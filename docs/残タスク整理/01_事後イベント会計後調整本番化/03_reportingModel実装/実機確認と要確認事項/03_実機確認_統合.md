# 実機確認: cashAction / reopen の reporting entry 作成

## 前提

- `storeMeta/config.features.reportingAggregatorEnabled = true` が設定されていること
- `storeMeta/taxReportingBehavior` が設定されていること（未設定の場合は defaults が使われる）
- settle 済みの bill が存在すること（`02_実機確認_settle.md` の確認 1 完了後）

---

## 進め方の方針

効率化のため、以下の3ラウンドに集約する。

| ラウンド | ユーザー操作 | AI確認 | 対象確認 |
|---------|-----------|-------|--------|
| ラウンド1 | 新 bill で settle → 即時返金 → pending 追加徴収 → cashAction 記録 | Firestore を直接確認（billId のみ報告でOK） | 確認5・確認6 |
| ラウンド2 | 会計済み bill を reopen | Firestore を直接確認（billId のみ報告でOK） | 確認7 |
| 確認8 | 操作不要 | コード・データで代替確認 | 確認8（冪等性） |
| ラウンド3 | flag OFF で adjustment → AI が error deploy → adjustment → AI が復元 | 各ステップ後に Firestore 確認 | 確認9・確認10 |

4. `recordPostSettlementCashAction` でその pending adjustment の cashAction を記録する
