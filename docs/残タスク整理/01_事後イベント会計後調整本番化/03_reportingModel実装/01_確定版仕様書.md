## 3. Firestore パス / ドキュメント ID

### `reportingEntries`

```
reportingEntries/{entryId}
```

`entryId` の採番規則：

| entryType | entryId |
|---|---|
| `settle` | `{billId}_settle_{cycleNo}` |
| `cashAction` | `{billId}_cashAction_{cashActionId}` |
| `reopen_rollback` | `{billId}_reopen_{cycleNo}` |
| `resettle` | `{billId}_resettle_{cycleNo}` |

予測可能な ID にすることで、同一イベントへの二重書き込みをドキュメント存在チェックで防ぐ。

### `reportingMonthly`

```
reportingMonthly/{monthKey}                         ← monthKey = yyyyMM
reportingMonthly/{monthKey}/aggregationMarkers/{id} ← 冪等性マーカー
```

`analyticsMonthly` と同一のルートコレクション方式。

## 4. `storeMeta/taxReportingBehavior` の仕様

処理ルール設定。初期設定後は原則変更しない。

### フィールド定義

```typescript
{
  dateRule: {
    settle:              "settledAt" | "businessDate"          // default: "settledAt"
    adjustment:          "adjustmentDate" | "originalBillDate" // default: "adjustmentDate"
    immediateCashAction: "cashActionDate" | "adjustmentDate"   // default: "cashActionDate"
    laterCashAction:     "cashActionDate" | "originalBillDate" // default: "cashActionDate"
    resettle:            "settledAt" | "businessDate"          // default: "settledAt"
  }
  revenueRecognition: {
    basis:                   "accrual" | "cash"         // default: "accrual"
    pendingAdjustmentTiming: "onCashAction"              // 固定（変更不可）
  }
  reopenPolicy: {
    reportingTreatment: "reverseInOriginalMonth"         // 固定（変更不可）
  }
  granularity: {
    reportingEntry: "lineLevel"                          // 固定（変更不可）
  }
}
```

### 各設定値の挙動

| 設定 | 値 | 挙動 |
|---|---|---|
| `dateRule.settle` | `settledAt`（デフォルト） | 会計完了タイムスタンプで月を決める |
| `dateRule.settle` | `businessDate` | 営業日で月を決める（`analyticsMonthly` と同一になる） |
| `dateRule.adjustment` | `adjustmentDate`（デフォルト） | adjustment 作成日時で月を決める |
| `dateRule.laterCashAction` | `cashActionDate`（デフォルト） | cashAction 実行日時で月を決める |
| `dateRule.laterCashAction` | `originalBillDate` | 元の伝票の営業日で月を決める |
| `revenueRecognition.pendingAdjustmentTiming` | `onCashAction`（固定） | cashAction が実行されたときのみ reportingEntries に書く |
| `reopenPolicy.reportingTreatment` | `reverseInOriginalMonth`（固定） | reopen rollback を同月内の負値エントリで記録 |
| `granularity.reportingEntry` | `lineLevel`（固定） | adjustment の明細行単位で categoryBreakdown を構築 |

> `reopen` は当日営業日の bill にしか実行できないため、rollback の月帰属設定は不要（常に同月）。

### ドキュメントが存在しない場合

全設定をデフォルト値として扱う。

## 5. `storeMeta/reportingGroupConfig` の仕様

商品カテゴリの表示グループ定義。

### フィールド定義

```typescript
{
  groups: Array<{
    key:          string    // グループ識別子（例: "group_a"）
    label:        string    // UI 表示名（例: "通常商品"）
    categoryKeys: string[]  // このグループに含めるカテゴリキーの配列
  }>
}
```

### 動作ルール

- グループは任意の数を定義できる
- 同じ `categoryKey` を複数グループに含めることができる
- **どのグループにも属さない `categoryKey` は `"other"` として自動集約する**
- `reportingMonthly` の `categoryBreakdown` と `categoryPaymentMatrix` には全カテゴリキーが保持される（グループ集計は UI 側で行う）

### UI での集計例

```
「グループA の現金売上」
= categoryPaymentMatrix["items_cash"]
+ categoryPaymentMatrix["tournaments_cash"]
+ categoryPaymentMatrix["extraCost_cash"]
```

### 既知のカテゴリキー

`bills` の `paymentMethodsByCategory` に保存されている確認済みキー：

| キー | 意味 |
|---|---|
| `items` | フード・ドリンク |
| `tournaments` | トーナメント参加費 |
| `sideGameChip` | サイドゲームチップ |
| `extraCost` | 入店料 |

## 6. `reportingEntries` フィールド仕様

### 6-1. 共通フィールド

```typescript
{
  entryId:            string    // ドキュメント ID と同値
  entryType:          "settle" | "cashAction" | "reopen_rollback" | "resettle"
  billId:             string
  cycleNo:            number
  reportingMonth:     string    // yyyyMM（dateRule に従って決定）
  eventAt:            Timestamp // イベント発生時刻
  originBusinessDate: string    // 元の営業日（参照用）
  linkedAdjustmentId: string | null  // cashAction に対応する調整がある場合
  linkedCashActionId: string | null  // cashAction エントリの場合
}
```

### 6-2. 金額の3層構造

**① categoryBreakdown**

```typescript
categoryBreakdown: {
  [categoryKey: string]: { amountIncl: number }
  // 例: "items": { amountIncl: 3000 }
  // "other" キー: どのグループにも属さないカテゴリの合算
}
```

**② paymentBreakdown**

```typescript
paymentBreakdown: {
  [paymentMethodKey: string]: number
  // 例: "cash": 5000, "card": 2000
}
```

現金移動がないエントリ（pending adjustment 等）は空 `{}`。

**③ categoryPaymentMatrix**

```typescript
categoryPaymentMatrix: {
  [`${categoryKey}_${paymentMethodKey}`]: number
  // 例: "items_cash": 2000, "tournaments_card": 1500
  // "other_cash" 等も含む
}
```

settle 時は `paymentMethodsByCategory`（`meta.paymentMethodsByCategory` または `draftAccountingInput.paymentMethodsByCategory`）から構築。

### 6-3. entryType ごとの記録範囲

| entryType | categoryBreakdown | paymentBreakdown | categoryPaymentMatrix | 備考 |
|---|---|---|---|---|
| `settle` | ○ | ○ | ○ | `paymentMethodsByCategory` から構築 |
| `cashAction`（即時・後続） | ○ | ○ | ○ | linked adjustment の lines からカテゴリを取得 |
| `reopen_rollback` | ○（負値） | ○（負値） | ○（負値） | 元 cycle 分を符号反転 |
| `resettle` | ○ | ○ | ○ | 通常 settle と同じ |

### 6-4. entryType ごとのイベント発生時刻と reportingMonth の決定

| entryType | `eventAt` | `reportingMonth` のデフォルト決定元 | `originBusinessDate` |
|---|---|---|---|
| `settle` | `settledAt` | `settledAt` | `businessDate` |
| carryover settle | `settledAt` | `settledAt`（会計した日） | `businessDate`（入店した営業日） |
| `cashAction`（即時） | `cashActionCreatedAt` | `cashActionDate` | 元の `businessDate` |
| `cashAction`（後続） | `cashActionCreatedAt` | `cashActionDate` | 元の `businessDate` |
| `reopen_rollback` | `reopenExecutedAt` | `reopenExecutedAt` | 元 cycle の `settledAt` |
| `resettle` | `settledAt` | `settledAt` | `businessDate` |

## 7. `reportingMonthly` フィールド仕様

### フィールド定義

```typescript
{
  monthKey:       string    // yyyyMM
  totalAmountIncl: number   // 全エントリの税込合計

  categoryBreakdown: {
    [categoryKey: string]: { amountIncl: number }
    // "other" キーを含む
  }

  paymentMethodBreakdown: {
    [paymentMethodKey: string]: number
  }

  categoryPaymentMatrix: {
    [`${categoryKey}_${paymentMethodKey}`]: number
    // "other_*" キーを含む
  }

  lastUpdatedAt: Timestamp
}
```

### 更新方式

**incremental**（`FieldValue.increment` を使用）。  
`reportingEntries` の書き込みのたびに差分を加算・減算する。

### 冪等性の担保

`analyticsMonthly` と同じ `aggregationMarkers` パターンを使用。

```
reportingMonthly/{monthKey}/aggregationMarkers/entries_{entryId}
```

マーカーが存在する場合は処理済みとみなしてスキップ。

### 失敗時の復旧

1. **1層目**: `aggregationMarkers` で二重計上を防ぐ
2. **2層目**: `rebuildReportingMonthly` admin callable で当該月を全件再集計

## 8. 既存 callable / trigger への変更箇所

### 変更対象（4箇所）

| ファイル | 変更内容 |
|---|---|
| `functions/src/domains/bills/triggers/billsOnSettle.ts` | settle / resettle 時に `reportingEntries` を書き、`reportingMonthly` を更新 |
| `functions/src/domains/bills/repos/createPostSettlementAdjustment.ts` | 即時 cashAction（`decrease_refunded` / `increase_collected` + `immediateCashAction`）のときのみ書く。pending 型は書かない |
| `functions/src/domains/bills/repos/recordPostSettlementCashAction.ts` | 後続 cashAction 時に書く（`processCashActionAnalyticsAtomically` と同じパターン） |
| `functions/src/domains/bills/repos/reopenAccountedBill.ts` | reopen 実行時に `reopen_rollback` エントリを書く |

### feature flag

`storeMeta/config`（`storeConfig.features`）に `reportingAggregatorEnabled: boolean` を追加。  
`false` の場合は `reportingEntries` / `reportingMonthly` への書き込みをスキップする。  
既存の `settlementAggregatorEnabled` と同じ制御パターンを踏襲。
