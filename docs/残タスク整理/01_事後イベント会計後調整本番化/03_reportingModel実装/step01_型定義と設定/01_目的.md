## 主要な型定義の要件

### `ReportingEntry`

```typescript
// 確定版仕様書 セクション 6 参照
// 必須フィールド: entryId, entryType, billId, cycleNo, reportingMonth,
//               eventAt, originBusinessDate, linkedAdjustmentId, linkedCashActionId,
//               categoryBreakdown, paymentBreakdown, categoryPaymentMatrix
```

### `TaxReportingBehavior`

- `dateRule` の各キー（`settle` / `adjustment` / `immediateCashAction` / `laterCashAction` / `resettle`）
- `revenueRecognition`、`reopenPolicy`、`granularity`
- **固定フィールド**（`pendingAdjustmentTiming`, `reportingTreatment`, `reportingEntry`）は union 型で 1値のみ許可する

### `feature flag`

```typescript
// storeConfig.features に追加
reportingAggregatorEnabled?: boolean
// デフォルト: undefined（= false 扱い）
```

## テスト方針

### AI が実行するテスト

- `taxReportingBehaviorLoader` のユニットテスト
  - `storeMeta/taxReportingBehavior` が存在する場合、値を正しく読み込むか
  - ドキュメントが存在しない場合、デフォルト値をすべて返すか
  - 一部フィールドのみ存在する場合、未設定分はデフォルト値で補完するか

### 実機確認（このステップでは不要）

型定義と設定ローダーのみのため、実機確認は不要。

---

## あなたの確認ポイント

- `ReportingEntry` の型が確定版仕様書（セクション 6）の全フィールドを網羅しているか
- `categoryBreakdown` / `paymentBreakdown` / `categoryPaymentMatrix` の型が正しく定義されているか
- `TaxReportingBehavior` の固定フィールドが union 型 1値のみになっているか（誤設定を型レベルで防止）
- `storeConfig.features` への追加が既存の型と矛盾していないか
