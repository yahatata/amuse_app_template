# Step 05: createPostSettlementAdjustment への統合（即時 cashAction）

## このステップの目的

`createPostSettlementAdjustment` repo に reporting 書き込みを組み込む。  
**即時 cashAction のとき（`decrease_refunded` / `increase_collected`）のみ** エントリを書く。  
pending 型（`decrease_refund_pending` / `increase_collection_pending`）では書かない。

> Step 05〜07 は同一パターンの繰り返しのため、1セッションで連続実施可能。

## 変更の概要

既存の `analyticsCapture` パターン（transaction 外で analytics を更新）と同じ構造で追加する。

```typescript
// 即時 cashAction のとき（immediateCashAction が存在し、cashActionDoc が作成された場合）
if (!reused && reportingEnabled && reportingCapture?.cashActionDoc) {
  const entry = buildCashActionEntry({ ... });
  await writeReportingEntry(db, entry);
  await applyEntryToReportingMonthly(db, entry);
}
```

**pending 型では何もしない:** `adjustmentType` が `_pending` の場合は `reportingCapture` 自体を null のままにする。

## テスト方針

### AI が実行するテスト（ユニット）

| ケース | 確認内容 |
|---|---|
| `decrease_refunded`（即時返金） | reporting 書き込みが呼ばれるか |
| `increase_collected`（即時徴収） | reporting 書き込みが呼ばれるか |
| `decrease_refund_pending`（pending） | reporting 書き込みが呼ばれないか |
| `increase_collection_pending`（pending） | reporting 書き込みが呼ばれないか |
| `reportingAggregatorEnabled = false` | 即時でも書き込みが呼ばれないか |
| 既存テストが全件 PASS すること | 既存動作を壊していないか |
