# 仕様整理

## ほぼ確定でよい仕様

### 1. Functions を最終判定に寄せる

金額、営業日、スケジューラー、勤怠、給与のような業務重要設定は、クライアントではなく Functions を最終判定にするのが自然です。

### 2. fallback 方針は設定ごとに変えるべき

見た目や軽微な表示設定は defaults で継続しやすいですが、会計・権限・自動実行系まで同じ扱いにするのは危険です。

### 3. `storeMeta/config` に何でも詰め込まない

`requiredStaffByTimeSlot` や `schedulerConfig` のように独立責務があるものは、別 doc のまま扱う方がわかりやすいです。

## ユーザー判断が必要な仕様

### 1. どの設定を fail-closed にするか

候補:

- 会計や課金額
- 権限系
- scheduler / Cloud Tasks 有効化系
- 給与計算基準日系

このあたりは「読めなければ defaults で続行」ではなく、「止める」または「最後の成功値を使う」に寄せるか判断が必要です。

### 2. 店舗別デフォルトの持ち方

選択肢:

1. 共通 defaults のみ
2. store ごとの初期値セットを持つ
3. defaults は共通、初期化 callable で store ごとに補正

おすすめは 3 です。  
共通コードを保ちつつ、店舗差も表現しやすいためです。

### 3. クライアント直読みにする範囲

選択肢:

1. 表示補助系のみ直読みにする
2. ほとんど直読みで済ませる
3. 重要設定は callable 経由に寄せる

おすすめは 1 と 3 の組み合わせです。  
表示は直読みにしつつ、最終判定や重要処理は server で確定する方が安全です。
