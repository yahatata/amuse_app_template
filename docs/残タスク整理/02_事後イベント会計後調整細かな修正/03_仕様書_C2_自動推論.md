# C-2 仕様書：paymentMethodsByCategory 自動推論

> ✅ **完了（2026-05-30）** — `billsOnSettle.ts` デプロイ済み（`paymentSplitCalculator` の `roundingUnits` 対応も統合）。`paymentMethodsInference.spec.ts` PASS。実機確認済み。

## 目的

settle 時に `paymentMethodsByCategory` が未設定の場合、`calculatePaymentSplit` と
`storeMeta/config` の `paymentPolicy` を使って自動推論し、`categoryPaymentMatrix` が
空になる問題を解消する。

単純な現金払いのみの会計では UI の `CategoryPaymentMethodDialog` が呼ばれないため
`paymentMethodsByCategory` が空になる。このケースを含む全会計に対して settle 時に
自動補完する。

---

## 対象ファイル

- `functions/src/domains/bills/triggers/billsOnSettle.ts`

---

## 発動条件（推論を実行する条件）

**以下の両方が null / 空のとき** のみ自動推論を実行する。

```
afterData.meta?.paymentMethodsByCategory → null または {}
afterData.draftAccountingInput?.paymentMethodsByCategory → null または {}
```

どちらか一方でも値が入っていれば既存値を使い、推論はスキップする（冪等性の確保）。

---

## 実装手順

### Step A：categoryBreakdown のキー変換

`CategoryBreakdown` 型は `sideGameChips`（複数形）を使うが、
`calculatePaymentSplit` の `categoryOrder` は `sideGameChip`（単数形）を使う。
`billsOnSettle.ts` 内の既存パターン（L363–367）と同じ変換を適用する。

```typescript
const billForSplit: Record<string, number> = {};
for (const [key, val] of Object.entries(categoryBreakdown)) {
  const splitKey = key === 'sideGameChips' ? 'sideGameChip' : key;
  billForSplit[splitKey] = typeof val === 'number' ? val : 0;
}
```

### Step B：selectedBaseMethod の決定

`paymentTotals` の non-special キーの中で金額が最大のものを選ぶ。

- **non-special キー**：`['cash', 'credit_card', 'electronic_money']`
- **special キー**（ポイント類）：`['pointA', 'pointB', 'sideGameChip']`
- 同額の場合は `cash` を優先（`['cash', 'credit_card', 'electronic_money']` の先頭順）
- non-special が 1 つも存在しない場合（全額ポイント払い）は推論をスキップし、空のまま

```typescript
const NON_SPECIAL_METHODS = ['cash', 'credit_card', 'electronic_money'] as const;
type BaseMethod = typeof NON_SPECIAL_METHODS[number];

let selectedBaseMethod: BaseMethod | null = null;
let maxAmount = 0;
for (const method of NON_SPECIAL_METHODS) {
  const amount = paymentTotals[method] ?? 0;
  if (amount > maxAmount) {
    maxAmount = amount;
    selectedBaseMethod = method;
  }
}
if (!selectedBaseMethod) {
  // 全額ポイント払い → 推論スキップ
  return;
}
```

### Step C：balances の作成

`paymentTotals` に記録された「実際に使われた量」を残高として渡す。
`sideGameChip` のみ `paymentTotals` が円換算値のため、枚数に逆算する。

```typescript
const chipRate = storeConfig.billing?.sideGameChipRate ?? DEFAULT_SIDE_GAME_CHIP_EXCHANGE_RATE;

const balances: Record<string, number> = {
  pointA: paymentTotals['pointA'] ?? 0,
  pointB: paymentTotals['pointB'] ?? 0,
  sideGameChip: (paymentTotals['sideGameChip'] ?? 0) / chipRate,
};
```

### Step D：calculatePaymentSplit の呼び出し

```typescript
const splitResult = calculatePaymentSplit({
  selectedBaseMethod,
  bill: billForSplit,
  balances,
  categoryPaymentMethods:
    storeConfig.billing?.paymentPolicy?.categoryPaymentMethods
    ?? DEFAULT_CATEGORY_PAYMENT_METHODS,
  pointPriority:
    storeConfig.billing?.paymentPolicy?.pointPriority
    ?? DEFAULT_POINT_PRIORITY,
  categoryOrder:
    storeConfig.billing?.paymentPolicy?.categoryOrder
    ?? DEFAULT_CATEGORY_ORDER,
  sideGameChipExchangeRate: chipRate,
});
```

### Step E：paymentMethodsByCategory の構築

`splitResult` の `categoryBreakdown` と `usedPoints` から変換する。

**フォーマット変換ルール：**

| ポイント使用 | 基本手段使用 | 出力形式 |
|---|---|---|
| なし | あり | `"cash"` 等の文字列形式 |
| あり | なし（全額ポイント） | `[{method: 'pointA', amount: X}]` 配列形式 |
| あり | あり（混在） | `[{method: 'pointA', amount: X}, {method: 'cash', amount: Y}]` 配列形式 |
| 両方ゼロ | — | そのカテゴリはスキップ（金額0のカテゴリ） |

ポイント複数使用時（pointA と pointB の両方）は `usedPoints` に記録された順で配列に追加する。

```typescript
// 疑似コード
const inferred: Record<string, string | Array<{method: string; amount: number}>> = {};

for (const category of categoryOrder) {
  const catAmount = billForSplit[category] ?? 0;
  if (catAmount <= 0) continue;

  const { pointsUsed, baseMethodAmount } = splitResult.categoryBreakdown[category];
  const splits: Array<{method: string; amount: number}> = [];

  // そのカテゴリで使われたポイントを特定
  for (const pointType of pointPriority) {
    if (usedPoints[pointType] > 0 && categoryAllowsPoint(category, pointType)) {
      // 按分が必要な場合もあるが、calculatePaymentSplit は categoryBreakdown に
      // カテゴリ単位の pointsUsed を返すため、各ポイントの寄与を
      // usedPoints から直接引き出すのではなく splitResult.categoryBreakdown から使う
    }
  }
  // ※ 実装時は splitResult.categoryBreakdown[category].pointsUsed と
  //    どのポイントが充当されたかを splitResult.usedPoints の按分で計算する
  //    （詳細は実装コメントで補足）

  if (splits.length === 0) {
    inferred[category] = selectedBaseMethod;
  } else {
    if (baseMethodAmount > 0) {
      splits.push({ method: selectedBaseMethod, amount: baseMethodAmount });
    }
    inferred[category] = splits;
  }
}
```

> **実装注意**：`splitResult.usedPoints` はカテゴリ横断の合計値。
> カテゴリ単位のポイント内訳は `splitResult.categoryBreakdown[category].pointsUsed` が合計値を持つが、
> どのポイント種別が何円かは `pointPriority` の順で `balances` を消費したロジックから
> 再現する必要がある。実装時に必要なら `calculatePaymentSplit` の戻り値型を拡張するか、
> 簡略化として「カテゴリの pointsUsed 総量を pointPriority の先頭から充当」とみなす。

### Step F：Firestore への書き込み

既存 `batch` に追加して書き込む（トランザクション不要、同一 batch に含める）。

```typescript
batch.update(billRef, {
  'meta.paymentMethodsByCategory': inferred,
  'draftAccountingInput.paymentMethodsByCategory': inferred,
});
```

## エラーハンドリング

- `calculatePaymentSplit` が例外をスローした場合：ログに記録し、`paymentMethodsByCategory` は空のままにする（reporting entry の `categoryPaymentMatrix` は空になるが、安全側に倒す）
- 推論が実行・完了した場合は `logOpsSuccess` でログに記録する
- 推論がスキップされた場合（全額ポイント払い等）もログに残す

---

## 影響範囲

| 影響箇所 | 内容 |
|---|---|
| `billsOnSettle.ts` | 自動推論ロジックの追加のみ |
| `reportingEntries` | 次回 settle 以降の新規 bill で `categoryPaymentMatrix` が自動充填される |
| 既存 bill | 過去の settled bill には影響しない（再処理は別途検討） |
| Flutter UI | 変更なし（`paymentMethodsByCategory` を読む側が自然に動く） |

## テスト方針

- ユニットテスト：`calculatePaymentSplit` 自体は既存のテストが対象
- 結合テスト：settle 後に `meta.paymentMethodsByCategory` が正しく生成されるかを実機確認
- 確認シナリオ：
  1. 現金のみ会計 → 全カテゴリに `"cash"` が入ること
  2. ポイントA + 現金会計 → 対象カテゴリが配列形式になること
  3. `paymentMethodsByCategory` が既存設定済みの bill → 上書きされないこと
