## Step 2：返金ダイアログの支払い手段制限

### 対象ファイル
`lib/Accounting/postSettlementRefundDialog.dart`

### 目的
元の支払い手段に含まれる non-special 手段のみを返金手段として提示し、
ポイント/チップで支払われた金額を現金/カードで過大返金できないようにする。

### データ取得の追加

`_loadEffectiveAdjustments()` 内の `billSnap` 取得時に `paymentTotals` もあわせて取得する。

```dart
final paymentTotalsRaw =
    billData?['paymentTotals'] as Map<String, dynamic>? ?? {};
```

State に以下を追加：
```dart
Map<String, int> _paymentTotals = {};
int _nonSpecialTotal = 0;
int _specialTotal = 0;
```

### 返金手段の定義

```dart
const _nonSpecialMethods = ['cash', 'credit_card', 'electronic_money', 'qr', 'bank_transfer'];
const _specialMethods = ['pointA', 'pointB', 'sideGameChip'];
```

### 返金可能上限の計算

```dart
_nonSpecialTotal = _nonSpecialMethods.fold(0, (sum, method) {
  return sum + (_paymentTotals[method] ?? 0);
});
_specialTotal = _specialMethods.fold(0, (sum, method) {
  return sum + (_paymentTotals[method] ?? 0);
});
```

### ドロップダウンの変更

**返金手段の選択肢**：`_paymentTotals` のキーのうち `_nonSpecialMethods` に含まれ、
かつ金額が 0 より大きいもの。

- 選択肢が 1 件のみ → ドロップダウンは表示せず固定表示にする
- 選択肢が 0 件 → 「現在返金対応可能な支払い手段が見つかりません」と表示しサブミット不可

初期値は選択肢の先頭（`_nonSpecialMethods` の優先順）。

### 返金金額の上限バリデーション

サブミット時に以下をチェック：

```
入力金額 > _nonSpecialTotal の場合 → エラー表示
「現金/カードでの返金上限は ¥{_nonSpecialTotal} です。」
```

TextField のバリデーションでもリアルタイムに上限を表示する（ヘルパーテキスト）。

### 注意書き表示

`_specialTotal > 0` のとき、フォームの先頭にカード型で注意書きを表示：

```
ポイント・チップでの支払い（¥{_specialTotal}）は現在返金対象外です。
現金/カードでの返金は最大 ¥{_nonSpecialTotal} まで可能です。
ポイント返金は将来対応予定です（C-2.5）。
```

複数の支払い手段がある場合の注意書き（`_paymentTotals` のキーが non-special で 2 件以上のとき）：

```
複数の支払い手段がある場合は、1回の操作で1手段のみ返金できます。
複数手段で返金する場合は2回に分けてください。
```

### C-2.5 への引き継ぎ

以下は現時点では実装しない。C-2.5 で追加する：

- `_specialMethods` の選択肢をドロップダウンに追加
- ポイント/sideGameChip の返金処理（残高加算）を Functions 側に実装
- Functions 側での「ポイント支払い分を現金で返金できない」バリデーション（現在は UI 側上限チェックのみ）

## Step 3：「この伝票を操作」サマリの折りたたみ表示

### 対象ファイル
`lib/Accounting/postSettlementOperationDetailPage.dart`

### 目的
- 不要な技術的 ID（billId, currentCycle）を削除してオペレーターが必要な情報のみ表示
- 支払い情報をカード内で見やすく整理し、展開すればカテゴリ別詳細も確認できるようにする

### State の追加

```dart
bool _summaryExpanded = false;
```

### UI 変更：削除する項目

- `Text('billId: ${widget.billId}')` → 削除
- `Text('currentCycle: ...')` → 削除

### UI 変更：サマリカードの再設計

現在の「current state」固定テキストを、折りたたみ対応のカードに変更する。

**折りたたみ状態（常時表示部分）：**

```
┌──────────────────────────────────────────┐
│ カテゴリ概要：                             │
│ 商品 X件 / 追加料金 Y件 / トナメ Z件 / ...  │
│                                          │
│ 支払い合計：                              │
│ 現金 ¥3,000 / クレジットカード ¥2,000     │  ← paymentTotals から生成
│                                      [▼] │
└──────────────────────────────────────────┘
```

**展開後（タップで表示）：**

```
┌──────────────────────────────────────────┐
│ ... （上記と同じ）                         │
│                                      [▲] │
├──────────────────────────────────────────┤
│ カテゴリ別支払い内訳：                      │
│ 入店料  ¥1,000  →  現金                   │  ← paymentMethodsByCategory から生成
│ items   ¥2,000  →  ポイントA ¥1,000      │
│                    現金 ¥1,000            │
│ ...                                      │
│ （情報なしの場合）支払い詳細は会計後に自動生成されます │
└──────────────────────────────────────────┘
```

### データ取得

`_bill` から以下を取得（`_load()` の setState 内で変数にセット）：

```dart
// 支払い手段別合計
final paymentTotals =
    (_bill?['paymentTotals'] as Map<String, dynamic>?) ?? {};

// カテゴリ別支払い手段（draftAccountingInput → meta の優先順）
final paymentMethodsByCategory =
    (_bill?['draftAccountingInput']?['paymentMethodsByCategory']
     ?? _bill?['meta']?['paymentMethodsByCategory'])
    as Map<String, dynamic>?;
```

### 支払い手段の表示ラベル変換

`_methodLabel()` を既存メソッドとして利用（すでに定義済み）。

カテゴリ別表示ラベル：

```dart
String _categoryLabel(String key) => switch (key) {
  'extraCost'    => '入店料',
  'sideGameChip' => 'ゲームチップ',
  'tournaments'  => 'トーナメント',
  'items'        => '商品',
  _              => key,
};
```
