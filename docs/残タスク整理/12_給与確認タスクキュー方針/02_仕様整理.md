# 仕様整理

## ほぼ確定でよい仕様

### 1. scheduler は「通知判定のみ」を担う

既存 spec のとおり、給与計算そのものではなく、通知条件を評価して admin へ知らせる役割にとどめるのは妥当です。

### 2. 通知は idempotency を前提に管理する

日次・週次で繰り返す通知が多いため、同一日の同一 triggerType を安定キーで管理する設計は維持すべきです。

### 3. 通知先はまず admin に限定でよい

将来 LINE やメールへ広げる余地はあっても、今は adminHome 中心で十分です。

## ユーザー判断が必要な仕様

### 1. この機能を本番採用するか

選択肢:

1. **現行構成のまま採用**
2. **簡略化して採用**
3. **今回いったん見送る**

現場で給与確認の抜け漏れが実際に痛いなら 1 か 2、そうでなければ 3 も合理的です。

### 2. 簡略化するならどこを削るか

候補:

- scheduler は残し、通知種別を減らす
- scheduler をやめ、給与計算完了時などのインライン通知だけ残す
- 通知はやめ、管理画面の警告表示だけにする

### 3. 強い通知の基準

`payroll_calc_remind` をいつ `strong_warning` にするか、現行 spec どおり支払日3日前で良いかは、運用に合わせて最終確認が必要です。
