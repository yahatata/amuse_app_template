# スタッフ退職処理

## このタスクの要点

スタッフ退職処理は、現状ほぼ未着手です。  
単に staff 一覧から消すだけでは足りず、勤怠・給与・認証・QR・過去データ保持までまたぐ横断設計が必要です。

## 現状整理

- staff 作成 callable は存在します。
- 時給や口座情報の更新もあります。
- しかし、退職専用の field / callable / UI / 運用ルールは見当たりません。
- `staffs` ドキュメントも、現状は退職状態を前提にした設計になっていません。

## いま言える状態評価

- 仕様: 未作成
- 実装: 未作成
- 影響範囲: 非常に広い

## このタスクの本質

このタスクは「削除機能」ではありません。  
本質は、「過去の給与・勤怠履歴を壊さず、今後の運用対象から外す仕組み」を作ることです。
