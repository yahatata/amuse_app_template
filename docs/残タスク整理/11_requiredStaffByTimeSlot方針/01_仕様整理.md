# シフト設定：営業スタイル・必要人数設定 仕様

## 1. 目的

本仕様の目的は、シフト作成時に、店舗の営業実態に即した不足判定および警告表示を正しく行えるようにすることである。

具体的には、営業日ごとの営業時間・営業スタイル・必要人数をもとに、以下を正しく判定・表示できる状態を目指す。

* 営業時間内にスタッフが配置されていない時間帯があるか
* 営業スタイルごとに定義された必要人数を満たしているか
* どの時間帯に、何人必要で、現在何人配置されているか
* 管理者が、どこを修正すれば不足が解消されるか

この目的を実現するために、店舗側で以下の設定を行えるようにする。

1. 営業スタイルごとの営業時間設定
2. 営業スタイルごとの必要人数設定

必要人数設定は、それ自体が目的ではなく、シフト作成時の不足判定・警告表示を正しく行うための判定条件として扱う。

---

## 2. 背景

シフト作成における不足判定は、単に「スタッフが何人いるか」だけでは成立しない。

店舗ごとの営業時間、日ごとの営業スタイル、時間帯ごとの必要人数が揃って初めて、実運用に合った判定が可能になる。

そのため、本仕様では「必要人数設定を作ること」自体を目的とはしない。
必要人数設定は、シフト作成時に不足判定・警告表示を正しく行うための入力条件として位置づける。

現状、シフト機能では営業時間や必要人数をもとに、日ごとの `isSufficient` を判定している。

ただし、現状には以下の課題がある。

### 2.1 営業スタイルの営業時間を店舗側で編集できない

現在、営業日編集では日ごとに営業スタイルを選択できる。

例：

* 平日
* 週末・祝日
* イベント
* 終日
* 休業日

しかし、各営業スタイル自体の営業時間、たとえば「平日は15:00-25:00」「週末祝日は12:00-25:00」といったマスタ値を、店舗側UIから編集する導線がない。

店舗ごとに営業時間は異なるため、営業スタイルの営業時間は店舗側で編集可能である必要がある。

### 2.2 必要人数が全営業日共通になっている

現状の `requiredStaffByTimeSlot` は、全営業日に対して共通の単一配列として扱われている。

```ts
{
  data: [
    { startHour: 19, endHour: 22, requiredCount: 2 },
    { startHour: 10, endHour: 12, requiredCount: 3 }
  ]
}
```

この形式では、平日・週末祝日・イベント日・終日営業で必要人数を変えることができない。

しかし実運用では、営業スタイルごとに必要人数は異なる。

例：

* 平日：18:00-22:00 に2人必要
* 週末祝日：15:00-23:00 に3人必要
* イベント：12:00-24:00 に4人必要

そのため、必要人数設定も営業スタイル別に持つ必要がある。

### 2.3 シフト編集時の不足警告が分かりにくい

現状の不足警告は、1時間単位の不足時間帯がそのまま羅列されるため、管理者が直感的に把握しにくい。

例：

```text
18:00 - 19:00（必要3人 / 現在2人）
19:00 - 20:00（必要3人 / 現在2人）
20:00 - 21:00（必要3人 / 現在2人）
21:00 - 22:00（必要3人 / 現在2人）
```

本来は、同じ条件で連続する不足時間帯はまとめて表示すべきである。

```text
18:00 - 22:00　必要3人 / 現在2人
```

## 3. 基本方針

### 3.1 シフトメニューに設定画面を追加する

シフトメニュー配下に、以下の画面を追加する。

```text
シフト
  - シフトカレンダー
  - シフトドラフト
  - 営業日編集
  - 営業スタイル・必要人数設定
```

新規追加する画面は、`営業スタイル・必要人数設定` とする。

### 3.2 営業スタイルと必要人数を同じ設定画面で編集する

新画面では、以下2つを編集可能にする。

1. 営業スタイルごとの営業時間
2. 営業スタイルごとの必要人数

営業スタイルと必要人数は、シフト作成時の不足判定・警告表示において密接に関係するため、同一画面または同一画面内のタブで管理する。

### 3.3 必要人数は営業スタイル別に管理する

`requiredStaffByTimeSlot` は、全営業日共通ではなく、営業スタイル別に管理する。

正式形式は `version: 2 / byStyle` とする。

旧形式 `data` との互換処理は不要とする。
本プロジェクトは開発中であり、既存 doc は v2 形式で上書きする前提とする。

### 3.4 runtime fallback は行わない

必要人数設定は店舗ごとの運用設定であるため、共通 default を runtime fallback として勝手に適用しない。

未設定・読取失敗・該当 style 未設定の場合は、人数不足判定を行わない。

ただし、営業時間内に誰もいない時間帯を検出する gap 判定は、必要人数設定とは独立して継続する。

### 3.5 `isSufficient` は boolean のみDB保存する

現状どおり、`shifts/{yearMonth}/days/{dateKey}.isSufficient` は DB に保存する。

ただし、保存するのは boolean のみとする。

不足時間帯・不足人数の詳細は保存しない。
詳細は画面表示時に都度計算する。

### 3.6 設定保存後に `isSufficient` を再計算する

営業スタイル設定または必要人数設定を保存した後、当月以降の未確定・overrideなしの日について `isSufficient` を再計算し、DBに保存する。

再計算対象に現在の `isSufficient` の true/false は使わない。

## 4. 用語定義

### 4.1 営業スタイル

営業日ごとに割り当てる営業パターン。

本仕様では以下5種類を扱う。

| styleId          | 表示名   | 説明                     |
| ---------------- | ----- | ---------------------- |
| `weekday`        | 平日    | 通常の平日営業                |
| `weekendHoliday` | 週末・祝日 | 土日祝日の営業                |
| `event`          | イベント  | イベント開催日など、通常より長い・特殊な営業 |
| `allDay`         | 終日    | 終日営業                   |
| `closed`         | 休業日   | 休業日                    |

### 4.2 営業スタイル設定

営業スタイルごとの営業時間マスタ。

例：

```text
weekday = 15:00-25:00
weekendHoliday = 12:00-25:00
event = 10:00-25:00
allDay = 06:00-25:00
closed = 休業
```

### 4.3 必要人数設定

営業スタイルごとに、時間帯別の必要スタッフ数を定義する設定。

例：

```text
weekday:
  18:00-22:00 必要2人

weekendHoliday:
  15:00-23:00 必要3人

event:
  12:00-24:00 必要4人
```

### 4.4 gap 判定

営業時間内に、スタッフが誰も配置されていない時間帯を検出する判定。

必要人数設定が未設定でも、gap 判定は継続する。

### 4.5 requiredStaff 判定

営業スタイル別の必要人数設定に対して、実際の配置人数が足りているかを判定する処理。

### 4.6 `isSufficient`

日ごとのシフト配置が十分かどうかを表す boolean。

DBには `isSufficient: true | false` のみ保存する。
不足時間帯や不足人数の詳細は保存せず、画面表示時に都度計算する。

## 6. 営業スタイル設定仕様

### 6.1 編集対象

以下5つの営業スタイルを表示する。

```text
weekday
weekendHoliday
event
allDay
closed
```

### 6.2 編集項目

各営業スタイルで編集できる項目は以下。

| 項目    | 内容              |
| ----- | --------------- |
| 表示名   | 例：平日、週末・祝日、イベント |
| 開始時刻  | 営業開始時刻          |
| 終了時刻  | 営業終了時刻          |
| 休業フラグ | 休業日かどうか         |

ただし `closed` は基本固定とする。

```ts
closed: {
  openMinute: 0,
  closeMinute: 0,
  isClosed: true
}
```

### 6.3 時刻表現

営業時間は minute で保存する。

例：

| 表示    |  保存値 |
| ----- | ---: |
| 06:00 |  360 |
| 10:00 |  600 |
| 12:00 |  720 |
| 15:00 |  900 |
| 24:00 | 1440 |
| 25:00 | 1500 |

25:00 のような翌日深夜表現を許容する。

### 6.4 保存先

営業スタイル設定は既存の以下に保存する。

```text
storeMeta/config.businessHoursStyles
```

### 6.5 保存イメージ

```ts
businessHoursStyles: {
  weekday: {
    styleId: 'weekday',
    label: '平日',
    openMinute: 900,
    closeMinute: 1500,
    isClosed: false,
  },
  weekendHoliday: {
    styleId: 'weekendHoliday',
    label: '週末・祝日',
    openMinute: 720,
    closeMinute: 1500,
    isClosed: false,
  },
  event: {
    styleId: 'event',
    label: 'イベント',
    openMinute: 600,
    closeMinute: 1500,
    isClosed: false,
  },
  allDay: {
    styleId: 'allDay',
    label: '終日',
    openMinute: 360,
    closeMinute: 1500,
    isClosed: false,
  },
  closed: {
    styleId: 'closed',
    label: '休業日',
    openMinute: 0,
    closeMinute: 0,
    isClosed: true,
  },
}
```

## 7. 必要人数設定仕様

### 7.1 保存先

必要人数設定は以下に保存する。

```text
storeMeta/requiredStaffByTimeSlot
```

### 7.2 正式スキーマ

旧形式との互換は不要。
正式スキーマは v2 のみとする。

```ts
{
  version: 2,
  byStyle: {
    weekday: [
      { startHour: 18, endHour: 22, requiredCount: 2 }
    ],
    weekendHoliday: [
      { startHour: 15, endHour: 23, requiredCount: 3 }
    ],
    event: [
      { startHour: 12, endHour: 24, requiredCount: 4 }
    ],
    allDay: [
      { startHour: 10, endHour: 24, requiredCount: 2 }
    ],
    closed: []
  },
  updatedAt: Timestamp
}
```

### 7.3 各フィールド

| フィールド               | 型         | 説明                   |
| ------------------- | --------- | -------------------- |
| `version`           | number    | スキーマバージョン。固定で `2`    |
| `byStyle`           | object    | 営業スタイル別の必要人数設定       |
| `byStyle.{styleId}` | array     | 指定 styleId の時間帯別必要人数 |
| `startHour`         | number    | 開始時刻。時単位             |
| `endHour`           | number    | 終了時刻。時単位             |
| `requiredCount`     | number    | 必要人数                 |
| `updatedAt`         | Timestamp | 更新日時                 |

### 7.4 `closed` の扱い

`closed` は空配列とする。

```ts
closed: []
```

休業日は必要人数判定を行わない。

### 7.5 UI項目

営業スタイルごとに以下を編集できるようにする。

| 項目   | 説明          |
| ---- | ----------- |
| 開始時刻 | 必要人数判定の開始時刻 |
| 終了時刻 | 必要人数判定の終了時刻 |
| 必要人数 | その時間帯に必要な人数 |
| 追加   | 時間帯行を追加     |
| 削除   | 時間帯行を削除     |

### 7.6 UI表示例

```text
平日
  18:00 - 22:00　必要2人
  [+ 時間帯を追加]

週末・祝日
  15:00 - 23:00　必要3人
  [+ 時間帯を追加]

イベント
  12:00 - 24:00　必要4人
  [+ 時間帯を追加]

終日
  10:00 - 24:00　必要2人
  [+ 時間帯を追加]

休業日
  判定しない
```

## 8. 判定ロジック仕様

### 8.1 基本

不足判定では、対象日の `businessHours.styleId` を参照し、対応する必要人数設定を使用する。

```text
shifts/{yearMonth}/days/{dateKey}.businessHours.styleId
↓
storeMeta/requiredStaffByTimeSlot.byStyle[styleId]
↓
対象日の必要人数設定として使用
```

例：

```text
businessHours.styleId = weekendHoliday
↓
byStyle.weekendHoliday を使用
```

### 8.2 休業日の扱い

以下の場合は必要人数判定を行わない。

```ts
businessHours.isClosed === true
```

または、

```ts
businessHours.styleId === 'closed'
```

### 8.3 requiredStaffByTimeSlot 未設定時

必要人数設定が未設定・読取失敗・該当 style 未設定の場合は、requiredStaff 判定を行わない。

ただし、gap 判定は継続する。

```text
requiredStaffByTimeSlot 未設定
  → 人数不足判定はしない
  → gap 判定はする
```

### 8.4 `isSufficient` 判定

`isSufficient` は以下をもとに判定する。

1. gap がないこと
2. requiredStaff 判定で不足がないこと

ただし requiredStaff 判定が未設定によりスキップされた場合は、gap 判定のみで `isSufficient` を判断する。

## 9. `isSufficient` 保存仕様

### 9.1 保存対象

`isSufficient` は引き続き DB に保存する。

```text
shifts/{yearMonth}/days/{dateKey}.isSufficient
```

### 9.2 保存する内容

保存するのは boolean のみとする。

```ts
{
  isSufficient: true | false
}
```

### 9.3 保存しない内容

以下のような不足詳細はDBに保存しない。

```text
18:00-22:00 必要3人 / 現在2人
20:00-23:00 必要4人 / 現在3人
```

不足詳細は画面表示時に都度計算する。

### 9.4 理由

不足詳細は、以下の設定・配置に依存して変化する。

* 営業時間
* 営業スタイル
* 必要人数設定
* シフト配置

そのため、詳細を保存すると設定変更時の整合性管理が複雑になる。
DBには代表値として `isSufficient` のみ保存し、詳細は都度計算する。

## 10. 設定保存後の再計算仕様

### 10.1 基本方針

営業スタイル設定または必要人数設定を保存した後、対象日の `isSufficient` を再計算してDBに保存する。

ここで再計算・保存するのは `isSufficient` のみであり、不足詳細は保存しない。

### 10.2 再計算対象

再計算対象は以下。

```text
当月以降
かつ
isFinalized !== true
かつ
sufficientOverride === null
```

つまり、

```text
当月以降の未確定・手動overrideなしの日をすべて再計算する
```

### 10.3 `isSufficient` の現在値は条件に使わない

再計算対象に、現在の `isSufficient` true/false は使わない。

理由は、設定変更によって以下の両方が発生するため。

```text
true → false
false → true
```

現在 `isSufficient === false` の日だけを再計算すると、現在 true の日が新設定で false になるケースを拾えない。

### 10.4 `sufficientOverride` の扱い

`sufficientOverride !== null` の日は自動再計算対象外とする。

理由は、管理者が手動で「十分」「不十分」と判断した状態を、設定保存時に勝手に上書きしないため。

## 11. 営業スタイル変更時の反映仕様

### 11.1 基本

営業スタイルの営業時間を変更した場合、`storeMeta/config.businessHoursStyles` を更新するだけでは不十分である。

既存の `businessHoursMonthlyMap` や `shifts.days.businessHours` には、すでに具体的な `openMinute` / `closeMinute` が保存されているため。

### 11.2 反映処理

営業スタイル変更時は、以下を行う。

```text
1. storeMeta/config.businessHoursStyles を保存
2. 当月以降の businessHoursMonthlyMap を確認
3. 該当 styleId の日を新しい営業時間に更新
4. shifts/{yearMonth}/days/{dateKey}.businessHours に同期
5. isSufficient を再計算
```

### 11.3 例

```text
weekday = 15:00-25:00
↓
weekday = 16:00-24:00
```

この場合、当月以降の `styleId = weekday` の日を対象に、営業時間を更新する。

---

## 12. 必要人数変更時の反映仕様

### 12.1 基本

必要人数だけ変更した場合、営業時間は変更しない。

### 12.2 反映処理

```text
1. storeMeta/requiredStaffByTimeSlot を保存
2. businessHours は変更しない
3. 当月以降の未確定・overrideなしの日について isSufficient を再計算
```

## 13. シフト編集時の不足警告表示仕様

### 13.1 現状の問題

不足時間帯が1時間単位で羅列され、分かりにくい。

例：

```text
18:00 - 19:00（必要3人 / 現在2人）
19:00 - 20:00（必要3人 / 現在2人）
20:00 - 21:00（必要3人 / 現在2人）
21:00 - 22:00（必要3人 / 現在2人）
```

### 13.2 修正方針

同じ条件で連続している不足時間帯はまとめて表示する。

例：

```text
18:00 - 22:00　必要3人 / 現在2人
```

途中で必要人数または現在人数が変わる場合のみ分ける。

```text
18:00 - 20:00　必要3人 / 現在2人
20:00 - 22:00　必要3人 / 現在1人
```

### 13.3 表示に含める情報

不足警告には以下を含める。

| 項目     | 説明              |
| ------ | --------------- |
| 営業スタイル | 平日、週末祝日、イベントなど  |
| 営業時間   | 対象日の営業時間        |
| 必要人数設定 | 該当営業スタイルの必要人数設定 |
| 不足時間帯  | 不足している時間帯       |
| 必要人数   | その時間帯に必要な人数     |
| 現在人数   | 実際に配置されている人数    |

### 13.4 表示例

```text
営業スタイル: 週末・祝日
営業時間: 12:00 - 25:00

必要人数設定:
15:00 - 23:00　3人

不足:
18:00 - 22:00　必要3人 / 現在2人
```

### 13.5 目的

管理者が以下を理解できるようにする。

* なぜ不足判定になっているのか
* どの営業スタイルの設定が使われているのか
* どの時間帯を埋めればよいのか
* 必要人数に対して現在何人足りていないのか

## 14. バリデーション方針

### 14.1 営業スタイル設定

以下を検証する。

* `openMinute` は 0 以上
* `closeMinute` は `openMinute` より大きい
* `closeMinute` は翌日深夜表現を許容する
* `isClosed === true` の場合は `openMinute = 0`、`closeMinute = 0`
* `closed` は休業固定

### 14.2 必要人数設定

以下を検証する。

* `startHour` は 0 以上
* `endHour` は `startHour` より大きい
* `requiredCount` は 0 以上の整数
* `closed` は空配列
* 同一 style 内で明らかに不正な時間帯は保存しない

重複時間帯を許容するかどうかは実装時に決める。
初期実装では、重複を禁止する方が運用上分かりやすい。

## 15. データ更新責務

### 15.1 UI

Flutter UI は、設定値の入力・表示・保存要求を行う。

ただし、複数ドキュメント更新や `isSufficient` 再計算を伴う処理は、原則として Cloud Functions 経由で行う。

### 15.2 Cloud Functions

以下の処理は Cloud Functions 側で実施する。

* 営業スタイル設定の保存
* 必要人数設定の保存
* 当月以降の対象日抽出
* `businessHoursMonthlyMap` 更新
* `shifts.days.businessHours` 同期
* `isSufficient` 再計算
* `updatedAt` 更新
* バリデーション

## 16. 実装対象外

初期実装では、以下は対象外とする。

* 旧 `requiredStaffByTimeSlot.data` 形式との互換処理
* 不足詳細のDB保存
* 必要人数設定の履歴管理
* 過去月の自動再計算
* 最終確定済み日の自動更新
* `sufficientOverride` 済み日の自動上書き

---

## 17. 最終確定方針

本仕様の最終方針は以下。

1. 目的は、シフト作成時の不足判定・警告表示を正しく行うことである
2. 必要人数設定は、その判定・警告表示を正しく行うための入力条件として扱う
3. シフトメニューに `営業スタイル・必要人数設定` を追加する
4. 営業スタイルごとの営業時間を店舗側で編集可能にする
5. 営業スタイル別の必要人数を店舗側で編集可能にする
6. `requiredStaffByTimeSlot` は `version:2 / byStyle` 形式のみ正式対応する
7. 旧 `data` 形式との互換処理は不要
8. 既存 doc は v2 形式で上書きする
9. 必要人数設定の runtime fallback は行わない
10. 未設定・読取失敗時は人数不足判定を行わない
11. gap 判定は必要人数設定と独立して継続する
12. 判定時は `day.businessHours.styleId` に対応する `byStyle` の必要人数設定を使う
13. `isSufficient` は現状どおり DB に boolean として保存する
14. 不足時間帯・不足人数の詳細は保存せず、画面表示時に都度計算する
15. 設定保存後は、当月以降の未確定・overrideなしの日について `isSufficient` を再計算して保存する
16. 再計算対象に現在の `isSufficient` true/false は使わない
17. 営業スタイル変更時は、当月以降の該当 `styleId` の日へ営業時間を反映し、`shifts` に同期したうえで `isSufficient` を再計算する
18. 必要人数変更時は、`businessHours` は触らず `isSufficient` だけ再計算する
19. シフト編集時の警告は1時間単位で羅列せず、連続時間帯をまとめて表示する
20. 警告表示には営業スタイル・営業時間・必要人数設定・不足時間帯・必要人数・現在人数を出す
