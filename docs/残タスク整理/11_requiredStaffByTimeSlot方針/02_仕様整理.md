# 仕様整理

## ほぼ確定でよい仕様

### 1. SoT は `storeMeta/requiredStaffByTimeSlot` のままでよい

専用 doc 化されている現在の形は、責務分離として自然です。

### 2. `[]` は「判定しない」の意味でよい

既存 docs / service / helper がその前提で揃っているため、ここは維持した方が混乱しません。

### 3. Functions と Flutter の fallback 方針は大きく変えなくてよい

この機能は会計や権限ほど高リスクではないため、未存在時 defaults、読取失敗時 defaults または最後の成功値維持という方針は比較的妥当です。

## ユーザー判断が必要な仕様

### 1. 機能自体を本番採用するか

選択肢:

1. このまま本番採用
2. 一度省略
3. より簡易な形に縮小

現場で不足判定を実務判断に使うなら 1、参考程度なら 3、使わないなら 2 です。

### 2. 粒度

選択肢:

1. 1時間単位のまま
2. 30分単位へ拡張
3. 曜日や営業スタイル別へ拡張

今すぐなら 1、将来精度を上げるなら 3 が候補です。

### 3. 何に使うか

候補:

- シフト作成画面の参考値
- 不足日の警告
- 採用判断や運営振り返り

用途が曖昧だと、設定だけ増えて活用されないので、ここは明確化が必要です。
