# phaseG.1 追加調査: リージョン漏れ再点検（LIFF / taskQueue 以外）

作成日: 2026-04-03

## 1. 目的

- phaseG.1 の当初方針（`us-central1` 既定到達の排除）に沿って、LIFF 側・taskQueue 側の修正以外にリージョン漏れが残っていないかを多角的に確認する。
- コードだけでなく、実環境（Functions / Cloud Tasks / Cloud Scheduler / Secret）も含めて確認する。

## 2. 確認観点（多角的）

1. クライアント呼び出し経路（Flutter / LIFF public）
- `FirebaseFunctions.instance` 直呼び、`cloudfunctions.net` 直書き、`us-central1` 直書きを確認。

2. Functions 定義（ソース）
- `onCall / onRequest / onSchedule / onTaskDispatched / Firestore Trigger` の region 指定有無を確認。
- `setGlobalOptions({ region: "asia-northeast1" })` の単一設定を確認。

3. Cloud Tasks / Cloud Scheduler / Functions の実環境リージョン
- `us-central1` 側に不要資産が残っていないか確認。

4. Secret Manager (`task-endpoints`) の実値
- `controlHookUrl / openAssessmentUrl / closeAssessmentUrl` が `asia-northeast1` 実体を向いているか確認。

5. デプロイ済み Functions の環境変数ドリフト
- `asia-northeast1` 関数設定内に `us-central1` 文字列が残っていないか確認。

## 3. 実施コマンド（抜粋）

```bash
rg -n "FirebaseFunctions\\.instance|instanceFor\\(|httpsCallableFromUrl|cloudfunctions\\.net|us-central1-|asia-northeast1-" lib public -S
rg -n "setGlobalOptions\\(" functions/src functions/lib -S

gcloud functions list --v2 --project=amuse-app-template --regions=us-central1 --format='value(name)'
gcloud functions list --v2 --project=amuse-app-template --regions=asia-northeast1 --format='value(name)'

gcloud tasks queues list --project=amuse-app-template --location=us-central1 --format='value(name)'
gcloud tasks queues list --project=amuse-app-template --location=asia-northeast1 --format='value(name)'

gcloud scheduler jobs list --project=amuse-app-template --location=us-central1 --format='value(name,httpTarget.uri,schedule,timeZone,state)'
gcloud scheduler jobs list --project=amuse-app-template --location=asia-northeast1 --format='value(name,httpTarget.uri,schedule,timeZone,state)'

gcloud secrets versions access latest --secret=task-endpoints --project=amuse-app-template

gcloud functions list --v2 --project=amuse-app-template --regions=asia-northeast1 --format=json > /tmp/functions_asia_20260403.json
jq -r '.[] | {name: .name, env: (.serviceConfig.environmentVariables // {})} | . as $f | [($f.env | to_entries[]? | select((.value|tostring|test("us-central1"))) | (.key + "=" + (.value|tostring)))] as $hits | select(($hits|length)>0) | "\($f.name)\t\($hits|join(" | "))"' /tmp/functions_asia_20260403.json
```

## 4. 確認結果

### 4.1 クライアント呼び出し（コード）

- `lib/**/*.dart`:
  - `FirebaseFunctions.instance` 直呼びは残存なし（`FunctionsClient.instanceFor(region: 'asia-northeast1')` に統一済み）。
  - `cloudfunctions.net` / `us-central1` 直書きは残存なし。
- `public/staff/index.html` / `public/user/index.html`:
  - `functionsRegion` を利用した動的URL生成へ統一済み。
  - `getFunctions(..., "asia-northeast1")` 系へ統一済み。

### 4.2 Functions 定義（ソース）

- `functions/src/index.ts` に `setGlobalOptions({ region: "asia-northeast1" })` は 1 箇所のみ。
- トリガ定義総数（`onCall/onRequest/onSchedule/onTaskDispatched/onDocument*`）: 175
  - `region` を関数定義で明示しているもの: 18
  - `setGlobalOptions` の既定リージョンに依存しているもの: 157

補足:
- 現状動作は問題ないが、157 件は「明示漏れ」ではなく「グローバル設定依存」という設計。
- `setGlobalOptions` 変更や将来の分割デプロイ時に影響が広がるため、運用リスク観点では要注意。

### 4.3 実環境リージョン（GCP）

- Cloud Functions:
  - `asia-northeast1`: 169
  - `us-central1`: 5
- `us-central1` に残存していた関数（いずれも probe 系）:
  - `probeAuthErrorShape`
  - `probeCloudTasksErrorShape`
  - `probeFirestoreErrorShape`
  - `probeFirestoreErrorShapeInvalidArgument`
  - `probeStorageErrorShape`
- Cloud Tasks queue:
  - `asia-northeast1`: 11
  - `us-central1`: 0
- Cloud Scheduler:
  - `asia-northeast1`: 1（`firebase-schedule-schedulerSupervisor-asia-northeast1`）
  - `us-central1`: 1（`firebase-schedule-schedulerSupervisor-us-central1`）
    - URI: `https://us-central1-amuse-app-template.cloudfunctions.net/schedulerSupervisor`

### 4.4 Secret (`task-endpoints`)

- `task-endpoints` は以下 3 URL とも `-an.a.run.app`（asia 実体）を指しており整合している。
  - `controlHookUrl`
  - `openAssessmentUrl`
  - `closeAssessmentUrl`

### 4.5 デプロイ済み関数設定のドリフト（重要）

- `asia-northeast1` 関数のうち 22 関数で、環境変数に `us-central1` 文字列が残存。
  - 代表:
    - `CONTROL_HOOK_URL=https://us-central1-amuse-app-template.cloudfunctions.net/controlHookHttp`
    - `WEEKLYPLANNER_TASKS_LOCATION=us-central1`
- これらのキーは現行ソースでは参照されていない（`process.env.CONTROL_HOOK_URL` 等の参照なし）。
- ただし設定ドリフトとしては望ましくないため、運用的には整理対象。

## 5. 結論（LIFF / taskQueue 以外）

LIFF 側・taskQueue 側以外でも、以下はリージョン観点の残課題として確認された。

1. `us-central1` 残存資産（実環境）
- probe 系 Functions 5 件（ソース管理外）。
- `schedulerSupervisor` の `us-central1` 側 Cloud Scheduler job 1 件。

2. 関数定義のグローバル依存
- 157 件が `setGlobalOptions` 依存（個別 `region` 明示なし）。

3. 環境変数ドリフト
- `asia-northeast1` の 22 関数に `us-central1` 文字列を含む env が残存。

上記はいずれも、LIFF と taskQueue の修正とは別系統の確認結果である。
