# phaseG 実機確認依頼（step2後）

作成日: 2026-04-02

## 1. 目的

- 自動検証でカバーしきれない実運用導線のみを、最小手数で実機確認する。
- 今回は `asia-northeast1` 移行後の外部連携実動作に焦点を当てる。

## 2. 実機で確認を依頼する項目（最小セット）

### M-01 開店/閉店の実運用導線

- 手順:
  1. 実機アプリで開店処理を実行
  2. 営業中に通常操作を行う
  3. 閉店処理を実行
- 期待結果:
  - 開店/閉店が正常完了
  - 関連タスクが `asia-northeast1` 側で実行される
  - 異常通知や権限エラーが出ない
- 重点確認:
  - close 系（`applyCloseSnapshot` / `close_process`）の結果整合

### M-02 トーナメント主要導線（作成〜開始〜レジ締め〜終了）

- 手順:
  1. テンプレートからトーナメント作成
  2. 開始・レジ締め・終了まで実行
- 期待結果:
  - 状態遷移が UI と Firestore で一致
  - スケジュール連携（enqueue/controlHook）が正常
- 重点確認:
  - `taskSyncNeeded/schedulePlanVersion` の挙動
  - startAt 変更時の整合

### M-03 注文履歴導線（ユーザー画面）

- 手順:
  1. 注文データを作成（複数件・状態差分あり）
  2. ユーザー注文履歴を表示
- 期待結果:
  - 当日営業日・status 条件に沿った履歴が表示される
  - 並び順・件数が期待どおり
- 重点確認:
  - `getUserOrderHistory` 関連

### M-04 会計更新/返金導線

- 手順:
  1. 会計更新（追加徴収/取消/再開）を実施
  2. 返金処理を実施
- 期待結果:
  - イベント記録が正常作成される
  - 画面・履歴・集計が矛盾しない
- 重点確認:
  - `eventBusinessDate` の欠落が起きないこと

### M-05 勤怠修正承認導線（深夜帯含む）

- 手順:
  1. 深夜帯を含む勤怠を作成
  2. 修正申請を承認
- 期待結果:
  - `actualWorkMinutes` / `nightWorkMinutes` が期待どおり
- 重点確認:
  - 深夜休憩控除ロジック

### M-06 LINE Webhook 実イベント連携

- 手順:
  1. 実 LINE イベントを送信
  2. Functions 側ログとアプリ側反映を確認
- 期待結果:
  - Webhook 受信〜処理完了まで正常
  - `asia-northeast1` 側関数で処理される

## 3. 実機確認時の記録テンプレート

各項目ごとに以下を記録する。

- 実施日時（JST）
- 実施者
- 端末/アプリバージョン
- 手順結果（成功/失敗）
- 失敗時スクリーンショット/ログURL
- 再現条件

## 4. 補足

- 外部状態（Functions/Queue/Scheduler/Secret/IAM）は自動検証で `asia-northeast1` 整合を確認済み。
- 本資料は「自動検証で代替できない実操作確認」に限定している。
