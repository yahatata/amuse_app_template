# 環境変数きれい化 改善の進め方（仕様詳細化とフェーズ設計）

作成日: 2026-03-30

## このドキュメントの目的

`仕様書/tobe仕様書_全体像.md` を起点に、どの順番で仕様を詳細化し、実装前準備を進めるかを明確にする。

## 決定事項（今回確定）

- `monthlyPayrollTrigger` は削除する（手動給与計算運用へ統一）。
- フェーズの順序・粒度は、全仕様の詳細確定後に再検討して決定する。
- `tobe仕様書_全体像.md` に記載されているフェーズ分けは、**現時点の案**として扱う。
- 進め方は、既存提案に追加推奨項目を加えた運用で進める。

## 作成フロー（確定版）

1. 全体仕様書を基に、以下4区分の詳細仕様書を作成する。  
`scheduler To-Be` / `コード固定 To-Be` / `Secret Manager To-Be` / `実行環境注入のまま使うものの To-Be`
2. 各詳細仕様書で、As-Is確認結果・To-Be仕様・変更対象・影響範囲・テスト観点を明記する。
3. 詳細仕様書の内容を横断レビューし、矛盾・依存関係・未決事項を解消する。
4. `monthlyPayrollTrigger` は削除方針を前提に、影響範囲（参照・テスト・運用導線）を確定する。
5. **全詳細仕様の確定後に初めて**、フェーズを作成する。
6. フェーズごとにフォルダを作成し、「どのフェーズがどの仕様範囲を担うか」を対応付けた管理ファイルを作成する。
7. 各フェーズで `changeSpec` を作成し、詳細仕様の反映漏れがない状態で実装・テストに進む。
8. 各フェーズ完了時に、サマリ・他フェーズへの伝達事項・未解決事項を記録し、次フェーズへ進む。

## 各フェーズで実施する標準ステップ（確定）

1. As-Isコードと直近修正の確認
2. 当該フェーズの `changeSpec` 作成
3. 必要テストの検討
4. 実装（必要に応じてユーザー依頼が必要な GCP 操作を明文化して依頼）
5. テスト実行
6. サマリ作成と引き継ぎ事項の記録

## 追加推奨項目（採用）

- 各フェーズに `Entry条件` / `Exit条件` / `ロールバック条件` を定義する。
- GCPコンソール作業が必要なフェーズは、依頼テンプレート（目的・操作手順・確認項目）を事前に用意する。

## フェーズ案の扱い（暫定）

- 現在の `tobe仕様書_全体像.md` のフェーズは、あくまで暫定案として保持する。
- 最終的なフェーズ順序・粒度・担当範囲は、詳細仕様確定後に再決定する。
