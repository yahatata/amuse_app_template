## 🔴 リリース前必須タスク

### PRE-01〜04: DeviceOption 実機検証（人間担当・4項目セット）

**何をするか:**  
各端末の DeviceOption 設定（Firestore の `optionKeys`）に対して、対応するボタンが正しくグレーアウト・アクティブになっているかを実機で確認する。

**なぜ必要か:**  
G1 で端末オプション連動のボタン制御ロジックを実装済みだが、実機での精度検証がまだ行われていない。  
誤ったボタン制御のまま営業開始すると「使えないはずの機能が使えてしまう」「使えるはずのボタンがグレーになる」などのオペレーション事故が発生する。

**確認内容:** `01_タスク一覧.md` の PRE-01〜04 チートシートを参照  
**担当:** 人間（Firestore で端末オプションを変えながら実機確認）  
**実施条件:** G1 の人間確認（G1-01/02/03）が完了してから実施

**何をするか:**  
G1 で実装済みのホーム画面（Terminal・Admin）を実機で確認する。

**確認内容:** `docs/UIデザイン調整/G1_ホーム画面/確認手順.md` を参照

### G6-02: `debugPrint` の削除

**何をするか:**  
`lib/tournament/scheduling/pages/create_single_tournament_page.dart` 等に残存している `debugPrint` 文を削除する。

**なぜ必要か:**  
`debugPrint` はデバッグビルドでのみ出力されるが、コードに残したままにするとリリース時の品質として問題がある。また、誤ってデバッグ情報が残ったまま本番運用になることを防ぐため。  
リリース前に必ず削除することを明示的に決定済み。

**担当:** AI（1〜2 ファイルの単純削除）  
**工数:** 10 分程度  
**実施タイミング:** リリース直前のコードフリーズ前に実施

---

### G6-08: 閉店ダイアログの内部実装情報露出

**何をするか:**  
閉店操作時に表示されるダイアログに `storeMeta` や Cloud Function の内部変数名がそのまま表示されている箇所を、ユーザー向けの適切な文言に修正する。

**なぜ必要か:**  
本番環境でユーザー（スタッフ）が内部実装の変数名やシステム用語を目にすることになる。  
セキュリティ上のリスクは低いが、ユーザーに不信感を与える・システム上の問題と誤解される可能性がある。

**担当:** AI（文言修正）  
**工数:** 1h  
**実施タイミング:** できれば G1 確認と並行して実施
