# G2 設計・方針

作成日: 2026-09-10

---

## なぜこの修正が必要か

`shiftMenuPage` と `businessDayMenuPage` の2ページで、Redmi Pad SE 11" の横向き表示時に
**「BOTTOM OVERFLOWED BY XX PIXELS」** エラーが発生している。

**原因:**
ボタンの高さを `screenHeight`（デバイスの画面全体の高さ）から引き算で計算しているが、
Redmi の画面下部にある**ソフトウェアナビゲーションバー（戻る・ホームボタン = 約48pt）**の分が引かれておらず、
実際の表示領域より大きな値が計算されてしまっている。

```dart
// ❌ 修正前: 画面全体高さ から引き算するが、ナビバーが考慮されていない
final screenHeight = MediaQuery.of(context).size.height;
final buttonHeight = (screenHeight - kToolbarHeight - 48 - 16) / 2 - 12;
//                                                  ↑
//                                          決め打ちの -48 が実際の値と一致しない
```

---

## 修正方針

**`LayoutBuilder` に切り替える代わりに、`Expanded` を使う。**

`Expanded` は「残った高さをすべて使う」ウィジェットで、サイズの計算が一切不要。
どんなデバイスでも自動的に画面に収まる。

```dart
// ✅ 修正後: Expanded が残り高さを自動で埋める（計算不要・overflow不可能）
body: Padding(
  padding: const EdgeInsets.all(24.0),
  child: Column(
    crossAxisAlignment: CrossAxisAlignment.stretch,
    children: [
      Expanded(child: ElevatedButton(...)),  // 残り高さの半分
      const SizedBox(height: 16),
      Expanded(child: ElevatedButton(...)),  // 残り高さの半分
    ],
  ),
),
```

---

## なぜ `LayoutBuilder` を使わないか

このページの構造（2ボタンを均等に並べるだけ）では `Expanded` が最もシンプルで安全。
`LayoutBuilder` は「計算した高さを子ウィジェットに数値で渡す必要がある場合」に使う。
今回は `Expanded` で完結するため不要。

## 対象外・しないこと

| 内容 | 理由 |
|-----|-----|
| `shiftHomePage`・カレンダーページ | 実機でoverflowが確認されていない。スクロール可能な構造のため影響なし |
| `dashboard_home_page` 等の特殊ページ | 重要度中の残タスク（G2-09/10/11）として別セッションで対応 |
| GridViewのcrossAxisCount動的化 | overflow非発生。重要度低の残タスク（G2-08）として後回し |
| 大掛かりな設計フェーズ | 今回の修正は原因・対策とも明確なため不要 |
