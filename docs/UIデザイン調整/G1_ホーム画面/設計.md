## 問題の再確認

### Terminalホーム（`lib/Home/terminalHomePage.dart`）

1. **16ボタンが1画面に収まらない**
   - 原因A: `buttonHeight = (screenHeight - kToolbarHeight - 80) / 2.3` という計算式でボタンが縦に大きすぎる
   - 原因B: ステータスバー・ジェスチャーバーの高さを引いていない
   - 結果: 複数端末でOverflow発生

2. **視覚的な整理が一切ない**
   - 全16ボタンがテキストのみ・同サイズ・同色で並んでいる
   - カテゴリの区別なし・重要度の差なし

3. **ラベルが英語混在**
   - "sideGame" / "Tournament 作成" / "Tournament Home" がそのまま表示

### Adminホーム（`lib/Home/adminHomePage.dart`）

1. **一部端末でOverflow**（G2-03と共通原因）

2. **視覚的な整理がない**（Terminalと同様）

3. **通知ベルアイコンが白くて見えない**
   - AppBarのベルアイコンに `color: Colors.white` が設定されているが、AppBar背景色が明るい場合に同化する

### 方針2: ボタンサイズの見直し

- 現在の大きすぎるボタン（`/ 2.3` の高さ計算）を廃止
- `LayoutBuilder` で利用可能な高さを正確に取得し、ボタン高さを動的に計算する
- 目標: 全ボタンが1画面に収まる高さ（スクロールなしで全カテゴリが見える）
- 安全弁として `SingleChildScrollView` でラップし、万一計算がずれてもOverflowにならないようにする

推奨ボタン高さの試算（11インチ横向き）:
```
利用可能高さ ≈ 800px（論理）- 56px（AppBar）- padding.top - padding.bottom
カテゴリヘッダー: 約28px × 6カテゴリ = 168px
ボタン行: 16ボタン / 4列 = 4行 → 行高さ = (残り高さ - gap) / 4
目標ボタン高さ: 64〜80px程度
```

## 追加確定事項（2026-09-10 デモ確認後）

### DeviceOptions非保有ボタンの扱い

- **決定: グレーアウト（非表示から変更）**
- 理由: 非表示より「存在するが使えない」が分かりやすい
- 実装: `_isBtnActive()` でアクティブ判定し、非アクティブ時は`HomeButtonGreyTheme`のスタイルを適用
- タップ: グレーアウト時は完全無効（onTap = null）

### ボタンレイアウト確定値

**Terminal（全オプション時 / Admin端末のTerminalモード）:**
- 3行ペア（行内に2カテゴリ × 最大6ボタン）
- Row1: 営業(3) + ユーザー(3) = 6ボタン
- Row2: 会計(3) + 注文(2) = 5ボタン（右端1スロット空き）
- Row3: Tournament(4) + SideGame(1) = 5ボタン（右端1スロット空き）
- スロット数: 6、btnW = (availW - 2×14 - 4×10 - 22) / 6

**Admin:**
- 2行ペア（行内に2カテゴリ × 最大5ボタン）
- Row1: シフト管理(2) + 勤怠(2) = 4ボタン（右端1スロット空き）
- Row2: スタッフ管理(2) + 設定・分析(3) = 5ボタン（フル埋め）
- スロット数: 5、btnW = (availW - 2×14 - 3×10 - 22) / 5
- ボタン高さ上限: btnW（正方形）、余剰スペースは上下均等配分

**共通レイアウト定数:**
| 定数 | 値 | 説明 |
|-----|---|-----|
| `_hPad` | 14.0 | 左右パディング |
| `_vPad` | 10.0 | 上下パディング |
| `_btnGap` | 10.0 | カテゴリ内ボタン間隔 |
| `_catDividerGap` | 22.0 | カテゴリ間隔 |
| `_rowGap` | 16.0 | 行間 |
| `_headerH` | 18.0 | カテゴリヘッダー高さ |
| `_headerGap` | 6.0 | ヘッダー→ボタン間隔 |
