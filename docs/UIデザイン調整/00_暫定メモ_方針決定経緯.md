## 決定②：ホーム画面の構成方針

### 採用案：ボタン小さくしてカテゴリヘッダー表示

**採用しない案:**
- 案A（ボタン統合 + サブページ）: DeviceOptionのフィルタリングが2層になり複雑化するため不採用
- 案B（NavigationRail）: 全ボタンを1画面で見渡せないため不採用
- 案C（Dashboardタイル型）: 主要/その他の境界設計コストが高いため不採用

**採用する方針の内容:**
- 現状の全ボタンリストを維持（統合しない）
- ボタンを小さくして全ボタンを1画面に収める
- カテゴリ別にヘッダーバーを表示して視覚的に分類する
- 各ボタンにアイコンを追加する
- カテゴリ別にカラートーンを統一する
- buttonHeightの計算式を修正してOverflowを解消する
- crossAxisCountを画面幅ベースで動的計算する

**この方針の優位性:**
- DeviceOptionのフィルタリングが現状コードのまま機能する
- カテゴリ内ボタンが全非表示の場合、ヘッダーごと非表示にできる
- 各ボタンから遷移先へ直接（1タップ）のまま
- 実装変更量が最小

### 11インチ横向きでの収まり試算
- 利用可能高さ: 約720px（画面高さ〜800px - AppBar 56px - padding）
- カテゴリヘッダー: 24px × 6カテゴリ = 144px
- ボタン行: 64px × 4行（4列×4行=16ボタン） = 256px
- パディング/gap: 約100px
- 合計: 約500px → 720pxに収まる ✅

## 決定③：レスポンシブ対応の基本方針

### 高さ計算のOverflow修正

**方針：計算式の正確化 ＋ スクロール化（組み合わせ）**

- `MediaQuery.of(context).size.height` から `kToolbarHeight` だけを引く現状の計算式を、ステータスバー・ジェスチャーバーを加味した正確な計算式に修正する
  ```dart
  // 修正後
  final padding = MediaQuery.of(context).viewPadding;
  final availableHeight = screenHeight - kToolbarHeight - padding.top - padding.bottom;
  ```
- さらに `SingleChildScrollView` でコンテンツを包み、万一計算が合わない端末でもOverflowエラーが出ないようにする
- 「推奨端末では完全表示・その他でもエラーは出さない」という目標を両方満たす

**対象画面の分類**

| グループ | 方針 | 対象ファイル |
|---------|------|------------|
| 通常対応（計算式修正 + スクロール化） | 基本対応 | shiftMenuPage, businessDayMenuPage, adminHomePage, terminalHomePage, shiftHomePage, scheduled_tournament_in_calendar_page, create_tournament_from_calendar_page |
| 特別対応（要個別検討） | 実装時に詳細検討。スクロール不可または部分スクロール等の特別対応をする | dashboard_home_page, table_detail_page, side_game_table_home |

**特別対応に関する制約**
- 特別対応3ファイルについては、通常対応の実装と同タイミングで必ず対応方針を決め切ること（先送り禁止）

### グリッドの列数

**方針：`LayoutBuilder`で画面幅に応じて動的計算**

```dart
// 例
crossAxisCount: (constraints.maxWidth / 160).floor().clamp(3, 6)
```

## 決定⑤：テーマ整備の範囲と順序

**方針：定義 + 主要箇所だけ修正（B案）**

- `lib/core/theme/app_theme.dart`（仮）等にテーマファイルを新規作成し、カラーパレット・TextTheme・ButtonThemeを定義する
- **既存コードの全置換はしない**。定義したテーマを以下の主要箇所にのみ適用する
  - AppBar（全画面）
  - ホーム画面（admin/terminal）のボタンスタイル
  - 主要な`ElevatedButton`スタイル
- 新規実装コードは必ずテーマを参照するルールにする（直書き禁止）
- 工数目安：4〜6h

## 決定⑦：Terminalモードインジケーターの実装方式

**方針：グローバルオーバーレイ（B案）**

AdminがTerminalモードに切り替えている間、アプリ全体の最上部に細いバナーを常時表示する。

```
┌──────────────────────────────────────┐
│ ▌ Terminal モード中                   │  ← 常時表示バナー
├──────────────────────────────────────┤
│ AppBar（各サブページのタイトル）        │
├──────────────────────────────────────┤
│ コンテンツ                            │
└──────────────────────────────────────┘
```

- 変更箇所：`AdminHomePage` + アプリルートWidget（数行追加のみ）
- 全サブページで自動的に表示される（新規ページ追加時も対応不要）
- 工数目安：1〜2h
