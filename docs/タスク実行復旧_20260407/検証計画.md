# 検証計画（タスク投入・自動投入・実行を網羅）

作成日: 2026-04-07

## 1. 検証方針

目的は「今回直した箇所が再発しないこと」の確認であり、以下を全フローで揃える。

1. 手動で task を投入できる
2. scheduler から自動投入される
3. task 実行が成功する（HTTP 2xx）
4. 処理結果が期待どおり残る（副作用確認）

運用方針:

- 可能な限り CLI で自動確認する（ユーザー手動は最小化）
- 今回はテンプレアプリ前提のため、フル本番相当検証を許容する（D-05 決定事項）
- 実行ログは「成功」「失敗」「再試行」を分けて記録する

## 2. 検証対象フロー

## 2.1 Assessment queue 系

対象:

- `openAssessmentTask`
- `closeAssessmentTask`
- queue: `business-date-assessment-queue`

確認項目:

- body 付き task が投入される
- 400 を返さず実行完了する
- 想定ドキュメント更新が発生する

## 2.2 Weekly planner 連鎖

対象:

- `scheduled-job-weekly-planner`
- downstream で生成される open/close task

確認項目:

- weekly planner 実行時に task 作成が失敗しない
- SA `NOT_FOUND` / 権限エラーが出ない

## 2.3 Tournament enqueue 系

対象:

- `scheduled-job-enqueue-tournament-tasks-by-scheduler`
- queue: `tournament-queue`（関連 queue 含む）

確認項目:

- `default-store` 由来のエラーが出ない
- task 生成から実行まで完走する

## 2.4 Payroll task queue 系

対象:

- `processPayrollNotifications`
- `processStaffPayroll`
- `finalizePayrollRun`

確認項目:

- task upsert が失敗しない
- 実行時エラーが出ない
- 期待する状態遷移が確認できる

## 2.5 Scheduler supervisor 系

対象:

- `schedulerSupervisor`
- scheduler execution logs 書き込み

確認項目:

- `reason: undefined` 由来の Firestore write error が再発しない
- supervisor 実行結果のログが正常保存される

## 3. 実行手順（CLI中心）

## 3.1 事前確認

- Functions / Queue / Scheduler の対象一覧を取得
- 失敗中タスク数を記録

## 3.2 手動投入テスト

- 各対象 queue に最小 payload で task を 1 件投入
- 実行ログで 2xx を確認

## 3.3 自動投入テスト

- 対象 scheduler jobs を `run` で起動
- queue に task が作成されることを確認
- 作成 task が実行完了することを確認

## 3.4 副作用確認

- 対象関数ごとに代表的な更新先（Firestore ドキュメント等）を確認
- 失敗時は task payload と関数ログを照合し、再現手順を残す

## 3.5 再試行/滞留確認

- 各 queue の pending/retry 数を確認
- 400/500 の連続再試行がないことを確認

## 4. 合格基準（PASS 条件）

- 対象フローで task 投入が成功する
- scheduler 経由の自動投入が成功する
- 実行ログに 400/500 の連続発生がない
- 主要副作用が期待どおりである
- 失敗タスクが滞留し続けない

## 5. 失敗時の切り分け順

1. queue 側（task body / header / scheduleTime / retry）
2. auth 側（OIDC SA 存在、権限）
3. function 側（payload validation、runtime config）
4. downstream 側（Firestore 書き込み、設定値不整合）

## 6. ユーザーの手間を最小化するための運用

- エージェント側で実行できる確認は、基本すべてエージェントで実施
- ユーザー依頼は以下のみに限定:
  - 必要時の権限昇格実行
  - 最終受け入れとして業務画面の目視確認（フル検証結果の受け入れ確認）

## 7. 今回追加予定の補助物

- 検証コマンドをまとめたスクリプト（`scripts/` 配下）
- 実行結果サマリ（PASS/FAIL と根拠ログ）
- 新規店舗導入時に再利用できるチェックリストへの転記
