# 実施手順（外部操作・CLI）

この手順は、今回のタスク復旧を実施するためのコマンドレベル手順です。  
実行前に `要判断事項.md` の D-01〜D-05 を確認し、未決定項目は決定してから進めること。

決定済み前提:

- D-01: 段階移行（復旧後に `default-store` 依存を排除）
- D-02: Task 実行 SA は `tasks-invoker@...` へ統一
- D-03: 失敗タスクはピンポイント削除
- D-04: `us-central1` 残存は今回作業内に段階移行フェーズを含める
- D-05: 本番相当フル検証を実施

## 0. 前提セット

```bash
export PROJECT_ID="amuse-app-template"
export REGION_ASIA="asia-northeast1"
export REGION_US="us-central1"
export PROJECT_NUMBER="$(gcloud projects describe "$PROJECT_ID" --format='value(projectNumber)')"
```

## 1. 現状スナップショット

```bash
gcloud functions list --project "$PROJECT_ID" --gen2 \
  --format="table(name,region,state,environment)"

gcloud tasks queues list --project "$PROJECT_ID" --location "$REGION_ASIA" \
  --format="table(name,state)"

gcloud scheduler jobs list --project "$PROJECT_ID" --location "$REGION_ASIA" \
  --format="table(name,state,schedule,timeZone)"
```

## 2. 失敗タスク（malformed）の確認と削除

## 2.1 対象タスク確認

```bash
gcloud tasks list \
  --project "$PROJECT_ID" \
  --location "$REGION_ASIA" \
  --queue "business-date-assessment-queue" \
  --limit 50
```

## 2.2 削除実行（対象限定）

```bash
# 例: 個別 task を削除
gcloud tasks delete "TASK_ID" \
  --project "$PROJECT_ID" \
  --location "$REGION_ASIA" \
  --queue "business-date-assessment-queue"
```

注記:

- 削除対象の範囲は D-03 の判断に従う
- 一括削除を行う場合は、実行前に task ID 一覧を保存する

## 3. SA / IAM の確認

## 3.1 SA 存在確認

```bash
gcloud iam service-accounts list --project "$PROJECT_ID" \
  --format="value(email)"
```

## 3.2 選択した SA への権限付与（例）

```bash
export DEPLOY_SA_EMAIL="github-functions-deployer@${PROJECT_ID}.iam.gserviceaccount.com"
export COMPUTE_SA="${PROJECT_NUMBER}-compute@developer.gserviceaccount.com"
export APPSPOT_SA="${PROJECT_ID}@appspot.gserviceaccount.com"

gcloud iam service-accounts add-iam-policy-binding "$COMPUTE_SA" \
  --project "$PROJECT_ID" \
  --member="serviceAccount:${DEPLOY_SA_EMAIL}" \
  --role="roles/iam.serviceAccountUser"

gcloud iam service-accounts add-iam-policy-binding "$APPSPOT_SA" \
  --project "$PROJECT_ID" \
  --member="serviceAccount:${DEPLOY_SA_EMAIL}" \
  --role="roles/iam.serviceAccountUser"
```

注記:

- 実際の SA 名は D-02 の選択に合わせる
- 追加ロールは最小権限で付与する

## 7. 失敗時の優先確認ポイント

1. `HTTP 400`:
   - task body が空でないか
   - Content-Type が `application/json` か
2. `NOT_FOUND`:
   - OIDC SA が存在するか
3. `PERMISSION_DENIED`:
   - SA の role/binding が不足していないか
4. Firestore write error:
   - `undefined` フィールド混入がないか
