# カテゴリD: 導入フロー設計 — 検討時叩き1

> 作成日: 2026-06-23  
> 目的: 新規店舗への導入に関するフロー設計・テスト・マニュアル作成タスクの概要を整理する

---

## D-1: 店舗導入フローの設計

### 概要
新規店舗にシステムを導入する際のステップを定義する。
`amuse_app_template` をテンプレートとして次店舗に適用する手順の整理が主目的。

### 主な検討事項
- Firebase プロジェクトの新規作成手順（環境変数・Secret Manager の初期設定含む）
- `storeMeta/config` の初期値設定手順（どの項目を最初に設定すべきか）
- スタッフ初期登録・管理者アカウント発行の手順
- amuse-admin への店舗追加手順（中央管理アプリへの登録）
- 初回デバイス設定・ログイン確認手順

### 残タスク
- [ ] 導入ステップの全体フローを定義（ゼロから本番稼働までの順序）
- [ ] amuse_app_template テンプレート適用手順の整理
- [ ] amuse-admin への店舗追加手順の整理
- [ ] 各ステップの所要時間・担当者の整理

## D-2: デバイス設定フローの設計・テスト

### 概要
Flutter アプリをデバイスにインストールし、各デバイス種別ごとに初期設定を行う手順を確立する。

参照: `docs/デバイスの再ダウンロード・アップデート時の挙動について.md`

### デバイス種別
| 種別 | role | 用途 |
|-----|------|------|
| admin | admin | 管理者操作（スタッフ管理・設定変更等） |
| terminal | terminal | フロント端末（受付・会計） |
| table | table | テーブルデバイス（各卓） |

### 残タスク
- [ ] Flutter アプリのデバイスへのインストール・初回設定手順の整理
- [ ] デバイス種別ごとの初期設定手順書の作成
  - パスコード・認証設定
  - role 割り当て手順
  - LINE / LIFF との連携設定
- [ ] デバイス再インストール時の挙動確認（既存データへの影響）
- [ ] アップデート配布手順の確立

## D-3: LINE / LIFF 設定フローの設計・テスト

### 概要
LINE 公式アカウントの設定から LIFF アプリ連携までの手順を整理する。
カテゴリE の外部サービス設定（E-1）と連動する。

### 対象
- ユーザー向け LIFF（`public/user/`）
- スタッフ向け LIFF（`public/staff/`）
- LINE リッチメニューの設定

### 残タスク
- [ ] LINE 公式アカウントの作成から LIFF 登録までの手順書作成
- [ ] リッチメニューの設定手順書作成（画像・アクション設定含む）
- [ ] スタッフ LIFF の設定手順書作成
- [ ] Webhook URL 設定・疎通確認手順の整理
- [ ] LINE 設定後の実機テスト手順の定義

## D-4: 導入マニュアルの作成

### 概要
上記 D-1〜D-3 の設計・テスト結果を踏まえて、実際に導入担当者が使用するマニュアルを作成する。

### 成果物（予定）
- 店舗導入チェックリスト（ゼロから本番稼働までの全ステップ一覧）
- 初期設定マニュアル（`storeMeta/config` の設定値の決め方と入力手順）
- 導入時トラブルシューティング集

### 残タスク
- [ ] 導入チェックリストの作成（D-1 完了後）
- [ ] 初期設定マニュアルの作成（config 項目の解説含む）
- [ ] よくあるトラブルと対処法の整理（D-2, D-3 のテスト中に収集）

---

## 進め方の方針
1. **D-1 → D-2 → D-3** の順で設計・テストを進める
2. **D-4 は D-1〜D-3 完了後**に成果物として作成
3. カテゴリE（外部サービス設定）と並行して進める部分あり（特に LINE 設定）
4. 導入フローのテストは実際に第2店舗への導入準備時に実施するのが理想
