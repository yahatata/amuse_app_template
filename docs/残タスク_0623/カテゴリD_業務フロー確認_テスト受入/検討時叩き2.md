# カテゴリD: 業務フロー確認・テスト受入 — 検討時叩き2

> 位置づけ: function 単位の整理をもとに、業務フロー単位で受入判定を出す工程

---

## このカテゴリで答える問い

- 実際の業務フローとして、一連で使って問題ないか
- どのフローを実機確認し、どのフローを自動テストで補えるか
- バグが見つかった場合、どの順で修正と再確認を回すか
- 最終的に営業開始してよい状態か

---

## 目標と実施内容

| 目標 | 実施内容 | 主な成果物 |
|---|---|---|
| 業務フローを網羅する | Flow 単位で `誰が / どの画面で / 何をして / 何が起きるか` を整理する | Flow Master |
| テスト観点を明文化する | 正常系、異常系、境界条件、権限差分、実機必須条件を定義する | テスト実行台帳 |
| 実行結果を記録する | 自動テスト、DB 確認、ログ確認、実機確認を実施して記録する | 実行結果記録 |
| 不具合を収束させる | 不具合起票、修正、再確認を繰り返し、go / no-go を決める | 不具合台帳、出荷判定メモ |

---

## このカテゴリで作成する資料

| 資料名 | 目的 | 資料だけで完了か |
|---|---|---|
| Flow Master | 業務フロー単位の正本 | いいえ |
| テスト実行台帳 | テスト観点と実行結果の記録 | いいえ |
| 不具合台帳 | 修正と再確認の追跡 | いいえ |
| 出荷判定メモ | 最終判断の記録 | いいえ |

---

## サブタスク

### D-1: Flow Master の作成

- 業務カテゴリ、フロー名称、完了条件、重要度、営業開始必須かを整理する
- 画面、操作者、起動 function、確認方法を紐付ける
- C の Function-Flow対応表を流用する

### D-2: テスト観点の詳細化

- 正常系、異常系、境界条件、権限差分、タイミング依存を洗い出す
- 実機必須かどうかをフロー単位で記録する
- 1回の操作で複数観点を確認できるように手順を組む

### D-3: 実行と記録

- 自動テスト、DB 確認、ログ確認、実機確認を実施する
- pass / fail / pending を記録する
- 時期制約のある確認事項は別管理で残す

### D-4: 不具合ループと出荷判定

- release blocker は即修正して再確認する
- 軽微なものは後回し可否を明示する
- 営業開始可否を最終判定する

---

## 完了条件

- 営業開始必須フローがすべて Flow Master に載っている
- 実機必須フローの確認が完了している
- release blocker が 0 である
- 不具合の残件について、営業開始可否の判断が明記されている
- 出荷判定メモが作成されている

---

## 他カテゴリとの依存

- C の Function/Contract台帳が前提資料になる
- A/B の修正が止まっていると D は回しにくい
- E/F/G の資料作成にも D の結果を使う
