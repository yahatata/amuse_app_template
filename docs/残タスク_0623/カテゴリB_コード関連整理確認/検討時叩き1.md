# カテゴリB 残タスク 検討時叩き 1

> このファイルはカテゴリB（コード関連の整理・確認系タスク）の概要をまとめた検討時叩き台です。  
> カテゴリAのような新機能実装ではなく、**既存実装の品質を本番レベルに引き上げるための整理・検証タスク**です。

## B-1: config 整理とデフォルト方針の確定

### 現状サマリ

loader の実装自体は整っている。以下は**実装済み**：

- `functions/src/shared/config/` に loader 4種（`configLoader` / `payrollConfigLoader` / `schedulerConfigLoader` / `getRequiredStaffByTimeSlot`）
- Flutter 側も `StoreConfigService` / `PayrollConfigService` 等が揃っている
- `storeMeta/config` / `storeMeta/payrollConfig` / `storeMeta/schedulerConfig` / `storeMeta/requiredStaffByTimeSlot` の分離も実施済み

**問題の本質:** 「読み取れなかったときに本当に defaults で続行してよいか」が設定ごとに整理されていない。会計・権限・自動実行系まで一律 defaults で継続すると本番事故につながるリスクがある。

### 残タスク

#### 1. runtime 設定の全項目一覧化

- 現在 `storeMeta` 配下に読まれている設定項目を網羅的にリストアップする
- 対象: `config` / `payrollConfig` / `schedulerConfig` / `requiredStaffByTimeSlot` の全フィールド

#### 2. 各設定を「読み取り失敗時の扱い」で分類する

以下の観点で全設定を分類する：

| 分類 | 説明 | 対象候補 |
|---|---|---|
| **fail-closed** | 読めなければ処理を止める or エラーを返す | 会計課金額・権限系・scheduler 有効化・給与計算基準日 |
| **last-good** | 読めなければ最後の成功値を維持する | 営業時間設定・表示に影響するが即時停止不要なもの |
| **defaults で継続** | 読めなければ defaults で続行して問題ない | 表示補助・UI 挙動系 |

#### 3. ユーザー判断が必要な決定事項

| 決定事項 | 選択肢 | 推奨 |
|---|---|---|
| fail-closed にする設定の範囲 | 上表「対象候補」を承認・修正 | ユーザー確認必須 |
| 店舗別デフォルトの持ち方 | ①共通のみ / ②店舗ごと初期値セット / ③共通 + 初期化 callable で補正 | ③推奨（既存 `initializeStoreConfigCallable` を活用） |
| クライアント直読みにする範囲 | ①表示補助系のみ / ②ほぼ全部直読み / ③重要設定は callable 経由 | ①③組み合わせ推奨 |

#### 4. docs とコードのズレ解消

- `docs/運用時資料/設定/storeMeta/configによる設定の詳細/features.md` 等が実装より古い記述になっている
- 一覧化した設定項目をもとに運用資料を最新化する

#### 5. loader の可読性整頓（任意）

- fallback 発生時のログや fallback 理由が追いにくい箇所の改善
- 必須ではないが、運用中の障害調査コストを下げる

### 完了の定義

- 全設定が一覧化されている
- fail-closed / last-good / defaults の分類が設定ごとに決まっている
- 店舗別デフォルトの持ち方が決まっている
- Flutter / Functions の直読み範囲の役割分担が明文化されている

### 参照ドキュメント

- `docs/残タスク整理/06_config整理とデフォルト方針/`（README・やること整理・仕様整理）
- `functions/src/shared/config/`（loader 実装）
- `lib/services/store_config_service.dart` / `payroll_config_service.dart`

## B-4: 不要 Function の整理・削除 + 環境変数整理

### 概要

`unused_function_lib/` に格納された 21 件の Functions を整理し、本当に不要なものを削除する。合わせて環境変数（`process.env`）の使用状況を整理し、基本的に環境変数を使わない方針に揃える。

### 主な作業内容（詳細は実施時に整理）

#### Functions 整理

- `unused_function_lib/` の 21 ファイルを `live / legacy / parked / 削除候補` に分類
- `index.ts` の export と実際に使われている functions の整合確認
- remote にのみ残存している functions の確認・削除
- 削除前にクライアントから呼ばれていないかの最終確認

#### 環境変数整理

- **方針: 環境変数（`process.env`）は基本的に使わない**
- ライブコード側で残っている `process.env` 参照（`CENTRAL_PROJECT_ID`・`SINGLE_STORE_PER_PROJECT_MODE` 等）を整理
- `docs/環境変数きれい化/` の Phase G.1 残件の完了
- `unused_function_lib/` のみで参照されている環境変数（`STORE_CLOSE_HOUR` 等）はファイル削除時に自動消滅するため確認のみ
