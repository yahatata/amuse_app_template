# カテゴリI: 中央管理アプリ — 検討時叩き2

> 位置づけ: `amuse-admin` 側の改善・監視補強・通知確認を扱う工程  
> 備考: 実装本体は `amuse-admin` リポジトリ側で進める。このフォルダでは残タスク整理と完了判定を管理する

---

## このカテゴリで答える問い

- `amuse-admin` は日常運用で十分使いやすいか
- scheduler / error / task 監視に不足がないか
- 通知や anomaly の補助機能が、本当に必要な粒度まで整っているか

---

## 目標と実施内容

| 目標 | 実施内容 | 主な成果物 |
|---|---|---|
| エラー運用を効率化する | ルール登録ショートカット、一括操作などの改善を行う | 改善仕様、受入記録 |
| 監視の不足を補う | blockers、central write health、都度 Task タブ要否を整理する | 監視改善メモ、判断記録 |
| 通知を実運用できる状態にする | LINE 通知設定と疎通確認を行う | 通知確認記録 |
| ドキュメント反映を漏らさない | 改善結果を `amuse-admin/docs/` に反映する | 反映メモ |

---

## このカテゴリで作成する資料

| 資料名 | 目的 | 資料だけで完了か |
|---|---|---|
| 改善仕様メモ | 何を変えるか、何を変えないかを固定する | いいえ |
| 受入記録 | UI 改善や通知確認の結果を残す | いいえ |
| 監視判断記録 | 都度 Task タブなどの存続判断を残す | いいえ |
| ドキュメント反映メモ | `amuse-admin/docs/` 更新箇所を管理する | いいえ |

---

## サブタスク

### I-1: エラー詳細からのルール登録ショートカット

- `functionEntry` `errorKey` `service` の入力補助を実装する
- 粒度が細かくなりすぎないように注意点も残す

### I-2: エラー一括操作

- チェックボックス選択
- 一括対応済み
- 一括 assessment 設定
- 誤操作防止の確認ダイアログ

### I-3: blockers / central write health の補強

- blockers の anomaly 化方針を決める
- central write health の検知と表示方針を整理する

### I-4: 都度 Task 監視タブの存続判断

- 観察期間を設ける
- このタブでしか気づけなかったケースがあるか確認する
- 存続 / 削除を決める

### I-5: LINE 通知送信機能の疎通確認

- 通知用 LINE 設定
- Secret 登録
- 通知先登録
- テスト通知実施

---

## 完了条件

- `amuse-admin` 側の改善項目について、実装可否と優先度が整理されている
- 採用した改善は実装・デプロイ・確認まで完了している
- 通知機能は実疎通確認まで終わっている
- `amuse-admin/docs/` 側の更新が必要なものは反映先が明確になっている

---

## 他カテゴリとの依存

- F-2 の中央通知設定と I-5 は連動する
- G-3 の技術資料には I の結果を反映する
- B-2 の scheduler / central write 確認結果を I-3/I-4 の判断に使う
