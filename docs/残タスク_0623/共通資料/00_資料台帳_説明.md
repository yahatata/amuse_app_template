# 00_資料台帳_説明

> 概要: `00_資料台帳.xlsx`（将来: `ART-001_資料台帳.xlsx`）の目的、管理対象、列定義、更新ルール、利用方法を定める説明資料  
> 主な目的: 全 ART 資料の正本管理、登録漏れ防止、資料間参照の可視化、更新運用の標準化  
> 正本区分: sheet正本の説明資料  
> 対象: `docs/残タスク_0623` および `docs/業務管理資料` 配下の正式資料（ART-xxx）全般。TSK 資料は対象外（`ART-902_タスク管理台帳` で管理する）
> 更新区分: 変更時  
> 参照元: `ART-002 01_資料ライフサイクル・更新ルール`  
> 参照先: `ART-003 02_用語・ステータス定義`; 各 ART 資料  
> 対応する workbook 名: `00_資料台帳.xlsx`（将来: `ART-001_資料台帳.xlsx`）  
> 主シート名: `資料一覧`  
> 1行の単位: `1資料（ART-xxx）= 1行`  
> 主な列: `資料ID`、`資料名`、`カテゴリ`、`資料区分`、`正本区分`、`正本ファイルパス`、`説明mdパス`、`主な目的`、`対象`、`更新区分`、`ライフサイクル状態`、`利用タイミング`、`参照元`、`参照先`、`備考`  
> 更新時の注意点: 行削除ではなく状態変更を優先する。TSK 資料はこの台帳に登録しない（ART-902 で管理）。正本変更時は関連資料の更新要否も確認する。列追加や意味変更の前に `ART-003 02_用語・ステータス定義` と `ART-002 01_資料ライフサイクル・更新ルール` の両方と整合を確認する

---

## 1. 位置づけ

`00_資料台帳` は、残タスク整理に関わる正式資料（ART-xxx）の目録である。  
この台帳は、各資料の中身そのものを説明する資料ではなく、次の内容を管理するための母艦として使う。

- どの ART 資料が存在するか
- どれが正本か
- どこに保存されているか
- 何のために存在するか
- いつ更新すべきか
- 他のどの資料と関係するか
- 現在どの状態にあるか

この台帳に書く事実は、資料本文の代替ではない。  
仕様や手順の内容は各資料の正本に持ち、`00_資料台帳` は「正本の所在と管理情報」を持つ。

TSK 資料（`TSK-xxx`）はこの台帳の対象外とする。TSK は `ART-902_タスク管理台帳` で管理する。

現時点の正本ファイルは `00_資料台帳.xlsx` / `00_資料台帳_説明.md` だが、再編後は `ART-001_資料台帳.xlsx` / `ART-001_資料台帳_説明.md` へ移設・改名する前提で運用する。  
ただし、実移設が完了するまでは、参照 path は現在の file path を正とする。

---

## 2. 管理対象

この台帳に登録する対象は、原則として次のいずれかに該当するものとする。

- md 自体が正本となる資料（`ART-xxx_資料名.md`）
- sheet が正本となる資料（`ART-xxx_資料名.xlsx`）
- sheet 正本に付随する説明用 md を持つ資料
- 今後の作成が確定または強く想定されている正式資料
- 営業開始前または導入開始後の運用で参照される正式資料

現時点で登録対象となる ART 資料は、`ART-900_全体再編方針.md` §5 の正式資料一覧に従う。  
具体的には `ART-001`〜`ART-304`（共通資料・実装定義台帳・確認実行テンプレ・導入手順書）が主な登録対象である。

**TSK 資料は登録しない。** TSK 資料（`TSK-xxx`）は `ART-902_タスク管理台帳` で管理する。

---

## 3. 管理対象外

次のものは、原則として `00_資料台帳` の登録対象外とする。

- `検討時叩き` などの検討用メモ
- 一時メモ、会話ログ、作業ログ
- function 1件ごとの詳細
- flow 1件ごとの詳細
- test case 1件ごとの詳細
- defect 1件ごとの詳細
- 単なるフォルダ
- 作成見込みのない一時資料

ただし、検討用資料であっても後に正式資料へ昇格させる場合は、その時点で `00_資料台帳` に登録する。

---

## 4. workbook 構成

本資料に対応する workbook は `00_資料台帳.xlsx` とする。  
原則は `1資料 = 1 workbook`、`1資料 = 1主シート` であるため、この workbook の主シートは `資料一覧` とする。

現時点の想定は次の通り。

- 主シート: `資料一覧`
- 補助シート: 原則なし

将来的に入力規則用の補助シートが必要になった場合は追加してよいが、その場合でも `資料一覧` が主シートであることは変えない。

---

## 5. 1行の単位

この台帳の 1 行は `1資料` を表す。

ここでいう `1資料` の扱いは次の通り。

- md 正本の資料: 1ファイル = 1行
- sheet 正本の資料: 1workbook = 1行
- sheet 正本 + 説明用 md: 2行に分けず、sheet 正本の 1 行にまとめる
- まだ未作成の資料: 正式に作る前提があるなら 1 行で登録してよい

`資料群` という単位は、初期整理では暫定的に許容する。  
ただし、`資料群` のままでは `1行1件` の粒度が粗くなりやすいため、実際の作成段階で子資料へ分割する見込みがある場合は、後で個別資料へ置換する。

---

## 6. 列の意味

主シート `資料一覧` では、以下の列を持つ。

| 列名 | 役割 | 記載ルール | 記入例 |
|---|---|---|---|
| `資料ID` | 資料の一意識別子 | 原則 `ART-xxx`。一度採番した ID は再利用しない | `ART-001` |
| `資料名` | 資料の正式名称 | ファイル名または成果物名と対応させる | `00_資料台帳` |
| `カテゴリ` | どの領域の資料か | `共通`、`B`、`C`、`D`、`E`、`F`、`G`、`H`、`I` など | `共通` |
| `資料区分` | 資料の種類 | `台帳`、`方針書`、`手順書`、`マニュアル`、`説明資料`、`チェックリスト`、`記録` など | `台帳` |
| `正本区分` | 正本の持ち方 | `md正本` または `sheet正本` | `sheet正本` |
| `正本ファイルパス` | 正本の保存先 | repo ルートからの相対パス。未作成は `TBD` | `docs/残タスク_0623/共通資料/00_資料台帳.xlsx` |
| `説明mdパス` | 対応する説明 md の保存先 | sheet 正本では原則必須。md 正本のみの資料では `該当なし` | `docs/残タスク_0623/共通資料/00_資料台帳_説明.md` |
| `主な目的` | 何のための資料か | 短く具体的に書く | `全資料の目録管理` |
| `対象` | 主な読者または利用対象 | 人、工程、領域のいずれでもよいが曖昧にしない | `開発者、資料作成者` |
| `更新区分` | どの頻度・契機で更新するか | `継続`、`変更時`、`節目`、`単発` | `継続` |
| `ライフサイクル状態` | 資料の現在状態 | `構想中`、`テンプレ確定`、`作成中`、`レビュー中`、`運用中`、`凍結`、`廃止予定`、`廃止済`、`アーカイブ` | `作成中` |
| `利用タイミング` | いつ使う資料か | `開発中`、`営業開始前`、`導入時`、`運用中`、`節目のみ` など | `開発中` |
| `参照元` | この資料を主に参照する資料 | `資料ID + 短い名称` を原則とする。複数ある場合は区切って記載 | `ART-002 01_資料ライフサイクル・更新ルール` |
| `参照先` | この資料が参照する資料 | `資料ID + 短い名称` を原則とする。複数ある場合は区切って記載 | `ART-003 02_用語・ステータス定義` |
| `備考` | 上記列に入らない補足 | 暫定事情、分割予定、制約などを書く | `将来個別資料へ分割予定` |

補足:

- `更新区分` の正式意味は `01_資料ライフサイクル・更新ルール` に従う
- `カテゴリ`、`資料区分`、`更新区分`、`ライフサイクル状態`、`利用タイミング`、`未確定値` の正式定義は `02_用語・ステータス定義` を正本とする
- `参照元` と `参照先` は、現時点ではこの台帳自体で管理する
- 独立した `03_資料対応表` は現時点では作成前提にしない

## 7. 入力規則と標準記法

この台帳では、少なくとも次の入力規則を持たせる。

- `カテゴリ`: 候補値リスト化する
- `資料区分`: 候補値リスト化する
- `正本区分`: `md正本` / `sheet正本`
- `更新区分`: `継続` / `変更時` / `節目` / `単発`
- `ライフサイクル状態`: `01_資料ライフサイクル・更新ルール` に定義された状態
- `利用タイミング`: 候補値リスト化する

入力規則の候補値そのものは、`02_用語・ステータス定義` に合わせる。  
この説明資料にある値は、初期設計の代表値であり、正式な候補値一覧は `02` を正本とする。

標準記法は次の通り。

- 日付: `YYYY-MM-DD`
- 時刻: `HH:mm`
- 日時: `YYYY-MM-DD HH:mm`
- タイムゾーンが意味を持つ場合: `JST` または `UTC`
- 真偽値: `TRUE/FALSE`
- 不明: `未確認`
- 将来確定予定: `TBD`
- 該当しない: `該当なし`
- 廃止済み: `廃止`
- パス表記: repo ルートからの相対パス
- 参照表記: `ID + 短い名称`
- 複数参照の区切り: `; `

色や装飾は補助として使ってよいが、意味は必ず列値でも持つ。

## 8. 更新ルール

### 8.1 新規資料を作る時

- 正式資料を作る前に、原則としてこの台帳へ登録する
- まだファイル未作成でも `構想中` または `作成中` で登録してよい
- path 未確定の場合は `TBD` を使う
- 既存資料で代替可能なら、新規資料は増やさない

### 8.2 既存資料を更新する時

- 資料名、正本区分、path、主な目的、更新区分、参照関係に変更がないか確認する
- 正本更新時は、関連資料の更新要否も確認する
- 意味変更を伴う更新と、体裁だけの更新を混同しない

### 8.3 分割する時

- 旧資料の行は削除せず、`廃止予定` または `廃止済` に変更する
- 子資料を新規行として追加する
- `備考` に分割理由と置換先を残す

### 8.4 統合する時

- 統合元の行は削除せず、状態変更で残す
- 統合先を新規または既存行で明記する
- `備考` に統合日と置換先を書く

### 8.5 廃止する時

- 行削除ではなく、`ライフサイクル状態` を `廃止済` または `アーカイブ` にする
- 廃止理由と置換先を `備考` に残す
- 正本 path を消さずに残し、履歴を追えるようにする

### 8.6 path を変更する時

- `正本ファイルパス` と `説明mdパス` を更新する
- 参照資料に path を直書きしている箇所がないか確認する
- フォルダ構造変更に依存しないよう、資料本文では可能な限り `資料ID + repo相対パス` を使う

## 9. 他資料との関係

この台帳と他資料の役割分担は次の通り。

- `ART-001_資料台帳`（本資料）: 何の ART 資料があり、どれが正本で、どう管理するかを持つ
- `ART-002_資料ライフサイクル・更新ルール`: 全資料に共通する作成・更新・廃止ルールを持つ
- `ART-003_用語・ステータス定義`: ID、状態、重要度、確認主体などの用語定義を持つ
- `ART-902_タスク管理台帳`: TSK 資料の進行状況・依存・成果物対応を持つ
- 各 ART 正式資料: 実際の仕様、台帳、手順、確認結果などの本体情報を持つ

補足:

- 独立した `03_資料対応表` は現時点では作成しない
- 資料間の参照関係は、まず `00_資料台帳` の `参照元` `参照先` で管理する
- それでも表現しきれない詳細同期関係が将来必要になった場合のみ、別成果物化を再検討する

`00_資料台帳` は、他資料の内容を重複保持しない。  
各資料の内容そのものが必要な場合は、必ずその資料の正本を見る。

## 10. AI / ChatGPT for Excel 利用時の読み方

AI が `00_資料台帳.xlsx` を扱う時は、次の順で読む。

1. まずこの `00_資料台帳_説明.md` を読む
2. 次に `02_用語・ステータス定義.md` を読む
3. その後に `01_資料ライフサイクル・更新ルール.md` を読む
4. その後、必要な列だけを ChatGPT for Excel に抽出させる
5. 抽出結果は、件数・抽出日時・抽出条件を含む機械可読形式で受け取る
6. 意味解釈が必要な時は、この説明 md と抽出結果をセットで読む

ChatGPT for Excel に依頼する時は、少なくとも次を指定する。

- workbook 名
- 主シート名
- 目的
- 1行1件の単位
- 必須列と列順
- 各列の意味
- 入力規則にする列と候補値
- 出力形式

大きな変更では、構造変更とデータ更新を同時依頼しない。  
まず構造を確定し、その後にデータ投入または抽出を行う。

## 11. 生成プロンプト要約

`00_資料台帳.xlsx` の初回作成時は、次の方針で生成する。

- 主シートは `資料一覧`
- `1資料 = 1行`
- 正式資料のみを登録対象にする
- 主な列は `資料ID`、`資料名`、`カテゴリ`、`資料区分`、`正本区分`、`正本ファイルパス`、`説明mdパス`、`主な目的`、`対象`、`更新区分`、`ライフサイクル状態`、`利用タイミング`、`参照元`、`参照先`、`備考`
- 入力規則を使って、カテゴリ、資料区分、正本区分、更新区分、ライフサイクル状態、利用タイミングを候補値選択にする
- 主シートはテーブル化し、先頭行固定、フィルタ有効化とする
- 色は補助であり、意味は列値で持つ

実際に ChatGPT for Excel へ渡した生成プロンプトを後で確定させた場合は、その代表版の要約を本章へ追記する。
