# 02_用語・ステータス定義

> 概要: 共通資料および各カテゴリ資料で再利用する用語、ID 接頭辞、状態値、候補値、標準記法を定義する文書  
> 主な目的: 用語ぶれ防止、入力規則の統一、AI と人の解釈ずれ防止、資料間参照の安定化  
> 正本区分: md正本  
> 対象: `docs/残タスク_0623` 配下の共通資料、カテゴリ資料、それに対応する sheet、rules / memory 要約  
> 更新区分: 変更時  
> 参照元: `00_資料台帳`、`01_資料ライフサイクル・更新ルール`  
> 参照先: 各カテゴリの正式資料

---

## 1. 目的

本書は、複数資料で共通利用する用語と候補値を定義する。  
本書の役割は「資料の中身を説明すること」ではなく、「資料同士で同じ言葉を同じ意味で使うこと」を保証することである。

現時点の正本ファイルは本ファイルだが、再編後は `ART-003_用語・ステータス定義.md` へ移設・改名する前提で運用する。  
ただし、実移設が完了するまでは、参照 path は現在の file path を正とする。

特に次を正本として持つ。

- ID 接頭辞の意味
- 状態値の意味
- 更新区分の意味
- 資料区分の意味
- カテゴリの意味
- 利用タイミングの意味
- 標準記法
- 未確定値や補助状態の使い分け
- 参照表記の基本形

---

## 2. 使い方

- 共通用語の定義は本書を正本とする
- `00_資料台帳` は列構造と運用方法を持ち、候補値の正式意味は本書を参照する
- `01_資料ライフサイクル・更新ルール` は作成・更新・廃止の共通ルールを持ち、個別の候補値意味は本書を参照する
- sheet の入力規則は、本書の候補値に合わせる
- rules / memory の要約文面も、本書と矛盾しないことを優先する

定義が衝突した場合の優先順は次の通り。

1. `02_用語・ステータス定義`
2. `00_資料台帳_説明`
3. `01_資料ライフサイクル・更新ルール`

ただし、作業手順や運用フローのルールは `01` を優先する。

---

## 3. ID 接頭辞定義

| 接頭辞 | 対象 | 使いどころ | 備考 |
|---|---|---|---|
| `ART-xxx` | 正式資料 | `00_資料台帳` で管理する資料の主 ID | 現時点で資料台帳上の標準 ID |
| `TSK-xxx` | タスク資料 | 残タスク管理側の `内容` `進め方` `実施まとめ` `申し送り` の識別 | 正式資料 `ART` とは分けて使う |
| `FN-xxx` | function | function 単位の識別 | `C-1` などで使用想定 |
| `CFG-xxx` | config 項目 | config 単位の識別 | `B-1` などで使用想定 |
| `FLOW-xxx` | 業務フロー | flow 単位の識別 | `D-1` などで使用想定 |
| `TEST-xxx` | テスト観点 / テスト項目 | test 単位の識別 | `D-2` などで使用想定 |
| `DEF-xxx` | 不具合 / defect | defect 単位の識別 | `D-3` などで使用想定 |

補足:

- `00_資料台帳` に登録する資料は、原則 `ART-xxx` を使う
- 残タスク管理側のタスク資料は、原則 `TSK-xxx` を使う
- 旧資料に残る `DOC-xxx` は移行対象であり、新規の正式資料命名には使わない
- 一度採番した ID は再利用しない
- 名称変更があっても ID は維持する

## 4. 資料ライフサイクル状態

| 値 | 意味 | 使う場面 | 使わない場面 |
|---|---|---|---|
| `構想中` | 作成要否や粒度を検討している段階 | 未作成だが作る可能性が高い資料 | 既に本文を書き始めている資料 |
| `テンプレ確定` | 形式や列構造だけ固まっている段階 | sheet 構造や章立てだけ決めた時 | 実データや本文を入れ始めた後 |
| `作成中` | 本文またはデータ投入を進めている段階 | 初回作成中の資料 | 内容確定済みの資料 |
| `レビュー中` | 内容確認中で確定前の段階 | 人レビューや整合確認中 | まだ初稿がない資料 |
| `運用中` | 正本として維持し続ける段階 | 現在有効な正式資料 | 単発記録で役目を終えた資料 |
| `凍結` | 当面更新予定がなく履歴として維持する段階 | 当面変更しないが残す資料 | 完全に廃止した資料 |
| `廃止予定` | 置換・統合などで終了予定の段階 | 新資料へ移行中の旧資料 | まだ現役の資料 |
| `廃止済` | 現行用途を終了した段階 | 役目を終えた旧資料 | 参照中の現行資料 |
| `アーカイブ` | 閲覧専用で保持する段階 | 履歴保存用資料 | 現在も更新する資料 |

---

## 5. 更新区分

| 値 | 意味 | 代表例 |
|---|---|---|
| `継続` | 運用中も継続的に更新する | 不具合台帳、資料台帳 |
| `変更時` | 内容や構成が変わった時だけ更新する | 方針書、説明資料、設定台帳 |
| `節目` | リリース前後や確認フェーズなどの節目で更新する | チェックリスト、確認記録 |
| `単発` | 特定の判定や成果物として一度作る | 出荷判定メモ、個別改善メモ |

---

## 6. 資料区分

| 値 | 意味 | 代表例 |
|---|---|---|
| `台帳` | 一覧管理を主目的とする資料 | 資料台帳、Config台帳 |
| `方針書` | 方針やルールを定める資料 | 資料ライフサイクル・更新ルール |
| `手順書` | 実施手順を説明する資料 | 実機確認手順書 |
| `マニュアル` | 利用者や運用者向けの操作説明資料 | ロール別操作マニュアル |
| `説明資料` | 概要、背景、関係整理、引継ぎを主目的とする資料 | 技術説明資料、用語定義 |
| `チェックリスト` | 確認項目を列挙し判定する資料 | 本番化チェックリスト |
| `記録` | 実施結果や判断結果を残す資料 | 出荷判定メモ、運用確認記録 |
| `仕様書` | 仕様そのものを定義する資料 | 改善仕様、個別機能仕様 |

補足:

- `資料群` は資料区分ではなく、複数の子資料を暫定的に束ねる表現として扱う
- `資料群` を使う場合は `備考` に「将来分割予定」などを残す

## 7. カテゴリ定義

| 値 | 意味 |
|---|---|
| `共通` | 全カテゴリ横断で使う資料 |
| `A` | システム構築・個別課題解消 |
| `B` | 本番化横断整理 |
| `C` | Function / Contract 確認 |
| `D` | 業務フロー確認・テスト受入 |
| `E` | 導入フロー設計 |
| `F` | 外部サービス・インフラ設定 |
| `G` | システム資料作成 |
| `H` | 営業・契約・費用資料 |
| `I` | 中央管理アプリ |

補足:

- 上記カテゴリ記号は旧方針の分類体系に由来する
- `ART-001_資料台帳` の `カテゴリ` 列では、上記に加え新方針の区分（`実装定義台帳` / `確認実行テンプレ` / `導入手順書` など）を扱う場合は `備考` と整合させる
- 既存カテゴリ記号は移行完了まで入力規則として維持する

## 8. 利用タイミング定義

| 値 | 意味 |
|---|---|
| `開発中` | 仕様整理、実装、資料設計、確認中に使う |
| `営業開始前` | 営業開始可否の判定前に使う |
| `導入時` | 新店舗導入や初期設定時に使う |
| `運用中` | 導入開始後の通常運用で継続利用する |
| `節目のみ` | リリース前後、重要変更前後、判定時のみ使う |

---

## 9. 未確定値・補助状態

| 値 | 意味 | 使い分け |
|---|---|---|
| `未確認` | 事実がまだ確認できていない | 調査が必要な時 |
| `判断待ち` | 事実は見えているが、方針や採用判断が未決 | 意思決定待ちの時 |
| `保留` | 今は意図的に進めない | 後回しや依存待ちの時 |
| `TBD` | 将来確定予定の仮置き値 | path、名称、日付など未確定の時 |
| `該当なし` | 対象項目が存在しない | `説明mdパス` が不要な md 正本など |
| `廃止` | その値や対象は既に有効でない | 旧状態や旧項目を明示する時 |

## 10. 標準記法

| 項目 | 記法 |
|---|---|
| 日付 | `YYYY-MM-DD` |
| 時刻 | `HH:mm` |
| 日時 | `YYYY-MM-DD HH:mm` |
| タイムゾーン | `JST` または `UTC` |
| 真偽値 | `TRUE/FALSE` |
| repo 内 path | repo ルートからの相対パス |
| 参照表記 | `ID + 短い名称` |
| 複数参照の区切り | `; ` |

補足:

- 色や装飾は意味の補助としてのみ使う
- 意味は必ず列値でも持つ
- 空欄は意味値として使わない

---

## 11. 参照表記ルール

- 他資料を参照する時は、原則として `ID + 短い名称` を使う
- path が必要な時は、repo ルート相対 path を併記してよい
- 複数参照は `; ` 区切りで 1 セルに書く
- フォルダの近さや同階層であることを前提に意味を持たせない
- `このフォルダの〜` のような相対位置依存の表現は避ける
