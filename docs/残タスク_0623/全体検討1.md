## このファイルの見方

- 各カテゴリは、以下の同じ軸で管理する
  - **このカテゴリで答える問い**
  - **目標**
  - **実際に行うこと**
  - **作成する資料**
  - **資料以外の完了条件**
- 基本ルールは以下とする
  - `done = 資料完成 + 実体反映 + 証跡記録 + 判定者承認`
  - ただしカテゴリC/G/Hは、他カテゴリに比べて資料中心で完了しやすい
  - カテゴリA/B/D/E/Fは、資料だけでは完了としない

## カテゴリ別詳細

### A

| 軸 | 内容 |
|---|---|
| このカテゴリで答える問い | 既知の不満・不足・未決事項を営業開始までにどう扱うか |
| 目標 | 営業開始に必要な個別課題を潰す |
| 主に行うこと | 仕様確定、実装、修正、個別確認 |
| 作成する資料 | 各 `A-X` の概要・詳細・完了記録 |
| 資料以外の完了条件 | 実装やルールが反映され、営業開始必須の未解決が残っていない |

### B

| 軸 | 内容 |
|---|---|
| このカテゴリで答える問い | システム全体として本番事故の火種が残っていないか |
| 目標 | 本番運用に耐える状態へ引き上げる |
| 主に行うこと | config 方針、scheduler、権限、rules、不要物、暫定実装を横断確認 |
| 作成する資料 | Config台帳、本番化チェックリスト、Scheduler確認記録、削除候補台帳 |
| 資料以外の完了条件 | コード、rules、Secrets、GCP 設定が実際に反映済み |

### C

| 軸 | 内容 |
|---|---|
| このカテゴリで答える問い | 各 function は何を受け、何を更新し、どう失敗するか |
| 目標 | function 単位の構造把握と確認責任の整理 |
| 主に行うこと | 関数棚卸し、contract 整理、テスト責任分担、リスク抽出 |
| 作成する資料 | Function/Contract台帳、Function-Flow対応表、高リスク論点一覧 |
| 資料以外の完了条件 | 営業開始対象の function が漏れなく台帳化され、未整理論点の返却先が決まっている |

### D

| 軸 | 内容 |
|---|---|
| このカテゴリで答える問い | 業務フローとして通しで使えるか。出荷してよいか |
| 目標 | 業務フロー単位の受入判定を出す |
| 主に行うこと | Flow 整理、テスト設計、実行、結果記録、バグ修正ループ |
| 作成する資料 | Flow Master、テスト実行台帳、不具合台帳、出荷判定メモ |
| 資料以外の完了条件 | 営業開始必須フローが pass。release blocker が 0 |

### E

| 軸 | 内容 |
|---|---|
| このカテゴリで答える問い | 次店舗へ迷わず導入できるか |
| 目標 | 導入から初回稼働までの手順を確立する |
| 主に行うこと | 導入順序、端末設定、LIFF 設定、初期データ移行、切替手順を整理 |
| 作成する資料 | 導入チェックリスト、初期設定手順書、デバイス設定手順書、移行手順書 |
| 資料以外の完了条件 | dry-run または模擬実施で手順が通る |

### F

| 軸 | 内容 |
|---|---|
| このカテゴリで答える問い | 外部サービスと本番インフラが、実際に使える状態か |
| 目標 | LINE / Secret / IAM / env を本番値でそろえる |
| 主に行うこと | LIFF/OA 設定、通知用 LINE、Secret Manager、IAM、接続確認 |
| 作成する資料 | 外部サービス設定台帳、Secret/IAM台帳、接続確認記録 |
| 資料以外の完了条件 | 実アカウント・実Secret・実権限が設定済みで疎通確認も pass |

### G

| 軸 | 内容 |
|---|---|
| このカテゴリで答える問い | 利用者・運用者・保守者が、口頭補足なしで扱えるか |
| 目標 | システム資料と運用資料を完成させる |
| 主に行うこと | 運用資料、操作マニュアル、技術資料、`amuse-admin` 運用資料を整備 |
| 作成する資料 | 運用資料インデックス、ロール別操作マニュアル、技術説明資料一式 |
| 資料以外の完了条件 | 現行実装とズレがなく、最低限のレビューを通過 |

### H

| 軸 | 内容 |
|---|---|
| このカテゴリで答える問い | 売る、契約する、請求するための外向け資料がそろっているか |
| 目標 | 営業資料、契約資料、費用資料を完成させる |
| 主に行うこと | 機能紹介、導入メリット、規約、契約書、料金表、SLA を整備 |
| 作成する資料 | 営業資料一式、利用規約、契約書類、料金表、見積書、サポート定義書 |
| 資料以外の完了条件 | 外部提示可能な表現になっており、必要な承認を通過している |

### I

| 軸 | 内容 |
|---|---|
| このカテゴリで答える問い | `amuse-admin` 側の運用補助は十分か |
| 目標 | 中央管理アプリの運用効率と監視性を上げる |
| 主に行うこと | UI 改善、異常検知補強、通知疎通、不要タブ判断 |
| 作成する資料 | 改善仕様、受入記録、運用反映メモ |
| 資料以外の完了条件 | `amuse-admin` 側の実装・デプロイ・確認が完了している |

## 進める順番の基本方針

| 順番 | 主カテゴリ | 理由 |
|---|---|---|
| 1 | A と B | 個別課題の解消と、本番化の火消しを先に進める |
| 2 | C | A/B の内容を踏まえて、function 単位の契約整理を行う |
| 3 | D | function 整理を材料に、業務フローの受入確認を行う |
| 4 | E と F | システムが固まり始めた段階で、導入手順と外部設定を整える |
| 5 | G と H | 実装・設定・運用方針が固まった内容を資料に落とす |
| 6 | I | 並行可能だが、B/F/G と依存するものは後半で締める |

## 標準の成果物種別

| 種別 | 用途 |
|---|---|
| 台帳 | 事実を網羅的に並べるための資料 |
| 手順書 | 誰が実施しても同じ順で進められるようにする資料 |
| 実行記録 | 実際に確認した結果を残す資料 |
| 判定メモ | 最終判断と保留理由を残す資料 |
| 仕様書 | 振る舞い・前提・境界条件を固定する資料 |
