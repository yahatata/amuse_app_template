## 1. この文書の役割

ART-900 §6 で固定された統合ワークブックの原則を、実際の作業手順として具体化する。  
作業は大きく「設計・構造確定フェーズ」「Excel 実体作成フェーズ」「通し実行フェーズ」「説明 md 完成フェーズ」の 4 段階で進める。

---

## 2. 全体の進め方

| 段階 | 目的 | この段階で行うこと | 気をつけること |
|---|---|---|---|
| 1. 検証プロファイル定義の確立 | 何が確認内容の差分要因かを明文化する | config × 外部設定 × 業務モードの組み合わせで確認内容がどう変わるかを整理する。代表的な分岐パターンを洗い出す | 「同一設定 = 同一チェック」ではなく「同一検証プロファイル = 同一チェック観点」で考える |
| 2. シート設計の確定 | 全シートの構成・列定義・ロジックを固定する | 8 シートそれぞれの列定義草案を作成。期待値計算の数式ロジック原理を整理 | 数式の原理を説明 md に残すことを前提に設計する |
| 3. ChatGPT for Excel プロンプト作成 | Excel 作成に使うプロンプトを生成する | 列定義・入力規則・数式・条件付き書式・固定行の考え方を含むプロンプトを作成 | 構造定義と初期データ投入を分けて依頼する |
| 4. Excel テンプレ作成 | ART-201_統合ワークブック_テンプレ.xlsx を作成する | ChatGPT for Excel でプロンプトを実行 | シート間の参照・数式の動作を確認してから次段階へ進む |
| 5. テンプレアプリ通し実行 | テンプレアプリ環境で全シートを通して確認する | Config入力・外部設定入力を埋め、期待値計算・Gateチェック・Function挙動・実機テスト・業務フロー確認・判定サマリを一通り実施する | 「資料作成」で done にしない。実行まで完了させる |
| 6. NG の修正ループ | release blocker をなくす | NG が出た場合は修正して再確認する | 軽微な NG の後回し可否を明示して記録する |
| 7. 説明 md 完成 | ART-201_統合ワークブック_テンプレ_説明.md を完成させる | シート構成・数式ロジック・検証プロファイル定義・派生ルールを記載する | 数式だけに意味を持たせず原理を文章で説明する |

## 3. 検証プロファイルの設計方針

検証プロファイルは、少なくとも次の組み合わせで決まる:

| 要素 | 説明 |
|---|---|
| config 値 | ART-101 の各設定項目の採用値 |
| 外部設定の状態・方式 | ART-104 の各外部サービス設定の方式（LINE方式 / Token種別 等） |
| 業務モード（必要な場合） | 機能の有効・無効等の条件 |

同一検証プロファイルであれば、どの店舗でも同一の確認内容になることを目標とする。  
プロファイルが違う場合は、確認内容（実行要否・期待状態）が自動的に変わる仕組みを数式で実装する。

## 4. 各シートの列定義方針

### 共通で持つ列（全確認シート）

| 列名 | 目的 |
|---|---|
| 確認項目 | 確認する内容の名称 |
| 実行要否 | 検証プロファイルに基づき対象か否か（数式または入力） |
| 期待状態 | 正常な状態の定義 |
| 結果 | pass / fail / pending / 対象外 |
| NG理由 | fail の場合の理由 |
| 対応状態 | 未対応 / 対応中 / 解決済 |
| 再確認要否 | TRUE / FALSE |

### Config入力シートの設計方針

- ART-101 の CFG-ID と紐付ける
- 採用する config 値を入力する列と、標準値からの乖離フラグを持つ
- 期待値計算シートへの参照元になる

### Gateチェックシートの設計方針

- rules / auth / secret / env / scheduler / debug 残存 を横断確認する固定行
- AI が事前確認できるものと人確認が必要なものを列で区別する
- ART-104 の外部設定確認と一部重複するが意図的に許容する（Gate は横断リスクの確認が目的）

## 5. 段階的着手方針

TSK-101〜104 が完了していなくても、次の順序で段階着手可能:

| 着手可能タイミング | 作業内容 |
|---|---|
| TSK-101 の初版完了後 | Config入力シートの骨格作成 |
| TSK-104 の初版完了後 | 外部設定入力シートの骨格作成 |
| TSK-102 の初版完了後 | Function挙動確認シートの項目草案作成 |
| TSK-103 の初版完了後 | 業務フロー確認シートの項目草案作成 |
| 全 TSK 初版完了後 | 期待値計算の数式設計・Gateチェック設計 |
| 全 TSK 一定完了後 | テンプレアプリ通し実行 |

## 6. done 条件と着手時再確認事項

done 条件:
- [ ] 全 8 シートが存在し、入力・計算・判定の基本ロジックが動作する
- [ ] テンプレアプリでの通し実行が完了し、release blocker が 0 である
- [ ] 検証プロファイルの定義原理が ART-201_説明.md に記載されている
- [ ] 店舗別インスタンスの派生方法が定義されている
- [ ] `ART-902_タスク管理台帳` のステータスが `完了` に更新されている

着手時に再確認すること:
- ART-101〜104 の初版がどの程度完成しているか
- テンプレアプリ環境が通し実行できる状態か（A タスクの進捗を確認）
- 店舗別インスタンスの派生後の保存場所が決まっているか
