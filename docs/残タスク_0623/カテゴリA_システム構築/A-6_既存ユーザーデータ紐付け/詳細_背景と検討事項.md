# A-6 詳細: 背景と検討事項

**調査基準日**: 2026-07-10（現リポジトリと照合済み）

---

## 背景

新規店舗にシステムを導入する際、店舗には既存の常連ユーザーが存在する。
これらのユーザーはすでにポイント・チップ等を保有していることが多い（台帳管理・物理チップ等）。
システム導入時に既存データをどう扱うかの設計が必要。

---

## 現状のユーザー登録フロー

登録経路は **2系統** あり、uid の付け方が異なる。現状、同一人物のデータを後から統合する API はない。

| 経路 | Callable | uid | LINE 連携 |
|------|----------|-----|-----------|
| LIFF 自己登録 | `createUserAccount` | LINE userId（`getFirebaseCustomToken` 経由） | あり（前提） |
| 店舗端末アプリ登録 | `createUserByApp` | Firebase Auth が発行するランダム uid | なし |

### ユーザーが自ら登録する（LIFF 経由）

- `getFirebaseCustomToken` で LINE ID トークンを検証し、`uid = LINE userId` のカスタムトークンを発行
- `createUserAccount` が `users/{uid}` を作成
- 初期残高は `pointA: 0`, `pointB: 0`, `sideGameChip: 0`
- `users/{uid}` が既に存在する場合は `alreadyRegistered: true` でスキップ（冪等）。**既存残高のインポートは行わない**
- `initializeUserLogs(uid)` で `pointALogs` / `pointBLogs` / `sideGameChipLogs` を空で初期化
- クライアント: `public/user/index.html`

### 店舗スタッフが端末アプリから登録する

- `createUserByApp` が `admin.auth().createUser({ email, password })` で **LINE 非連携** の Auth ユーザーを作成
- `users/{randomUid}` に Firestore ドキュメントを作成（初期残高は 0 固定）
- **LINE 未連携のままユーザードキュメントは作成できる**（`uid = LINE userId` ではない）
- クライアント: `lib/UserRegisterView/createUserAccountPage.dart`（`terminalHomePage` / 手動チェックイン画面から遷移可）
- 後から同じ人物が LIFF で登録すると **別 uid の `users/{lineUid}`** が作られる。現状マージ手段なし

### 共通制約

- 両経路とも `pokerName` の重複チェックあり（台帳上の名前と衝突する可能性は A-6 の検討事項）
- QR 生成方式は経路ごとに異なる（LIFF: `qrCodeUtils` + 有効期限、アプリ: 自前生成 + 長期 signed URL）

---

## ポイントを後から付与する仕組みの現状

現状、管理者が任意のユーザーにポイントを直接付与する専用の Callable は**存在しない**。

ポイントが変動する経路は以下のみ：

- トーナメント賞金（`setRankingData`）
- 会計時のポイント利用（`accounting`）
- サイドゲームチップの入出金（`depositChip` / `withdrawChip`）
- 精算後調整（`createPostSettlementAdjustment` — 会計 bill に紐づく操作）

初期ポイントを付与するための「管理者が手動で任意のポイントを加算する」機能は未実装。

`logUtils.ts` の `reasonType` に `'manual'` は定義されているが、ポイント付与経路では未使用。

## 未実装（A-6 で検討対象）

- 既存台帳残高のインポート（単体・一括）
- 店舗スタッフによる初期ポイント手動付与 Callable / UI
- CSV 等によるユーザー一括登録
- `createUserByApp` で作成した uid と LINE uid のマージ・紐付け
- ユーザー向け migration スクリプト（参考: スタッフ用 `migrateStaffStatusActive.ts` のみ存在）
- 運用正本 `ART-304`（既存ユーザー移行手順書）— `ART-900` に計画のみ、ファイル未作成

※ `linkUserRichMenu` / 置きバケの `linkedUserId` 等は本タスクの「既存会員データ引き継ぎ」とは無関係。

---

## 検討が必要な事項

### 既存ユーザーの登録フロー

- 既存ユーザーが LINE 連携していない場合の登録手順をどうするか
- 店舗スタッフが代理で登録する場合のフローをどう設計するか
- 端末アプリ先行登録と LIFF 後登録が両方起きたとき、同一人物をどう扱うか

### 初期ポイント付与方法

- 管理者が手動で初期ポイントを入力できる Callable / UI を新規作成するか
- CSV 等での一括インポートが必要か、1件ずつの手動入力で許容できるか
- 付与時に `pointALogs` / `pointBLogs` 等のログを残す必要があるか（`reasonType: 'manual'` の利用方針）

### 引き継ぎデータの範囲

- ポイント残高のみでよいか
- 過去のトーナメント参加履歴等まで引き継ぐ必要があるか
