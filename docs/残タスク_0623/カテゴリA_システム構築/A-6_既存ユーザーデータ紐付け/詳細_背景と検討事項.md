# A-6 詳細: 背景と検討事項

> 担当エンジニアは実装完了後にこのファイルを更新してください。

---

## 背景

新規店舗にシステムを導入する際、店舗には既存の常連ユーザーが存在する。
これらのユーザーはすでにポイント・チップ等を保有していることが多い（台帳管理・物理チップ等）。
システム導入時に既存データをどう扱うかの設計が必要。

---

## 現状のユーザー登録フロー

### ユーザーが自ら登録する（LIFF 経由）

- `createUserAccount.ts` が担当
- LINE ログインにより uid = LINE userId として Firebase Auth ユーザーが作成される
- `users/{uid}` に `pointA: 0`, `pointB: 0`, `sideGameChip: 0` で初期化
- ユーザー自身が LINE から操作するため、既存ユーザーへの初期データ付与は別途対応が必要

### 店舗スタッフがアプリから登録する

- `createUserByApp.ts` が担当
- アプリ側からユーザーを作成できるが、こちらも初期ポイントは 0 固定
- LINE 未連携の状態でユーザードキュメントを作ることはできない（uid = LINE userId 前提）

---

## ポイントを後から付与する仕組みの現状

現状、管理者が任意のユーザーにポイントを直接付与する専用の callable は**存在しない**。

ポイントが変動する経路は以下のみ：
- トーナメント賞金（`setRankingData`）
- 会計時のポイント利用（`accounting`）
- サイドゲームチップの入出金（`depositChip` / `withdrawChip`）
- 精算後調整（`createPostSettlementAdjustment` — 会計 bill に紐づく操作）

初期ポイントを付与するための「管理者が手動で任意のポイントを加算する」機能は未実装。

---

## 検討が必要な事項

### 既存ユーザーの登録フロー
- 既存ユーザーが LINE 連携していない場合の登録手順をどうするか
- 店舗スタッフが代理で登録する場合のフローをどう設計するか

### 初期ポイント付与方法
- 管理者が手動で初期ポイントを入力できる callable / UI を新規作成するか
- CSV 等での一括インポートが必要か、1件ずつの手動入力で許容できるか
- 付与時に `pointALogs` / `pointBLogs` 等のログを残す必要があるか

### 引き継ぎデータの範囲
- ポイント残高のみでよいか
- 過去のトーナメント参加履歴等まで引き継ぐ必要があるか
