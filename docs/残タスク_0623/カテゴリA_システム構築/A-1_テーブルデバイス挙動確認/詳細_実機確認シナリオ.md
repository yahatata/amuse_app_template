## 確認項目と結果

### 1. テーブルデバイスの登録動線

admin デバイスから卓端末を `role: table` として登録し、卓 ID を紐付けるまでの一連の動線。
紐付け前・登録無効時の UI 表示状態も含めて確認。

**結果:** ✅ 問題なし

**実装済みコードの補足:**
- `tableDeviceRegistrationEnabled`（`storeMeta/config`）が `false` の場合、CF 側で登録を拒否する
- 紐付け未完了は `TableDeviceHomeKind.unregistered` で制御（`lib/tableDevice/models/table_device_home_state.dart`）

### 2. テーブルデバイス側からトーナメントを解除した場合のデータ

Drawer から「トーナメント解除」を行った際の Firestore 更新。

更新対象:
- `tables/{tableId}.status`
- `tables/{tableId}.tournamentDetail`
- `scheduledTournaments/{tournamentId}/tablesSeat/{tableId}.isEnabled`

**結果:** ✅ 問題なし

**実装:** `unregisterTableFromTournament` が上記を 1 トランザクションで更新。`tablesSeat` は `isEnabled: false` による論理削除。

### 3. トーナメント側から卓を外した場合のテーブルデバイスへの影響

admin のトーナメント管理画面から卓を取り外した際の卓端末側状態。

**結果:** ✅ 問題なし（`inconsistent` にならず Home が正しく更新されることを確認）

**実装:** `tables/{tableId}` をリスナー監視し、`tournamentDetail` 消失で `TableDeviceHomeKind` が変化。
