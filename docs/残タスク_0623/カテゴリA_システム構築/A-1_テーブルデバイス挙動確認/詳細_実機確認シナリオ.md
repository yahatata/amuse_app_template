# A-1 詳細: 実機確認シナリオ

## 残っている理由

コア実装は PR #131 でマージ済みだが、実機での動作確認が未実施のまま。
以下の3点は実装の正確性がコードレビューだけでは担保しきれないため、実機確認を必須としている。

---

## 確認項目

### 1. テーブルデバイスの登録動線

admin デバイスから卓端末を `role: table` として登録し、卓 ID を紐付けるまでの一連の動線。
紐付け前・登録無効時のUIの表示状態も含めて確認が必要。

**実装済みコードの補足:**
- `tableDeviceRegistrationEnabled`（`storeMeta/config`）が `false` の場合、CF 側で登録を拒否する実装がある
- 紐付けが完了していない状態の表示は `TableDeviceHomeKind.unregistered` で制御している（`lib/tableDevice/models/table_device_home_state.dart`）

### 2. テーブルデバイス側からトーナメントを解除した場合のデータ

テーブルデバイスの Drawer から「トーナメント解除」を行った際に、Firestore の関連ドキュメントが正しく更新されるかを確認する。

更新対象は以下3点：
- `tables/{tableId}.status`
- `tables/{tableId}.tournamentDetail`
- `scheduledTournaments/{tournamentId}/tablesSeat/{tableId}.isEnabled`

**実装済みコードの補足:**
- `unregisterTableFromTournament` callable が上記3点を1トランザクションで更新する実装になっている
- `tablesSeat` は物理削除ではなく `isEnabled: false` による論理削除

### 3. トーナメント側から卓を外した場合のテーブルデバイスへの影響

admin デバイスのトーナメント管理画面から卓を取り外した際に、テーブルデバイス側の状態が正しく更新されるかを確認する。

**実装済みコードの補足:**
- テーブルデバイスの状態は `tables/{tableId}` を Firestore リスナーで監視しており、`tournamentDetail` が消えると `TableDeviceHomeKind` が変化する設計
- `inconsistent` 状態（`tournamentDetail` は残っているが `tablesSeat.isEnabled` が `false`）になるケースがないかを確認する必要がある
