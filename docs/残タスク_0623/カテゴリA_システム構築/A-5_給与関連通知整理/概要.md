# A-5: 給与関連通知の整理

## このタスクで何をしたか

給与まわりの **通知9種**（いつ・どの重要度で出すか）の仕様を整理し、方針を確定した。

- 通知は `notifications` コレクション（`operationCategory: payroll`）に保存される
- **イベント駆動4種** … 計算完了・失敗・勤怠修正など、事象発生時に即時作成
- **スケジューラー駆動4種** … 毎日 `payrollNotificationScheduler` → `processPayrollNotifications` で条件評価
- **hold 通知** … `registerPaymentStatus` で hold 初回発生時にイベント駆動（scheduler では出さない）

**結論: 9種すべて残す。** 種別の削除・統合は行わない。

詳細は [詳細_通知仕様と残課題.md](./詳細_通知仕様と残課題.md) を参照。

## 確定方針の要点（他開発者向け）

### スケジューラー駆動（4種）+ hold（イベント）

| triggerType | type | いつ出すか | メモ |
|-------------|------|-----------|------|
| `payroll_period_start` | report | 給与期間終了の **翌日**（`periodEnd + 1`） | 案内通知。督促ではない |
| `payroll_calc_remind` | warning → strong_warning | `periodEnd + reminderStartDaysAfterPeriodEnd` 以降、計算未実行 | **支払日7日前**から strong_warning 昇格 |
| `payroll_confirm_remind` | warning | 上記以降、計算済みだが `draft` | **strong_warning 昇格なし** |
| `payroll_payment_overdue` | strong_warning | 支払日超過後、`confirmed` のまま | 条件が続く限り毎日でよい |
| `payroll_hold_reminder` | report | **hold が初めて発生したとき**（`registerPaymentStatus`） | scheduler の毎週月曜は廃止 |

※ `payroll_period_start` は名前は period_start だが、実際のタイミングは「期間終了翌日」。

### イベント駆動（4種）

| triggerType | type | いつ出すか |
|-------------|------|-----------|
| `payroll_run_completed` | report | 給与計算 run が正常完了 |
| `payroll_run_completed_with_errors` | error | run は完了したが一部スタッフ計算失敗 |
| `payroll_run_failed` | error | run 全体の開始・投入・実行継続に失敗 |
| `payroll_attendance_corrected` | warning | 給与反映済み勤怠が後から修正されたとき |

`payroll_attendance_corrected` の文言は再計算または差額調整を促す内容（**反映済み**）。

### 分類の考え方

- **1対1対応で維持** … period_start, hold（初回）, run_completed, run_completed_with_errors, run_failed, attendance_corrected
- **必須・warning 開始後に strong 昇格** … calc_remind（支払日7日前から strong_warning）
- **必須だが warning で十分** … confirm_remind
- **急ぎ対応・毎日 strong_warning 可** … payment_overdue

## A-5 のスコープ外（触らない）

以下は **今回の仕様整理では決めない**。後続で検討する。

- 通知 doc を1件更新するか、発生ごとに新規作成するか
- `isRead` の再通知制御、`reminderCount`
- `resolved` / `isResolved` / `resolvedAt` などの対応済みフラグ
- 通知タップ時の画面遷移（導線）
- 給与通知 ON/OFF（`payrollFeatureEnabled` / `payrollNotificationsEnabled` 等）
- **給与関連機能をリリース時に実装しない場合**の UI・Functions・scheduler 停止など
