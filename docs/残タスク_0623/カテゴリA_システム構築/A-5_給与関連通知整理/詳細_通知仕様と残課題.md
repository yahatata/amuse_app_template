# A-5 詳細: 通知仕様と残課題

## 通知ドキュメントの構造

保存先: `notifications` コレクション

| フィールド | 型 | 内容 |
|-----------|-----|------|
| `type` | string | `report` / `warning` / `strong_warning` / `error` |
| `operationCategory` | string | `'payroll'` 固定 |
| `triggerType` | string | 通知種別の識別子 |
| `title` | string | テンプレートから生成された通知タイトル |
| `body` | string | テンプレートから生成された通知本文 |
| `isRead` | boolean | 既読フラグ（デフォルト `false`） |
| `isFlagged` | boolean | フラグフラグ（デフォルト `false`） |
| `createdAt` | Timestamp | 作成日時 |
| `targetDeviceIds` | null | 現状 null 固定（将来の個別配信用）|

---

## イベント駆動通知（3種）

アクション発生時に即時作成される。実装: `finalizePayrollRun.ts`・`attendanceOnWrite.ts`

| triggerType | type | トリガー条件 | 埋め込みパラメータ |
|------------|------|------------|-----------------|
| `payroll_run_completed` | `report` | 給与計算が正常完了 | periodStart, periodEnd, staffCount, totalGrossPay |
| `payroll_run_completed_with_errors` | `error` | 一部スタッフの計算が失敗 | periodStart, periodEnd, failedCount |
| `payroll_attendance_corrected` | `warning` | 確定済み期間の勤怠データが修正された（`attendanceOnWrite` 検知） | staffName, date |

**冪等キー形式:** `{triggerType}_{runId}`（計算実行 ID に紐づく）

---

## スケジューラー駆動通知（5種）

毎日 05:00 JST に `payrollNotificationScheduler` → `processPayrollNotifications` が実行し、
直前の給与期間の `monthlyPayroll` ドキュメントを読み取って条件を評価する。

| triggerType | type | 発火条件 | 埋め込みパラメータ |
|------------|------|---------|-----------------|
| `payroll_period_start` | `report` | 期間終了翌日 == 今日、かつ計算未実行 | periodStart, periodEnd |
| `payroll_calc_remind` | `warning` → `strong_warning` | reminderStartDate 以降、かつ計算未実行。支払日 3 日前以降は `strong_warning` に昇格 | periodStart, periodEnd, paymentDate |
| `payroll_confirm_remind` | `warning` | reminderStartDate 以降、かつ計算済みで status が `draft` | periodStart, periodEnd |
| `payroll_payment_overdue` | `strong_warning` | 支払日を超過、かつ status が `confirmed` | periodStart, periodEnd |
| `payroll_hold_reminder` | `report` | 月曜日、かつ status が `hold` で holdCount > 0 | holdCount |

**`reminderStartDate`**: `periodEnd + reminderStartDaysAfterPeriodEnd`（`payrollConfig` で設定）

**冪等キー形式:** `{triggerType}_{periodKey}_{date}`（日付込みのため、条件が継続する限り**毎日新しいドキュメントが作成される**）

## 通知管理の現在の仕様

### UI（`lib/payroll/widgets/notification_list.dart`）

- `operationCategory == 'payroll'` かつ過去 60 日以内の通知を一覧表示
- フィルター: すべて / 未読のみ / フラグ付き
- タイルのタップ: `isRead: true` に更新（既読化）
- フラグアイコンのタップ: `isFlagged` をトグル
- 表示場所: 管理者 HOME のベルアイコン（未読バッジ付き）+ `PayrollNotificationListPage`

### 対応済みフラグ・完了フラグ

**現状は存在しない。** `isRead`（既読）と `isFlagged`（フラグ）のみ実装されており、通知を「対応済み」として解決済み扱いにする仕組みはない。

## 残課題

### 1. 頻度の問題
スケジューラー通知の冪等キーに日付が含まれているため、条件が解消されるまで毎日同じ内容の通知が積み上がる。
「1期間につき1通知」のような頻度制限ルールの設計が必要。

### 2. `strong_warning` 昇格タイミング
`payroll_calc_remind` は支払日 3 日前以降に `strong_warning` に昇格するが、このタイミングが業務上適切かを確認する必要がある。

### 3. 通知の精査
8種類のテンプレートが定義されているが、すべての通知が本番で必要かの判断が未実施。
特に `payroll_period_start`（期間開始の毎期通知）は必要性を確認する。

### 4. 対応済みフラグ
通知を解決済みとしてマークする手段が `isRead` しかなく、既読にしても条件が継続すれば翌日また同じ通知が作成される。
「この通知は対応済み（次回から出さない）」に相当する仕組みが必要かを検討する。

### 5. 導線
通知タップ時に対象の給与計算画面へ遷移する導線が未実装。既読になるだけ。

### 6. E2E 確認未実施
スケジューラー経路（`payrollNotificationScheduler` → `processPayrollNotifications`）が実際に動作して通知が作成されることを実機で確認していない。
