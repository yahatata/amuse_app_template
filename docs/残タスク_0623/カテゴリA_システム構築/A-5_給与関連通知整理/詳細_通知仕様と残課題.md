# A-5 詳細: 給与関連通知 確定仕様

> **更新**: 2026-06。A-5 における **通知9種の種別・重要度・発火タイミング** を確定した記録。

---

## 最終結論

- **給与関連通知9種はすべて残す。**
- **1, 5, 6, 7, 8, 9** … 起きた事象と通知が1対1対応するため、種別として維持する。
- **4** … 支払日超過は店舗が急ぎ対応すべき事項のため、`strong_warning` を条件継続中毎日で問題ない。
- **2** … 必須通知。`warning` で開始し、**支払日7日前**から `strong_warning` に昇格する（計算後の確認・確定・支払い管理の猶予を確保するため、旧実装の3日前より前倒し）。
- **3** … 必須通知だが支払日超過ではないため、通常の `warning` とする（`strong_warning` 昇格は採用しない）。
- **5** … 毎週月曜の定期通知はやめ、**hold 初回発生時のみ**通知する。
- **9** … 再計算または差額調整を促す文言へ修正する。
- **通知 doc の生成方式・再通知制御**（1 doc 更新型、`isRead` 制御、`reminderCount`、対応済みフラグ等）は **A-5 スコープ外**。
- **給与関連機能をリリース時に実装しない場合**の UI・Functions・scheduler・通知停止は **A-5 スコープ外** → [../../後続検討事項/給与関連機能.md](../../後続検討事項/給与関連機能.md)

## 確定仕様: スケジューラー駆動（4種）

**実行経路:**
1. 毎日 **05:00 JST** — `payrollNotificationScheduler` が child task を enqueue
2. 当日 **`payrollConfig.schedulerNotificationHour` JST**（デフォルト 10）— `processPayrollNotifications` が評価

評価対象: **直前に完了した給与期間 1 本**（`recentPeriodKey`）。

### 1. payroll_period_start

| 項目 | 内容 |
|------|------|
| type | `report` |
| 位置づけ | 給与計算可能期間に入ったことの **開始案内**（督促ではない） |
| タイミング | `periodEnd + 1`、かつ計算未実行 |
| 判断 | **現状維持** |
| 実装 | `processPayrollNotifications.ts` |

※ triggerType 名は period_start だが、発火は **給与期間終了翌日**。

### 2. payroll_calc_remind

| 項目 | 内容 |
|------|------|
| type | `warning`（**支払日7日前から `strong_warning` に昇格**） |
| 位置づけ | 給与計算が未実行であることを知らせる必須通知 |
| タイミング | `periodEnd + reminderStartDaysAfterPeriodEnd` 以降、計算未実行 |
| strong_warning 昇格 | `today >= actualPaymentDate - 7日`（支払日未設定時は昇格しない） |
| 判断 | **残す**。warning 開始タイミングは現状維持 |
| 実装 | `processPayrollNotifications.ts` |

### 3. payroll_confirm_remind

| 項目 | 内容 |
|------|------|
| type | `warning`（**strong_warning 昇格なし**） |
| 位置づけ | 計算済みだが `draft` のまま未確定であることの必須通知 |
| タイミング | `reminderStartDate` 以降、`latestRunId` あり、`monthlyPayroll.status == draft` |
| 判断 | **残す** |
| 実装 | `processPayrollNotifications.ts` |

### 4. payroll_payment_overdue

| 項目 | 内容 |
|------|------|
| type | `strong_warning` |
| 位置づけ | 支払日超過後も支払い済み登録がされていない強警告 |
| タイミング | `today > actualPaymentDate`、`status == confirmed` |
| 判断 | **残す**。条件継続中は **毎日 strong_warning で問題ない** |
| 実装 | `processPayrollNotifications.ts` |

### 5. payroll_hold_reminder（イベント駆動）

| 項目 | 内容 |
|------|------|
| type | `report` |
| 位置づけ | 保留中の支払いが **初めて発生した** ことの通知 |
| タイミング | `monthlyPayroll.status` が **初めて `hold` になったとき**（`confirmed` → `hold` 等） |
| 判断 | **残す**。毎週月曜の scheduler 通知は **廃止** |
| 実装 | `registerPaymentStatus.ts`（冪等キー: `{triggerType}_{periodKey}`） |

**hold の意味（`monthlyPayroll.status`）:**

| status | 意味 |
|--------|------|
| `draft` | 給与計算結果をまだ確定していない |
| `confirmed` | 確定済みで支払い管理中 |
| `hold` | 確定済みだが一部スタッフの支払いを意図的に保留中 |
| `paid` | 支払い完了 |

**継続管理:** hold が続いている間の定期通知は出さない。支払い管理画面で hold 状態のスタッフを常時表示する方針。

## 確定仕様: イベント駆動（4種）

### 6. payroll_run_completed

| 項目 | 内容 |
|------|------|
| type | `report` |
| タイミング | 給与計算 run が正常完了時 |
| 判断 | **現状維持** |
| 実装 | `finalizePayrollRun.ts` |

### 7. payroll_run_completed_with_errors

| 項目 | 内容 |
|------|------|
| type | `error` |
| タイミング | run 完了、`failedStaffCount > 0` |
| 判断 | **現状維持** |
| 想定例 | 一部勤怠が計算不能、時給等の前提欠落、`processStaffPayroll` 失敗、一部 `staffResults` が failed |
| 実装 | `finalizePayrollRun.ts` |

### 8. payroll_run_failed

| 項目 | 内容 |
|------|------|
| type | `error` |
| タイミング（確定） | run の開始・タスク投入・実行継続に失敗したとき |
| タイミング（現状実装） | `executeMonthlyPayroll` の **Cloud Tasks dispatch 失敗時のみ** |
| 判断 | **現状維持**（種別として。発火範囲の拡張は実装タスクで検討可） |

### 9. payroll_attendance_corrected

| 項目 | 内容 |
|------|------|
| type | `warning` |
| タイミング | `payrollStatus == reflected` の勤怠が実質修正され `corrected_after_reflection` になったとき |
| 判断 | **残す。文言を修正する** |
| 実装 | `attendanceOnWrite.ts` |

**確定文言:**

| | 文面 |
|---|------|
| タイトル | 給与反映済み勤怠が修正されました |
| 本文 | {staffName} の {date} の勤怠データが給与反映後に修正されました。給与は自動再計算されません。必要に応じて再計算または差額調整を行ってください。 |

**現状実装との差分:** なし（2026-06 反映済み）。
