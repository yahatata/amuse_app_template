# A-3 詳細: 実装スコープ

## 前提

以下のスコープは業務定義（`詳細_業務定義と決定事項.md`）の決定内容によって変化する。
方針確定後に実装者が参照する資料として整理する。

---

## 既存コードの状態

### `staffs` コレクション（現在のフィールド）

`createStaffByApp.ts` が作成する `staffs` ドキュメントには現在 **status フィールドが存在しない**。
退職処理を実装するには `status`（例: `active` / `retired`）フィールドの追加が必要。

主なフィールド: `uid`, `StaffName`, `fullName`, `fullNameKana`, `email`, `phoneNumber`, `birthMonthDay`, `loginId`, `staffRole`, `qrCodeUrl`, `qrExpiresAt`

### Firebase Auth

`createStaffByApp.ts` の中で `admin.auth().createUser()` を呼び出して Auth ユーザーを作成している。
退職時に `admin.auth().updateUser(uid, { disabled: true })` で無効化することが可能。

### LINE リッチメニュー

`createStaffAccount.ts` のスタッフ登録フロー内で、スタッフ用リッチメニューの設定処理が呼ばれている（コメント「提案C-A」）。
退職時にはこのリッチメニューを解除する処理が必要。

### QR コード

`qrCodeUrl`・`qrExpiresAt` が `staffs` ドキュメントに保存されている。
退職時に QR を無効化する方法（`qrExpiresAt` を過去日時に更新する等）の設計が必要。

### シフト・給与

`functions/src/domains/staff/callables/` 配下にシフト関連 callable（`createMultipleShifts`, `confirmShiftRequest`, `updateShiftRequest`）が実装済み。
退職後のスタッフに対してこれらの操作をどこまで許可・ブロックするかの方針に従って、各 callable にガードを追加する必要がある。

給与計算は `functions/src/domains/attendance/` 配下に実装済みで、`staffs` コレクションを参照している。

---

## 実装が必要な範囲（概要）

1. **`staffs` へのステータスフィールド追加**  
   既存スタッフドキュメントへのマイグレーションも必要（既存 doc に `status: 'active'` を付与）

2. **退職処理 callable の実装**  
   `staffs.status` の更新・Firebase Auth 無効化・QR 無効化・LINE リッチメニュー解除を一括処理

3. **既存 callable へのガード追加**  
   シフト・打刻・給与確認等の callable において `status: 'retired'` のスタッフを拒否するチェックを追加

4. **管理者向け退職処理 UI の実装**  
   スタッフ管理画面（`lib/StaffDate/createStaffAccountPage.dart` 周辺）に退職操作の UI を追加

5. **再雇用フローの実装**（方針に応じて）  
   `status` を `active` に戻す、または新規登録フローに誘導する
