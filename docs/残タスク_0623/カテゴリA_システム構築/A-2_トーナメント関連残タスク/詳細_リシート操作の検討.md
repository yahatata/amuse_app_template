## ステータス

**方針決定済・実装完了・実機確認済（2026-06-26）** — クローズ。

---

## 決定した業務フロー

トーナメント中に卓数を減らす場合、**リシートと卓削除は一体化せず**、以下の二段階で運用する。

```text
Step 1: 使用卓選択付きリシート
  → 残したい卓だけを選択して全員リシート
  → 未選択卓は空になる

Step 2: 卓削除（既存機能）
  → 空になった卓を removeTableFromTournament で削除
```

「削除する卓を選ぶ」のではなく、「**リシート先として使う卓を選ぶ**」という UI 表現とする。

---

## 実装内容

### 使用卓選択付きリシート

| 項目 | 内容 |
|------|------|
| UI | `reseat_all_dialog.dart` — 「リシート先の卓」チェックボックス（初期は全有効卓選択済み） |
| 配分 | 選択卓のみ `SeatDecisionLogic` で assignment 生成 |
| パラメータ | `reseatTableIds` を Flutter → CF `reseatAllPlayers` に送信 |
| 検証 | `ReseatTableSelectionHelpers`（席数不足・0卓選択を拒否） |
| CF 検証 | 空配列・無効卓 ID・選択外 assignment・席数不足を拒否 |

### 着席者・waiting・置きバケ

| 対象 | 扱い |
|------|------|
| 着席者（通常） | 自動で全員リシート対象（除外不可） |
| 着席中 okibake | 通常着席者と同様に対象 |
| waiting | 追加選択した場合のみ対象 |
| busted | 対象外 |

### 卓削除との連携

| 項目 | 内容 |
|------|------|
| 空卓判定（UI） | `ScheduledTournamentSeatMap.isTournamentTableEmpty` — `seat*UserId` と `seat*OkibakeEntryId` の両方を参照（CF `removeTableFromTournament` と一致、空白文字は trim 後未着席） |
| 卓削除 | 既存 `remove_table_dialog.dart` のまま（仕様変更なし） |

---

## 実機確認結果

- 全卓選択のまま実行 → 従来どおり全卓に配分されること
- 一部卓を未選択 → 選択卓のみに再配置され、未選択卓が空になること
- 空卓になった卓を卓削除できること
- 置きバケのみ着席の卓が空卓扱いされず、削除候補に出ないこと

**問題なし。**
