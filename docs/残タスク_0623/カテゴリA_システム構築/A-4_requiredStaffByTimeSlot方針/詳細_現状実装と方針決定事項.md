## 機能概要

営業スタイルごとの営業時間・必要人数を設定し、シフト作成時に不足判定と警告表示を行う機能。

シフト画面では、対象日の営業スタイルに応じて以下を判定する。

* 営業時間内にスタッフがいない時間帯があるか
* 営業スタイル別の必要人数を満たしているか

不足時間帯は1時間単位で羅列せず、連続する時間帯をまとめて表示する。

## 採用方針

採用方針は **採用**。

主な方針は以下。

* 必要人数は営業スタイル別に管理する
* `requiredStaffByTimeSlot` は v2 `byStyle` 形式のみ正式対応
* 旧 `data[]` 形式への fallback は行わない
* 未設定・不正形式・読取失敗時は requiredStaff 判定を行わない
* `[]` は「その営業スタイルでは必要人数判定なし」という正常設定
* gap 判定は Functions / Flutter ともに60分単位
* 不足詳細は DB 保存せず、画面表示時に都度計算する
* `businessHoursStyles.label` は保存せず、UI 固定ラベルを使う

## データ形式

### `storeMeta/config.businessHoursStyles`

営業スタイルごとの営業時間を保持する。

対象 styleId:

```text
weekday
weekendHoliday
event
allDay
closed
```

表示名は DB に保存せず、UI 固定ラベルを使用する。

```text
weekday        → 平日
weekendHoliday → 週末・祝日
event          → イベント
allDay         → 終日
closed         → 休業日
```

---

### `storeMeta/requiredStaffByTimeSlot`

必要人数は v2 `byStyle` 形式で保存する。

```ts
{
  version: 2,
  byStyle: {
    weekday: [
      { startHour: 18, endHour: 22, requiredCount: 2 }
    ],
    weekendHoliday: [
      { startHour: 15, endHour: 23, requiredCount: 3 }
    ],
    event: [],
    allDay: [],
    closed: []
  },
  updatedAt: Timestamp
}
```

旧形式の `data[]` は正式対応しない。

## 再計算仕様

設定保存後、対象日の `isSufficient` を再計算する。

対象条件:

```text
dateKey >= todayJst
かつ
isFinalized !== true
かつ
sufficientOverride === null
```

以下は自動更新しない。

* 過去日
* 最終確定済み日
* sufficientOverride 済みの日

---

## 不整合時の扱い

`businessHoursMonthlyMap/{yearMonth}` が存在しないにもかかわらず `shifts/{yearMonth}` が存在する場合は、データ不整合として扱う。

この場合、`shifts` 側だけを救済的に更新せず、Callable を失敗させる。

理由:

* `businessHoursMonthlyMap` が予定営業日・営業時間の SSoT
* `shifts.days.businessHours` はそれを前提に同期される派生データ
