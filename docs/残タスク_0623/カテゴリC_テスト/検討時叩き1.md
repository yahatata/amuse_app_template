## C-1: テスト機能一覧シートの作成

### 概要
システムの全フローを網羅した「テスト機能一覧シート」を作成する。
このシートはテスト実施・出荷判定の基準となる中心資料であり、最終的にシステムの品質保証ドキュメントとして機能する。

### シートのカラム構成（予定）

| グループ | カラム |
|---------|--------|
| フロー情報 | Category / Flow / 業務カテゴリ / フロー名称 |
| 仕様 | 必須操作(要約) / 完了条件(出荷判定=期待状態) / 重要度 / 備考/境界条件 |
| 確認記録 | 確認結果 / memo |
| UI | 画面名(UI) |
| 操作者 | アプリユーザー操作内容 / LINEユーザー操作内容 |
| 実装 | 起動アプリ関数名 / 起動Function名 / 呼び出し種別（callable/trigger/schedule） |
| バックエンド | バックエンド処理要約 / 入力パラメータ(主要) / 前提条件(status/role等) |
| DB | 主要更新コレクション / 主要更新フィールド |
| ログ | 操作ログの必要性 / 監査/イベント記録先 |
| 確認方法 | 確認方法(UI/DB/Log) / 期待レスポンス / 代表的なエラー条件 / エラー出力方法 |
| 冪等性 | 冪等性確認 / idempotencyKey(有無/生成箇所) / businessDate使用有無 |
| テスト結果 | 全テスト結果(作成時) / 全テスト結果(最終) |

### 残タスク
- [ ] 全フロー（アプリフロー一覧 Step1〜3 を元に）の洗い出し
- [ ] シートのカラム定義・テンプレート確定（上記は案、調整可）
- [ ] 各フローの記入（仕様・関数名・コレクション等の列を埋める）
- [ ] 確認結果の記録欄の運用方法の決定（誰がどのタイミングで記録するか）

## C-3: 実機確認の未完了項目の消化

### 概要
過去の実機確認で積み残しになっているシナリオを消化する。
一部は特定の日程・条件でのみ確認できるものを含む。

### 残タスク

#### 随時確認可能
- [ ] Task 02.1 残3シナリオ
  - 繰越会計再起動シナリオ（前日の会計を翌日に再開した場合の挙動）
  - マルチデバイスリアルタイム更新（2台同時操作時の競合・同期確認）
  - `reportingDailyCheck`（日次集計の正確性確認）

#### 時期制約あり
- [ ] 給与計算 Task Queue の次回実際確認（直近 30 日間トリガーされていない場合）
- [ ] `scheduleGenerateNextYearBusinessHours`（1/29 前に確認が必要）

### 備考
- DB 確認（Firestore の値チェック）は Cursor が担当
- ユーザーはアプリ操作のみを担当
- 1回の操作で複数の確認事項をまとめて検証できる操作手順を設計すること

## 進め方の方針
1. **C-1 を先行して着手**（テンプレート作成）
2. **C-3 の時期制約なし項目**は並行して随時消化
3. **A カテゴリの実装が完了次第 C-2**（テスト作成）に移行
4. **C-4 はシステム完成に近い段階**で集中的に実施
