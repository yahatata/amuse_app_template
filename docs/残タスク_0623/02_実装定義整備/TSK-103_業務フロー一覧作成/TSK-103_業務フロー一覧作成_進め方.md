## 1. この文書の役割

カテゴリ D 検討時叩き2 の D-1「Flow Master の作成」を実際の作業手順として具体化する。  
本台帳はテスト実行・記録の器ではなく、フローの定義正本として整備する。

## 2. 全体の進め方

| 段階 | 目的 | この段階で行うこと | 気をつけること |
|---|---|---|---|
| 1. 業務カテゴリ整理 | フローを分類する軸を決める | 業務カテゴリ（会計・シフト・予約・外部連携 等）を列挙 | カテゴリが多すぎると使いにくくなる。5〜8 カテゴリ程度が目安 |
| 2. フロー一覧草案 | 全フローの初期一覧を作る | 各カテゴリ配下のフロー名称・操作者・画面・起動 function を整理。ART-102 の Function-Flow 対応表を参照 | 「フロー」と「操作ステップ」の粒度を統一する |
| 3. 営業開始必須区分・重要度の判定 | どのフローを先に確認するか決める | 営業開始必須 / 後続 を決め、重要度（高 / 中 / 低）を付与 | 全フローを「必須」にしない |
| 4. 完了条件の整理 | 各フローのゴールを明確にする | 「このフローが正常完了した状態」を簡潔に記載 | 確認手順ではなく完了条件を書く |
| 5. 正本反映 | ART-103.xlsx へ投入 | ChatGPT for Excel プロンプトで反映 | 構造変更と内容更新を同時依頼しない |
| 6. 説明 md 完成 | ART-103_業務フロー一覧_説明.md を完成させる | 行粒度・列定義・更新ルールを埋める | Excel 正本と整合していることを確認する |

## 4. 業務フロー一覧の想定列

| 列名 | 内容 | 型・候補値 |
|---|---|---|
| FLOW-ID | フロー識別子（FLOW-xxx） | 文字列 |
| 業務カテゴリ | 会計 / シフト / 予約 / 外部連携 等 | 入力規則 |
| フロー名称 | フローの短い名称 | 文字列 |
| 操作者 | 誰が操作するか（管理者 / スタッフ / お客様 等） | 入力規則 |
| 主な画面 | 操作する画面名 | 文字列 |
| 起動 function | 主に呼び出される FN-ID | 文字列（複数なら `;` 区切り） |
| 営業開始必須 | 営業開始時点で確認が必須か | TRUE / FALSE |
| 重要度 | 高 / 中 / 低 | 入力規則 |
| 完了条件 | フローが正常完了した状態の定義 | 文字列 |
| 確認方法 | 自動テスト / 実機 / AI確認 等 | 入力規則 |
| 備考 | 時期制約や注意事項 | 文字列 |

## 5. done 条件と着手時再確認事項

done 条件:
- [ ] 営業開始必須フローが全件列挙されている
- [ ] 各フローに必須列が埋まっている（不明は `未確認` で明示済み）
- [ ] ART-102 の Function-Flow 対応表と FLOW-ID / FN-ID が整合している
- [ ] ART-103_業務フロー一覧_説明.md と Excel 正本が整合している
- [ ] `ART-902_タスク管理台帳` のステータスが `完了` に更新されている

着手時に再確認すること:
- ART-102 の Function-Flow 対応表の初版が存在するか
- 業務カテゴリの粒度が ART-201 統合ワークブックと整合しているか
- D-2〜D-4（テスト実行・不具合ループ）は TSK-201 で担うことを再確認する
