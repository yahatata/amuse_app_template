## 1. この文書の役割

本書は旧 `B-1_Config台帳_進め方.md` の内容を引き継ぎ、TSK-101 の実施手順を固定する。  
旧進め方の設計原則・根拠優先順位・段階設計はそのまま活用する。

---

## 2. 根拠の優先順位

| 優先順位 | 根拠 | 使い方 |
|---|---|---|
| 1 | 実装コード | 設定項目の存在・保存先・型・fallback・利用元の主根拠 |
| 2 | テストコードと実行結果 | 実装解釈の正しさ、境界条件確認の根拠 |
| 3 | Firestore 実値 / Emulator / Log | 実装想定と実データ構造の一致確認 |
| 4 | 既存ドキュメント | 背景説明・業務意図の補助根拠 |

原則: 既存ドキュメントだけを根拠に row を確定しない。実装と docs が食い違う場合は実装を正とする。

## 3. 全体の進め方

| 段階 | 目的 | この段階で行うこと | 気をつけること | 中間成果物 |
|---|---|---|---|---|
| 0. 着手判定 | 今着手してよいか確認 | A タスク進捗・対象範囲・参照元準備状況を確認 | 構造変動中に row 大量投入しない | 着手可否メモ |
| 1. 対象範囲固定 | 何を入れるか確定 | 対象設定群と対象外を明示 | 現在値管理と定義管理を混同しない | 対象一覧 |
| 2. 根拠棚卸し | どこを見れば埋められるか揃える | 実装・テスト・実環境確認方法・既存 docs を棚卸し | docs を先に正にしない | 根拠一覧 |
| 3. AI 一次草案 | row のたたきを作る | AI がコードを読み各 row の草案を出す | 推測を断定しない。未確定は未確定と残す | row 草案 |
| 4. 根拠強化 | 草案に証拠を付ける | テストコード確認・必要に応じて実環境 shape 確認 | コード上の定義と実運用 shape の差を見逃さない | 根拠付き草案 |
| 5. 人判断 | 業務判断を確定 | 標準値・変更方法・初期設定方法・現役区分を確定 | AI が埋めにくい運用判断を放置しない | 確定前レビュー版 |
| 6. 正本反映 | Excel 正本へ投入 | 承認済み row を ART-101_Config台帳.xlsx へ反映 | 構造変更と内容更新を混ぜない | 正本更新版 |
| 7. 閉じ方整理 | 完了状態を整える | 説明 md との整合・残課題返却先・done 判定を整理 | 未解決を台帳に埋め込んだまま閉じない | 完了記録 |

## 4. 各段階での考え方

### 4.1 AI 一次草案で優先して埋める列

- `保存path` / `field名` / `型` / `許容値・形式` / `未設定時挙動` / `デフォルト値` / `主な利用元` / `業務意味`（草案）

### 4.2 AI が仮置きに留める列

- `標準値（推奨値）` / `変更方法` / `初期設定方法` / `現役区分`

### 4.3 根拠強化時の確認観点

- defaults と loader の整合
- runtime fallback と initialize 時の初期値の差
- enum / 範囲 / null 許容の扱い
- Firestore 実値の shape が実装想定とズレていないか

### 4.4 特に確認強度を高くする設定

- `requiredStaffByTimeSlot`：挙動設計が他の設定と異なる
- `taxReportingBehavior`：実装・テスト根拠が相対的に薄い可能性あり

## 5. AI と人の役割分担

| 領域 | AI が担うこと | 人が担うこと |
|---|---|---|
| 実装把握 | code search・loader/defaults/types 読解・利用元洗い出し | 解釈の最終承認 |
| 草案作成 | row 草案・業務意味の初稿・候補値整理 | 初稿の採否判断 |
| テスト整理 | 対応テスト抽出・実行候補整理・結果要約 | 実行要否判断・結果の最終評価 |
| 実環境確認 | 実行用コマンド案・抽出観点整理・結果整理 | 認証が必要な確認実行・結果の信用判断 |
| 運用判断 | 判断論点の列挙・選択肢整理 | 標準値・変更方法・現役区分の最終決定 |
| 正本反映 | Excel 反映用の整形出力 | ChatGPT for Excel 実行・最終確認 |

## 7. done 条件と着手時再確認事項

done 条件:
- [ ] ART-101_Config台帳.xlsx に対象範囲の row が投入済み

- [ ] `標準値` `変更方法` が放置されていない
- [ ] 差し戻し先（ART-102 / ART-201 等）が決まっている
- [ ] `ART-902_タスク管理台帳` のステータスが `完了` に更新されている

着手時に再確認すること:
- A タスクの config 系修正で対象 field が変わっていないか
- ART-101 の列構造に追加修正が必要ないか
- ART-102 / ART-201 との役割分担が変わっていないか
