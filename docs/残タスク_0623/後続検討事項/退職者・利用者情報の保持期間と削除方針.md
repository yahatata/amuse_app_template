# 退職者・利用者情報の保持期間と削除方針

**作成日**: 2026-07-03  
**ステータス**: 後続検討事項（現時点では実装対象外）  
**関連タスク**: [A-3 スタッフ退職処理](../カテゴリA_システム構築/A-3_スタッフ退職処理/概要.md)

---

## 1. 背景

A-3 スタッフ退職処理の検討中に、退職者の個人情報をいつまで保持するか、どのタイミングで削除・マスクするかという論点が出た。

ただし、この論点はスタッフ退職処理だけでなく、ユーザー情報、スタッフ情報、勤怠、給与、支払い、会計、問い合わせ対応、法務・労務・税務保存期間にも関わる。

そのため、A-3の初期実装には含めず、**プロジェクト全体の後続検討事項** として扱う。

---

## 2. 検討対象

- 退職済みスタッフの情報
- 利用停止・退会済みユーザーの情報
- 勤怠履歴
- 給与計算結果
- 支払い状態管理
- 会計関連履歴
- LINE userId / Firebase uid
- 連絡先
- 銀行口座情報
- QR関連情報
- その他個人情報に該当する可能性がある情報

---

## 3. A-3での暫定方針

A-3では、退職時に以下を **削除・クリア** する。

- `email`
- `phoneNumber`
- `birthMonthDay`
- `loginId`
- QR関連情報（`qrCodeUrl` / `qrExpiresAt` / `qrExpiresAtMs` 等）

A-3では、以下を **保持** する。

- `uid` / docId
- `fullName`
- `fullNameKana`
- `hourlyWage`
- `bankInfo`
- 退職情報（`retiredAt` / `retiredDate` / `retiredReason`）
- 給与・勤怠・履歴に必要な情報

`hourlyWage` / `bankInfo` は、退職時も給与支払い完了後も **A-3 初期実装では削除しない**。

詳細は [詳細仕様書.md](../カテゴリA_システム構築/A-3_スタッフ退職処理/詳細仕様書.md) §7 を参照。

---

## 4. 後続で検討すべき論点

- 退職者情報をいつまで保持するか
- 給与支払い完了後に `bankInfo` を削除・マスクするか
- 一定期間経過後に `hourlyWage` を削除・マスクするか
- `fullName` / `fullNameKana` を一定期間後にマスクするか
- LINE userId / Firebase uid をどこまで保持するか
- 再登録・再利用との整合
- ユーザー退会時の情報保持・削除方針
- 法務・労務・税務上の保存期間
- 店舗側が閲覧できる情報の制限
- 管理者のみ閲覧できる情報の分離
- 削除済み・マスク済み情報を履歴画面でどう表示するか
- 削除依頼が来た場合の対応
- 漏えい時の影響を減らすための設計

---

## 5. 現時点の扱い

このファイルは **後続検討事項** であり、現時点では実装対象ではない。

A-3では、退職処理・本人操作停止・再登録・LINEリッチメニュー制御・退職済み表示を優先する。

情報保持期間や一定期間後の削除・マスクについては、別途プロジェクト全体の方針として整理する。
