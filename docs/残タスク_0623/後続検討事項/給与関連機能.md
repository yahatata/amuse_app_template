# 給与関連機能のリリース時対応に関する後続検討事項

## 1. 背景

- **A-5** では給与関連 **通知9種** の種別・重要度・発火タイミングのみを整理・確定した。
- 給与関連機能そのもの（計算・確定・支払い管理・通知基盤）を **リリース対象に含めるか** は別判断である。
- 給与機能をリリースしない、または一部を対象外にする場合、通知仕様だけでは不十分で、**UI・Functions・scheduler・設定** の扱いを別途検討する必要がある。

関連: [../カテゴリA_システム構築/A-5_給与関連通知整理/概要.md](../カテゴリA_システム構築/A-5_給与関連通知整理/概要.md)

---

## 2. 検討対象

- Admin HOME の **給与計算** ボタンを非表示にするか
- 給与計算画面への遷移を止めるか
- 給与関連 **Callable** を拒否するか（`executeMonthlyPayroll`, `getPayrollCandidates` 等）
- 給与 **scheduler** / `payrollNotificationScheduler` を止めるか
- 給与 **通知を生成しない** ようにするか
- 既存の給与関連 **Firestore データ**（`monthlyPayroll` 等）をどう扱うか
- 設定として `payrollFeatureEnabled` / `payrollNotificationsEnabled` のようなフラグを追加するか
- 開発環境・検証環境・本番環境で挙動を分けるか

---

## 3. 想定される方針案

### 案A: 給与関連機能を完全に非表示・無効化する

- UI 非表示 + Callable 拒否 + scheduler 停止 + 通知停止
- 誤操作・誤通知のリスクが最も低い
- 実装・運用コストは最大

### 案B: UI は非表示だが、既存処理は残す

- 画面からは触れないが、scheduler や既存データは動きうる
- 段階的リリース向き。バックエンドだけ先行デプロイしている場合に該当しうる

### 案C: 給与機能は残し、通知だけ止める

- 計算・確定は使えるが `notifications` への給与通知作成を止める
- A-5 で確定した通知仕様の実装前に、通知だけ出したくない場合の暫定策として検討可

### 案D: 店舗設定で給与機能 ON/OFF を切り替える

- `payrollFeatureEnabled` 等で店舗単位に制御
- マルチテナント・段階導入向き。設計・テストコストは案Aより高い

---

## 4. 未決事項

- リリース初期状態で **給与機能を出すか**
- 出さない場合、**UI だけ隠すか、Functions 側でも拒否するか**
- scheduler を止める **単位**（親 job のみ / child 含む / 給与系全体）
- 通知を止める **単位**（全9種 / スケジューラーのみ / triggerType 単位）
- `payrollFeatureEnabled` を導入するか
- `payrollNotificationsEnabled` を導入するか
- 既存ドキュメント（`07_NOTIFICATION_SCHEDULER_SPEC.md`、運用資料等）の **どこへ反映するか**

---

## 5. A-5 との関係

| 区分 | 内容 |
|------|------|
| **A-5 で確定したこと** | 通知9種の種別・重要度・発火タイミング |
| **A-5 スコープ外** | 通知 doc 生成方式、再通知制御、導線、通知 ON/OFF、**本ドキュメントのテーマ** |
| **本ドキュメント** | A-5 の後続検討事項として管理。給与機能のリリース ON/OFF はここで扱う |

A-5 スコープ外として明示した項目（通知方式・導線・ON/OFF 等）も、必要に応じて本ドキュメントまたは別資料で具体化する。
