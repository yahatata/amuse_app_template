## 1. 位置づけ

本資料は、`B-1_Config台帳.xlsx` の説明資料として最終的に完成させることを前提とした叩きである。  
現時点では列構造、候補値、更新ルールの初期案を持ち、B-1 作業の進行に合わせて Excel 正本との整合を取りながら完成させる。

`B-1_Config台帳` は、業務設定項目の定義台帳である。  
この台帳は「現在その値が何か」を管理する資料ではなく、次の内容を管理するために使う。

- どの設定項目が存在するか
- どこに保存されるか
- 何を制御する設定か
- どの値を許容するか
- 値ごとにどう振る舞うか
- 未設定時にどう動くか
- 標準的にどの値を採用すべきか
- 誰がどの方法で変更するのか
- 導入時にどう初期設定するのか
- どの function / 画面 / 処理がその設定を読むのか

この台帳は、設定項目の意味と運用方法の正本であり、環境ごとの実値台帳ではない。

---

## 2. 管理対象

この台帳に登録する対象は、原則として次の条件を満たす設定項目とする。

- 店舗運用や本番動作に影響する業務設定である
- 設定値により function、画面、scheduler、業務フローの挙動が変わる
- 導入時または保守運用時に設定内容を判断する必要がある

現時点の主対象は次の設定群とする。

- `config`
- `payrollConfig`
- `schedulerConfig`
- `requiredStaffByTimeSlot`
- `reportingGroupConfig`
- `taxReportingBehavior`

必要に応じて新たな業務設定群を追加してよいが、追加時は `02_用語・ステータス定義` と整合を確認する。

---

## 3. 管理対象外

次のものは、この台帳では原則管理しない。

- 環境ごとの現在値そのもの
- Secret や credential の値
- 単なるコード定数
- 一時的なデバッグフラグ
- 仕様化されていない試験用設定

ただし、将来設定項目として正式運用する前提があるものは `planned` として登録してよい。

---

## 4. workbook 構成

本資料に対応する workbook は `B-1_Config台帳.xlsx` とする。  
主シートは `Config一覧` とし、原則 `1資料 = 1主シート` に従う。

現時点の想定は次の通り。

- 主シート: `Config一覧`
- 補助シート: 原則なし

入力規則用の補助シートが必要になった場合は追加してよいが、その場合でも `Config一覧` を主シートとする。

---

## 5. 1行の単位

この台帳の 1 行は `1設定項目` を表す。  
原則として 1 leaf field を 1 行で管理する。

例:

- `stores/{storeId}/storeMeta.config.someFlag` が 1 設定なら 1 行
- `stores/{storeId}/storeMeta.payrollConfig.cutoffDay` が 1 設定なら 1 行

同じ object 配下に複数 field がある場合も、field ごとに行を分ける。  
1 行の中に複数設定をまとめない。

---

## 6. 列の意味

主シート `Config一覧` では、以下の列を持つ。

| 列名 | 役割 | 記載ルール | 記入例 |
|---|---|---|---|
| `CFG ID` | 設定項目の一意識別子 | `CFG-xxx` 形式を原則とする | `CFG-001` |
| `config区分` | どの設定群に属するか | `02_用語・ステータス定義` と整合する候補値を使う | `config` |
| `現役区分` | 現在の位置づけ | `live` / `legacy` / `planned` / `delete候補` を使う | `live` |
| `論理名` | 人が理解しやすい設定名 | 日本語中心で、業務上の意味が分かる名称にする | `締日` |
| `保存path` | 設定の保存先 path | repo 依存ではなく、実データ構造を表す path を書く | `stores/{storeId}/storeMeta` |
| `field名` | path 配下の field 名 | leaf field を原則とする。必要なら dot notation を使う | `payrollConfig.cutoffDay` |
| `適用スコープ` | どこに効く設定か | 候補値を使う | `店舗単位` |
| `型` | 値の型 | 候補値を使う | `integer` |
| `必須区分` | 必須性 | `必須` / `任意` / `条件付き必須` | `必須` |
| `業務意味` | 何を制御する設定か | 1〜2文で簡潔に書く | `給与計算の締日を定義する` |
| `許容値・形式` | 取りうる値や形式 | enum は `; ` 区切り、範囲は `0..60`、形式は `HH:mm` などで書く | `1..31` |
| `各許容値での挙動` | 値ごとの挙動 | `値 => 挙動` の形式で書く | `1 => 毎月1日締め; 15 => 毎月15日締め` |
| `未設定時挙動` | 欠落時の挙動 | 候補値を使う | `default使用` |
| `デフォルト値` | 未設定時に採用する値 | `未設定時挙動 = default使用` の時は必須 | `15` |
| `標準値（推奨値）` | 推奨する運用値 | 原則 1 値を入れる | `15` |
| `主な利用元（function/画面/処理）` | どこが読むか | `FN:` `UI:` `JOB:` などの接頭辞を付け、複数は `; ` 区切り | `FN: finalizePayrollRun; UI: 給与設定画面` |
| `反映タイミング` | いつ効くか | 候補値を使う | `次回読取時` |
| `変更方法` | 誰がどう変更するか | 候補値を使う | `保守手動変更` |
| `初期設定方法` | 導入時の初期投入方法 | 候補値を使う | `テンプレ投入` |
| `更新区分` | 台帳としての更新契機 | `継続` / `変更時` / `節目` / `単発` を使う | `変更時` |
| `備考` | 補足 | 例外、移行中事情、判断保留、分割予定などを書く | `旧設定から移行中` |

---

## 7. 入力規則と標準記法

この台帳では、少なくとも次の列に入力規則を持たせる。

- `config区分`
- `現役区分`
- `適用スコープ`
- `型`
- `必須区分`
- `未設定時挙動`
- `反映タイミング`
- `変更方法`
- `初期設定方法`
- `更新区分`

候補値の正式意味は `02_用語・ステータス定義` を正本とする。  
現時点の運用開始案としては次を使う。

| 列名 | 初期候補値 |
|---|---|
| `config区分` | `config`; `payrollConfig`; `schedulerConfig`; `requiredStaffByTimeSlot`; `reportingGroupConfig`; `taxReportingBehavior`; `その他` |
| `現役区分` | `live`; `legacy`; `planned`; `delete候補` |
| `適用スコープ` | `全体共通`; `店舗単位`; `日付単位`; `時間帯単位`; `スタッフ単位`; `機能単位` |
| `型` | `boolean`; `string`; `number`; `integer`; `enum`; `object`; `array`; `map` |
| `必須区分` | `必須`; `任意`; `条件付き必須` |
| `未設定時挙動` | `default使用`; `fail-closed`; `fail-open`; `legacy fallback`; `last-good使用`; `処理停止`; `該当なし` |
| `反映タイミング` | `即時`; `次回読取時`; `次回ジョブ実行時`; `再ログイン後`; `再起動後`; `デプロイ後` |
| `変更方法` | `UI変更可`; `保守手動変更`; `導入時設定`; `コード変更` |
| `初期設定方法` | `テンプレ投入`; `手動入力`; `既存値移行`; `スクリプト投入`; `system default` |
| `更新区分` | `継続`; `変更時`; `節目`; `単発` |

標準記法:

- 未確定は `未確認` または `TBD`
- 該当しない場合は `該当なし`
- 複数値の区切りは `; `
- 色は補助として使ってよいが、意味は列値でも持つ
- 結合セルは禁止
- 空行・空列を構造として使わない

---

## 8. 列間ルール

次の列間ルールを持たせる。

- `未設定時挙動 = default使用` の時は `デフォルト値` を必須にする
- `型 = enum` の時は `許容値・形式` を必須にする
- `型 = enum` の時は `各許容値での挙動` を原則必須にする
- `必須区分 = 条件付き必須` の時は、条件を `備考` に明記する
- `変更方法 = UI変更可` の時は、必要に応じて `主な利用元（function/画面/処理）` に変更画面情報を含める
- `現役区分 = legacy` または `delete候補` の時でも、既存利用元は消さずに残す
- `デフォルト値` と `標準値（推奨値）` が異なる場合は、理由を `備考` に残す

---

## 9. 更新ルール

### 9.1 新規設定項目を追加する時

- 正式に運用する設定項目は、この台帳へ追加する
- path と field が未確定なら `TBD` を使う
- 候補値、未設定時挙動、変更方法が未定なら `未確認` ではなく判断待ちであることを `備考` に残す

### 9.2 既存設定項目を更新する時

- `業務意味`、`許容値・形式`、`各許容値での挙動`、`未設定時挙動` が変わるなら台帳も更新する
- 読取側 function や画面が変わった時は `主な利用元` も更新する
- `現役区分` が変わる場合は `備考` に理由を残す

### 9.3 廃止・置換する時

- 行削除ではなく `現役区分` を `delete候補` または相当状態へ変更する
- 実廃止が完了したら `備考` に置換先や廃止理由を残す
- 利用元情報は後追い確認のため残す

## 10. 他資料との関係

この台帳と他資料の役割分担は次の通り。

- `B-1_Config台帳`: 設定項目の定義そのものを持つ
- `B-2_本番化チェックリスト`: 設定が正しく反映されているかを確認する
- `C-1_FunctionContract台帳`: どの function がどの config に依存するかを整理する
- `G-3_技術説明資料群`: 設定項目の説明を外向け・引継ぎ向けに再構成する

この台帳は「設定の定義」と「設定の運用方法」を持つ。  
現在値や環境別の実設定確認は、別資料または実機確認で扱う。

## 11. AI / ChatGPT for Excel 利用時の読み方

AI が `B-1_Config台帳.xlsx` を扱う時は、次の順で読む。

1. まずこの `B-1_Config台帳_説明.md` を読む
2. 次に `02_用語・ステータス定義.md` を読む
3. その後に `01_資料ライフサイクル・更新ルール.md` を読む
4. 必要な列だけを ChatGPT for Excel に抽出させる
5. 抽出結果は件数・抽出日時・抽出条件付きで受け取る

構造変更とデータ更新は同時依頼しない。  
まず構造を整え、その後に設定項目の row を投入する。

## 12. 生成プロンプト要約

`B-1_Config台帳.xlsx` の初回作成または構造更新時は、次の方針を使う。

- 主シートは `Config一覧`
- `1設定項目 = 1行`

- 候補値列には入力規則を設定する

- 主シートはテーブル化し、先頭行固定、フィルタ有効化とする
- 条件付き書式は補助用途に限定する
