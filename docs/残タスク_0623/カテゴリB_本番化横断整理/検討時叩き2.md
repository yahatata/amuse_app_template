# カテゴリB: 本番化横断整理 — 検討時叩き2

> 位置づけ: 個別機能の実装とは別に、システム全体を本番レベルに引き上げる工程

---

## このカテゴリで答える問い

- 本番で事故につながる設定や暫定実装が残っていないか
- scheduler / queue / log / central write は運用に耐える状態か
- rules / auth / secret / debug 導線に危険な穴が残っていないか
- 削除すべき不要物と、残してよい暫定物が区別できているか

---

## 目標と実施内容

| 目標 | 実施内容 | 主な成果物 |
|---|---|---|
| 設定方針を固める | `config` `payrollConfig` `schedulerConfig` `requiredStaffByTimeSlot` などの設定群を一覧化し、未設定時挙動・デフォルト値・標準値・変更方法を整理する | `B-1_Config台帳_進め方`、Config台帳 |
| 非同期実行を本番基準で確認する | scheduler job、Cloud Tasks queue、handler log、`amuse-admin` 表示、central write の整合を確認する | Scheduler運用確認記録、横断マトリクス更新版 |
| 権限と境界を本番化する | Firestore Rules、Auth ガード、role ごとの許可範囲、dev 用全許可、固定値、secret 利用を確認する | 権限本番化チェックリスト |
| 不要物と暫定物を整理する | `unused_function_lib/`、`lib/to_be_deleted/`、debug route、未使用 env、placeholder を分類し、削除または残置理由を決める | 削除候補台帳、残置理由一覧 |

---

## このカテゴリで作成する資料

| 資料名 | 目的 | 資料だけで完了か |
|---|---|---|
| `B-1_Config台帳_進め方` | B-1 の根拠優先順位、役割分担、進行段階、done 条件を固定する | はい |
| Config台帳 | runtime 設定の全項目と fallback 方針を整理する | いいえ |
| 本番化チェックリスト | rules / auth / secret / debug / fixed value を横断確認する | いいえ |
| Scheduler運用確認記録 | 非同期実行の運用結果を残す | いいえ |
| 削除候補台帳 | 不要コード・不要UI・不要function の判断を残す | いいえ |
| 横断マトリクス更新版 | B の結果を全体進捗に反映する | いいえ |

---

## サブタスク

### B-1: config / runtime / fallback 方針の確定

- `storeMeta` 配下の設定を網羅的に列挙する
- 未設定時挙動、デフォルト値、標準値、変更方法、初期設定方法を整理する
- docs とコードのズレを修正する

#### B-1 の担い範囲

| 検討時叩き2 の要素 | 担い手 | 備考 |
|---|---|---|
| 設定群の一覧化（`config`、`payrollConfig` など） | B-1 タスク | Config台帳の row として管理する |
| `fail-closed / last-good / defaults` 分類 | B-1 タスク | `未設定時挙動`、`デフォルト値`、`備考` へ統合し、独立した fallback 方針表は作らない |
| `client 直読み / callable 経由 / last-good` の扱い | 要整理 | B-1 の `主な利用元`、`備考` で持つか、C-1 へ委譲するかを B-1 進め方で固定する |
| `storeMeta` 配下の網羅列挙 | B-1 タスク | 実装コードを主根拠として行う |
| docs とコードのズレ修正 | B-1 タスクの副次成果 | B-1 だけで閉じない差分は差し戻し先を明記する |
| 本番化チェックリスト（B-2） | B-1 では担わない | B-2 へ |
| scheduler / queue / central write 確認 | B-1 では担わない | B-2 へ |
| rules / auth / secret 本番化 | B-1 では担わない | B-3 へ |
| 不要コード・UI 整理 | B-1 では担わない | B-4 へ |

### B-2: scheduler / Cloud Tasks / central write の再確認

- Phase 7 の残件を完了する
- job、queue、handler log、`taskLogs`、`amuse-admin` 表示を突合する
- `scheduleGenerateNextYearBusinessHours` のような時期制約項目は別管理で残す

### B-3: rules / auth / 権限境界の本番化

- dev 用全許可ルールを洗い出す
- table device、side game、admin 操作、staff 操作の境界を見直す
- 固定パスワードや危険な暫定値が残っていないか確認する
- Secret Manager 利用へ寄せるべき箇所を整理する

### B-4: 不要コード・不要UI・暫定実装の整理

- `unused_function_lib/` の live / legacy / parked / 削除候補を分類する
- `lib/to_be_deleted/`、debug page、test route を本番 UI から外す
- `.env`、`process.env`、プレースホルダー、古い docs を整理する

---

## 完了条件

- Config台帳が埋まり、重要設定の fallback 方針が確定している
- scheduler / queue / handler / central write の確認記録がそろっている
- dev 用全許可や危険な固定値の扱いが決まっている
- 不要物の削除または残置理由が記録されている
- 必要な修正がコード、rules、Secrets、GCP 設定に反映済みである
