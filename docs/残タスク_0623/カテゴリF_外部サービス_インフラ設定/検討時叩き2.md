# カテゴリF: 外部サービス・インフラ設定 — 検討時叩き2

> 位置づけ: 外部サービスと本番インフラを、実際に使える状態へそろえる工程

---

## このカテゴリで答える問い

- LINE / LIFF / 通知 / Secret / IAM は、本番値でそろっているか
- 店舗側と中央側で、どのアカウントと Secret を使うか明確か
- 設定後の疎通確認まで終わっているか

---

## 目標と実施内容

| 目標 | 実施内容 | 主な成果物 |
|---|---|---|
| 店舗側 LINE / LIFF を使える状態にする | OA 作成、LIFF 登録、Webhook、Channel Access Token、疎通確認を行う | 店舗LINE設定台帳、疎通確認記録 |
| 中央通知の設定を完了する | `amuse-admin` 通知用 LINE の方針決定、Token 保存、通知先登録、送信確認を行う | 中央通知設定記録 |
| Secret / IAM / env を本番値にする | Secret Manager、`.env`、SA 権限、中央プロジェクト設定を確認する | Secret/IAM台帳 |
| 補助サービスの扱いを決める | SendGrid など優先度の低い外部サービスを導入するか判断し、必要なら設定する | 補助サービス設定記録 |

## サブタスク

### F-1: 店舗側 LINE / LIFF 設定

- LINE Official Account 作成
- 顧客向け / スタッフ向け LIFF 登録
- リッチメニュー設定
- Webhook URL 設定
- Token 保存と疎通確認

### F-2: 中央通知設定

- `amuse-admin` 用 LINE の運用方針を決める
- 中央プロジェクトの Secret Manager に Token を保存する
- テスト通知を送って動作確認する

### F-3: Secret / IAM / env の本番化

- `.env` のプレースホルダー除去
- Secret の本番値設定
- SA 権限付与
- どの権限がどの用途かを記録する

### F-4: 補助サービスの判断

- SendGrid を使うか、後回しにするかを決める
- 使う場合は認証と API キー登録まで行う

### F-5: 接続証跡の保存

- 実設定を行っただけで終わらせず、疎通確認ログや画面キャプチャの所在を残す

---

## 完了条件

- 店舗側と中央側の外部サービス設定が完了している
- Secret / IAM / env の本番値化が終わっている
- LINE 通知や LIFF の疎通確認が pass している
- 設定責任者と更新手順が残っている
