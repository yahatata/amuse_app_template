## 1. この文書の役割

本書は、`TSK-xxx` 系のタスク資料を作成・更新・完了させる際に適用する共通ルールを定める。

対象とする作業:
- `TSK-xxx` の新規作成
- `TSK-xxx` の内容・進め方の更新
- `TSK-xxx` の完了処理（実施まとめ・申し送り）
- `ART-902_タスク管理台帳` への登録

---

## 2. タスク資料の構成

各 `TSK-xxx` は、必要に応じて次の 4 ファイルで構成する。

| ファイル | 必須・任意 | 役割 |
|---|---|---|
| `TSK-xxx_[タスク名]_内容.md` | **必須** | そのタスクで何を扱うか、何を達成するかを定める |
| `TSK-xxx_[タスク名]_進め方.md` | **必須** | どの順で、何を根拠に、どう進めるかを定める |
| `TSK-xxx_[タスク名]_実施まとめ.md` | 必要時のみ | 実際に何をやったかを記録する |
| `TSK-xxx_[タスク名]_申し送り.md` | 必要時のみ | 他タスクへ返す論点・依存・未解決事項を残す |

原則:
- すべての予定タスクに空の `実施まとめ` を先置きしない
- `申し送り` は必要時のみ作成する。閉じた議論を残さない
- `内容` と `進め方` は着手前に作成する

---

## 3. 命名規則

```
TSK-xxx_[タスク名]_[種別].md
```

| 要素 | ルール |
|---|---|
| `TSK-xxx` | 3桁ゼロ埋め採番。一度採番したIDは再利用しない |
| `[タスク名]` | 日本語可。スペース不可。アンダースコア区切り |
| `[種別]` | `内容` / `進め方` / `実施まとめ` / `申し送り` のいずれか |

採番の大まかな区分:

| 番台 | 対象 |
|---|---|
| `001〜009` | 再編基盤タスク |
| `010〜019` | 再編基盤補助タスク |
| `101〜199` | 実装定義整備タスク |
| `201〜299` | 確認基盤整備タスク |
| `301〜399` | 本番化実行・差分収束タスク |
| `401〜499` | 導入準備整備タスク |
| `501〜599` | 後続資料整備タスク |
| `601〜699` | 後続整備（運用資料、営業・契約等） |
| `701〜799` | 中央管理アプリ対応タスク |
| `901〜999` | 再編基盤・管理台帳自体に関するタスク |

## 5. 各ファイルの先頭必須記載

すべての `TSK` ファイルの先頭に次を記載する。

```
> 概要:
> 主な目的:
> 正本区分: md正本
> 対象:
> 更新区分: 変更時
> 参照元:
> 参照先:
```

加えて `内容.md` には次も記載する:

```
> TSK-ID:
> タスク名:
> 対応 ART:
> 依存 TSK:
> 優先度:
> ステータス:
> done 条件:
```

---

## 6. done 条件の定め方

`done` は資料完成だけにしない。  
次の基準をすべて満たした時に `done` とする。

1. `内容.md` と `進め方.md` が最新状態である
2. `進め方.md` に記載した確認・実行が完了している
3. 対応する `ART` が作成・更新されている
4. 未解決事項の返却先が決まっている（または存在しない）
5. `ART-902_タスク管理台帳` のステータスが `完了` に更新されている

---

## 7. ART-902 への登録タイミング

`TSK-xxx` を新規作成したら、必ず `ART-902_タスク管理台帳` へ登録する。  
登録は `内容.md` 作成と同タイミング、または直後に行う。

登録に必要な情報は `内容.md` の先頭メタデータから取得する。

---

## 8. TSK と ART の関係

- `TSK` は `ART` を作成・更新・確認するために存在する
- `TSK` 自体は恒久資料ではない
- `ART` に昇格すべき内容が `TSK` に残ったまま閉じない
- `TSK` 完了後も参照価値のある内容は、対応 `ART` の説明資料へ転記してから `TSK` を閉じる
