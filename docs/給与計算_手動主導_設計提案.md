# 給与計算システム設計提案：手動主導・スケジューラー補助

最終更新: 2026-03-04

---

## 1. 一般的な給与計算の運用

### 1.1 締め日・支払日の関係

| 項目 | 一般的な運用 | 根拠 |
|------|-------------|------|
| **締め日** | 末日 or 25日など固定日 | 集計の区切りを明確にする |
| **支払日** | 締め日から15日以上後 | 給与計算・銀行振込の営業日数を確保 |
| **計算期間** | 締め日〜支払日の間に実施 | 勤怠確定→計算→支払の流れ |

### 1.2 よくあるパターン

- **月末締め・翌月25日払い**: 1/1〜1/31 → 2/25 支払
- **26日締め・翌月25日払い**: 1/26〜2/25 → 3/25 支払（本テンプレートのデフォルト）

### 1.3 手動実行が主である理由（実務）

1. **勤怠修正の反映**: 締め日後に修正申請が入ることがある
2. **確認フロー**: 計算前に管理者が勤怠を目視確認したい
3. **店舗ごとの締め日差異**: 26〜25日締め、1〜末日締めなど店舗により異なる
4. **支払日とのずれ**: 締め日と支払日が店舗ごとに異なり、計算タイミングも変わる

## 2. 提案するシステム構成

### 2.1 全体像

```
┌─────────────────────────────────────────────────────────────────────┐
│                        給与計算の入口                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  【主】手動実行                                                       │
│  ┌─────────────────┐     ┌──────────────────┐     ┌──────────────┐ │
│  │ Flutter 管理画面  │ ──► │ executeMonthlyPayroll │ ──► │ monthlyPayroll │ │
│  │ 「給与計算を実行」 │     │ (Callable)            │     │ コレクション   │ │
│  └─────────────────┘     └──────────────────┘     └──────────────┘ │
│         │                            │                              │
│         │ 期間選択                    │ 期間・実行者を記録              │
│         │ 確認ダイアログ               │ payrollReflectedAt 付与        │
│         ▼                            ▼                              │
│  ┌─────────────────┐     ┌──────────────────┐                      │
│  │ 勤怠一覧で事前確認 │     │ 実行履歴・監査証跡  │                      │
│  └─────────────────┘     └──────────────────┘                      │
│                                                                     │
│  【補助】スケジューラー                                                │
│  ┌─────────────────┐     ┌──────────────────┐                      │
│  │ monthlyPayroll   │ ──► │ 同上（同一ロジック） │                      │
│  │ Trigger          │     │ triggerSource:    │                      │
│  │ (25日 23:59等)   │     │ 'scheduler'      │                      │
│  └─────────────────┘     └──────────────────┘                      │
│         │                                                           │
│         │ schedulerConfig.monthlyPayrollTriggerEnabled で ON/OFF   │
│         │ 手動実行を忘れた場合の補完・リマインダーとして機能           │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 役割分担

| 入口 | 役割 | 想定ユースケース |
|------|------|------------------|
| **手動実行** | 主たる実行手段 | 勤怠確認後に管理者が実行。締め日翌日〜支払日前の任意タイミング |
| **スケジューラー** | 補助・リマインダー | 手動実行を忘れた場合の自動実行。または「毎月25日締め翌日に実行」の定型運用 |

## 3. 実装詳細

### 3.1 新規 Callable: `executeMonthlyPayroll`

**目的**: 管理者が任意の期間で給与計算を手動実行する。

**引数**:
```typescript
{
  periodStart: string;  // "YYYY-MM-DD"
  periodEnd: string;    // "YYYY-MM-DD"
}
```

**バリデーション**:
- `periodEnd` が今日以前であること（未来の勤怠を含まない）
- `periodStart` < `periodEnd`
- 認証済みであること（`request.auth` あり）
- 呼び出し元デバイスの `role` が `admin` であること（または適切な権限）

**処理内容**:
- `monthlyPayrollTrigger` と同一の給与計算ロジックを実行
- 期間内の勤怠を集計し、`monthlyPayroll` に保存
- `payrollReflectedAt` を付与
- `attendanceLogs` に `monthly_payroll_reflect` を書き込み
- `calculatedBy`: `'manual'` または `deviceId` / `uid` を記録
- `triggerSource`: `'manual'` を追加（任意）

**戻り値**:
```typescript
{
  success: true,
  periodStart: string,
  periodEnd: string,
  staffCount: number,
  result: Array<{ staffId, staffName, totalPay, ... }>
}
```

### 3.2 既存ロジックの共通化

`monthlyPayrollTrigger` と `executeMonthlyPayroll` で重複するロジックを共通関数に抽出する。

```
functions/src/domains/attendance/
  ├── scheduler/
  │   └── monthlyPayrollTrigger.ts   # スケジューラー用エントリ
  ├── callables/
  │   └── executeMonthlyPayroll.ts   # 手動実行用 Callable（新規）
  └── helpers/
      └── runMonthlyPayrollLogic.ts  # 共通ロジック（新規）
```

**共通関数のシグネチャ**:
```typescript
async function runMonthlyPayrollLogic(params: {
  db: Firestore;
  periodStart: Date;
  periodEnd: Date;
  triggerSource: 'manual' | 'scheduler';
  performedBy?: { deviceId?: string; uid?: string };
}): Promise<RunMonthlyPayrollResult>;
```

### 3.3 期間計算の修正（endDay≠0 の場合）

前回の議論で指摘した通り、**実行日が endDay より前**のときは「前々月 startDay 〜 前月 endDay」を対象にする。

| 条件 | 対象期間 |
|------|----------|
| 実行日 ≥ endDay | 前月 startDay 〜 今月 endDay |
| 実行日 < endDay | 前々月 startDay 〜 前月 endDay |

スケジューラーは `executeMonthlyPayroll` の共通ロジックを呼ぶ際、上記ルールで「直近で終了した期間」を計算して渡す。

### 3.4 再実行（上書き）の扱い

- **同一期間・同一 staffId の重複**: 給与計算を再実行した場合、既存の `monthlyPayroll` ドキュメントを**上書き**する（または `staffId` + `periodStart` でユニークにして upsert）。
- **payrollReflectedAt**: 再付与で上書き（問題なし）。
- **attendanceLogs**: 再実行のたびに `monthly_payroll_reflect` を追加（監査証跡として残す）。

**推奨**: `staffId` + `periodStart` をユニークキーにして upsert。既存データがあれば更新、なければ新規作成。

### 3.5 monthlyPayroll スキーマの拡張

| フィールド | 型 | 説明 |
|------------|-----|------|
| `triggerSource` | `'manual' \| 'scheduler'` | 実行元 |
| `calculatedBy` | `string` | `'system'`（スケジューラー）または `deviceId` / `uid`（手動） |
| `performedByDeviceId` | `string \| null` | 手動実行時のデバイスID |
| `performedByUid` | `string \| null` | 手動実行時のユーザーID（あれば） |

既存データは `calculatedBy: 'system'`、`triggerSource` 未設定の場合は `'scheduler'` とみなす。

## 4. Flutter UI の変更

### 4.1 給与期間ごとタブの改善

| 項目 | 現状 | 改善後 |
|------|------|--------|
| 給与データ表示 | 表示のみ | 表示 + 計算状態の表示 |
| 計算実行 | なし | 「給与計算を実行」ボタン |
| 期間選択 | 前後ボタンで移動 | 同上 + 期間が終了しているか表示 |

### 4.2 「給与計算を実行」ボタン

**配置**: 給与期間ごとタブ内、期間表示の下または右

**表示条件**:
- 選択中の期間の `periodEnd` が今日以前であること
- 例: 今日が 4/1 のとき、3/26〜4/25 は選択不可

**押下時のフロー**:
1. 確認ダイアログ: 「この期間（YYYY-MM-DD 〜 YYYY-MM-DD）で給与計算を実行しますか？」
2. 既に計算済みの場合: 「この期間は既に計算済みです。再計算しますか？」（再実行の許可）
3. `executeMonthlyPayroll` 呼び出し
4. 成功時: スナックバー表示、データ再取得
5. 失敗時: エラーメッセージ表示

### 4.3 計算状態の表示

- **未計算**: 該当期間の `monthlyPayroll` が 0 件 → 「未計算」バッジ
- **計算済み**: 件数あり → 「計算済み（YYYY/MM/DD HH:mm）」または「スケジューラーにより実行」

## 5. スケジューラーの位置づけ

### 5.1 現在の状態

- `schedulerConfig.monthlyPayrollTriggerEnabled` で ON/OFF
- デフォルト CRON: `59 23 25 * *`（毎月25日 23:59 JST）
- `payroll.endDay` が 25 でない店舗では CRON の見直しが必要

### 5.2 運用方針

- **手動主導**: 通常は `monthlyPayrollTriggerEnabled: false` で無効化し、手動実行のみとする
- **補助として有効化**: 手動実行を忘れがちな店舗では有効化し、締め日翌日などに自動実行
- **CRON の柔軟化**: 環境変数 `MONTHLY_PAYROLL_TRIGGER_CRON` で上書き可能（現状済み）

### 5.3 期間計算の修正（スケジューラー）

スケジューラー実行時も「実行日時点で終了している期間」を対象にする。

- 4/26 23:59 実行 → 3/26〜4/25（4/25 は過ぎている）
- 4/1 実行 → 2/26〜3/25（4/25 はまだなので、前の期間）

## 7. まとめ

| 項目 | 内容 |
|------|------|
| **主入口** | 手動実行（`executeMonthlyPayroll` Callable） |
| **補助** | スケジューラー（`monthlyPayrollTrigger`） |
| **共通化** | 給与計算ロジックを `runMonthlyPayrollLogic` に集約 |
| **期間** | 実行日時点で終了している期間のみ対象 |
| **再実行** | 許可（upsert で上書き、監査ログは追加） |
| **UI** | 給与期間タブに「給与計算を実行」ボタン |
| **スケジューラー** | 手動忘れ時の補完として任意で有効化 |

この構成により、一般的な給与計算の運用（勤怠確認→計算→支払）に沿い、手動を主・スケジューラーを補助とする運用が可能になります。
