# アプリフロー一覧 - Step 2: 詳細フロー列挙

**作成日**: 2025-01-XX  
**目的**: 各機能領域の詳細フローをMECEに列挙

---

## 1. 認証・デバイス管理領域のフロー

### 1.1 デバイス登録フロー
1. アプリ起動
2. デバイスID取得（端末固有ID）
3. Firestore `devices` コレクションでデバイス存在確認
4. 未登録の場合：
   - デバイス登録画面表示
   - デバイス名入力
   - プラットフォーム情報取得（iOS/Android/Web）
   - `registerDevice` Cloud Function呼び出し
   - `devices` コレクションに登録（status: 'active', role: 'terminal'）
5. 登録済みの場合：
   - デバイス情報取得
   - デバイスステータス確認（active/blocked/retired）
   - デバイスロール確認（admin/terminal）
   - 適切なホーム画面へ遷移

### 1.2 デバイス管理フロー（管理者）
1. デバイス管理画面表示
2. `devices` コレクションから全デバイス取得
3. デバイス一覧表示（名前・ステータス・ロール・プラットフォーム・登録日）
4. デバイス操作：
   - **ステータス更新**: active ↔ blocked ↔ retired
   - **オプション編集**: プリセットオプションのON/OFF、卓紐づけ設定
   - **削除**: デバイス削除（確認ダイアログ表示）

### 1.3 デバイスオプション設定フロー
1. デバイス管理画面で「オプション編集」ボタン押下
2. 現在のオプション状態を取得
3. オプション編集ダイアログ表示
4. プリセットオプション一覧表示（チェックボックス）
5. オプション選択：
   - 排他制御（tournamentTable ↔ sideGame）
   - 卓紐づけ可能オプションの場合は卓選択ドロップダウン表示
   - 利用可能な卓一覧取得（逆用途に指定されている卓を除外）
6. 「保存」ボタン押下
7. `updateDeviceOptions` Cloud Function呼び出し
8. デバイス一覧を再読み込み

## 2. ユーザー管理領域のフロー

### 2.1 ユーザーアカウント作成フロー
1. ユーザー作成画面表示
2. 入力項目：
   - ポーカーネーム
   - ログインID
   - PIN（4桁）
   - メールアドレス（任意）
3. フォームバリデーション
4. `createUserAccount` Cloud Function呼び出し
5. QRコード生成（`generateQRCode` Cloud Function）
6. QRコード画像をFirebase Storageに保存
7. ユーザー情報をFirestore `users` コレクションに保存
8. 成功メッセージ表示

### 2.2 QRコードチェックインフロー
1. QRチェックイン画面表示
2. カメラ起動（mobile_scanner）
3. QRコード検出
4. QRデータを`processVisitByQR` Cloud Functionに送信
5. バックエンド処理：
   - QRデータからユーザー情報取得
   - 再入店判定（`activeStays` に存在するか）
   - 再入店の場合：入店料徴収設定に応じて処理
   - 新規入店の場合：入店料徴収
   - `bills` ドキュメント作成（status: 'open'）
   - `activeStays` ドキュメント作成/更新
6. 結果表示（成功/失敗メッセージ）
7. ユーザーチェックインページへ遷移

### 2.3 手動チェックインフロー
1. 手動チェックイン画面表示
2. ログインID入力
3. PIN入力（4桁）
4. フォームバリデーション
5. `manualCheckIn` Cloud Function呼び出し
6. バックエンド処理：
   - ログインIDとPINで認証
   - ユーザー情報取得
   - 再入店判定
   - `bills` ドキュメント作成
   - `activeStays` ドキュメント作成/更新
7. 結果表示
8. ユーザーチェックインページへ遷移

### 2.4 入店中ユーザー一覧表示フロー
1. 入店中ユーザー一覧画面表示
2. `activeStays` コレクションをStreamで監視
3. ユーザー一覧をアルファベット順・あいうえお順でセクション分け表示
4. ユーザー選択時：
   - ユーザーアクションホーム表示

### 2.5 ユーザーアクションホーム表示フロー
1. ユーザー選択（入店中ユーザー一覧/サイドゲームテーブル/トーナメント卓詳細）
2. ユーザーアクションホーム表示
3. 利用可能なアクション一覧表示：
   - **プロフィール**: ユーザー情報、ポイント残高、チップ残高
   - **注文**: メニューから注文
   - **注文履歴**: 過去の注文一覧
   - **現在の会計**: 未会計伝票の詳細
   - **現在の座席**: トーナメント/サイドゲームの座席情報
   - **トーナメント履歴**: 参加したトーナメント一覧
   - **チップ・ポイントログ**: チップ・ポイントの入出金履歴
   - **追加料金**: 手動で追加料金を追加
   - **サイドゲーム関連**: Tip管理、Chip購入
   - **トーナメント関連**: Addon、リエントリー、バースト処理

## 3. トーナメント管理領域のフロー

### 3.1 トーナメントテンプレート作成フロー
1. トーナメントテンプレート作成画面表示
2. 基本設定入力：
   - トーナメント名
   - エントリーフィー
   - 開始スタック
   - プライズ割合
   - ポイントタイプ（pointA/pointB）
   - 色設定
3. リエントリー設定：
   - リエントリー可能フラグ
   - 最大リエントリー数（任意）
   - リエントリーフィー（任意）
4. アドオン設定：
   - アドオン可能フラグ
   - アドオンフィー
   - アドオンスタック
5. ブラインド構造選択：
   - ブラインドテンプレート一覧取得（`getBlindTemplates`）
   - ブラインドテンプレート選択
6. 「保存」ボタン押下
7. `createTournamentTemplate` Cloud Function呼び出し
8. `tournamentTemplates` コレクションに保存

### 3.2 ブラインドテンプレート作成フロー
1. ブラインドテンプレート作成画面表示
2. 基本設定入力：
   - ブラインド名
   - アンティタイプ（ante/none）
   - レジスト前ブラインド間隔（分）
   - レジスト後ブラインド間隔（分）
   - レジスト期限レベル
3. ブラインドレベル設定：
   - 各レベルのSB/BB/アンティ設定
   - ブレイク時間設定
4. 「保存」ボタン押下
5. `createBlindTemplate` Cloud Function呼び出し
6. `tournamentBlindTemplates` コレクションに保存

### 3.3 定期開催トーナメント設定フロー
1. 定期開催トーナメント作成画面表示
2. トーナメントテンプレート選択
3. 開始日選択
4. 開始時刻選択
5. 開催間隔選択（1週間/2週間/3週間/4週間/5週間）
6. 開催曜日選択（複数選択可）
7. 終了日設定（任意）
8. 「作成」ボタン押下
9. `createTournamentRecurrence` Cloud Function呼び出し
10. `tournamentRecurrences` コレクションに保存
11. 定期生成トリガーが設定される

### 3.4 単発トーナメント作成フロー（直接入力）
1. 単発トーナメント作成画面表示
2. トーナメントテンプレート選択
3. 開始日入力（YYYY-MM-DD）
4. 開始時刻入力（HH:MM）
5. 「作成」ボタン押下
6. 日時をJST→UTC変換
7. `createScheduledTournament` Cloud Function呼び出し
8. `scheduledTournaments` コレクションに保存

### 3.5 単発トーナメント作成フロー（カレンダー）
1. カレンダー表示画面表示
2. カレンダーから日付選択
3. トーナメントテンプレート選択
4. 開始時刻入力
5. 「作成」ボタン押下
6. `createScheduledTournament` Cloud Function呼び出し

### 3.6 スケジュール済みトーナメント一覧表示フロー
1. スケジュール済みトーナメント一覧画面表示
2. 表示期間選択（昨日/今日/今後7日/7日前以降）
3. `scheduledTournaments` コレクションから該当期間のトーナメント取得
4. トーナメント一覧表示（日付・時刻・テンプレート名・ステータス）
5. トーナメント選択時：
   - トーナメントホーム画面へ遷移

### 3.7 トーナメントホーム表示フロー
1. トーナメントホーム画面表示
2. トーナメント基本情報表示（名前・開始時刻・ステータス）
3. メインビューデータ取得（参加者数・エントリー数等）
4. 操作メニュー表示：
   - **参加者登録**: 入店中ユーザーから参加者を選択して登録
   - **待機者を着席**: 待機リストからユーザーを選択して座席に割り当て
   - **全員リシート**: 全参加者をランダムにリシート
   - **卓追加**: トーナメントに卓を追加
   - **卓削除**: トーナメントから卓を削除
   - **プライズ確定**: プライズ配分を設定
   - **順位確定**: 順位を確定
   - **トーナメント終了**: トーナメントを終了
   - **ブラインドタイマー**: ブラインドタイマー画面へ遷移

### 3.8 参加者登録フロー
1. 参加者登録ダイアログ表示
2. `activeStays` コレクションから入店中ユーザー取得
3. 既に参加登録済み/座席に着席済みのユーザーを除外
4. ユーザー一覧表示（チェックボックス）
5. 参加者を選択（複数選択可）
6. 「参加登録」ボタン押下
7. `registerParticipants` Cloud Function呼び出し
8. バックエンド処理：
   - 各ユーザーの参加登録処理
   - `bills` サブコレクション `tournaments` にエントリー情報追加
   - エントリーフィー徴収
   - 待機リストに追加
9. 結果表示（成功数・失敗数）

### 3.9 待機者を着席させるフロー
1. 待機者を着席させるダイアログ表示
2. 待機リスト取得（待機時間順）
3. テーブル一覧取得（リアルタイム状態監視）
4. 待機者選択
5. テーブル選択
6. 座席番号選択（空席のみ選択可能）
7. 「着席」ボタン押下
8. `assignSeatToPlayer` Cloud Function呼び出し
9. バックエンド処理：
   - 座席にユーザーを割り当て
   - 待機リストから削除
   - `tablesSeat` コレクション更新
10. トーナメントホームを更新

### 3.10 全員リシートフロー
1. 全員リシートダイアログ表示
2. 待機リスト取得
3. 既着席者情報取得
4. リシート対象者選択（待機者・既着席者）
5. 座席容量チェック
6. 「リシート実行」ボタン押下
7. 確認ダイアログ表示
8. 座席決定ロジック実行：
   - テーブルごとの人数を振り分け
   - プレイヤーをランダムにシャッフル
   - 優先順位付けされた座席に割り当て
9. `reseatAllPlayers` Cloud Function呼び出し
10. バックエンド処理：
    - 全座席をクリア
    - 新しい座席割り当てを適用
    - 待機リストをクリア
11. トーナメントホームを更新

### 3.11 卓追加フロー
1. トーナメントホームで「卓追加」ボタン押下
2. 利用可能なテーブル一覧取得（`getAvailableTables`）
3. テーブル選択ダイアログ表示
4. テーブル選択
5. 「追加」ボタン押下
6. `addTableToTournament` Cloud Function呼び出し
7. バックエンド処理：
   - `scheduledTournaments/{tournamentId}/tablesSeat/{tableId}` ドキュメント作成
   - テーブルステータス更新
8. トーナメントホームを更新

### 3.12 卓削除フロー
1. トーナメントホームで「卓削除」ボタン押下
2. トーナメントに紐づいているテーブル一覧取得
3. テーブル選択ダイアログ表示
4. テーブル選択
5. 確認ダイアログ表示（座席に着席者がいる場合は警告）
6. 「削除」ボタン押下
7. `removeTableFromTournament` Cloud Function呼び出し
8. バックエンド処理：
   - 座席に着席しているユーザーを待機リストに移動
   - `tablesSeat` ドキュメント削除
   - テーブルステータス更新
9. トーナメントホームを更新

### 3.13 ブラインドタイマー表示フロー
1. ブラインドタイマー画面表示
2. `scheduledTournaments/{tournamentId}/views/runtime` をStreamで監視
3. 現在のブラインドレベル取得
4. 次のブラインドレベルまでの残り時間計算
5. リアルタイムでタイマー表示（1秒ごとに更新）
6. ブラインド情報表示（SB/BB/アンティ）
7. ブレイク時間表示
8. 操作ボタン：
   - **一時停止/再開**: `api.pause` / `api.resume` Cloud Function呼び出し
   - **次のレベルへ**: 手動でブラインドレベルを進める

### 3.14 プライズ確定フロー
1. プライズ確定画面表示
2. トーナメント情報取得（`getPrizeData`）
3. 売上合計計算（エントリー・リエントリー・アドオンの合計）
4. プライズ割合入力
5. プライズ受け取り人数入力
6. 各順位の配分比率入力（%）
7. 各順位の金額自動計算
8. プライズプール合計表示
9. 「確定」ボタン押下
10. `setPrizeData` Cloud Function呼び出し
11. バックエンド処理：
    - `scheduledTournaments/{tournamentId}/views/main` にプライズ情報保存
    - 各順位のプライズ金額を保存（`1stPrize`, `2ndPrize`, ...）

### 3.15 順位確定フロー
1. 順位確定画面表示
2. バストプレイヤー一覧取得（`getRankingData`）
3. プライズ受け取り人数取得
4. 各順位にプレイヤーを割り当て（ドロップダウン選択）
5. 既に確定済みの順位はロック表示
6. 「確定」ボタン押下
7. 確認ダイアログ表示
8. `setRankingData` Cloud Function呼び出し
9. バックエンド処理：
    - `scheduledTournaments/{tournamentId}/views/main` に順位情報保存
    - 各順位のプレイヤー情報を保存（`1stPlayerName`, `1stPlayerUid`, ...）
    - プライズをユーザーのポイント残高に加算

### 3.16 トーナメント終了フロー
1. トーナメントホームで「トーナメント終了」ボタン押下
2. 確認ダイアログ表示
3. 「終了」ボタン押下
4. `endTournament` Cloud Function呼び出し
5. バックエンド処理：
    - トーナメントステータスを 'ended' に更新
    - 全座席をクリア
    - 待機リストをクリア
    - バストリストをクリア
6. トーナメント一覧画面へ戻る

### 3.17 リエントリーフロー
1. ユーザーアクションホームで「リエントリー」選択
2. トーナメント情報取得
3. リエントリー可能かチェック（`isReentry`, `maxReentries`）
4. 既にリエントリー済み回数確認
5. リエントリー確認ダイアログ表示
6. 「リエントリー」ボタン押下
7. `bustAndReentry` Cloud Function呼び出し
8. バックエンド処理：
    - リエントリーフィー徴収
    - スタックを開始スタックにリセット
    - 待機リストに追加
    - `bills` サブコレクション `tournaments` の `reentryCount` をインクリメント

### 3.18 アドオンフロー
1. ユーザーアクションホームで「Addon」選択
2. トーナメント情報取得
3. アドオン可能かチェック（`isAddon`）
4. 既にアドオン済みかチェック（`addonCount >= 1`）
5. アドオン確認ダイアログ表示
6. 「Addon」ボタン押下
7. `addon` Cloud Function呼び出し
8. バックエンド処理：
    - アドオンフィー徴収
    - スタックにアドオンスタックを加算
    - `bills` サブコレクション `tournaments` の `addonCount` をインクリメント

### 3.19 一括アドオンフロー
1. 卓詳細画面で「まとめてAddon」ボタン押下
2. その卓に着席している全プレイヤー一覧表示
3. アドオン対象者を選択（チェックボックス、複数選択可）
4. 「Addon実行」ボタン押下
5. `bulkAddon` Cloud Function呼び出し
6. バックエンド処理：
    - 選択された各プレイヤーに対してアドオン処理
    - 各プレイヤーのスタックにアドオンスタックを加算
    - 各プレイヤーの `addonCount` をインクリメント

### 3.20 バースト処理フロー（リエントリーあり）
1. ユーザーアクションホームで「バースト&リエントリー」選択
2. トーナメント情報取得
3. リエントリー可能かチェック
4. 確認ダイアログ表示
5. 「バースト&リエントリー」ボタン押下
6. `bustAndReentry` Cloud Function呼び出し
7. バックエンド処理：
    - 座席から削除
    - バストリストに追加
    - リエントリーフィー徴収
    - スタックを開始スタックにリセット
    - 待機リストに追加

### 3.21 バースト処理フロー（退場）
1. ユーザーアクションホームで「バースト&退場」選択
2. トーナメント情報取得
3. 確認ダイアログ表示
4. 「バースト&退場」ボタン押下
5. `bustAndExit` Cloud Function呼び出し
6. バックエンド処理：
    - 座席から削除
    - バストリストに追加
    - トーナメントから完全に退場

### 3.22 卓詳細表示フロー
1. トーナメントホームで卓を選択
2. 卓詳細画面表示
3. `scheduledTournaments/{tournamentId}/tablesSeat/{tableId}` をStreamで監視
4. 座席情報表示（座席番号・プレイヤー名・スタック）
5. 操作ボタン：
   - **まとめてAddon**: その卓の全プレイヤーに一括アドオン
   - **操作履歴確認**: その卓の操作履歴を表示
6. 座席タップ時：
   - 着席済みの場合：ユーザーアクションホーム表示
   - 空席の場合：座席割り当てダイアログ表示

## 4. 会計管理領域のフロー

### 4.1 会計開始フロー
1. 会計管理画面表示
2. 営業日計算（店舗締め時間を考慮）
3. 未会計・会計中の伝票一覧取得（`bills` コレクション、status: 'open' or 'settling'）
4. 伝票選択
5. 「会計開始」ボタン押下
6. `startAccounting` Cloud Function呼び出し
7. バックエンド処理：
    - 伝票ステータスを 'settling' に更新
    - `ops.accountingStartedAt` を設定
    - イベントログに記録
8. 会計編集画面表示

### 4.2 会計前編集フロー
1. 会計編集画面表示
2. 伝票のサブコレクション取得：
   - `extras`（入店料等）
   - `items`（フード・ドリンク）
   - `sideGameChips`（サイドゲームチップ購入）
   - `tournaments`（トーナメント参加）
3. カテゴリ別金額表示
4. 編集操作：
   - **注文追加**: メニューから注文を追加

## 12. 自動処理フロー（バックエンド）

### 12.1 夜間売上再計算フロー
1. 夜間バッチトリガー実行（`nightlyRecalculateBalanceDue`）
2. 前日の営業日を計算
3. `analyticsMonthly` の `net.balanceDueIncl` を再計算
4. 再計算結果を更新

### 12.2 夜間整合性チェックフロー
1. 夜間バッチトリガー実行（`nightlyReconciliationCheck`）
2. `todaysBills` と `bills` の差分をチェック
3. 不整合を検出した場合はログに記録

### 12.3 夜間整合性チェックフロー（全般）
1. 夜間バッチトリガー実行（`nightlyIntegrityCheck`）
2. 各種コレクションの整合性をチェック：
   - `bills` と `activeStays` の整合性
   - ポイント残高の整合性
   - その他の整合性チェック
3. 不整合を検出した場合はログに記録

### 12.4 定期トーナメント自動生成フロー
1. 定期生成トリガー実行（`generateRecurringTournaments`）
2. `tournamentRecurrences` コレクションから有効な定期設定取得
3. 各定期設定について：
   - 次回開催日を計算
   - 該当日が来ている場合、トーナメントを作成
   - `createScheduledTournament` を呼び出し
4. 終了日に達した定期設定は無効化

### 12.5 注文追加時の分析データ更新フロー
1. `placeOrder` Cloud Function実行時
2. `addToDailySummary` を呼び出し
3. `analyticsDaily/{date}` の日次サマリーを更新
4. `addToMonthlyIndex` を呼び出し
5. `analyticsMonthly/{monthId}` の月次インデックスを更新
6. `addToByUser` を呼び出し
7. `analyticsMonthly/{monthId}/byUser/{userId}` のユーザー別データを更新

### 12.6 会計確定時の分析データ更新フロー
1. `completeAccounting` Cloud Function実行時
2. `addToDailySummary` を呼び出し
3. `addToMonthlyIndex` を呼び出し
4. `addToByUser` を呼び出し
